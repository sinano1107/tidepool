# Tidepool WebUI kit

Interactive recreation of the Tidepool PWA — the single-user steering surface, mobile-first (440px), designed from the decided UX docs (no prior UI existed).

Screens (all composed from `components/`):
- **Morning triage** (`triage-screen.jsx`) — the 3-section single-path flow: questions (`TpQuestionCard` — a question task's shared context once, then 1–4 items each with its own title/detail/2–4 options, recommendation marked, free-text override per item; approval questions get an "out-of-authority → approval" badge + risk-propagation note) → decision-log skim (issue #44: entries group by workspace, each entry annotated server-side with its resolved workspace name; groups with unread sort most-recent-unread-first, above any fully-read group, which stays hidden until the section's "show N fully-read workspaces too" toggle reveals it — that toggle only unhides the group, its own read entries still fold same as any other group's; within a group entries run oldest→newest and read entries are always the oldest-side prefix, collapsed behind a single "N more read decisions — show" control that reveals backward in batches of `LOG_READ_BATCH`, with same-frame scroll compensation on `.tp-scroll` since iOS Safari has no CSS overflow-anchor; silence = approval; tap a decision row to object with a required direction; tap a completion row to unfold its handoff doc in place — the objection entry point moves inside the expansion) → queue preview (front-inserted highlighted, scratchpad lines triaged into task / meta-review / discard). A question's answer is atomic (issue #30): the card fires once every item in its bundle has a pick, submitting the whole set in one shot — there is no separate submit button and no partial-answer state, whether the bundle is the common single-item case or a 2–4-item one. Atomic triage commit; waterline shows progress. A floating scratchpad (pain capture, free text allowed) follows all three sections. With zero questions the flow starts at the log skim; "Low tide" shows only when there are no questions AND no unread log entries. Live-mode props (all optional; absent, the screen runs standalone on mock data): `onAnswer` / `onObject` / `onScratchAdd` persist immediately — answers then lock (one-way), removed pad lines become discard dispositions; `onDisplayed` reports each unread entry once it actually enters the viewport (the objection-rate denominator); `loadPreview` fetches the server's staged S3 queue instead of deriving it client-side — live S3 is read-only (nothing touches the queue before commit; reorder lives on the queue screen). Scratchpad disposition keys are the domain vocabulary: `task` / `meta_review` / `discard`.
- **Board** (`board-screen.jsx`) — kanban progress overview: todo / in_progress / blocked / done. `skipped` never appears here.
- **Queue** (`queue-screen.jsx`) — TODO queue with slot line in four states (busy / free / warning / limit — limit renders every row as skipped, the Swell throttle), FIFO order, hover "↑ front" (= run now, also on the head row: front on the head is the immediate-poll trigger), dashed skipped rows, dimmed derived-blocked rows (they hold their position; the slot skips them), an optional "workspace needs human" banner (tree-rule failure), plus the "Your tasks" human list outside the queue.
- **Register** (`register-screen.jsx`) — brain dump → LLM-drafted fields → confirm; appends to queue tail. Plain-form fallback for LLM outage (same fields, no draft).
- **Single question** (`single-question-view.jsx`) — the deep-link target of a daytime push: banner (`TpPushBanner`) → one question card (reuses `TpQuestionCard`, same atomic-bundle behavior as triage — 1–4 items, submits once every item is picked) → parent to front (`TpSingleQuestion`). Trigger via "simulate question push" in the tweaks panel. Live in production (`public/index.html`) as the `?question=<id>` deep-link view — `onAnswer` there POSTs `{ answers }` (one entry per item) to `/api/tasks/:id/answer` instead of touching mock data.
- **Settings** (`settings-screen.jsx`) — the board's admin surface: board-wide preferences (display language, quiet hours, pace offsets) plus the three registry surfaces (workspaces, agents, authority profiles), each a read-only card list + an add form. Structural recreation of `public/index.html`'s `SettingsScreen` for design review — no per-item edit dialogs (WorkspaceCard/AgentCard/ProfileCard's PATCH flows), no API calls; add-forms reset and report through a toast instead of growing the lists, since this kit has no registry behind it.
- **Handoff assist** (in `index.html`) — completing a human task that blocks AI work opens a bottom sheet: free-text dump → LLM-drafted 6-field handoff with ⚠ gap flags → complete with handoff / explicit skip. Isolated human tasks close one-tap.

`index.html` is the interactive shell (bottom tab nav, toasts, working triage commit that front-inserts unblocked parents, one repair task per objected entry, and scratchpad-triaged tasks to the tail). `data.js` holds the fake board state. The tweaks panel's States section switches slot state and the workspace alert for demo purposes.
