# Coding standards

- **A comment whose why comes from a recorded decision names that decision** — `// ADR 0109 決定1: merge-back の前に昇格すると古い remote-tracking ref を読む`. ADR numbers and 決定N are citation addresses (`docs/agents/domain.md`), so the reference makes this code one of the citers counted before an ADR is rewritten or superseded; the why stays beside it so the reader does not have to open the ADR. A why with no recorded decision behind it carries no reference.
- **A record that would be false if its state change did not commit is written in that state change's transaction** (ADR 0405) — the caller wraps the committing helper and the record in one outer `db.transaction` (nesting is a savepoint). A helper that fires non-DB effects after its own transaction (slot, reclaim, poll) is not wrapped; it takes the record as a callback. Two kinds stay outside, and the code says which and why: a fact that is true whether or not the state change happens (a record written before a refusal, the record of an outside write), and a record whose failure was decided not to stop the state change. Writes separated by an `await` or an outside write cannot share a transaction and are read by ADR 0401 instead.
