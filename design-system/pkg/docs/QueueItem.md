The hover "↑ front" action means two different things depending on `isHead`: on the true head row it's "run now" (tide-filled pill, fires an immediate pickup poll); on every other row it's plain reorder-to-head (same tide hue but outlined/transparent, no poll — press it again once the row becomes head to actually run it). Same color family so both read as "the queue action," never a neutral/rock treatment, which this design system reserves for disabled. `skipped` renders dashed and means this row's own resource cannot take it right now; `skipReason` is optional extra text after `skipped ·` — omit it and the row says just `skipped`, never a hardcoded fallback cause. The skip label (`skipped` or `skipped · <reason>`) drops to its own second line inside the row (the same two-row form as the queue slot row's meta, issue #396), so it is readable in full at 375px, where the first line has no width left for it; rows that are not skipped stay a single line. `frontInserted` gets a tide fill.
