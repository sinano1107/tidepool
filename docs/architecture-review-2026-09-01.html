Problem

「この完了は着地したか、次に何をするか」の決定が5ファイルに散り、interface が verdict を返さないので呼び出し側が DB から結果を再導出している。

Solution

着地の3面(merge question / PR 昇格 / open PR への push)と祖先再発火、失敗 question の引退を1つの module に収め、verdict を返す interface にする。

Wins
  • · locality: 着地のバグが1箇所に集まる
  • · 呼び出し側の DB 再読み込みが消える
  • · strict boolean の2方言が1つに
  • · 4 transport が同じ decision を1度だけ叩く
  • · race を pin していたテスト群が不要に
  • · leverage: 1 interface, 4 call sites
Friction evidence

src/mcp.ts:316 のコメントがこの shallow さを自ら書いている — 「着地が成立したかは『throw しなかったこと』では測れない —— 非 strict の handleRootWorkLanding は workspace 不在・needs-human・門の不成立で黙って return する」。 呼び出し側は taskHasLanded を呼び出しの前後で撮り、差分から verdict を再構成する(src/mcp.ts:299-322)。

「今この着地は走れるか」も3つの綴りがある — mcp.ts:216(付帯子のみ、登録時)、 triage.ts:149 landingBlock(未束ねの異議を追加、回答時)、merge.ts:39,43(merge 時)。同じ概念、3つの家。

co-change: mcp.ts / merge.ts / github.ts / tasks.ts のうち2つ以上を同時に触った commit が全史で 47件。 8月の着地系だけで #402 #403 #406 #412 #413 #414 #468 #400 #504 #508。同じ種類のバグが何度も別ファイルで直っている。

Deletion test — concentrates. 昇格失敗 question の引退は既に2度書かれ(mcp.ts:321 と human-verbs.ts:625)、2度直っている(#406 → #412)。

現状が ADR 0041 に反している — この候補がそれを解消する。 relandRootAncestor? / retryPrPromotion? は optional callback として3つの transport に注入されており、配線を落とした盤面は黙って着地しない。ADR 0041「合成 root の option は観測可能で、不在は宣言される」に対する未宣言の不在。ADR 0092 / 0079 / 0073 / 0053 / 0064 の意味論はすべて保存される。再開の必要な ADR は無い。

関連: 「観測が決裁を引退させる」の4サイト(mcp.ts:299-322 / human-verbs.ts:625 / merge.ts:94-113 / merge.ts:50-58)は独立候補として立てられるが、この module の interface に畳んだ方が良い。

Solution

Wins
  • · locality: 検証・ADR 0092 の再発火が1箇所
  • · 4動詞 × 2 transport の drift が消える
  • · leverage: 1 interface, 2 adapters
  • · テストが扉 + 薄い mapping に分かれる
  • · api.ts は 2 exports のまま(深さは不変)
Friction evidence

Deletion test — concentrates. 反実仮想が既に走っている: 扉のある2動詞は1コピー、扉のない4動詞は2コピー。

ADR 0032 は追い風。 義手モデルは管理MCP を「WebUI と同格のもう一つの人間向け UI」と定めており、記録された差は経路 tag(webui / mcp)だけ — 1枚の扉が transport ごとに残す残余そのもの。ADR 0036 の credential 線も同じ信頼域内なので跨がない。

Top recommendation

1. 着地の決定を1つの deep module にする

友人テスト前の直近8週で、同じ種類のバグ — 着地の判定と昇格失敗 question の race — が別々のファイルで 10回以上直っている。 interface が verdict を返さないので呼び出し側が DB から結果を再導出しており、それを src/mcp.ts:316 のコメント自身が認めている。 これは locality の欠如が実測された唯一の候補で、他の4件はまだ「観測された痛み」の手前にある。

次点: 2. 人間面の扉 — 2重化が逐語で、扉は半分建っている 4. 着地済み述語 は候補1の下地としても切れる
探索で反証された仮説(記録として)

· src/claude-worker.ts の29 exports = テストのためだけの抽出 — 反証。16/29 が非テストの importer を持ち、合成後の argv/env は tests/claude-worker.test.ts の40箇所以上で実測されている。むしろ合成に最も絡む2つ(workerSpawnEnv / advisorSpawnFlags)には個別テストファイルが無い。WorkerAdapter の seam は4実装 + contract suite で既に real。

· src/tasks.ts の94 exports = shallow — 反証。20 exports が3以上の caller を持つ leveraged core。問題は shallowness ではなく over-export(候補5)。

· src/api.ts が1921行だから分割すべき — 探索対象外とした。2 exports の背後に1921行は deep であり、分割は shallow module を製造する。
