Top recommendation

1. 確認型 question の登録と解除を1つの deep module にする Strong

7候補のうちこれだけが名前を CONTEXT.md が既に持っていて、module がコードに無い。 ADR 0068 は「新しい停止が生まれたとき増えるのは列挙の1行」という受入基準を書き、読み口にはそれを与えた —— 書き手はいまも6ファイル7箇所で、種類は8つに増えている。決めることが少なく(表の欄を決めるだけで、どの停止がどう振る舞うかは全部 ADR にある)、 触る範囲が既存の挙動と1対1に対応する。grilling の焦点は1つ —— 受理の門の8種類の検査(workspace 解決 / agent 登録 / containment probe / 後始末の再実行 / registry 到達性 / cliAuth / provider 別 auth / harness containment)が表に載るのか、deps の手渡しが別の形で残るのか。

次に置くなら 候補3(Board call の runner) —— 写しが実際に穴を1つ産んでいて(#652)、範囲が5ファイルに閉じている。 候補2(着地の帳簿) は純粋な移動で判断がほぼ要らないので、 他の作業のついでに片付く形をしている。
