# 無人 merge は盤面が最後に push した head だけを merge し、盤面が push していない head への人間の merge は1回拒む

**Status 追記: 決定2・4 の「伝えた」と印の検査を3点で補う(2026-11-21、実装 PR #3489 のレビュー)。決定4 の印の検査だけでは足りない —— 盤面の push と記録は同期で1度に終わるので、回答が head を読む await の間に収束が push・記録・印の解放まで済ませると、回答は印を見ないまま古い head と新しい最後に push した値を組み合わせて読む。(1) 「伝えた」は回答が始まった時点で既にあった記録だけを数える —— 同じ question に同時に走る2つの `merge` の一方が刻んだ記録で、もう一方が commit を見ないまま通らない。(2) 人間の `merge` 回答は最後に push した値を head を読む前にも読み、読んだ後に値が変わっていれば、印があるときと同じく判定せずに答え直させる。(3) 収束の push が転送の後で失敗と報告されたら、印を持ったまま origin の head を読み直し、push した sha と一致すれば最後に push した値として刻む —— 盤面自身の commit を盤面が push していない commit として人間に列挙しない。読み直しも失敗すれば刻まず、Consequences の落ちた場合と同じく止まる側に倒れる。**

2026-11-20 の grilling(issue #3210、発端は #3205 の前提の確認と #3233 の申し送り)で決定。無人 merge が merge してよいかを決める条件は、
CI が緑・積み残しが無い・head が書き換えも巻き戻しもされていない(ADR 0242 決定4 / ADR 0376 決定7)の3つだった。どれも
「盤面の内容が head に含まれるか」を見ていて、「head が盤面の push したものか」は見ていなかった。そのため、盤面が最後に
push した commit の上に外から commit が足された head(以下、**外から進んだ head**)は、足された commit が人間しか書けない
path(ADR 0362)を変えていても、完了の門と人間の目のどちらも通らずに保護ブランチへ入った。書き手が CI の token で動く workflow でも、
人間でも、それ以外でも同じである。読んだコードと道筋は #3210 に置く。

1. **無人 merge は、head が盤面の最後に push した sha(ADR 0242 決定2 の値)と一致するときだけ merge する。** 判定は一致だけで、
   祖先関係は倒し先を選ぶのにだけ使う。最後に push した値を祖先に持たないと確かめられた head(書き換え・巻き戻し)は今どおり
   ADR 0376 決定7 が受ける。それ以外の一致しない head —— 外から進んだ head、祖先関係を確かめられない head、最後に push した値が
   無い head —— は、キューの行を外し、推奨 hold の merge question を立てる。開いていれば足さない。本文は、盤面の知らない commit が
   あることと、その中身を見るコマンド(最後に push した sha から head までの log)を言う。CI の色は待たない —— 緑になっても無人では
   merge せず、CI 赤と重なればこの本文を先にする。
   理由: 足された commit を書いたのが誰かを、盤面は見分けられない。人間しか書けない path に限って止める形は、ADR 0376 が退けた
   「外の commit に完了の門と同じ検査を掛ける」と同じで、門が見ない path(`.github/workflows/*` など)を素通りさせる。
2. **人間の `merge` の回答は、決定1 が question に倒す head(外から進んだ head、祖先関係を確かめられない head、最後に push した値が無い head)に対しては、盤面がその head の外の commit をまだ人間に伝えていなければ1回拒む。**
   拒否文は足された commit を列挙する。伝えた head への次の `merge` は merge する(他の条件は今どおり)。「伝えた」は、
   その head について決定1 の question を新しく立てたか、この拒否を返したかである —— 決定1 の question への最初の `merge` は
   拒まない。すでに開いていた question を返しただけでは伝えていない(本文はその head を言っていない)。判定は決定1 と同じ一致で、
   祖先関係で ADR 0376 の拒否(作業台を開く)と分ける。
   伝えたことの印は盤面の記録に置き、作業台は開かない(落ちた内容が無いので、人間が merge を commit するものが無い)。
   ADR 0376 決定7 の「1回拒んだ」印は作業台の中にあるので、それとは別の置き場になる。理由: merge question は PR ごとに1つで
   head を記録しない。CI 赤などの question が開いている間に commit が足されると、人間は足された commit を見ないまま `merge` と答える。
   伝えた後の `merge` は見たうえでの同意である(ADR 0376 決定5 と同じ読み)。
3. **人間が PR の head へ push して conflict を解いた後(ADR 0376 決定9)も、盤面は人間の push を見分けない。** 人間が答え直すのは
   merge が失敗したときの question で、それは push の前の head について立ったものだから、最初の `merge` は決定2 で拒まれ、
   自分の push した commit が列挙される。次の `merge` で merge する。conflict を解く案内の文は、この1回の拒否を前もって言う。
   この question の上でだけ拒まない形は退けた —— question が開いている間に足された commit を、人間が見ないまま merge する。
   この手間は、人間が PR の head へ push しなくて済むようにする形(#3478)で置き換える方針である。
4. **収束が記録済みの PR へ push するときは、push の前から `pr_branch_pushed` を書くまで、tick と人間の merge 回答と同じ PR の
   in-flight 印(ADR 0236)を持つ。取れなければ撃たず、次の突きに回す(人間の回答の中の収束なら、回答を拒んで答え直させる)。人間の `merge` 回答は、head を読んだ後の同期区間で印を見て、
   印があれば判定せずに拒んで答え直させ、無ければ最後に push した値をその場で読む。** push と記録の間に tick や回答が新しい head を
   読むと、盤面自身の push を決定1 の一致しない head と読む。tick は印を持って読むので飛ばすだけで足りるが、回答は印を merge の
   直前まで取らない。

## Considered Options

- **足された commit が人間しか書けない path を変えるときだけ止める** —— 決定1 の理由で退けた。
- **外から進んだ head をキューに残して待つ** —— 盤面が次に push しない限り着地が止まったまま、人間にも知らされない。
- **昇格失敗 question に倒す** —— ADR 0242 が退けた形と同じで、`retry` が何も変えない。
- **人間の `merge` を拒まない** —— 決定2 の理由で退けた。
- **push の前に「push する sha」を記録する** —— push が落ちても記録が残り、最後に push した値が GitHub に無い sha になる。

## Consequences

- `external` の dial は範囲の外 —— 盤面は merge せず、人間は GitHub の PR 面で足された commit を含む diff を見て merge する。
- 書き手の側 —— worker が書いた workflow 定義が CI で repo の資格情報で走ること、保護ブランチと `task/*` への push の規則 —— はこの決定の外で、比べていない。workflow の token が保護ブランチへ直接 push できるなら、この決定は門の穴を塞がない(#3482 が持つ)。
- 外から進んだ head の CI を GitHub の token の workflow が緑にできるか(#3210 の道筋 2・5)は、この決定に依らない。測らない。
- PR が無いか未記録のときの写しの古さ(#3410)は前提に入らない —— 決定1 は記録済みの PR の event の値だけを読む。
- 決定4 の印は盤面のプロセスの中にあり、push が通って `pr_branch_pushed` を書く前に盤面が落ちると、再起動後は盤面自身の push を決定1 の一致しない head と読む(ADR 0236 が別に扱う落ちた場合と同じ範囲の外、#1820)。止まる側に倒れ、推奨 hold の question が盤面自身の commit を外の commit として列挙する。
- 決定1 の question に `hold` と答えた後の道は、他の PR の hold と同じ —— 人間が GitHub で merge するか close する。足された commit を消して head を最後に push した sha に戻しても、盤面は無人 merge に戻さない。新しい道は作らない。
- 人間が外の commit を作業台で merge し、盤面がそれを push した後は、その sha が最後に push した値になる。決定1 は通常どおり通る。
