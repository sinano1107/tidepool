# workspace の削除の扉も、着地を待つ完了タスクを数える

**Status 追記: 決定1 の「既定は扉が先に拒むので名前の一致だけを数えればよい」の理由は ADR-0233 で置き換わった** — 扉が守るのは今の既定だけで、既定を差し替えた後の旧既定を守れていなかった(issue #1728)。ADR 0233 で着手したタスクは解決した名前を持つので、名前の一致だけを数える決定はそのまま成り立つ。

2026-10-09 の grilling(issue #1627)で決定。workspace の削除の扉は未決着タスクの参照だけを数えていたので、無人 merge
キューに PR がいる完了タスクの workspace を消せた。次の tick は PR も CI も読む前にその workspace を解決して
quarantine に落とし、解除の検査は registry で解決できることを要求するので、修理は扉が消してよいと言ったエントリを戻す
ことしかない。GitHub で PR を閉じてもキューの行は外れない。ADR 0217 決定4 は同じ形を agent 名についてだけ塞いでいた。
再現と経路は #1627 に置く。

## 決定

1. **workspace の削除の扉は、その workspace の着地を待つ完了タスクを数えて拒む。** 数える集合は ADR 0217 決定4 と同じ
   (無人 merge キューにいる、または未着地で PR 昇格失敗の question が開いているか、門で止まって昇格を abandon して
   いない)で、照合する参照だけがタスクの workspace になる。workspace を持たないタスクは実行の瞬間の既定へ解決されるが、
   既定は扉が先に拒むので、名前の一致だけを数えればよい。拒否の理由は agent の扉と同じ「着地を待つ完了タスク」で、
   件数を人間に返す。扉の外で registry から消した場合の修理は、ADR 0217 決定4 と同じくエントリを戻すことである。
2. **workspace の quarantine の解除は変えない。** agent 名の解除には「その名前に依存するものが無ければ通る」道があるが、
   workspace の quarantine は registry からの消失だけでなく、汚れたツリー・`.git` がディレクトリでない・盤面の状態パスと
   の重なり(ADR 0040 / ADR 0146)でも落ちる。それらはエントリが registry に残ったまま壊れている状態なので、依存の
   消失で解除を通すと、壊れたままの workspace が解除される。決定1 の後は、キューにいる PR と門で止まった昇格について
   は、扉を通した削除が quarantine を作らない(abandon 済みのタスクが別 workspace の付帯子の決着で問い直される経路は
   数えの外で、#1729 に置く)。

## Considered options

- **解除の側に「依存するものが無ければ通る」道を足す** — 決定2 の理由で退けた。キューの行は workspace の解決の後で
  しか外れないので、足しても #1627 の行き止まりは解けない。
- **扉は今のまま、余波は quarantine が受け止める** — ADR 0019 の安全網は帯域外の手作業のためのもので、扉が意図的に
  quarantine を作る根拠ではない(CONTEXT.md「削除」)。
