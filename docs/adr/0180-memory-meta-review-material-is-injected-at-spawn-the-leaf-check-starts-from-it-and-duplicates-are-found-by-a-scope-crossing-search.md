# memory meta-review の材料は盤面が spawn 時に注入し、leaf の検査は材料から読み、重複の相手は scope を通した検索で探す

2026-10-01 の triage / grilling(issue #1226)で決定。memory meta-review の task の完了基準は「前回の meta-review 以降の
candidate と店の変更をすべて」処理せよと言うが、その集合を返す読み口が無く、review は前回の watermark も知らされない
まま、`list_memory_entries` の全ページを読むしかなかった。purpose は `list_memory_candidates` も `list_precedents` も名指して
おらず、読まれるかは review の規律に掛かっていた。実測(全件読みの回数と応答量、FTS の AND / OR の当たり)は #1226 の
コメントに置く。

## 決定

1. **leaf の検査は店の全体ではなく周期の材料から読み、それぞれを店に照らす。** 材料 = 前回の登録の watermark より後、
   自身の登録の watermark まで(due が数えた集合そのもの —— 登録から spawn までに入った変更は次の周期の材料)に作成か
   無効化があったエントリで、同じ主題の meta-review 自身の産物は除く(ADR 0151 決定1 と同じ述語)。本文が同じ鎖
   (`path_moved`・復元)は末尾の1行で表し、旧は載せない。candidate は窓ではなく残高(生きているものすべて)。木の検査
   (未定義の枝・複数 workspace の同じ path の定義)は毎周期、枝の一覧の全体を見る。全件を読む口(`list_memory_entries`)は
   残る。前の review が見落とした置き場違いと重複は、その枝に次の変更が来るまで再検査されない —— 誤った本文は異議 →
   cause `memory` の名指しで戻る(ADR 0166)。
2. **材料は review が pull するのではなく、盤面が spawn 時に prompt へ入れる。** 節に入るのは 店の変更(決定1)・生きている
   candidate・前回以降の異議つき判断(`list_precedents` と同じ行)・前回以降に決着した提案(回答・修正値・comment・陳腐化)・
   枝の一覧。必ず読むものを review の呼び出しの規律に任せない —— worker のプロトコルを盤面が注入する線(ADR 0017)と
   同じ。上限は置かない: 完了基準が材料を全部読めと言う以上、上限は「session が始まること」しか守らず、その場面は
   issue #614 が分割の契機とする観測そのものである。渡した材料の id・両端の watermark・token 量を記録に残し、#614 の観測は
   そこで取れる。読み口の verb は、無効化済みの candidate・遡る読み・自分の書き込みの後の読み直しのために残す。
   本 ADR が改める先例: ADR 0020 の「注入は当事者レビューのみ」、ADR 0122 追記(#1225)の前提「meta-review は spawn 注入
   を受けない」、ADR 0122 追記(#1209)決定5 の「枝の一覧は引数なしの verb」(注入に加えて verb も残る)、ADR 0159 決定1 の
   「過去の提案は読み口で読む」(前回以降の決着は注入、それより前は verb)。worker の記憶の節が meta-review に組まれない
   理由(scope の解決と案内する verb、ADR 0122 決定2)はそのまま —— 材料の節は別物である。
3. **重複の相手は scope を通した検索 verb で探す。** 全 scope・全宛先、OR で引いて FTS の順位で返す(AND は言い換えに
   当たらない —— #1226 の実測)。入力は自由文の `query` か `like`(エントリの id。盤面がその title + text で引き、そのエントリ
   自身と本文が同じ鎖は除く)。返すのは生きている approved / candidate と、後継なしで落とされたエントリ(理由つき ——
   人間が誤りとして落とした事実の書き直しを、生きた重複が無いからと残さないため。candidate の「人間が reject したものを
   再提案しない」と同じ規律)。Definition(枝の一覧が全部運ぶ)と置き換えられた行(後継が代表する)は返さない。ポインタ
   だけを 20 件ごとのページで返し、本文は `read_memory_entries` で読む。管理MCP には出さない。

## 退けた案

- **毎周期、店の全体を読み、完了基準の文を全体に直す** —— 材料が1件でも全件読みで、周期ごとのコストが店の履歴に比例する。
- **`list_memory_changes` verb** —— 決定2 で注入に置き換わった。同じ接続の `since_watermark` の既定が verb ごとに違う形も避ける。
- **`list_memory_entries` に `since_watermark` を足す** —— 省略時の意味(全件)が `path` の読みと人間の面で固定されている。
- **盤面が材料の行に似たエントリのポインタを添える** —— 何位までかを盤面が決めることになり、切られた先を見るには結局
  検索が要る。検索の回数が痛むと観測されたら足す(派生 issue)。
- **purpose で verb を名指して読ませる** —— 読まれるかが review の規律に戻る。
- **注入に上限を置く** —— 残りを verb で読む2経路になり、守るのは session の開始だけ。
