# 状態変化が commit されなければ偽になる記録は、その状態変化と同じ transaction で書く —— 呼び出し側が外側の transaction で包む

2026-11-23 の triage → grilling(族の根 issue #3689)で決定。盤面には、状態変化(回答・決着・キューから外す)を1つの transaction で
commit し、対になる記録(決定ログの行・後始末の印・判断行)を、その後の別の文で書く形があった。間で throw するかプロセスが落ちると、
状態変化だけが残る。点で直すたびに別の場所で見つかった(#1935 → #2025 → #3555)。domain の helper が自前の transaction で commit
するので、記録を足す呼び出し側は helper が返った後に書く形になりやすく、「同じ transaction で」は個別の修正にしか残っていなかった。
洗い出しの表、実行時の検出器の実測と試作は #3689 のコメントに置く。

## 決定

1. **DB の中の対の書き込みには原子性を求める。** 両方が残るか、両方が残らないかである。ADR 0401 決定1 が自動の収束を求めなかった
   理由は、外への書き込みが DB の transaction に入らないことだけで、DB の中の2つの書き込みにその理由は無い。最低線に揃えると、
   欠けた記録ごとに最低線を破るかを照らす作業が箇所の数だけ残る。間に await か外への書き込みが要る箇所は1つの transaction に
   できないので、この ADR の外で、ADR 0401 で読む。
2. **線は「状態変化が commit されなければ偽になる記録」である。** 書く順(状態が先か、記録が先か)は問わない。記録どうしでも、
   一方が他方の id を指すなら同じ線で入る(`worker_spawned` と注入の記録)。
3. **外に置くのは2種だけで、置く場所にその理由を書く。** (a) 状態変化が起きなくても真の事実 —— ADR 0288 決定3 の
   `agent_tier_changed`、拒否の前に刻む記録、外への書き込みの記録、`spawn_failed`。transaction の中に置くと拒否や後続の throw で
   巻き戻るので、外に置くことが必須である。(b) 記録の失敗で状態変化を止めないと決めてあるもの —— 今は学習器の shadow 行だけ。
4. **機構は、呼び出し側が外側の transaction で包む形で、新しい機構は足さない。** 入れ子は savepoint になり、外側の throw で
   helper の書き込みも巻き戻る。この形は既に広く使われている。transaction の後に DB の外の効果(slot・回収・poll)を撃つ helper は
   包まない —— 外側が巻き戻っても撃たれた後になる。そういう helper は呼び出し側の記録を callback で受け取る。
5. **同じ帰結の書き込みも包む。** 着地の終わりの記録と、それで閉じる PR 昇格失敗 question は、決定2の線には当たらない(記録は
   question が閉じなくても真)が、割れると着地が進んだのに開いたままの question が残る。記録の後に根が候補から外れる経路では
   閉じ直す機会が無い。
6. **ガードは置かず、規則を CODING_STANDARDS.md に書き、直した箇所ごとに巻き戻りをテストで固定する。** 規則が効くのはレビューの
   時点である(CODING_STANDARDS.md の読み手は code-review)。テストは、記録の挿入を失敗させて状態変化も残らないことを assert する。

## 退けた形

- **ADR 0401 の最低線に揃える** —— 決定1。
- **helper が呼び出し側の記録を受け取る形を既定にする** —— 包めば足りる helper の全部に引数を足すことになる。決定4の例外にだけ残す。
- **実行時の検出器(1つの同期区間で top-level の commit が2回、共通の呼び出し元が `src`)を CI に置く** —— テスト 52 ファイルで
  測った。既知の8箇所のうち3箇所を見逃した(テストのデータで2つ目の書き込みが 0 行になるか、走らない)。当たり 98 種のうち規則の
  対象は約10種で、残りの例外の一覧を行番号で保つことになる。
- **静的検査** —— 決定2の線は記録の意味の判定で、構文や型からは引けないと読んだ。試作はしていない。

## 帰結

- 規則を書いた後に同じ形がもう一度出たら、検出器を検討し直す。試作のパッチは #3689 のコメントにある。
- 限界: 洗い出しは `src` の全部を読んでいない(読んだ範囲は #3689 のコメント)。検出器はテストが通る経路しか見ない。
- 包んだ箇所では、記録の書き込みの失敗が状態変化を巻き戻す。閉じた PR の観測は刻まれず、キューの行か merge question が残って
  次の読みが通り直す。
- 実装は #3555 のコメントの spec。規則の外に置いて最低線に照らしていない行は #3702 が持つ。閉じた観測の告知が workspace を
  読めないときに黙って流れない疑い(#3703)は、包んでも直らない別の欠陥である。
- `retireAutoMerge` のコメントが「外すことと記録を1つにする」の根拠に引く ADR 0105 決定3 に、その決定は無い。根拠はこの ADR に差し替える。
