# purely-local の着地は ff しない —— 常に、第1親が保護ブランチの旧値である merge commit を盤面が書く

2026-11-25 の triage → grilling(issue #3646)で決定。ADR 0401 決定4 は、保護ブランチを動かした後・記録の前に死んだローカル着地の
答え直しに、履歴から「その task を持ち込んだ commit」を読ませる。読む先は保護ブランチの first-parent の列だが、着地は「ff 可能なら ff」
(ADR 0103 決定2)だったので、列は着地の並びにならなかった —— ff した根の履歴がそのまま列になる。死んだ着地の後に、別の根が保護ブランチを
自分のブランチへ merge してから ff で着地すると、先の根の着地は列から外れ、答え直しは後の根の着地の commit を先の根の
`local_merge_executed` に刻んだ(2つの根に同じ sha)。実際の扉での再現と測定は #3646 のコメントに置く。

## 決定

1. **purely-local の着地は ff しない。** ff できる場合も、盤面が Tidepool 名義で、第1親が保護ブランチの旧値・第2親が task の tip の
   merge commit を書く。tree は merge の結果で、ff できる場合は task の tip の tree と同じ。ADR 0103 決定2 の「ff 可能なら今日どおり ff」を
   置き換える —— その ff は ADR 0053 決定3 の写しで、理由だった「ff できない = 帯域外」は ADR 0103 決定1・5 が既に手放している。
2. **着地の commit は、保護ブランチの first-parent の列で読む。** 列の上で task の tip を初めて含む commit がその task の着地で、tip 自身が
   列の上にあれば tip である。purely-local の保護ブランチへの盤面の書き込み(着地の merge、取り込みの包む commit、封じ込めの回答の取り込み)は
   どれも第1親に旧値を置くので、列は盤面の書き込みの並びになる。「基準へ戻す」は盤面の記録の値へ戻すだけで、列に盤面の知らない commit を
   足さない。盤面は動いた ref を受け入れない。
3. **答え直しが残った作業台を片付けるのは、着地の commit の第2親が task の tip と違うときだけ。** 違えば取り込みの包む commit、同じなら
   着地の merge と読み、作業台に触れない(ff の着地で触れなかった線を引き継ぐ)。
4. **変えるのは保護ブランチへの着地だけ。** merge back(子 → 帰り先の `task/*`)の「ff できれば ff」は変えない —— 履歴から着地を読むのは
   保護ブランチだけである。

## 退けた形

- **読み方だけを変える**(列でなく子孫の範囲から、盤面が書いた commit を探す)—— 人間の `merge(自分の commit, 着地した tip)` と盤面の着地の
  merge は形が同じで、名義で分けても、誤って返る commit(別の根の取り込みの包む commit)も盤面の名義である。保護ブランチへ書いた commit かを
  commit message で読む推測が1段増える。
- **限界として閉じる** —— `local_merge_executed` の sha を読むコードは無く、ADR 0401 決定1 の (2) には厳密には当たらない。それでも、
  置いた commit を刻む(ADR 0289 決定1)記録に別の根の commit が入れば、後から見分けて直せない。
- 取り込みで「tip が1つなら fast-forward」を退けた ADR 0371 と同じ向きの決定である —— 記録に入る形を1通りにする。

## 帰結

- すべての local 着地に merge commit が1つ増える。保護ブランチの値は、盤面が `commit-tree` で作った commit だけになる。
- 限界: 他の task のブランチの commit が `task/*` に入りうる残りの道(外の head、ブランチが失われた task、remote-backed で squash された
  ブランチ —— ADR 0382 の追記と ADR 0417 が持つ)で別の根の tip が保護ブランチに入れば、その根の最初の `merge` の回答でも、列の上で
  初めて含む commit は運んだ側の着地である。
