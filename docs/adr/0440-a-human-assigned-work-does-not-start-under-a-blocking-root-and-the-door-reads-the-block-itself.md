# 人間担当の work は塞ぐ根の下で書き始めない —— 扉が pickup と同じ述語を自分で読み、取り込みと完了は止めない

2026-11-27 の grilling(issue #3994)で決定した。pickup は、閉じた根に塞がれた子を飛ばす(ADR 0265 決定6 / ADR 0399 決定6)。人間担当の work の扉(ADR 0374)は、この塞ぎを読んでいなかった。そのため、根の PR が盤面の外で閉じられていても、人間が根の着地を終えていても、`start_work` は通り、作業台は着地しない根のブランチから分かれていた。着地を終えた根のブランチが名前の場所に無いときは、系譜の読みが git で失敗し、名前全体の workspace の Quarantine になった。塞ぎの述語は呼び手が任意で渡す形で、渡さない扉では素通りしていた(#3849 の族と同じ形)。測った手順と表は #3994 にある。

## 決定

1. **人間担当の work の書き始め(`start_work`)は、pickup が飛ばすのと同じ述語で塞がれた子を拒み、何も書かない。** 拒否文は、塞ぐ根と根の種類ごとの出口を言う。盤面の外で閉じた PR の根なら、PR を開き直して merge するか、cancel する。人間が着地を終えた根なら cancel だけである(ADR 0413 決定2)。系譜を読む前に拒むので、根のブランチが名前の場所に無くても workspace の Quarantine にならない。人間の扉が拒否で返し何も書かない形は、ADR 0419 決定4 と同じである。
2. **書き始めた後の取り込み(`take_in_work`)と完了は止めない。** agent も、走っている途中で根が閉じた session の完了と merge back は止まらない。閉じた PR の根は開き直せば着地するので、途中の作業を止める理由が無い。
3. **塞ぎは扉が自分で読み、呼び手が渡さない。** 付け忘れると素通りする形を残さない(ADR 0421 の Status 追記「扉が拒む条件は扉自身が読む」と同じ線)。ADR 0419 の入口の門に同居させるかと、置く行は spec が決める。

## 退けた形

- **人間の着地の終わりを、系譜の「帰り先なし」(ADR 0421 決定3)として記録で読む** —— 着地を終えた根のブランチが無いときの Quarantine は閉じる。ただし、盤面の外で閉じた PR の根は塞がらない。その根には「開き直して merge する」出口があり、帰り先が無いとは言えないからである。
- **止まりを `start_work` の呼び手の側で足す** —— 今の漏れと同じ形を、扉の数だけ写すことになる。

## 帰結

着地を終えた根の下への子の登録を拒むかと、未決着の子を持つ根の PR を draft にするかは、この ADR の外に残る(#4007 / #4008)。WebUI から書き始める操作が無いことは #3454 にある。操作を置くときは、塞がれた子では伏せられる。
