# 無人 merge で merge できない PR は状態で分けてキューから外し、閉じた PR は盤面が決裁を持つ面すべてで観測する

2026-10-10 の grilling(issue #1624、発端は #1392 / ADR 0217 の帰結)で決定。無人 merge キューの PR の merge が失敗し、
PR も merge されていなければ、例外が tick の外へ抜けていた。後ろの PR はその回処理されず、handler の無い rejection で
プロセスが落ち、再起動しても同じ PR で落ちる。ADR 0217 の帰結のとおり、人間が個別の PR を止める手段は GitHub で PR を
閉じることだけで、閉じた PR はまさにこの経路に入る。調べた経路と実測は #1624 に置く。

## 決定

1. **失敗は PR ごとに閉じ込め、tick は reject しない。** 1件の失敗が後ろの PR とプロセスを巻き込まない。分類できない
   失敗はログに出してその PR をキューに残す — 行は着地を待つ完了タスクとして見えたままなので、無言で消える経路
   (ADR 0105 決定3)にはならない。毎 tick event を書く案は、60秒ごとに記録が積もるだけなので退けた。
2. **PR の状態は CI と同じ読み取りで、行為の前に読む。** merge の失敗の後にも読み直す(読んでから merge するまでに
   閉じられ・merge されうる)。同じ読み取りに載せるので網の呼び出しは増えず、60秒面の発火条件も広げない(ADR 0079 決定3)。
   失敗の後だけ読む案は、閉じた PR の CI が赤なら question を立ててしまうので退けた。
3. **状態で分ける。** merge 済みは今どおり観測。**閉じた PR** はキューから外し、盤面の名義の event を残し、question は
   立てない — PR を閉じたこと自体が人間の判断であり、閉じた PR への question は `merge` と答えても執行できない。
   reopen されてもキューへは戻さない(盤面が持つのは「閉じた」という観測だけで、戻せば閉じる行為が止める手段で
   なくなる)。**開いたまま merge が失敗した PR**(conflict・保護による拒否など)はキューから外し、失敗を本文に書いた
   merge question(推奨 hold)を立てる。立てる前に ADR 0217 決定1 の2点目の読み直しを通る。conflict は push が無い限り
   直らないので、キューに残せば同じ失敗を黙って繰り返すだけになる。人間が直さずに merge と答えれば回答は拒まれ、
   question は開いたまま残る — CI 赤の question と同じ形で、新しい種類の question は作らない。**状態が読めない**
   (網・認証)ならキューに残して次の tick へ回す。回数の上限は設けない — 読めた失敗はその回のうちに外れるので、
   打ち切る場面が無い。
4. **閉じた PR の観測を、盤面が決裁を持つ面すべてに揃える。** ADR 0079 決定3 の観測は merge 済みだけを読んでいた。
   遅い走査と回答受理直前のバックストップ(merge question 面)、quarantine 回答の受理直前(ADR 0217 決定5)も、閉じた
   PR を観測して決裁を引退させる。キュー側だけ揃えると、1つの規則が面によって食い違う。quarantine 中の PR は tick に
   スキップされるので、ここで観測しなければ閉じた PR が解除の検査と agent 削除の扉を塞ぎ続ける。

## Considered options

- **merge できない PR はキューに残して event だけ残す** — 待っても直らない失敗を60秒ごとに繰り返し、人間に何も届かない。
- **`mergeStateStatus` で conflict と保護を見分ける** — 閉じた PR でも `BLOCKED` を返し(#1624 の実測)、分類に使えない。
  失敗の中身は question の本文に書けば足りる。

## 帰結

- head を固定した merge(#1625)の「CI を読んだ後に head が動いた」失敗は、この分類に枝を足す形で #1625 が決める。
- 閉じた PR のブランチへ再発火の修理が push される経路(#1734)は別に残る。
