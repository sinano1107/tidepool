# ログ流し読みの面に常時のアクショングリフは置かない — 唯一の明示アクションは行そのものに乗る

issue #231 のグリリングで決定。decision log のエントリに異議を打てないという申告を追ったところ、**経路は存在していた** —— `LogEntry` は行全体がクリック可能で、handoff を持たない行(decision エントリ、および handoff の無い完了エントリ)のタップはそのまま異議入力を開く。欠けていたのは経路ではなく**アフォーダンス**である。可視の印は `@media (hover: hover)` の背景色だけで、コンポーネントの設計意図(「hover reveals the single Object action」)にあったラベルは実装されておらず、そして**朝のトリアージの主面はホーム画面に入れた PWA = タッチであり hover が存在しない**。

**決定: この面では、情報を運ばない常時アクショングリフを置かない。** 全行に異議ボタンを並べる案は却下する —— ログは1画面に何十行も流れる読み面であり、行ごとに同一のグリフが並ぶことは情報量ゼロの視覚ノイズを行数分だけ増やすことに等しい。CONTEXT.md の Objection が「ログ流し読みにおける**唯一の**明示アクション」と言い「沈黙 = 承認」と言う面で、その唯一の例外を全行に描くのは強調の反転でもある。

代わりに、**行タップの意味を kind によらず「異議」に統一する**。今日は handoff を持つ完了行だけタップが展開を意味し、他の行ではタップが異議を意味していた —— 同じジェスチャーが行によって「読む」と「異議する」に分かれていた。handoff の展開は完了行にだけ付くシェブロンへ退く。このグリフは全行には並ばず、「ここに読むものがある」という情報を実際に運ぶ。発見可能性は行ごとではなく、セクション先頭の案内1行が一度だけ負う。

handoff パネルの中の異議ボタンは残す(文言は kind 中立へ)—— handoff を読み終えた瞬間が異議を決める瞬間であり、そこから入れることに価値がある。入口は2つになるが意味は1つなので、統一の線とは衝突しない。

Consequences:

- **サーバ側は一切変わらない。** `raiseObjection` / `bundleObjections` / `renderObjectionPairs` は `HUMAN_FACING_KINDS`(`decision_logged` と `task_completed`)を等しく扱い、束ねの purpose は decision エントリを本文行として、完了エントリを `completion report: …` として既に書き分けている。この issue は最初から UI だけの問題だった。
- **「どの kind が異議可能か」は事実で閉じている。** decision log は `HUMAN_FACING_KINDS` への絞り込みであり、そこに現れる kind はこの2つだけである。`task_escalated` のような kind は元からログに流れないので、異議可能な kind の一覧はログに出る全部と一致する。
- **既存の小さな欠陥が構造的に直る。** 今日 `clickable = !!onObject && !objection` は異議済みの行のクリックを封じるため、handoff を持つ完了行に異議を打つとその handoff を二度と展開できなくなっていた。展開が独立のシェブロンへ移ることで、この結合そのものが消える。
- **スクロール中の誤タップで異議入力が開きうる。** 行全体が的である以上避けられないが、入力して確定するまで何も永続化されないので実害は低い。可視ノイズを全行に増やす代償のほうが大きい、という判断。

Considered options:

- **全行の右端に常時見える異議アクションを置く** — 行タップの意味は「展開があれば展開、無ければ無反応」に統一でき、誤タップも消え、唯一の明示アクションが常に目に見える。却下したのは、そのグリフが行ごとに何の情報も運ばないまま流し読みの静けさを削るため。
- **行タップの意味を今のまま残し、案内1行だけ足す** — 差分は最小でグリフは1つも増えないが、案内文が「handoff のある行は展開、それ以外は異議」という2文になる。規則を覚えさせる側にコストを寄せることになり、ジェスチャーの不整合そのものは残る。
- **decision 行にも展開を作り、全行タップ = 展開に揃える(異議は展開の中のボタン)** — 完了行と完全に同じ形になりグリフも増えないが、decision 行の展開に何を出すかを新たに設計する必要があり、中身が薄ければ「異議ボタンを置くためだけの展開」になる。
- **hover のラベルを設計意図どおり実装する** — 主面がタッチである以上、そこでは何も解決しない。
