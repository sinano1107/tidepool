# skill 許可リストが空の agent のツール面には Skill を載せない

2026-10-01 の triage(issue #1268)で決定。`skills: []` の agent は `--disable-slash-commands` で全禁止される(ADR 0025 点5)。
このフラグは CLI が session の面から `Skill` ツールそのものを外す。一方、盤面は `--tools` に `Skill` を常に載せ、session
の init 行を同じ期待集合で照合する(ADR 0039 決定3)。そのため盤面が自分で書いた食い違いが「観測 ⊂ 期待」の
封じ込めドリフトと読まれ、有効な agent 定義1件で盤面全体の pickup が止まっていた。実測は #1268 のコメントに置く。

## 決定

1. **ツール許可リストは task type と、agent の skill 許可リストが空かどうかで決まる。** 空のとき `Skill` を外す。
   `--tools` と封じ込めの期待集合は、これまでどおり同じ1つの導出から取る。
2. **`--disable-slash-commands` は残す。** 空リストは ping 無しで全禁止する形のまま(ADR 0025 点5)である。
3. **session が実際に受け取る面は変わらない。** `--disable-slash-commands` の下では、`--tools` に `Skill` を載せても
   載せなくても、init の `tools` は同じだった(実測、#1268 のコメント)。変わるのは盤面の宣言だけで、宣言が実際の面に
   合うようになる。

## 退けた案

- **空リストも列挙 ping を通し、列挙された skill をすべて `Skill(名前)` で deny する。** この形なら面は `Skill` を
  保ったままで(実測)、ツール面は task type だけで決まるまま残せる。退けた理由は次の3つである。
  - 空リストの spawn に ping の約2秒と、ping が失敗したら spawn も失敗する失敗経路が乗る。
  - ADR 0038 が測った注入量の削減(約2,800トークン)を失う。
  - 1つも呼べない `Skill` ツールと skill 一覧がモデルに見え続ける。
- **期待集合の側だけで `Skill` を引く。** `--tools` の宣言とセッションが実際に受け取る面が食い違ったまま残る。
