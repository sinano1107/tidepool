# 名前の場所は盤面が最初に触れた時点から盤面の専有領域になり、作業台を開く操作もその1つである

**Status 追記: 決定2 の開く前の項は、着地の最初の撮り(基準の行が無い名前で着地が撮るとき)にも求める。最初に触れる4つの入口のうち着地だけが外れていた([ADR 0399](0399-a-task-remembers-the-repo-its-content-goes-to-and-a-root-that-disagrees-with-the-declaration-stops-alone.md) 決定5、2026-11-22、issue #3390)。**

2026-11-18 の grilling(#3367)で決定。ADR 0351 決定1 は checkout を「最初の pickup 以降」盤面の専有領域とし、最初の撮りはその時点の
中身をまるごと基準に入れる。その後 ADR 0371 が、purely-local の保護ブランチへ人間が内容を入れる道を作業台を開く操作と `take in` に
した。`take in` は local 着地の条件(保護ブランチが基準と同じ)を掛けるので、一度も pickup されていない workspace では基準の行が無く、
盤面は行の無いことを帯域外の移動と読んで workspace の Quarantine を立て、答えても行は作られずに同じことを繰り返した(#3287 の
review で再現、#3367)。task を持たず人間だけが保護ブランチを書く workspace は、線が「最初の pickup」のままでは盤面のものにならない。
観測と、退けた形の穴の表は #3367 に置く。

## 決定

1. **名前の場所が盤面の専有領域になるのは、盤面がその名前に最初に触れた時点 —— pickup・着地・書き始める(`start_work`)・作業台を
   開く操作(`open_workbench`)のどれかの最初の撮り —— からである。** ADR 0351 決定1 の「最初の pickup 以降」を置き換える。
   purely-local と remote-backed で分けない。それより前は人間のもので、checkout に直接書いた内容は最初の撮りが基準に入れる。
2. **作業台を開く操作は、基準の行の無い名前では pickup の最初の撮りと同じ準備を通ってから撮る** —— remote-backed の拒否(text A9)の
   後に、pickup が開く前に掛ける述語、基準の行を持つ workspace の Quarantine が開いている間の待ち(ADR 0373 決定13 追記)、決定13 の
   確認、全撮り。落ちれば作業台も question も開かずに拒む(`start_work` の text C1a の形。Quarantine の立たない落ち方 —— registry が
   読めない —— はその理由を言う)。撮れていない場所に作業台を開けば、`take in` が基準なしで走る。
3. **登録の扉は撮らない。** ADR 0373 決定13 の括弧書き(登録の扉も記録を残さない)と、登録の門の信号を拒否でなく提示する線(#383)は
   そのまま残る。

## 退けた形

- **登録の扉で撮り、登録の時点から盤面のものにする**(この grilling で一度採った)—— 規則は1つになるが、Quarantine が開いている間は
  撮れずに隙間が残り、一度も使わない workspace の Quarantine が削除の扉を止め、汚れた checkout の登録を拒むために #383 を覆し、扉の
  応答に「撮れなかった」を運ぶ口が要る。管理の外に残る workspace を無くす目的は決定1 が作業台を開く操作を数えることで果たせる。
- **`take in` を最初の撮りにする** —— 作業台を開いてから答えるまでの間の直接の書き込みを、比べずに基準へ入れる。
- **行の無い名前の `take in` を比べずに通す**(ADR 0373 決定7 の読み)—— 盤面が持つ前の場所へ盤面が書き、その workspace は
  管理の外に残る。
- **「盤面が持ったことがある」を基準の行と別に記録する** —— 行の無い名前の読み方は読み手ごとに逆(着地は fail-closed、受理は素通し)
  だが、書き込む入口はどれも書く前に最初の撮りを通り、行と task の記録は同じ盤面 DB にあるので、食い違いが出る普通の経路が無い。

## 帰結

- ADR 0351 の表題と決定1 の「最初の pickup 以降」、ADR 0373 決定13 の最初の撮りの場面の列挙(作業台を開く操作が加わる)を、この ADR が
  置き換える。着地と書き始めるの最初の撮りは spec #3273 と #3167 が実装する。
- 人間に見える規則は「盤面がまだ触れていない workspace には直接書いてよい。触れた後は名前の場所に書かず、purely-local は作業台、
  remote-backed は origin の保護ブランチへ」。作業台を開く操作の応答と docs が境目を言う。人間が作った linked worktree での commit も、
  触れた後は同じく止まる。
- spec #3273 と #3287 への上書きは各 issue のコメントが持つ。
