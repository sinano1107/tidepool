# 出元 repo へ push した根は PR を持ちうるものとして扱い、その昇格の断念は探して PR が無いと確かめたときだけ受ける

2026-11-27 の triage と grilling(issue #3887)で決定。

PR 昇格失敗の question は、断念を出すかを根の PR 番号の記録で決めていた。盤面は PR を作ってから番号を記録するので、その間に
落ちた根、作った後の止まりで記録を見送った根(ADR 0429)、作成の要求が失敗と報告された根は、GitHub に PR を持ちながら番号を
持たない。番号の無い根は作る前の探索(ADR 0241 決定4)で拾われるはずだが、食い違い(ADR 0399 決定5)は探索より先に根を止め、
断念が効いた根には収束が撃たない。そこで断念を受けると、判断行は「内容はタスクブランチに残る」と書き、開いた PR は誰も記録
しないまま残る。question の選択肢は立てた時点で固まり、失敗した retry は元の question を開いたまま残すので、立てた後に PR を
作った根にも古い断念が残る。読みの表は #3887 に置く。決定はコードの読みに依り、走らせたものは無い。

## 決定

1. **根が PR を持ちうるかは、PR 番号か出元 repo の記録のどちらかがあることで読む。** 出元 repo は push が届いた後にだけ記録し
   (ADR 0399 決定1 の Status 追記)、PR はその後にしか作らない。記録が無いことを「PR は無い」と読まない —— ADR 0430 決定2 と
   同じ fail-closed の側である。新しい記録は足さない。
2. **番号が無く出元 repo の記録がある根は、番号のある根と同じ選択肢の組を持つ。** 食い違っていなければ retry・断念・「この根の
   着地を終える」、食い違っていれば retry と「この根の着地を終える」である。どちらの記録も無い根は今どおり retry と断念。
3. **番号の無い根の断念は、受ける前にそのタスクブランチの PR を探し、無いと確かめられたときだけ受ける。** 見つかるか探せなければ
   断念を拒み、retry を名指す。retry は作る前の探索を通るので、見つかった PR はそこで記録される。番号のある根の断念は探さない ——
   PR は記録されており、盤面は見失わない(ADR 0241 決定3)。
4. **番号の無い根の「この根の着地を終える」も、PR の根と同じく下の子を塞ぐ。** 盤面が手を引き GitHub にあるものを残すことは、
   PR の有無によらず事実である。ADR 0399 決定6 の「終えられるのは PR を記録した根だけ」はここで変わる。
5. **選択肢の組を決める判定は1つで、question を立てる時点と、断念の回答を受ける時点の両方で読む。** 答える時点の根に断念が
   当たらなければ拒む。番号のある根が立てた後に食い違った場合(ADR 0399 決定5)も同じ読みで塞がれる。

## 退けた形

- **食い違いの question だけ選択肢を直す** —— 作った後の失敗でも同じ断念が出る。
- **作成を試みた記録を PR の作成の直前に足す** —— push が届いて作成が失敗した根も「持ちうる」と読む点で出元 repo の記録と
  変わらず、記録が増えるだけである。
- **持ちうる根から断念を外し「この根の着地を終える」だけにする** —— 作成の要求が拒まれただけの根(最も多い形)が、子孫を
  黙らせない断念を失い、下の子を塞ぐ終わりしか選べなくなる。

## 帰結

- 食い違いで止まった、番号の無い根の PR が GitHub で merge されても、盤面は気づかない。食い違いを解いた後の retry の探索で拾う。
- 告知の文が番号の代わりに何を名指すか、探索の拒否文、断念の回答の探索が見つけた PR を記録するかは spec が決める(#3887)。
- ADR 0399・ADR 0241 に Status 追記を置いた。spec #3920 / #3925 が #3887 に預けた選択肢の組は、決定2 の組である。
