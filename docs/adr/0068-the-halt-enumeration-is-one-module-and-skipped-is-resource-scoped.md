# 盤面全体の停止は1つの読み口 module が列挙で答え、`skipped` は資源単位の理由だけを運ぶ

アーキテクチャレビュー(2026-08-12)からのグリリングで決定。ADR 0058 は「盤面全体の停止は1つの読み口が列挙で答える」と決めたが、実装では列挙が module にならず、4〜5箇所の手組みの部分集合として散っていた — `GET /pause` だけが完全(6信号)、`GET /queue` と管理MCP `list_queue` は同一の3信号コピー(トリアージとレジストリ到達性が欠落)、scheduler は poll の3地点に分散、WebUI は優先順位を JSX の三項演算子連鎖で再表現。帰結として、トリアージセッション中に `list_queue` を読んだエージェントには「キューは流れている」と見え、理由も届かなかった(MCP にはバナーの補完チャネルが無い)。独立に走らせた2つの探索が同じ結論に到達したことも、この欠落が構造的であることの傍証である。

## 決定

### 1. 順序つき列挙は module が1箇所で持つ

`src/board-halt.ts`(用語集「盤面全体の停止」を名乗る)が、停止の**順序つき列挙**を返す唯一の場所になる。順序は トリアージ → Pause → containment → レジストリ到達性 → throttle で、今日 WebUI の連鎖が持っていた表示優先順位を interface に昇格させたもの — 順序が interface に入らない限り、読み手がまた並べ替えるという殺したい形が生き残る。中身は ADR 0058 決定1 の5つで固定し、spend-down(停止ではなく線を外す操舵)と fable 線(資源単位 — 盤面は流れ続けるので「盤面が止まっている」と答えたら嘘になる)は入れない。

### 2. 鮮度と再観測中は throttle entry の属性である

`observedAt` を持つのは throttle の entry だけ — 他の4つは「row / question が存在する」という盤面自身の事実であり、事実の記録に偽の鮮度を与えない(ADR 0058 の「答えは観測の鮮度を伴う」の精密化)。`revalidating`(再観測中)は独立の kind ではなく throttle entry の属性で、entry は「throttled または revalidating」のとき存在する — 再観測中とは「throttle の答えの鮮度が今まさに更新中」という throttle 自身の状態だからである。revalidating の出所は DB ではなく scheduler のメモリ内状態なので、module は合成 root で callback を明示注入される(ADR 0041 の作法)。

### 3. 表示系は同じ列挙を消費し、queue 読み口は envelope になる

- `GET /pause` の応答は `{ halts, throttle, spendDown }` に置き換え(4つの boolean は列挙から導出可能になるため削除 — 残せば同じ答えの2つの綴りを応答の中に作る)。ルート名は据え置き(消費者は WebUI とテストのみで、改名は churn だけを買う)
- `GET /api/queue` と `list_queue` は裸の `BoardTask[]` から `{ halts, tasks }` の envelope になる。管理MCPのエージェントが「なぜ静かか」を同じ1読みで受け取る — 本 ADR が直す実害の本体

### 4. `skipped` は資源単位の理由だけを運ぶ

行の `skipped` から盤面全体の事情(throttle の全体線・Pause・封じ込め能力)を外し、**その行に固有の資源単位の理由**(workspace / agent の quarantine・fable 線)専用にする。盤面全体の停止は行の性質ではなく面の性質であり、envelope の `halts` が1回で答える。`listQueue` の第1引数(盤面全体 boolean)は削除される。行単位の理由文言は当面付けない — quarantine には修理 question が、fable 線にはスロット行の表示が既にあり、減光だけで沈黙は生まれない(痛みが観測されたら足す)。

### 5. scheduler は同期プレフィックスとして同じ列挙を消費する

pickup の同期短絡(トリアージ・Pause・開いている確認 question 2種)は module の列挙から導出する。**stored throttle 状態は消費しない** — scheduler は常に再観測する(ADR 0008 の just-in-time)。生きた検査(containment probe・/usage 観測・registry fetch)とその順序は今の位置に残る — 順序は ADR 0008/0030/0052 が根拠を持つ設計であり、この ADR は列挙だけを共有する。帰結として、registry の確認 question が開いている間は候補選定の前で止まり、その poll では /usage 観測が走らなくなる(壊れている間の無駄な観測が消える — pickup しないという結果は同一)。

### 6. ブラウザのキュー行は `/api/queue` 由来に一本化する

WebUI はこれまで `/api/queue` を読まず、行集合を board(`/api/tasks`)から client 側で再導出し、`skipped` も `paused || throttled` だけから再計算していた — 資源単位の skipped(quarantine・fable)は用語集が「キュービューで現れる」と言っていたにもかかわらず、ブラウザには一度も現れていなかった。fetchData のファンアウトに `/api/queue` を足し、行集合と行単位 skipped をサーバから取る(アイコン付与や front-insert の演出は client 側に残る)。halts も同じ envelope から取る — 行とスロット行が**同一の読みの同一瞬間**から出るので、2つの fetch の隙間で食い違う裂け目が消える。スロット行の常設描画はキュー画面専属である(実測)。

### 7. 盤面全体の停止による全行減光は廃止する

JSX の優先順位連鎖は「サーバ順序の先頭 → kind 別コピー」の写像に置き換わり、pause / throttle 中に全行が薄くなる今日の見た目は消える — 停止は面(スロット行)が1回言う。資源単位の減光(決定6 で初めてブラウザに現れる)は残る。バナーは従来どおりトリアージのみ(ADR 0058 の「確認 question を持たない停止だけが常設」の線は無傷)。

## 挙動の変化

pickup の判断そのものは1ミリも変わらない。観測可能に変わるのは4点 — ①3つの読み口の応答形(破壊的)②盤面全体の停止中の行が `todo` のまま(面が1回答える)③registry 質問が開いている間の無駄な /usage 観測の消滅 ④quarantine / fable 減光のブラウザ初出現。

## 根拠

**1. ADR 0058 の受け入れ基準が既に書かれていた。** 「新しい盤面全体の停止が生まれたとき、増えるのは配線ではなく列挙の1行になる」— 今日それは4〜5箇所の編集であり、`/queue` と `list_queue` の欠落(トリアージ・レジストリ到達性)はこの帰結が実装されなかったことの直接の症状である。

**2. skipped の二義性が欠落の根本原因である。** 行のモディファイアである `skipped` に盤面全体の事情を混ぜた結果、「全行を skipped にする」ことが停止を伝える手段になり、伝え漏れ(トリアージ)と client 側の再計算(6つ目の方言)を生んだ。行の語と面の語を分ければ、面の答えは1箇所から出るしかなくなる。

**3. translation.ts の raw throttle 読みは列挙に巻き込まない。** 表示時翻訳が `getThrottleState` の生の最終観測値を読むのは文書化された意図的な選択であり(その経路に /usage ポーリングが無いため)、盤面全体の停止の問いとは別物である。

## Considered options

- **boolean を残した追加的変更**(halts を足すだけ)— 消費者の追従が要らない。採らなかったのは、同じ答えの2つの綴りを1つの応答の中に作り、drift の芽をむしろ増やすため。消費者は WebUI とテストだけで、どのみち触る
- **revalidating を独立の kind にする** — 今日の連鎖の6腕がそのまま列挙に写る。採らなかったのは、「観測中」と「観測結果」という同じ主題が2 kind に割れ、鮮度は throttle にだけ付くという決定2 と綴りが分かれるため
- **skipped に盤面全体の停止も含める**(全行 skipped + CONTEXT.md 改訂)— 変更が最小。採らなかったのは、盤面全体の停止は行の性質ではなく、WebUI ではバナー/スロット行と二重表現になり、MCP では「全行 skipped だが理由は別読み」という形が残るため
- **行単位の skip 理由文言を今足す** — 減光の説明が行に付く。採らなかったのは、listQueue の SQL に理由列を足すコストに対し、quarantine には修理 question・fable にはスロット行という既存の説明面があり、沈黙が生まれないため(YAGNI — 痛みが観測されたら足す)
- **scheduler のプレフィックスをトリアージ・Pause だけに絞る** — 挙動変更が完全にゼロ。採らなかったのは、「question 型の停止を1つ足すと scheduler が自動で追従する」という共有の利得が半分になり、registry 質問中の /usage 観測の消滅はむしろ良化であるため
- **ブラウザの halts を `/pause` から取る** — 盤面状態の読み口として自然に見える。採らなかったのは、スロット行の常設描画がキュー画面専属である(実測 — キュー画面の外にあるのはヘッダの接頭辞・トリアージバナー・一過性トーストのみ)ため、行と同一の読みから取るほうが裂け目なく座るため
- **`/pause` ルートの改名** — 名前が実態(盤面状態の読み)に合う。採らなかったのは、消費者がテストと app.jsx だけで、改名は追従の churn しか買わないため
