# 無人 merge の読み直しは着地の面を PR の状態の後に読む

2026-10-11 の grilling(issue #1774、発端は #1720 / ADR 0232)で決定。無人 merge キューの tick は、CI を読む前の読み直しで
profile → 門 → 面を一度に読み、その後で PR の状態と CI を読んでいた。そのため GitHub で閉じられた PR(盤面の外で merge
された PR)でも、面が question 側へ変わっていれば推奨 `merge` の merge question が立った。ADR 0229 決定2・3(状態は
行為の前に読む、閉じた PR に question は立てない)の外である。CI が赤の PR でも同じ question が立ち、ADR 0217 決定2
(CI 赤なら推奨 hold の question)とも食い違っていた。再現は #1774 に置く。

## 決定

1. **面は PR の状態の後で読む。** CI を読む前の読み直しは profile と門だけにする。面は、閉じた・merge 済みを観測した
   後で読む。面が question 側へ変わっていれば、CI が赤か、猶予を過ぎても未報告なら CI 赤の question(推奨 hold)を
   立て、それ以外は推奨 `merge` の question を立てる。`external` への変化は、今どおり event を残して外す。こうすると
   ADR 0229 決定2・3 と ADR 0217 決定2 が同じ1か所で満たされる。ADR 0232 の順(profile → 門 → 面、門が閉じていれば
   待つ)と、門が閉じている間は網を読まないこと(ADR 0079 決定3)は保たれる。ADR 0217 決定1 の「CI を読む前と後の
   2点」は、面については後の1点になる。状態の読み取りから行為までに await は無いので、この1点が行為の直前の読みを
   兼ねる。merge が失敗した後の読み直し(ADR 0229 決定3)は await を挟むので残す。増える読み取りは、面が変わった
   PR が外れる前の1回だけである。
2. **CI が pending の PR も、面が変われば同じ tick で外す。** 猶予内の未報告も pending と同じに扱う(ADR 0227 決定2)。
   面の変化をキューで待たせる理由は ADR 0232 の門だけである。ADR 0217 決定2 の「いま開けば立つ question と同じ形」も
   CI を待たない。待たせると、`external` への取り下げも CI の間遅れる。
3. **状態が読めない tick では、面が変わっていてもキューに残す。** 閉じているか分からないまま question を立てれば、
   ADR 0229 決定3 の穴と同じになる。`external` だけ先に外すと、面によって読む順が2通りになる。これは ADR 0232
   決定2 で退けた形である。代償は、網が落ちている間だけ取り下げが遅れることである。

## Considered options

- **面の読みを pending の後に置く** — 決定2 の理由で退けた。
- **閉じた PR への question は回答時の検査に任せる** — 執行は起きないが、閉じた PR の question が一度人間の面に出る。
  ADR 0229 決定3 が退けたのと同じ形である。
