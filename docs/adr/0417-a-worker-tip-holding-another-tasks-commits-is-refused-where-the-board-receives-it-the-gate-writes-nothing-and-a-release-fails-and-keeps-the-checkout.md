# 他の task のブランチの commit を持つ worker の tip は、盤面が tip を受ける口で拒む —— 門は何も書かずに拒み、解放は書かずに失敗にして checkout を残す

2026-11-25 の triage → grilling(issue #3824)で決定。ADR 0382 の追記(#3769)は、他の task のブランチの commit を持つ作業台の tip を
`task/*` へ書く入口でも拒み、取り込みの入口に数える範囲の宣言を必須にした。その型が及ぶのは作業台の入口だけで、worker の tip を
`task/<id>` へ運ぶ2つの手(完了の門と、完了以外の解放の WIP の退避)は別の読み口を直に呼び、履歴を検査しなかった。盤面は worker に
他の task の commit を渡さない(ADR 0411 決定1)が、worker が手に入れる道は設定しだいで在る —— workspace の `allowed_domains` に git host
が入り、盤面が push した別の根のブランチを匿名で読める repo(コードの読み。実測はしていない。読んだ範囲は #3824 のコメント)。
そういう tip が `task/<id>` に入れば、その task の着地が他の task の成果をその task の着地なしに保護ブランチへ運ぶ。

## 決定

1. **検査は、盤面の外で作られた tip を受ける口に置く。** worker の tip を受ける手は1つの受け口にまとめ、他の task の検査の宣言を
   省略できなくする(作業台の入口と同じ形)。ref を書く口には置かない —— そこは盤面自身が作った値(子の merge back、fork 元、
   復元)も通り、merge back は定義上ほかの task の commit を運ぶので、正当かどうかを見分けられない。
2. **数え方は ADR 0382 の追記の「`task/*` へ書く入口で、運ばれる側の無いもの」と同じにする。** 範囲はすべての task。数えないのは
   `task/<id>` の今の値、保護ブランチの今の値、帰り先の今の値にある commit。計算の出所は1つのまま。
3. **完了の門は、`task/<id>` を書く前に検査し、拒否のとき ref も記録も書かない。** 拒否は worker への domain error で、ブランチを
   名指し、自分の commit だけで作り直す手を言う。他の task の変更が要るなら写さずに escalate と言う —— 内容を写すこと自体は
   検査を通る(ADR 0289 決定3)が、未着地の別の根の変更を worker が写せば着地で同じ変更が衝突し、順序を決めるのは人間である。
4. **完了以外の解放の WIP の退避は、`task/<id>` を書かず、解放の失敗にして checkout を残す。** worker の repo が読めないときと
   同じ経路で、failure question が checkout の在り処とブランチを名指す。決着済み(完了済みで門の掛からない task、cancel 済み)では
   event だけを刻み、question は立てない。

## 退けた案

- **門だけに検査を置く** —— 退避が書いた `task/<id>` は、次の session の門で「書く先の今の値」として数えない集合に入り、他の task の
  commit が洗われて通る。
- **退避で盤面が履歴を落とす**(tip の tree だけを旧い値の上の WIP commit にする)—— 内容は残るが、worker 自身の commit の履歴も
  黙って落ち、盤面を迂回した振る舞いが人間に見えない。
- **決着済みの task では観測を刻んで checkout を消す**(checkout が読めないときの形、ADR 0359 決定5 / ADR 0367 決定3)—— あちらは
  残しても読めるものが無い。こちらは読める唯一の写しである。
- **道を塞ぐ**(git host を `allowed_domains` に入れさせない)—— ミラーや別の host が残り、塞ぎきれない。
- **VM で道を実測してから決める** —— 決定1〜4 の形は、どの道が実在するかに依らない。

## 帰結

- ADR 0053 決定4(worker がタスクブランチの土台を動かすことは検知しない)と ADR 0064 の「自分のタスクブランチへの merge は合法」は、
  他の task のブランチの commit についてだけ狭まる。保護ブランチや帰り先を merge して土台を動かす操作は合法のまま。決定4 が検知を
  退けた理由(fork 事実の記録が要る)には当たらない —— 数えるのは今の ref の値だけである。
- 決定4 の失敗では解放の後段(session の間の基準の比較、休止位置へ戻す手)は走らない。ブランチが失われた task の解放(ADR 0393)と
  同じで、次の比較が拾う。
- 限界: remote-backed で worker が、盤面がまだ読んでいない着地を含む origin の保護ブランチを merge した tip は拒まれる(盤面が
  origin を読み直した後の呼び直しは通る)。面接室で走る task では、数える相手は面接室の `task/*` だけで、Interview の root が実
  workspace から取った commit は数えられない(その先は #3859)。ADR 0382 の追記の限界(失われたブランチ、外の head そのもの
  —— ADR 0376 決定11)は残る。
- ADR 0382 の追記、ADR 0359、ADR 0053 決定4、ADR 0064 に Status 追記で指す。実装は1 slice、#3824 のコメントが spec。
