# 着地済みは履歴ではなく内容で測り、fork 元に先立たれた根は merge で追いついてから PR を開く

issue #504 の grilling(2026-08-29)で決定。#400 のトリアージが切り出したケース — W の PR が open の
間に `task/W` から fork した修理 P の完了より先に W の PR が merge されると、P は系譜規則(ADR 0053)
により死んだ `task/W` へ merge back され、W の着地再発火は merge 済み PR の前で**無言で**止まる。
トリアージの静的確認で範囲が絞れた: 盤面自身の merge は常に merge commit なので、fetch 後の
`rev-list` が収束して P は自分で PR を開く(ADR 0053 根拠2 どおり)。座礁するのは**盤面の外で squash /
rebase merge されたとき**だけで、内容は着地しているのに履歴が収束しないことが原因である。測定と
`file:line` は #504 にある。

## 決定

1. **「着地済み」は履歴ではなく内容で測る。** 系譜規則(ADR 0053 決定1)の「候補へ未着地の独自
   コミットを持つ」を「候補へ運ぶ内容を持つ」に置き換える — 祖先のブランチを候補へ merge しても候補の
   木が変わらないなら運ぶものは無い。merge commit / squash / rebase を区別せず、GitHub への問い合わせも
   盤面の記録も要らないので `external` の merge にも効く。fork 時と完了時の両方に同じ述語を使う
   (「着地は fork 元の双対」は維持)。ADR 0073 の「運ぶものが無い完了」も同じ述語で測る — 同一内容が
   既に着地していれば、独自コミットがあっても PR は開かない。
2. **fork 元に先立たれた根は、保護ブランチを Tidepool 名義で merge して追いついてから PR を開く。**
   走行中に fork 元が盤面の外で squash / rebase merge されたタスクは、完了時の規則が保護ブランチを指す
   ので根になるが、履歴に fork 元の元コミットを抱えており、そのまま PR を開くと差分に fork 元の全体が
   重複して載る。盤面は PR を開く前に保護ブランチをそのタスクブランチへ merge し、差分をそのタスクの分
   だけにする。ADR 0103 決定2 の対称形 — タスクブランチは rebase しない。撃つのは系譜の下りで「内容は
   着地済みだが履歴は未収束」の work 祖先を見たときだけで、全 PR の base を追いつかせる形にはしない。
   合わなければ PR は開かず、既存の PR 昇格失敗 question に落ちる(資源は無傷なので quarantine では
   ない — ADR 0103 決定4 の型)。retry は同じ経路を再走するので、人間がセッション外で手で解決すれば通る。
3. **修理が無言で消える経路は残さない。** 内容で測っても「運ぶ内容あり」と読まれる祖先(着地後に
   保護ブランチ側が同じ行を書き換えた)へ merge back した修理が merge 済みの PR に行き当たったときは、
   同じ PR 昇格失敗 question を立てる。立てるのは祖先のブランチがまだ運ぶ内容を持つときだけ — 盤面の外で
   merge された後にレビュー子が決着しただけの再発火は、運ぶものが無いので今日どおり黙って通る。
4. **`auto_if_ci_green` の無人 merge は merge の瞬間にも門を読み直す。** ADR 0092 決定3 の「条件は
   起動の瞬間に読み直す」を、キュー投入時だけでなく merge 実行の直前にも適用する。読む条件は人間の
   merge 回答が回答時に検証されるもの(ADR 0092 決定5 — 未決着の付帯子ゼロ かつ 未束ねの異議ゼロ)と
   同一で、満たさなければ CI を読まずに行を残して次 tick へ。merge commit なので座礁はしないが、修理中の
   成果を無人で運ぶのは ADR 0092 が止めたかった形そのものであり、無人 merge だけが回答時検証を持たない
   面だった。

## Considered options

- **GitHub に live で merge 状態を訊く**(remote-backed では `pr_number` を持つ祖先に `isPullRequestMerged`)
  — 正確だが、同期の系譜規則の外で先に解決して渡す配線が要り、purely-local と規則が二股になる。決定3 の
  残余ケース(squash + 同一行の後続書き換え + 走行中の修理)を根の側で捕まえられる利点はあるが、三重条件で
  しか起きないので、無言を止める最小の手で足り、痛みが観測されたら上乗せする。
- **盤面の記録(`pr_merged` / `pr_merge_observed`)で測る** — `external` の merge は記録が無いので単独では
  成立しない。
- **差分の重複を受け入れてそのまま PR を開く** — GitHub の merge 自体は同一 hunk で自動解決されるので
  座礁はしないが、PR の粒度 = 説明責任の単位(ADR 0073)が崩れ、レビュアーは fork 元の差分をもう一度読む。
- **追いつき merge を slot 解放時に checkout で撃つ** — 綴りは既存の merge back と同じだが、conflict の
  行き先が quarantine の try に入り、決定2 の「資源は無傷 → question」と食い違う。再発火は別セッションの
  走行中にも走るので、checkout に触れない plumbing で着地時に撃つ。
- **無人 merge の門を付帯子だけにする** — 束ね待ちの異議がある間に無人 merge が抜ける。人間回答と同じ
  述語にすれば、異議が立った瞬間から止まる。
