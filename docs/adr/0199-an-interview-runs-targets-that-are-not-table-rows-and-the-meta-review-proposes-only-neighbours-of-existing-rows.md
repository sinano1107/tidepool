# Interview は表に無い対象を走らせられ、meta-review が提案できる対象は表の行の近傍だけである

2026-10-05 の triage / grilling(issue #1347)で決定。ADR 0182 で表の行が具体 id になり、spawn が行の綴りで pin されるように
なってから、表に無いセルは「走ったあとに消された・書き換えられた行」しか現れない。一方で #550 は Interview の子を表の行で
固定し、#921 の提案は「対象が表に無いまま」を pin にしていたので、2枚を合わせると meta-review 発の Interview には走らせ
られる対象が無かった。行に限ったのは #550 の本文だけで、ADR 0111 決定6 は「候補セル」としか書いていない。行に限ると、
測るには行を足すしかなく、足した行はその瞬間に本番の候補になる(`cost` の task では最安の行が先頭で走る)。effort の比較も、
本番の行を書き換えずには測れない。コードの照合は #1347 のコメントに置く。

## 決定

1. **Interview の子は、表の行でない対象で走れる。** 表は本番の候補だけを持ち、Interview は候補になる前に通れる場所になる。
   ADR 0181 決定1 が未観測のセルを最初に走らせるものとして名指した Interview を、表の編集とは別の入口にする。人間が
   第三者の測定を根拠に行を足し、それを Interview で測る道(ADR 0114 決定2 / ADR 0182 決定2)は残る。
2. **対象は (provider, model, effort, tier) で名指し、advisor は本番と同じ規則で導出する。** Interview が答える問いは「この
   model はこのティアの品質を満たすか」(ADR 0114 決定2)で、ティアは問いの一部である。子の要求ティアはこの tier になる。
   advisor を直接名指すと、行を足したあとの本番と別のセルになりえて、Interview の観測が同じセルに数えられない(ADR 0181
   決定4)。「対象が表にある」は4欄の完全一致で判定する。
3. **root review が対象の一覧を欄で持ち、子の pin はその一覧のどれかでなければ盤面が拒む。** 行に限っていたあいだは「表に
   ある」が歯止めだった。purpose の散文のままだと、何が走るかを review agent が決める。登録の扉は行を書く扉と同じ検査
   (既知の Provider、alias の拒否 —— ADR 0182 決定1)をする。走る対象は、人間が1つずつ承認したものだけになる。
4. **行でない対象を Provider が断ったら、対象を名指す Tidepool 名義の question を1枚立て、出口を2つ持たせる。** pin された
   子には別の候補が無いので、ADR 0184 決定4 の「判断が存在しない」は当たらず、`todo` の先頭へ戻すと断られ続ける。鍵は
   (provider, model) で、開いているあいだ子は走らない。「走らせ直す」は盤面が検査し直してから受理し(ADR 0184 決定5 と
   同じ検査)、「この対象は測らない」はその model の子だけを cancel する。兄弟は続く —— 対象は人間が1つずつ承認した
   もので、1つ外すのは分解判断の破棄ではない。openai は pickup 前に読んでいる一覧で対象も照合する。Quarantine の機構を
   借りるが、資源には数えない: 回答が修理の確認とは限らない。
5. **meta-review が提案できる対象は、表にある model の別の effort か別のティアだけで、根拠の episode を添える。** ADR 0150 の
   「根拠を持てるのは分類と effort だけ」をそのまま使う —— 既存の行の提案と同じ軸で、違いは本番を動かす前に測れること
   だけである。表に無い model を持ち込むのは人間だけ。pin は根拠の行の全欄と、対象と一致する行が表に無いこと。approve の
   修正値は purpose に加えて対象の effort / tier で、修正は question の中で行う線(ADR 0150 決定2)を保つ。
6. **Interview の結果を表に入れる提案種別は足さない。** 決定5 の対象の結果は、既存の行の提案(tier / effort の書き換え)に
   根拠として加わる。人間が持ち込んだ model は、findings を読んだ人間が行を足す —— 価格は人間にしか書けず、決める場面は
   Interview の完了であって次の周期ではない。ADR 0150 の「追加は Interview と人間」は変えない。

## 帰結

- ADR 0110 決定4 の新セルの出どころ「観測された未知の id」は、ADR 0182 以後は現れない。新しく観測されるセルは Interview が
  初めて走らせた行でない対象になり、行の提案と人間の行追加の読み物になる。#921 の発火事象「新セル」は消え、提案は根拠の
  episode から出る(ADR 0111 決定6 の「meta-review の要求」)。
- 未知の model への入口を開けるのは引き続き人間である。変わるのは、開けるのに本番を賭けなくてよいことである。人間の把握の
  外にある model に盤面が自分で辿り着くことは、この決定では解けない。
- 人間が足した未観測の行が Interview より先に本番で走ること(#1246)は決めていない。行を足す前に測れるので、行を候補から
  外す門の必要は薄れる。
- 同じ model を別の effort で2行並べられるか(表の主キー)は段の形の問いで、#1346 で決める。この決定は主キーに依らない。
- effort の値域は、行を書く扉も行の提案も検査していない(#1409)。Interview を通せば、走らない effort で落ちるのは本番では
  なく Interview の子になる。

## 退けた案

- **子を表の行に限る(#550 の本文のまま)** —— 冒頭のとおり対象が無くなり、測る前に本番の候補にするしかない。
- **対象をセルの4つ組 (provider, model, effort, advisor) で名指す** —— 決定2。
- **対象を purpose の散文に書く** —— 決定3。
- **断られた子を failure question に落とす** —— abandon は判断ごと破棄で、走れる兄弟の子も道連れになる。
- **断られたことを Interview の結果として黙って決着させる** —— 走れなかったことも、走らせ直す手段も人間に出ない。
- **meta-review に表に無い model を提案させる(Provider の model 一覧、外部の評価、agent の知識)** —— 根拠が「一覧にある」
  だけで、ADR 0110 が退けた一様な探索の代金を、人間の承認の時間と Interview の費用で払う。
- **行の追加の提案種別を足し、価格を修正値で必須にする** —— 決定6。
