# 管理MCP の呼び手は原文の言語を申告し、申告は写しの一致に勝つ

2026-10-10 の grilling(issue #1697)で決定。人間が新しく打った原文には書き込み時点の表示言語が付く(ADR 0175 決定3 の
「人間が書いたものを表示言語で書かれたものとみなす」線)。English の盤面で、チャット側の人間が日本語で話し、管理MCP の
呼び手が日本語の原文を添えると、原文に `English` が付く。管理MCP の説明文はこの添え方を案内してもいた。言語の値は、表示言語
の候補が増えた日に過去の原文が何語かを復元する唯一の手段である(ADR 0223 決定1)。経路と `file:line` は #1697 のコメントに置く。

## 決定

1. **管理MCP の呼び手は、原文を送るなら原文の言語も申告する。申告は必須。** 盤面は言語を判定しない(ADR 0175 決定3)が、
   呼び手は人間が何語で書いたかを知っている。知っている側に言わせる。省略を許して表示言語に戻すと、申告を忘れた English の
   盤面の書き込みにこの issue の偽りがそのまま残る。対象は Memory の書き込みの4つの verb と `answer_question` の修正値で、
   Exemplar は注釈ごとに申告する(言語を注釈ごとに保存しているので、1回の呼び出しに1つでは言語の違う注釈が混ざると偽る)。
2. **付ける言語は、申告 → 写しの一致(ADR 0223 決定2)→ 表示言語、の順で決める。** 申告は写した原文にも勝つ。原文を見て
   申告するのは呼び手で、一致で継ぐと過去に偽って付いた言語が写しに付いて回り、直す手段が無い。ADR 0223 決定2 の「wire に
   言語を足してクライアントに申告させない」は、言語を知らないクライアント(WebUI)についての線として残る。
3. **申告できる値は表示言語の固定リストそのもので、English を含む。** 原文は正文の元になった人間の言葉で、訳元に限らない
   —— 人間の雑な英語を原文に、AI の清書を正文に置く運用がありうる。機械が書いた文で人間の意図の一次資料を置き換えない
   (ADR 0015 四度目の精密化)理由は、訳でも清書でも同じである。リストは写さず表示言語のものを使い、候補が増えれば一緒に増える。
4. **WebUI は申告を送らず、原文欄のラベルは保存したときに付く言語を前もって出す。** 写した原文のまま(Knowledge / Behavior /
   Definition は title と text の組、Exemplar は注釈ごと)ならその原文の言語、書き換えたら今の表示言語。

## 退けた代替案

- **English の盤面では原文を拒む** —— 一次資料を落とす(ADR 0223 が「言語が違えば写さない」を退けたのと同じ理由)。
- **申告を任意にし、省略したら一致か表示言語** —— 決定1 のとおり、忘れた書き込みが偽りを残し続ける。
- **申告と一致が食い違ったら拒む** —— 過去の偽りを直す書き込みが通らない。
- **English を申告の値から除く**(原文は訳元だから) —— 決定3 の清書の運用を消す。
- **WebUI の原文欄にも言語の欄を出す** —— この issue の外。#1732 で扱う。
