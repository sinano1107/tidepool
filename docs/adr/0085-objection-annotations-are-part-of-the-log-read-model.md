# 異議の注釈はログ read model の一部 — セッションの一時表示ではない

issue #371 のグリリングで決定。triage 画面の `objection: …` バッジは画面のローカル state だけで描かれており、`GET /api/log` も `GET /api/triage` も異議を運んでいなかったため、リロードや PWA の再オープンでセッションが開いたままでも打った異議が行から消えていた。直し方には「今の open セッション分だけを配信して復元する」線もあったが、**打たれた全異議をログエントリの注釈として `listLog` に join し、WebUI と管理MCP のログ読取の両方に届ける**ことに決めた。

理由: CONTEXT.md の Objection は「個々のログエントリへの注釈として即時永続化」であり、注釈はエントリの事実であってセッションの状態ではない。ADR 0083 で異議が学習の唯一の入力になった以上、既に束ねられた判断に気づかず同じ異議を重ねる = 重複信号は実コストであり、注釈が読めることがそれを防ぐ。管理MCP のログ読取は純読取なので、そこにも載せることは「Objection の操作は WebUI 専用」の線と衝突しない — エージェントがログを読むとき「この判断には既に人間の異議が付いている」は隠す理由のない判断材料である。

Consequences:

- `LogEntry` に `objections: { comment, session_id }[]` が生える。`session_id` は WebUI が open セッション由来(commit 待ち)と閉じたセッション由来(束ね済み)を読み分け、「N objections bundle at commit」の件数を commit 待ちだけに絞るための最小の事実。`at` などは読み手が現れてから。
- 表示は2状態を区別する — commit 待ちは今日の見た目のまま、束ね済みは退いた見た目で `bundled` を名乗る。ADR 0057 が退けたのは情報を運ばないグリフであり、この区別は情報を運ぶ。
- 画面のローカル state は「今打った分の即時反映」だけの補助になり、真実は配信側にある。

Considered options:

- **今の open セッションで打った分だけ配信する** — 症状には最小で一致するが、注釈が実質「セッションの一時表示」になり glossary とずれ、束ね済みの判断への重複異議を防げない。
- **WebUI 専用の overlay として `/api/triage` に別配列で載せる** — 管理MCP のログ読取は今日のまま保てるが、read model が2つに割れるだけで、異議の可視性を WebUI に閉じ込めたい理由が無い。
