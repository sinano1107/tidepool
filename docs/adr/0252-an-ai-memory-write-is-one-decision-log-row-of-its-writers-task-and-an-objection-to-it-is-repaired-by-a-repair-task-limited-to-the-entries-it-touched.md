# AI の記憶の書き込みは書き手の task の決定ログの1行になり、その異議は触ったエントリに限った修理 task が直す

2026-10-14 の triage / grilling(issue #632)で決定。ADR 0122 決定3 は「記憶の書き込みは書き手の task の記録に属し、決定ログで異議の
対象になる」を原則として置き、実装を #632 に回した。記憶の event は盤面スコープ(task を持たない)の型で固定されたままで、決定ログに
現れず異議も付けられない。今の実装の walk-through と `file:line` は #632 のコメントに置く。

## 決定

1. **異議の対象は AI が直接適用した書き込み —— 作成・畳み・移動・無効化。** candidate の作成は含めない(承認 question が門を兼ね、
   reject の理由 comment が学習の経路 —— ADR 0159)。人間の書き込みと承認(`memory_entry_approved`)も含めない。
2. **行の単位は verb の呼び出し1回で、盤面が task 帰属の「書き込みの記録」を別に書く。** 記憶の店の event(`memory_entry_*`)は
   task を持たないまま残し、書き込みの記録が生まれた記憶 event の id を持つ。pull の記録(`memory_pulled`、spec #586 D)と同じ形。
   畳み1回は判断1回なので、異議も1行に付く。
3. **行の文は盤面が書き込みの記録の構造から組み(自己申告ではない —— ADR 0083 決定8)、エントリへのリンクを持ち、未読に数える。**
4. **書き込みの行への異議は、修理 task が直す。** 修理 task は今どおり異議された task ごとに1本で、束に書き込みの行への異議がある
   ときだけ記憶の修理 verb を登録する(主題つき verb の登録 —— ADR 0122 決定2 と同じ形)。verb の対象は異議された書き込みが触った
   エントリ(作ったもの・無効化したもの、`path_moved` の鎖はたどる)に限る。持つ操作は3つ:
   - 逆操作 —— 作ったものの無効化、無効化したものの復元、移したものの移し戻し。書き込みの前の状態に戻すだけなので門を掛けない。
   - 置き換え —— Knowledge / Definition だけ、同じ scope と path、出所の規則は worker の `record_knowledge` と同じ。Behavior /
     Exemplar の本文を AI が変える経路は candidate → question のまま。
   - 移動 —— meta-review の直接の移動と同じ門(scope は広げる向きだけ、ADR 0176)。

   帰責の入力は行の文と書いた本文(無効化なら落とした本文)、その書き込みより前に読んだ記憶。cause の語彙は増やさない。修理 task の
   書き込みも決定1 の対象なので、それへの異議も同じ形で閉じる。どの異議の修理かは、書き込みの記録の task → 修理 task の
   `objection_event_ids` → 異議の `entry_id` で読め、操作の対象が書き込みの行を一意に決める —— 新しい欄は要らない。
5. **書き込みの記録は Episode のマーカーになり、異議された書き込みは meta-review の材料(Objected decisions)と `list_precedents`
   に載る。** meta-review のセッションには Behavior が注入されず、自分の産物は材料から外れるので、載せなければ meta-review への異議は
   誰にも読まれない。

## 改めるもの

- **ADR 0163 決定1「復元は人間の面だけの操作」に修理 task を加える。** 0163 が meta-review に復元を与えなかった理由は「自分の畳みを
  自分で戻す経路は異議の門を迂回する」で、修理 task は人間の異議を起点に立つので門の内側にある。人間の直接の復元はそのまま残る。

## 退けた案

- **記憶の event そのものに task id を持たせ決定ログの種類に加える** —— 畳み1回が作成1行 + 無効化 N 行に割れ、判断1回への異議が
  行ごとに分かれる。記憶の店の event の「task を持たない」意味も崩れる。
- **修理 task を立てず、人間が settings で直す** —— 判断の行への異議と形が違い、ADR 0163 決定2 の手順(後継を落としてから復元)を
  人間が手で踏む。
- **修理 task を立てず、次の meta-review が材料から直す** —— 周期でしか動かず、復元の verb も無い。
- **修理 task に新しい本文を書かせない** —— meta-review の制約(ADR 0122 決定1)を持ち込んだ誤り。修理 task は worker で、worker は
  今も出所つきで本文を書く。その理由の文自体の誤りは #1916。

meta-review の判断の行への異議が meta-review に届かない既存の穴は #1915。

## 追記(2026-10-17 の grilling、issue #2150 / ADR 0272)

決定4 の「修理 task は異議された task ごとに1本で、束に書き込みの行への異議があるときだけ記憶の修理 verb を登録する」は、行の種類で分ける形に
改めた —— 判断の行は work の修理子、記憶の書き込みの行は第4の task type `memory_repair` の修理子で、記憶の修理 verb は後者が type で持つ。
記憶の修理子は親が cancelled でも Interview の root でも立つ(ADR 0272 決定1・2)。3つの操作と射程の線は変わらない。

## 追記2(2026-10-19 の triage / grilling、issue #1919 / ADR 0278)

決定2 の「行の単位は verb の呼び出し1回」の根拠は判断1回 = 1行で、書き込みの verb が判断を1つ運ぶから呼び出し1回と一致していた。
種別ごとの完了 verb(ADR 0278 決定4)は判断を N 個運ぶので、行は呼び出し1回ではなく判断1つにつき1行(対象を名指す型つきの
`decision_logged`)になる。決定2 の単位は「判断1回」と読む。書き込みの行の形は変わらない。

## 追記3(2026-10-19 の grilling、issue #1915 / ADR 0279)

決定5 の「meta-review のセッションには Behavior が注入されず」は ADR 0279 決定2 で変わる —— 主題つきの meta-review にも盤面全体の
Behavior / Exemplar の節が注入される。材料(Objected decisions)に載せる決定はそのまま。書き込みの行への異議の帰責の入力「その書き込み
より前に読んだ記憶」には、指針の節から読んだ行が `read` として入る(#1927 の答え)。

## 追記4(2026-10-20 の grilling、issue #2304 / ADR 0281)

決定4 の3つの操作の verb 名は code の写しで、本 ADR は名指していなかった。逆操作のうち「移したものの移し戻し」は、エントリ1つなら
`move_memory`(移し戻しの行き先なら門なし)、枝なら `restore_memory_branch`(旧・`move_memory_branch` —— meta-review の枝の改名・統合と
同名で操作が違ったので改名)。「作ったものの無効化」は `invalidate_memory`、「無効化したものの復元」は `restore_memory`、置き換えは
`replace_memory`。移動は meta-review と同じく枝ごとの移動(`move_memory_branch`)を含み、枝は「その書き込みが定義を作った・そこへ
エントリを移した」で射程に入る —— code はエントリ1件の移動しか写していなかった。同じ操作の verb は meta-review 版と1つの tool で、射程は
門に付く(ADR 0281)。
