# root の exit は強制回収の契機で、結果は root の出力の読み切りで確定させる

2026-10-05 の grilling(issue #1336)で決定。worker session の adapter(Claude / Codex)と Board call は、root process の
`exit` の時点で stdout / stderr から読んだ結果を確定させていた。ところが、出力を pipe している先が書き込みに追いつかない間は
読み元が止まり、その間に root が exit すると、`exit` の時点では最後の出力がまだ読み手に届いていない。そのことを計測で確かめた
(`close` の時点では毎回届いていた)。計測表と経路の `file:line` は #1336 の triage コメントに置く。落ちるのは result 行で、
欠けるのは消費の記録だけではない。上限到達による中断(ADR 0104)・行の拒否(ADR 0184)・動力の認証の失効(ADR 0097)の判定も
同じ行から読むので、落ちると「報告なき exit」の failure question(ADR 0145)に化ける。ADR 0145 の観測の瞬間と、ADR 0136
決定5 の「結果は root の exit で返してよい」を改める。

## 決定

1. **root の exit と root の出力の読み切りは別の瞬間であり、exit は強制回収の契機、読み切りは記録の確定点である。** exit を
   見たら強制回収を撃つ(ADR 0109 決定4 のまま)。exit code・消費・stderr 末尾の記録、上限到達・行の拒否の一撃、ADR 0145 の
   盤面側の一撃、Board call の結果は、root が書いたものを最後まで読んだ時点で確定させる。強制回収を読み切りより先に撃っても、
   root が書き終えた出力は失われない。
2. **読み切りには上限を置き、超えたらそれまでに読めた分で確定させる。** 孤児が出力の口を握ったまま回収に失敗したときと、
   出力の写し先が詰まったときは、読み切りが来ない。上限が無いと、worker session は ADR 0145 の一撃を受けずに種別の時間制限
   まで待ち、#724 の偽の question が劣化した経路で戻ってくる。worker session の上限は回収 timeout で、新しい設定値は作らない。
   超えた事実は `worker_exited` に残し、question の文面は変えない。Board call の上限は既存の時間上限で、超えれば結果は無い
   (fail-closed)。
3. **exit から読み切りまでの間に watchdog が畳み込み停止を送った session は、梯子のものとして読まれることを受け入れる。**
   ADR 0145 決定4 の見分けは一撃の時点の送達記録を読むので、この間に止められた session は、停止より先に自分で exit していても
   梯子の底の question で決着する。間はふつう出力が流れ切るだけの長さで、どちらに読まれても question は1枚、root の exit も
   逐語で添えられる(ADR 0191)。
4. **pty の Board call(使用量 TUI)は対象の外である。** 読み手が画面を読み終えた時点で自分で決着させており、root の exit で
   結果を読んでいない。

## 退けた案

- **exit を確定点に残し、全量の記録を pipe でなく自前の書き込みにして読み元を止めない** —— 写し先が遅い間はメモリに溜める。
  しかも「exit は最後の出力より後に来る」という順序に寄りかかる。pipe の無い形で欠けなかったのは観測であって、保証ではない。
- **exit の時刻を控えて、停止の送達時刻と比べて見分ける** —— 決定3 の間のために、一撃の引数を増やすほどの重さは無い。
- **Board call を別の issue に分ける** —— 仕組みが同じで、分けると確定点が2通りになる。
