# 盤面は盤面の家を1つ持ち、2つの盤面は書く置き場を共有しない —— 家の lock が2つ目の process を拒み、家の外の置き場には所属の印を付ける

2026-11-27 の triage と grilling(issue #3961、元は #3931)で決定。

ADR 0001 は盤面を単一 process と決めたが、それを保つ仕組みは無かった。起動時の復旧(restart interrupted の failure
question、閉じていない session の close と一時領域の削除 —— ADR 0315・0344)は、db に行が残っていることを「持ち主はもう
死んでいる」の証拠として読み、生存を確かめない。同じ db を指す2つ目の盤面は、listen の前に1つ目の走行中の task と生きた
session をこの推論で壊す。db が違っても、盤面が書く置き場(Codex home、workspaces、registry clone、tmpdir、容器、cookie)は
既定値のままだと共有され、相手の生きた状態を自分の残骸と読む同じ型の欠陥が置き場の数だけ起こりうる。洗い出した置き場の表と
コードの位置は #3961 に置く。決定はコードの読みと、macOS での SQLite の排他 lock の実測(2つ目は待たずに `SQLITE_BUSY`、
`kill -9` で外れる)に依る。Linux では測っていない。

## 決定

1. **盤面が書く置き場は、すべて盤面の家から導く。** 盤面の家は1つの盤面が書く状態をすべて収める置き場で、2つの盤面は家を
   共有しない。読むだけの credential は共有してよい。置き場を個別に上書きする env は廃し、家を指す env 1つにする(workspaces の
   基点は ADR 0082 のまま残す)。ADR は規則だけを持ち、置き場の一覧と、それを解決する1つの口は spec が持つ。
2. **家の lock が2つ目の process を拒む。** 盤面は最初の書き込みより前に、家の中の lock file を SQLite の排他 lock で取り、process が
   生きている間持つ。取れなければ何も書かずに非 0 で終わり、待たない。OS が持つ lock は process の死で必ず外れるので、lock を取れた
   起動では「前の持ち主は死んでいる」が事実になり、既存の復旧はそのまま正しくなる。cgroup の容器の残骸は既存の前提検査が捕まえる(#463)。
3. **家の外に置くものには所属の印を付ける。** 名前の場所(workspace の checkout の git dir)と registry の repo には、最初に
   使った家の識別子を印として置く。registry の印は seed のときに人間のコマンドが commit で置く(ADR 0089)。lock は「今誰が
   使っているか」、印は「誰のものか」で、二重起動は lock が、共有は印が拒む。印を付け替えるのは人間だけ。
4. **印の食い違いは壊れた資源の軸で1回止める。** checkout の印が別の家を指せばその workspace の Quarantine、registry の印が別の家を
   指せば registry が読めないことの盤面全体の停止(ADR 0403)。起動を拒むのは家の lock が取れないときだけ —— そのときは自分の
   家にさえ書けない。
5. **家は起動前の人間のコマンドが作る。** 識別子は作るときに乱数で生まれて家の中に残り、家を移しても変わらない。盤面は家が無ければ
   起動を拒み、自分で作らない —— seed が識別子を要り、env の綴りの誤りで空の盤面が黙って立たない。家の既定は HOME の下の固定の
   場所で、2つ目の盤面は家を明示する。家の複製は検出せず、人間の操作として扱う。
6. **家ごとに名前が要る共有の名前空間は、家の識別子で分ける。** 容器の名(残骸と読むのは自分の家の容器だけ)と人間面の cookie の名。
   port は env で分け、listen の失敗は名前の付いた停止として非 0 で終わる。

## 退けた形

- **盤面の db 自体を排他 lock で開く** —— 走っている盤面の db を外から `sqlite3` で読む運用(scratch の盤面、実験の台本)を塞ぐ。
- **pid file** —— process の死で残り、stale の判定が要る。ADR 0342 の床で終わる process も残す。
- **lock が空くまで待つ** —— 正常な再起動は古い process を止めてから起動するので待つ必要が無く、待つと二重起動が黙って居残る。
- **db 単位の lock だけ** —— db が違う盤面同士の共有を残す。
- **置き場ごとに lock** —— 置き場を足すたびに lock が増え、足し忘れた置き場は守られない。
- **家の識別子をパスから導く** —— 正当な移動のたびに印と容器の名が食い違う。
- **印の食い違いで起動を拒む** —— grilling で一度採った。1つの名前の場所の食い違いで盤面全体が立たなくなり、壊れた資源の軸で
  止める既存の型(ADR 0040 は起動を拒まず pickup で止める)から外れる。
- **盤面が家を自分で作る** —— seed が家の識別子を要るので家は seed より前に要り、env の綴りの誤りで空の盤面が黙って立つ。
- **盤面ごとに別の cgroup で走らせることを義務にする** —— 独立した盤面を立てるたびに人間の手順が増える。
- **registry の印を置かず、盤面ごとに分けることを文書で決めるだけにする** —— 家の中の記録だけでは2つの家が同じ repo を指すことを
  見抜けず、fail-closed でない。

## 扱わないもの

- 2つの盤面が1つの workspace の remote に push すること(issue #3962)。
- host の Claude CLI の状態(`~/.claude`)を Board call が使うこと —— tidepool の置き場ではなく vendor CLI の状態で、人間の
  Claude Code とも共有する(issue #3963)。
