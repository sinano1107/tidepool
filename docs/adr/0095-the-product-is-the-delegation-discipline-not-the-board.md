# 製品の主語は盤面ではなく委任の規律であり、既存トラッカーは入口になる

issue #437 の grilling(2026-08-22)で決着。直下の README を初めて書くにあたり「そもそも何なのか」を
問い直し、2026-08 時点の OSS 状況を調べ直した(比較表は issue #437 のコメント欄)。

## 決定

1. **製品の主語は「委任の規律」— 決裁権を先に宣言する / 質問は非同期に置く / 判断は記録する —
   であって、Kanban 盤面ではない。** 調査の帰結: モデル非依存と read-only レビューはもはや差別化に
   ならず(Vibe Kanban / Kandev / Paperclip など主要 OSS は10〜49ハーネス対応)、他の誰も試みて
   いないのは「委任ごとに決裁権を先に宣言する」ことだけである。業界は「トラッカーがキューと人間
   ループ(Plane / Linear の `awaiting` / elicitation)を持ち、エージェントが実行を持つ」形に収束
   しつつあり、盤面 UI を主語にすると成熟したトラッカーと正面で競合する。
2. **既存トラッカー(Plane / Linear / GitHub Issues)をタスクの入口にする方向を公開の Roadmap に
   書く。自前 WebUI は捨てず、参照実装として残す。** 友人テストと OSS での実使用の証拠を集めている
   段階で入口を差し替えると着地が遅れる。tidepool 固有として残るのは、決裁権の宣言と検査、判断ログの
   流し読みと異議、Condensation の3つであり、これらはトラッカーの UI では表現できない。
3. **対象は「どんな組織の仕事でも」であり、開発タスク限定とは書かない。** 今日の実装が要求するのは
   「作業が git リポジトリの中で行われ、ワーカーが CLI エージェントである」ことだけで(ADR 0066 の
   purely-local workspace なら GitHub も不要)、文書作業も git に置けばそのまま乗る。

## 退けた案

- **盤面を主語にし、Kanban UI で競う**: Vibe Kanban(27.9k★)・Plane(57k★)と UI で戦うことになり、
  差別化点が2文目以降に沈む。
- **今すぐ WebUI を捨ててトラッカーに乗る**: Plane は AGPL-3.0 なので組み込みは不可で webhook / MCP
  越しの隣接に限られるうえ、エージェント実行は Beta。入口の差し替えは証拠集めの後。

## 帰結

- README / GitHub description は「痛み(babysitting)→ 同僚の比喩 → 決裁権」の順で書き、盤面の
  語を先頭に置かない。
- 競合との軸は1製品1軸: Paperclip「自律する組織 vs 人間が舵を取る委任」、Vibe Kanban 系「許可
  プロンプトを列にする vs 質問を置いて進む」、Ruflo「同期の加速 vs 非同期の委任」。
- 既存記録の「v1」は「最初の完成形の範囲」の意味で据え置き、公開面では 0.x と呼ぶ(CONTEXT.md)。
