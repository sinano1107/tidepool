# トリアージセッションはキュー効果をステージし、放置はタイムアウトで自動コミットする

朝のトリアージ(issue #6)は1つの開いたセッションとして表現される。セッション中は pickup が停止し、人間の入力(回答・異議・scratchpad)は即時永続化される一方、キューへの効果 — 回答で unblock された親の先頭挿入 — はセッションにステージされ、コミット1トランザクションで一括適用される。コミット自体が「run now」であり即時ポーリングを発火する。S3 のプレビューは staged 状態の読み取り専用ビューで、コミット前にライブキューへ触れる経路はトリアージ内に存在しない(「途中離脱してもキューは変化しない」の構造的保証)。

放置されたセッションは活動なし30分で watchdog が自動コミットする。pickup 停止はシステム全体の実行を止めるため、人間の離席が無期限の停止に変換されてはならない。自動コミットは dispositions を持たないので、振り分けられなかった scratchpad 行は消えず、次のセッションが引き取る(書き捨ての中断安全はセッションを跨いで保たれる)。

Considered options:

- **即時適用 + 取り消し** — 回答のたびにキューを動かし、離脱時に巻き戻す。スケジューラから中間状態が見え、巻き戻しの失敗モードが生まれる。アトミックコミットの要件と両立しない。
- **タイムアウトなしのセッション** — 実装は最少だが、朝スマホを置いた瞬間にシステムが無期限停止する。安全弁がない。
- **放置時はステージ破棄** — 「未コミットは無効」と一貫するが、即時永続化した人間の入力(回答・異議)は既に効いており、scratchpad だけ消えるのは記録の劣化(nothing may degrade recording)。採用案は「効果は適用、未振り分けは持ち越し」で入力を失わない。
