# Quarantine の受理は全 ref が基準と同じであることだけを確かめる —— 動いた ref は盤面が「基準へ戻す」で戻し、失われた ref だけが名指しの選択肢で基準に入る

**Status 追記: 決定5 が別の ADR に送った「失われた `task/<id>` を持つ task の後始末」は ADR 0375 が決めた —— task ごとの event、「成果が捨てられた」の数え、着地が終わる根。決定3 と決定5 の選択肢の側は1点だけ変わる —— remote-backed の workspace では、どちらの選択肢も、戻す先の「object が無い」を確かめる前に、盤面が origin からその sha を取りに行き、届いた ref は基準へ書き戻す。origin に届かなければ回答を拒む。決定3 が object の無い ref を名指しして拒むのも、決定5 が失われた ref が無ければ拒むのも、取った後の判定である([ADR 0380](0380-a-lost-task-branch-is-read-through-the-lineage-as-transparent-or-dead-the-board-fetches-the-lost-sha-from-origin-before-counting-and-the-cancel-term-stays-on-the-tree.md) 決定4)([ADR 0375](0375-giving-up-lost-refs-also-settles-the-tasks-whose-branch-was-lost-a-task-whose-git-artifact-is-really-gone-counts-as-discarded-and-its-root-stops-landing.md) 決定1・3・7、2026-11-15、issue #3178)。**

2026-11-13〜15 の wayfinder(map #3178、入口は #3158)で決定。ADR 0370 は「残る穴と根」で、Quarantine の受理が比べずに全撮りし、
開いている間に動いた ref を見せないまま受け入れて merge back で運ぶ穴を、人間の内容の扉の設計に渡した。渡された要件は「門を通った内容を、
回答1つで落とせない」。人間が書く場所と取り込みは ADR 0371 が決めた。この ADR は、受理が何を確かめるか、動いた ref の出口、基準が
やり直される場面を決める。失われたブランチを持つ task の後始末、Codex の封じ込めの検査は、同じ map の別の ADR が持つ。実測・受理の今の順・
`file:line` は ticket に置く(#3183・#3185・#3196・#3208・#3239・#3247。盤面を走らせた実測は #3242・#3243・#3248・#3250、コードの読み直しは #3245)。

## 決定

1. **受理は、全 ref が基準と同じであることを確かめる。「動いた ref を受け入れる」道と受理の全撮りは消す。** ADR 0064 決定7 の動機(動いた
   ref のほうが正しい)は、作業台からの取り込み(ADR 0371)と、決定4 が残す値の拾い直しで表す。動いた値を見せたうえで受け入れる選択肢は
   作らない —— 見せた値は workspace の2つ目の帳簿になる(ADR 0370 が取り下げた形)。比較を通った後の盤面の書き込みは全部口を通るので、
   受理の終わりに基準と ref は一致していて、撮り直すものが無い。受理の中で基準を作り直す道は決定11 の選択肢だけである。
2. **workspace の Quarantine の選択肢は常設の3つで、場面ごとに出し分けない。** `repaired by hand`(違う ref があれば名指しして拒む。意味は
   「ref 以外を手で直した。確かめてほしい」)、`restore the baseline`(基準へ戻す)、`give up the lost refs and restore the baseline`(失われた
   ref を諦めて基準へ戻す)。面接室の名前には `run with an empty room`(空の面接室で走らせる)が加わって4つになる。Quarantine は名前ごとに
   1枚で、本文と選択肢は最初の登録で固定されるので、後から重なった理由に合わせて選択肢を替えられない。「修理を捨てる」と「origin に揃える」は
   選択肢にしない —— 前者は門を通った内容を回答1つで落とす形で、作業台の merge commit で表す(ADR 0371 決定3)。後者の出口は、人間が
   自前の clone から origin へ push することである(squash で入って分岐が残れば、task を cancel → 削除の扉 → 手で直して再登録。この重さは
   承知の上で払う)。
3. **「基準へ戻す」は、最後に受理した状態へ戻す。** 盤面が口を通して、基準と違う ref を全部基準の値へ書き戻し、基準に無い ref は消す。
   戻す先は基準の値そのもので、人間の値(最初の pickup が撮った値など)が入っていてよい。全部を確かめてから書く —— 戻す先の object が
   1つでも無ければ、その ref を名指しして拒み、何も書かない。書く前に tree が clean なら書いた後に tree を HEAD へ揃え、先に dirty なら
   今どおり拒む。予告中の行は、ref がどの値とも違うときだけ、予告の前に行が持っていた値へ戻す。盤面自身が予告なしに ref を変える経路は
   書き手の側で直し(#3197)、この選択肢に例外を作らない。同じ repo を clone し直した checkout で object が全部そろって成功するのは、
   差し替えの受け入れでなく復元として認める。取り下げなかったのは、取り下げると出口が「名前の場所で ref を手で書く」か「受理が動いた ref を
   迎え入れる」に戻るからである。
4. **戻すときに外す値は、盤面が `refs/keep-around/<sha>` で持ち続ける。** 上書き・削除する値のうち sha を持つものごと(`refs/stash` は reflog の
   各件)に、口を通して書いてから戻し、値を event にも残す。口を通した ref は基準に入るので、退避した ref が違反と読まれることは無い。人間は
   作業台で merge か cherry-pick して拾い直す。消す仕組みも本数の警告も作らない —— 数千本は違反を数百回戻した先の数字で(#3247)、重く
   なった workspace の出口は「削除の扉 → 手で消す → 登録し直す」を docs が言う。面接室には何も足さない(決定11 の `git init` で消える)。
5. **「失われた ref を諦めて基準へ戻す」は、戻す先の object が無い ref だけを、今の値で基準に入れる**(ref が無ければ行を消す)。ほかは
   決定3 と同じ手順で、ref と失われた sha を event `lost_refs_accepted` に残す。失われた ref が無ければ拒み、書き戻しの前に保護ブランチの
   ref が在ることを明示で確かめる。盤面が確かめるのは「object が無い」という事実だけである。**基準に無い値を基準に入れる道は、受理の中で
   これ1つである。** object が本当に失われた ref は、内容が回答の前に失われているので要件に当たらない。disk ごと失われた
   checkout の出口もこれである。要件に当たるのは、registry の `path` を無関係な repo へ差し替えた場合で、これも全 ref が失われたと読んで
   通す —— 内容が旧い path に残っていても、手の差し替え1つと回答1つで盤面の記録から外れる。承知の上で採ったのは、名指しの選択肢と event を
   経るので見えるからである。全 ref が失われた形を拒んで「削除の扉 → 再登録」だけにすると、着地待ちの
   task を持つ workspace は扉も通れず、出口が無くなる。失われた `task/<id>` を持つ task の後始末は別の ADR が持つ(#3249)。
6. **`repaired by hand` と「基準へ戻す」は path の差し替えを受け入れない。** 差し替えの正規の道は 削除の扉 → 再登録で、registry の `path` の
   手編集は ref の違いとして同じ文で拒まれる。同じ `.git` を移しただけ、`.git` の形を直しただけなら、ref が基準と同じなので通る。専用の文も
   扱いも作らない。削除の扉は未決着と着地待ちの task を拒むので、それらを持つ workspace は差し替えられない。
7. **比較は受理の中で2回。基準の行が無い名前は比べずに通し、行も作らない。** 比べる場所は名前の場所1つで(面接室の
   名前なら面接室)、Interview の root が読む実環境は入らない。1回目は workspace を引いた直後で、ほかのどの検査よりも前。
   2回目は merge back のやり直しの直前(await の後に `task/<id>` を読んで運ぶので、ADR 0370 決定1 の規則を当てる)。後半の fetch が
   食い違いを吸収する今の振る舞いは残さない。行が無い名前の最初の撮りは最初の pickup がする。受理の順は、workspace を引く → in-flight の
   守り → 比較 → 前半の項 → clean と状態 path → 走行中の session と後始末 → 書き戻し(決定3・5)→ 後半の項 → 済まなかった解放の
   やり直し(ADR 0369 決定1)→ 比較 → merge back のやり直し。比較で拒まれた回答は ref を書かず、後半より後で拒まれた回答は口を通した
   盤面の書き込みが残る(今と同じ)。
8. **in-flight の守りを、同じ名前の場所の ref を書く回答と操作で共有する。** 鍵は workspace の名前1つで、検査中の2つ目は拒む。対象は
   workspace の Quarantine、封じ込めの Quarantine、`intake` の question の回答と、人間担当の work の操作(書き始める・取り込み・完了)。
9. **Quarantine が立つ場面の作業台は、conflict に当たった操作の中で開く**(ADR 0371 決定7 が残した時点)。merge back の conflict は解放の中でも
   受理の中でも開く —— Quarantine を新しく立てた解放なら理由の文が path を言って回答は1回、別の理由で先に開いていれば最初の回答の拒否文が
   言って2回になる。purely-local の封じ込めの修理の作業台は、組の Quarantine の登録の時点で開く。開くのは鍵ごとに冪等である。
10. **封じ込めの Quarantine の受理も、先頭と fetch の後に全 ref を基準と比べる。** 違えば拒み、動いた ref を名指しして workspace の
    Quarantine を立てる。比較器は1つで、基準は撮り直さない。Codex の組にも同じに当たる。
11. **出題前に消えた面接室は「空の面接室で走らせる」で盤面が作り直す。** 在り処に repo が無く出題前であることを確かめ、面接室の基準の行と
    sparse の pin を消してから `git init` し、前半の項から続ける。比較は飛ばす(比べる repo が無い)。ほかの選択肢で repo の無い場所に
    当たれば、比較の前に拒む。ADR 0277 追記 決定2 の fail-closed は保たれる —— 既定では作り直さず、名指しの選択肢への回答が記録になる。
12. **門の掛からない解放は、`task/<id>` の今の値を基準の行と突き合わせてから書く。** 違えば何も書かずに workspace の Quarantine に落とし、
    行は読み返した値でなく書いた値で畳む —— 人間が session 中に動かした値を WIP の退避で黙って上書きし、受理を経ずに基準へ入れていた
    (上書きは #3242・#3248 の実測、畳みはコードの読み)。完了の門は今どおり worker を拒むだけで Quarantine を立てず(ADR 0359 決定4)、人間への知らせは session の
    終わりの解放の比較が出す。門が worker を拒む文は「retry では直らない、escalate する」と言う。書かずに落とした解放の task の checkout は残り、
    成果は受理のやり直し(ADR 0369 決定1)が運ぶ。
13. **registry から引く名前の最初の撮りの前に、基準の行を持つ workspace を全部確かめる** —— 名前が引け、その checkout の全 ref が基準と
    同じであること。欠ければ撮らない。pickup・着地・「書き始める」の最初の撮りに掛け、面接室(鍵は root id)には掛けない。引けない名前は
    (数えるのは名前が registry に無い場合だけで、registry が読めない失敗は数えない)既存の `unknown workspace` の Quarantine がその名前で立ち、ref が違う名前はその名前の普通の違反になる。`workspaces.yaml` の手編集の改名は
    これで止まり、出口は名前を registry に戻すことだけ —— 選択肢も改名の操作も足さない。通るのは、どの行の名前も基準どおりの checkout を
    指しているときだけで、そのとき門を通った内容は元の名前の下に残っている。扉を経ずに足された新しい名前は、この確認を通れば今どおり
    最初の撮りをする(登録の扉も盤面に記録を残さないので、扱いは同じ)。守る線は「`workspaces.yaml` と git の操作だけでは、削除の扉を
    通らずに基準をやり直せない」までで、盤面の DB の直接の書き換えは守らない。名前や path で同一性を追う規則は採らない(どちらも人間が
    書き換えられ、手がかりを足すたびに抜け道が出た)。
14. **基準の寿命は登録から削除までで、削除の扉 → 再登録の全撮りは認める。** 削除から再登録までの間は盤面の持ち物でない。ただし削除の扉は、
    その名前を名指す Quarantine(workspace・封じ込め)が開いていて、かつ名前が基準の行を持つ間は拒む —— 見つかっている違反を 削除 →
    再登録 → `repaired by hand` で比べずに通す道を塞ぐ。行を持たない名前の削除は通し、開いていた Quarantine は削除が閉じて event に残す。
15. **人間が作った linked worktree に盤面は手を出さない。** 「基準へ戻す」と決定5 の選択肢は ref を戻すだけで、掃除もせず、linked worktree を理由に拒みも
    しない —— 値は決定4 が、未 commit の内容は linked worktree の disk が持つ。基準に linked worktree の HEAD も専用の ref も足さない。
    名前の場所の作業ツリーの中に作ったものは、休止中の変更(dirty)の停止で受ける。片付けは docs が言う。
16. **文が言う要素。** Quarantine の本文は「受理は全 ref が基準と同じであることを確かめる」と選択肢がそれぞれ何をするかを言い、違いを
    拒む文は動いた ref を比較器と同じ `was:` / `now:` の形で名指しして出口を言う。merge back の conflict の場所は拒否文か理由の文が言い、本文は
    「conflict があれば拒否文が場所を言う」の固定の1文だけを持つ。封じ込めの修理の文は、purely-local なら作業台の path と branch、
    remote-backed なら origin へ push することを言う。最終文面は spec が書く。

## 退けた形

- **`repaired by hand` の違いを後半の fetch の後に比べる** —— 盤面の予告なしの書き込みの食い違いを今どおり吸収できるが、その食い違いは
  書き手の側で直す(決定3)。
- **退避しない**(event に値を残すだけ)—— 消えた branch は reflog ごと消え、最初の gc で object が落ちうる(#3194 の実測)。
- **口が予告の前に行を畳む** —— 効くのは巻き戻しが1段浅くなることだけである。
- **改名に追随する / 引けない名前を「削除済み」として片付ける回答 / 手編集を塞ぐ / 削除の扉が消す前に基準と比べる** —— 行に path が要る、
  回答1つが削除の扉の検査を迂回する、registry の正規の変更(PR)も key を変えられる、消した後に動かせば同じ結果になる。
- **盤面が linked worktree を掃除する / checkout 中なら拒む** —— 掃除は未 commit の内容を消す唯一の案で、拒む案が守る再違反は次の比較が捕まえる。

## 帰結

- `done` ⇔ tip が記録にある(ADR 0359 決定1)は、失われた ref を受理した task で破れ、event がその例外を記録する。
- 基準の行に入る値は、最初の撮り・盤面が予告した値・決定5 が入れる今の値の3つになる(ADR 0243 決定2)。
- 解放の中で立った Quarantine は、その後始末が終わるまでどの選択肢でも答えられない。
- 最初の撮りは無関係な workspace の違反で止まりうる。止まった task と着地をどの資源の停止として持つかは spec が決める。
- 実装の spec は ADR 0369 の spec(#3152)、#3197、ADR 0370 の spec(#3166)に依る。
