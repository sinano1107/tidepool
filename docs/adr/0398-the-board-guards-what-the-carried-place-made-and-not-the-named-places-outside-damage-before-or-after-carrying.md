# 盤面が運ぶときに守るのは運んだ場所が作った object —— 名前の場所に外から起きた損傷は、運ぶ前でも後でも守らない

2026-11-21 の grilling(issue #3494、#3222 の実装の派生。#3484・#3501 を畳んだ)で決定。ADR 0388 決定1 は、運ぶときの集合を「運ぶ tip の閉包のうち、運んだ場所の自前の store にある object」とし、借りている object を「消しても失われない」として外した。実装では、名前の場所の損傷を、確かめが3つの形で素通しした。

- (a) 借りている tree の下にある自前の object を、集合の walk が数えない。
- (c) 集合の object の loose が、名前の場所で zlib として正しく別の中身になっていても、確かめの `pack-objects` が通す。
- (b) 盤面の staging repo の `git add` が、名前の場所の壊れた同じ id の loose を使い、自前の store に書かない。

この grilling では、族の根を二度置き直した。最初の根「解放は消す前に、中身が別の場所にあることを確かめていない」は、ADR 0388 が採ってから取り下げた「消す前に確かめる」と同じ形で、退けた理由に答えていなかった。次に (a) を ADR 0388 決定1 の文面の実装の欠けと読み、名前の場所を読んで閉包をたどる数え方を組んだ。しかし、名前の場所の bytes に頼る分だけ、穴(在って壊れている object、帰責の割れ、借りている tree そのものの欠け)が続いた。守る範囲を bytes の置き場で決めていたことが根だった。実測と各形の手順は #3494 に置く。

1. **守るのは、tip から自前の object だけをたどって届く、自前の object である。** これは運んだ場所が作ったもので、消せば最後の写しを失う。ADR 0388 決定1 の集合はこの意味に読み直す。今の walk(alternates を外し、借りている tree で止まる)がちょうどこれを数えている。
   - 新しい tree が直に指す object はこの集合に入る。名前の場所で読めなければ、ADR 0364 決定1 の検証の段でも ADR 0388 決定2 の入れ直しへ進める(#3501)。ADR 0388 決定3 の「除外で取りこぼした object は決定1 の確かめが捕まえ、決定2 が補う」は、これで直に指された object にも成り立つ。
   - 集合の object の名前の場所の loose が別の中身になっていれば、破損に数える((c))。
2. **借りている tree の下の object は守らない。** 名前の場所が無傷なら、その object は名前の場所に在る。自前の store にも写しがあることはある(sandbox で freshen が落ちると、worker の git は手元に書く)が、その写しは最後の写しではない。自前の写しが最後の写しになるのは、名前の場所が先に外から壊れ、worker がたまたま同じ bytes を書き直していたときだけである。(a) と (b) の違いは、git が自前の store に書いたかどうかだけで、損傷の性質は同じである。
3. **名前の場所に外から起きた損傷は、運ぶ前でも後でも守らない。** ADR 0388 決定4 の線を、運ぶ前に延ばす。ADR 0388 決定1 の「借りている object は消しても失われない」は成り立つ前提ではなく、この限界の言い換えである。名前の場所で先に欠けているか壊れている借りている object は、正しい bytes が checkout にしか無くても、運んで checkout を消す。守るには、名前の場所の閉包を運ぶたびに読むか、staging が名前の場所を借りずに作業ツリーの全 file を書く必要があり、どちらも費用が repo か作業ツリーの大きさに比例する。worker 自身の commit は盤面が制御できない。
4. **盤面は名前の場所の健全性を確かめない。** 欠けや破損は、人間か盤面の次の git の操作が出す。確かめの費用は repo 全体に比例するうえ、決定3 で守らない損傷に気づいても盤面にできることが無い(#3484 は not planned)。

## Considered Options

- **消す前に、中身が別の場所にあることを確かめる** —— ADR 0388 が退けた形。保証を「消す」に置くと、窓の幅が偶然で決まり、消す箇所ごとに出口が要る。
- **自前の store の object を、閉包のどこにあっても守る**(ADR 0388 決定1 の文面の字面)—— 借りている tree の下まで数えるには、名前の場所の bytes を読んで閉包をたどるしかない。名前の場所が壊れているときに頼れない bytes に、守る範囲の判定が乗る。この grilling で一度採り、穴が続いたので取り下げた。
- **名前の場所に無い自前の object を全部入れ直す** —— worker が捨てた届かない object を名前の場所に積む。ADR 0388 が「毎回入れる」を退けた理由と同じ。

## Consequences

- Status 追記: ADR 0388 決定1(集合の意味と、借りている object の前提)・決定3(直に指された object)・決定4(運ぶ前に延ばす)、ADR 0364 決定1(検証の段から入れ直しへ進む)。
- #3494 から分けた問い(門の無い完了済みの解放で、worker の段の失敗で checkout を消すか)は #3579 に置く。
