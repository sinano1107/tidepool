# Spend-down の arm は窓に結ばれ、idle の窓は次に開く窓への arm を受ける

2026-10-15 の grilling(issue #853)で決定。ADR 0143 の決定4・5 を置き換える。arm が当たるかを「arm の時刻 ≧ 窓の
開始(reset − 窓の長さ)」で決めていたが、Claude の `/usage` の reset 表示は分単位で早い側へ揺れ(実測は #853)、
idle の間の arm の直後に開いた窓に Spend-down が当たっていた。時刻の比較に余裕を持たせる直し方は、窓が開く前・
開いた直後に arm したいニーズ(week の期限が迫り、session がまだ idle のとき)を、窓を開いて数分待ってから押し
直す手間に変える。session の予算は窓の頭でも窓の終わりに失効するので、頭からの arm は指針「使い切ってよいのは、
もうすぐ失効する予算だけ」に反しない。

## 決定

1. **arm は窓に結ばれる。** arm の時点でその (provider, window) の最新の観測を見て、窓があって今がその reset より
   前ならその窓に、そうでなければ(idle・観測不能・観測が古い)次に観測に現れる窓に結ぶ。窓の同定は reset 時刻
   (許容幅つき)で行い、窓の開始の逆算は使わない —— 逆算の誤差が当たり外れを決めなくなる。
2. **失効は「結んだ窓と別の窓が観測されたこと」。** 各窓が自分のリセットで失効する、という意味は変えない。
3. **idle の窓にも入口を置く**(ADR 0143 決定4 を置き換え)。押した arm は次に開く窓に当たり、表示はどの窓に
   当たっているか(その窓の reset か、次の窓か)を言う。人間専用・WebUI 専用は変えない。
4. **表示の reset を過ぎて5分以内の arm は拒む**(ADR 0143 決定5 の「門は既知の組だけ」に足す唯一の例外)。
   表示が早い側へ揺れるので、この区間で押した人は終わりかけの窓を燃やすつもりでありうる。黙って次の窓に
   結ぶと、意図しない窓が丸ごと Spend-down になる。どちらの窓のつもりか分からない区間だけ拒み、押し直しを促す。
5. **次の窓に結んだ arm に期限は付けない。** 誤って残った arm の損失は、arm していない窓のペース線が抑える ——
   session だけの arm は week の線が残り、week も arm していれば week のリセットで week の arm が先に失効して、
   週の頭の線が戻る。
6. **規則は Provider を問わない**(ADR 0143 決定1 のまま)。openai の primary / secondary も同じ述語を通る。

## 退けた案

- **窓の開始の比較に余裕(数分)を持たせる** —— 直し方として最小だが、窓が開いて数分の arm を黙って捨て、窓が
  開く前の arm には入口が無いままになる。
- **リセット直後の arm を黙って次の窓に結ぶ** —— 表示の揺れの区間で、終わりかけの窓のつもりの arm が次の窓を
  丸ごと燃やす。
- **次の窓への arm に期限を付ける** —— 損失の上限は残った線が既に抑えており、期限は守るものの無い規則になる。
