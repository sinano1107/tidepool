# routing の提案の根拠は対象が決める母集団の部分集合で、検査・組・引用の外は盤面が母集団から組む

2026-10-23 の triage / grilling(issue #2485)で決定。#2438 で学習器の昇格 / 降格の提案に根拠を必須にし、盤面が根拠の shadow
行から detail を組む形にした(ADR 0181 追記)。残る5つの op は、`row` が根拠を拒み、他の4つは `Evidence: N worker session(s)`
の件数1行で、人間はどの session か辿れず、`add_tier` は根拠が移す行で走った session かも検査していなかった。op ごとに検査・
組の鍵・引用の外の範囲を決めていくと3つとも op ごとに違う形になり、根本は「根拠の母集団が暗黙で、5つの検査関数がその一部の
条件を手書きしている」ことだった。測定の表と `file:line`、影響するテストは #2485 のコメントに置く。

## 決定

1. **routing の提案の根拠は、op の対象が決める母集団の部分集合である。** 対象は提案が動かすもの —— 表の行、agent、段、
   学習器のフラグ、Interview の対象。母集団は「その対象について配分評価や outcome が語る本番の session」で、対象の**今の世代**に
   限る: 行は今の段で走った session(学習器が数える世代と同じ、ADR 0210 決定2。段を足して行を移す提案は、移す行の段の全行 ——
   主張が段の中の対比だから、ADR 0200 決定8)、学習器のフラグは最後の変更以降の同じ向きの
   乖離行(ADR 0181 追記 決定1)、段の説明は最後の説明の編集以降にその段を要求した task の session、agent は `source.tier` が
   `agent` の session の全期間(registry に変更の event が無い、ADR 0150 決定1)。review 側の session は配分評価を持たないので
   どの母集団にも入らない。根拠は全 op で必須、種類は `worker_spawned` の event id で揃える。pin には入れない。
2. **検査・組の鍵・引用の外は、母集団から導く1本の機構で全 op が共有する。** 検査は「引用した id が母集団に入るか」で、
   外れた条件を理由に名指す。組の鍵は session の文脈(走った行・段・workspace・task の書き手)のうち対象が固定しないもの。
   引用の外は母集団から引用を除いた残りを同じ鍵で畳んだ1行(ADR 0181 追記 決定3 の一般化)。op が持つのは母集団の述語と
   鍵だけで、検査の文も detail の組み立ても op ごとには書かない。
3. **detail の各行は盤面が母集団の session から組み、meta-review の文は `Rationale:` 1行に留まる。** 組ごとに件数と task id、
   outcome の内訳(accepted / rejected / excluded)、配分評価の内訳(allocation × cause の件数と、まだ注釈の無い session の数)。
   昇格の提案が outcome を伏せるのは学習器固有の理由(ADR 0181 決定6: 昇格前の outcome は表の結果)で、他の op には当たらない。
   行は session ごとでなく組ごと(ADR 0181 追記の退けた案、応答予算 ADR 0195)。

op ごとの帰結(決定1・2 から導いたもので、独立の決定ではない):

| op | 対象 | 母集団 | 組の鍵 |
| --- | --- | --- | --- |
| `row` | 行 | その行で、今の段で走った本番 session | workspace |
| `add_tier` | 移す行 | 移す行の今の段にある全行で、その段で走った本番 session(ADR 0200 決定8 の主張は段の中の対比) | 走った行, workspace |
| `interview` | 対象(表に無い) | 根拠の各行で、今の段で走った本番 session | 走った行, workspace |
| `agent_tier` | agent | その agent の `source.tier = agent` の本番 session、全期間 | 走った行, 段, workspace |
| `tier_description` | 段 | 最後の説明の編集(position だけの `edit_tier` は数えない)以降にその段を要求した task の本番 session | workspace, task の書き手 |
| `promote` / `demote` | フラグ | ADR 0181 追記 決定1 のまま | ADR 0181 追記 決定2 のまま |

`tier_description` の書き手は段を申告した task の登録者(`task_registered` の worker_id、人間も含む)で、走った agent ではない ——
purpose が問うのは「1 workspace / 1 書き手の癖か、段の定義か」である(ADR 0200 決定7)。

## 退けた案

- **根拠の件数だけを出す(今の4つの op の形)** —— ADR 0181 追記が退けた理由は op によらない。
- **op ごとに検査・鍵・範囲を個別に決める** —— 3 round の問いが全部「母集団を決めれば導ける」ものだった。暗黙の母集団を
  op ごとに写すと、世代や本番の条件が op ごとに抜ける(`add_tier` が無検査、`agent_tier` / `interview` が他の段の session を通す)。
- **根拠を引数から外し、meta-review は対象だけ名指して盤面が母集団を丸ごと見せる** —— 引用は meta-review の主張が依拠した
  部分集合で、記録が示せない判断(ADR 0181 追記 決定1・3、#1919)。母集団が見えるので引用の偏りは人間に見えるが、
  どこに依拠したかは引用でしか分からない。
- **行の母集団を「行の最後の書き込み以降」で切る** —— 行の書き込みは価格の編集でも起き、世代を言わない。学習器と同じ
  「今の段」で切る。
- **Interview の受験者 session を `row` の根拠に認める** —— Interview の結果は受理の種として学習器と材料の節に既に出る
  (ADR 0273 決定7)。痛みが観測されてから。

触らないもの: op ごとの分岐が pin の照合・段名の解決・修正値・提案の組み立ての4か所に散っている形(#2234 / #2491)。
母集団の述語を足しても「op を足すと複数か所を触る」ことは変わらず、それは別の軸の整理である。
