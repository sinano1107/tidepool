# 名前の場所で読めるとは、集合の id の loose の写しが全部と、git が選ぶ pack の写しが読めること —— pack 同士で別の中身を持つ entry は守らない

**Status 追記: 決定1 の「集合の id」は、複製では tip の閉包の全部になる。確かめが上限を越えたときは入れ直しに進まず拒む([ADR 0411](0411-task-checkouts-and-workbenches-do-not-borrow-the-named-places-objects-they-are-copies-holding-their-whole-closure-and-blame-follows-the-stage.md) 決定4、2026-11-24、issue #3734 / #3735)。**

2026-11-23 の triage(issue #3585、#3494 の実装のレビューの派生)で決定。ADR 0388 決定1 は運ぶときの確かめを、集合を pack に組む1本の git の読みで決め、その読みが選ぶ写しを読み手が読む写しと見なしていた。名前の場所が同じ id の写しを複数持つと、この見なしは崩れる。確かめの `pack-objects` は pack を先に読む。ところが git 2.53 以降の blob の stream の読み手は loose を先に開き、pack 同士では読み手ごとに引く pack が違った。正しい pack の写しの陰にある壊れた loose は確かめを通り、読み手には別の中身か読めない byte が届いた。決定2 は確かめ直しだけを2つの形にしていた。実測は #3585 に置く。

1. **集合の id が名前の場所で読めるとは、次の2つが成り立つことである。**
   - その id の、名前の場所自身の objects にある loose が、在れば全部、loose として読めて中身が名前と合う。
   - git が選ぶ pack 側の写しが、欠けずに読めて中身が名前と合う。

   最初の確かめと確かめ直しは、この1つの判定を使う。読めなければ ADR 0388 決定2 の入れ直しと退避に進む。pack の写しが既に正しくても、入れ直しは飛ばさない —— 重複する pack が増えるのは損傷を見つけたときだけである。読み手に害の無い、zlib として壊れた loose も退避の対象になる。
2. **pack 同士で同じ id を別の中身で持つ entry は守らない。**
   - 退避で取り除けるのは loose の file だけで、pack の中の1つの entry は取り除けない。守るには盤面が人間の pack を書き直すことになり、ADR 0388 決定4 の「名前の場所で repack しない」とぶつかる。
   - zlib として壊れた entry は git が飛ばして別の写しを読む。読み手に届くのは、zlib として正しく別の中身を持つ entry だけである。
   - 盤面はそういう entry を作らない(入れ直しの pack は `index-pack --strict` を通る)。作るのは外の手で、ADR 0398 決定3 の外からの損傷に入る。

## Considered Options

- **写しを全部確かめる(pack の entry も1つずつ)** —— 壊れた pack の entry が見つかっても、決定2 の理由で取り除けない。
- **最初の確かめに loose を読む形を足すだけ** —— 確かめと確かめ直しで「読める」を2通りに計算する形が残る。
- **入れ直しと退避の順を入れ替える(退避が先)** —— 盤面が自分で作る「正しい pack + 壊れた loose」は消える。しかし外からできた同じ形は残り、ADR 0398 決定1 を満たさない。

## Consequences

- Status 追記: ADR 0388 決定1(確かめ方)・決定2(確かめ直しは同じ判定。loose を先に開く読み手は git 2.53.0 でも観測した)。
- 名前の場所が alternates で借りる先の repo にある写しは、決定1 の loose に数えない。この形は測っていない。
- 実装は #3585。
