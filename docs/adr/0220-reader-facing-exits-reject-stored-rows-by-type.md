# 読み手へ出す口は、盤面の解決を通っていない行を型で拒む

2026-10-09 の grilling(issue #1224)で決定。CONTEXT.md「Assignee」の「盤面のあらゆる読み口が解決を通す」を、保存された行を
解決(`presentTask` / `boardRows`)に通さず読み手へ出す欠陥が4回破った(#1208・#1215・#1220・#1221)。どれも typecheck は
捕まえず、守っていたのは書き手の記憶だけだった。試作の実測は #1224 のコメントに置く。

## 決定

1. **解決を通っていない値に型だけの目印を付ける。** 目印は実行時に存在しない省略可能な欄(`unique symbol`)で、`Task` と
   SQLite の行(`TaskRow`)が持ち、外すのは解決の出力(`BoardRow` / `BoardTask`)だけである。`keyof` で判定するので、
   spread・キャスト・入れ子・配列の中でも目印は残る。
2. **読み手へ出す口は、目印を持つ値を型エラーで拒む。** 管理 MCP と worker MCP が共有する `toolResult`、型を消していた
   包み(`runVerb` / `domainResult`、予算つきの読み口の `packItems` の封筒と item)、HTTP のすべての JSON 応答。worker 側を
   外さないのは、「あらゆる読み口」が worker の読み口を除いていないためである。
3. **HTTP は型付きの出口を1つ設け、すべての応答をそこへ通す。** Express の `res.json` はプロパティなので型を上書きできない。
   タスクを返す route だけに通すと、新しい route が `res.json` で書かれたとき #1215 と同じ所で漏れる。
4. **付け忘れは lint で防ぐ。** 拒むのは型、型付きの出口を迂回させないのは lint、と役目を分ける。HTTP は `.json(…)` の直書きを、
   MCP は応答の content の手書きを、それぞれの出口の中を除いて禁じる。両方に置くのは、片方だけの規則に説明を要しないためである。

## 帰結

- 捕まらないもの: `presentTask` そのものが欄を欠く欠陥(#1208 の形)、欄を選び出した値、`as never` などで型を消した値。
- 型の拒否は `@ts-expect-error` を並べた fixture で釘を打つ(#927 の形)。ADR 0107 の3つの seam の外にある、typecheck だけの釘である。

## 退けた案

- **`satisfies` を出口ごとに書く**: 書き忘れれば効かない。`WireContract` は WebUI が読む欄だけを約束するので、包んでいない行も
  満たす(#1215)。`BoardTask` は構造で比べるので、欄を手で足した行が満たす(#1221)。
- **`TaskRow` から目印を外す**: SQLite の行は `Task` より手前の、解決を通っていない値である。外す型を解決の出力に限れば、
  目印の意味を1つの規則で言える。
