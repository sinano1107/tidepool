# agent の verb が拒否文を返すのは agent が自分で直せる失敗だけ —— 直せない失敗は盤面が failure question を登録して session を回収し、資源の停止は今の観測者に残す

2026-11-26 の triage → grilling(issue #3861、#3814 の ponytail-review の派生)で決定。`pose_probe` と `complete_task` の catch-all は、
名前の場所の側の失敗も host の失敗も盤面の不変条件の破れも「Retry or escalate」の1文で root / worker に返していた。verb の時点の
失敗を「拒むだけ」とした決定は3つの理由に立っていた。ADR 0359 決定4 は「verb の時点の失敗は資源の署名を持たない」を理由にしたが、
その前提は ADR 0388 と #3814 で崩れた。verb の時点でも、名前の場所の壊れを示す `NamedPlaceFetchError` が出るようになったからである。
ADR 0363 決定2(と ADR 0373 決定12)は「後始末が一歩あとに同じ失敗を観測するので、verb で資源の停止を登録しても止まるものが無い」を
理由にした。これは今も正しいが、答えているのは「verb で止めれば何かが早く止まるか」だけである。ADR 0253 決定3 は「root には直せない
ので escalate を指す」を理由にした。拒否文を受けた agent は、直せない失敗に retry を1回撃ってから escalate するしかなく、盤面が
コードで決められる次の手を agent に遠回りさせていた。同じ形の拒否の全件と、catch-all に落ちる失敗の表は #3861 のコメントに置く。

## 決定

1. **agent 向けの verb が拒否文を返すのは、agent が自分で直せる失敗だけである。** 直せるとは、agent が自分の worktree・commit・入力を
   直すか、別の verb を選べば通ることを言う。拒否文はその直し方を言う。
2. **直せない失敗では、盤面が見た失敗の文を載せた failure question を登録して session を後始末へ回収する。** agent への応答は
   session が終わったことだけを言う。対象は、名前の場所の側の失敗・host の失敗・盤面の記録の食い違い・型の無い throw、
   それに agent に escalate を指すだけだった拒否(registry から消えた workspace、既定の agent で走れない受験者、動かされた
   `task/<id>`)である。
3. **資源の停止は今の観測者が登録する。verb は登録しない。** 観測者は、走った後なら後始末、走る前なら pickup の門である(ADR 0363 決定2)。
   ターンが走った session なので、資源の question と failure question は2枚になる(ADR 0331 決定2 / ADR 0145 決定5)。
   verb の時点で一過性だった失敗は後始末で通るので、failure question 1枚だけで終わる。
4. **例外: 委任の verb が自分の agent 定義を解けない場合は、今どおり拒否文で session を続ける**(ADR 0366 の Status 追記)。
   agent には委任せずに進める手が残っている。
5. **直せない失敗を分けるための型は足さない。** 盤面の不変条件の門や面接室の側の素の git に型を付ける理由は、拒否文を分けることだけ
   だった。決定2 の後は、どれも同じ扱いになる。後始末の側の分類は別の問いである(派生 issue)。

前提の「後始末が同じ失敗を観測する」と、catch-all に落ちる失敗の原因の表は、コードの読みで未測定である。

## 受け入れる代償

- `complete_task` で一過性の lock が1回起きただけでも、終わった worker の session を回収して人間に問う。
- 回収で verb の入力(handoff の欄、出題・rubric)は transcript にしか残らず、retry の session が作り直す。写す欄は足さない
  (ADR 0121)。成果は task branch に残る。

## 退けた案

- **verb がその場で資源の停止を登録する** —— 観測者が2人になる(ADR 0363 決定2 の線)。一過性の失敗で止まり、人間が受理するまで
  止まったままになる。止めた場所へ後始末が書き込む矛盾も生む。
- **失敗の型ごとに拒否文を分け、原因の文を載せる** —— 読むのは root / worker で、直せない以上、次の手は変わらない。人間が読む原因は
  failure question と、後始末が登録する停止の理由に残る。
- **盤面がコードで1回 retry してから回収する** —— 検討していない。一過性の失敗の実例が観測されたときに問い直す。
