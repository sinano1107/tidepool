# サンドボックスの shadow 残骸の削除は slot-release tree rule の唯一の例外である

issue #310 のグリリング(2026-08-13)で決定。実環境動作確認 第3段(ADR 0052)で、worker セッション中に
workspace のルートへホーム相当の 0 バイトファイルが約20件現れることが観測された。Claude Code サンドボックスの
既知のバグである(upstream: anthropic-experimental/sandbox-runtime#139、open) — `denyRead` された protected
paths(`~/.bashrc` 等)を遮断する bind mount のプレースホルダが、CWD(= workspace ルート)相対に解釈されて
実体として作られる。正常時はサンドボックス化されたコマンドの実行中にだけ存在するが、**kill されたセッションでは
残留する**。`releaseTree` の `git add -A` が拾えば WIP コミットに入り、PR の差分へ混入する — 正常完了の経路では
タイミング依存のレース、watchdog kill 後の解放経路では**確定的**である。

## 決定

### 1. 射程は shadow 残骸に限る

「盤面が管理しないプロセスが workspace に書いた」の一般検知は作らない — worker の正当な書き込みと原理的に
区別できない。ADR 0064 が見張る対象を ref に限って引いた線と同じ割り切りである。

### 2. tree rule の意味論は堅持する — 例外は「確定的に識別できるもの」だけ

「セッションが残したものは何であれ WIP として記録する。取りこぼしのほうが混入より危険」という設計判断は
変えない。WIP の外へ出られるのは**セッションの遺物ではないと確定的に識別できるもの**だけであり、識別基準の
確度が例外の広さを縛る。

### 3. 処分は「削除してから add」— 除外して検査を緩めるのではない

`git add -A` の直前に、次の**3条件をすべて**満たすファイルを削除する:

1. 既知の shadow パスリストに一致(ルート直下の dotfile 群と `.claude/` 配下)
2. untracked
3. 0 バイト

1つでも欠くもの — 中身のあるファイル、追跡済みのファイル — は現行どおり WIP に入る(迷ったら取りこぼしゼロ側に
倒す)。追跡済みのパスにはそもそもプレースホルダ生成が起きない — 既存の実体がマウントポイントとして流用され、
ホスト側の中身は無傷である。

対案(`add` の対象から除外し、除外分が untracked で残る前提でクリーン検査も緩める)は退けた — tree rule の
検査を緩めるのは一段重い変更で、削除方式なら退避後の「ツリーは完全にクリーン」という検査を現行のまま保てる。

### 4. 削除の失敗は quarantine — 管理外プロセスの生存の露見である

削除が EBUSY 等で失敗するのは、サンドボックスの mount namespace がまだ生きている(盤面の管理外のプロセスが
workspace で生存している)ことの露見なので、現行の例外 → quarantine の経路に落とすのが正しい封じ込めである。
リトライや待機の機構は、この失敗が実際に観測されてから(observed pain over speculation)。

### 5. リストは定数で持ち、ドリフトは fail-safe に倒れる

既知 shadow パスのリストは、サンドボックス設定を所有するモジュールの隣に定数として置き、upstream
(sandbox-runtime#139)への参照を添える。Claude Code の更新で protected paths が増えた場合、リストにない
新しい shadow はそのまま WIP に入り **PR の差分として人間の目に見える形で現れる** — 静かな取りこぼしは
起きず、気づいた人間がリストを更新する。

### 6. 掃除の継ぎ目は releaseTree の1箇所

pickup 側には足さない。削除は slot 解放の全経路(完了・エスカレーション・watchdog 失敗)で走るので、kill
残留も次の解放で始末される。唯一残る「quarantine された workspace に残留が居座る」は人間の修理が入る場所で
ある。残留が次セッションの worker の目に触れる実害が観測されたら再訪する。

## 退けた対案

- **各リポジトリの `.gitignore` に足す** — 他人のバグの回避策を、盤面が扱う全 workspace のリポジトリへ
  1つずつ埋め込むことになる。tidepool 以外の workspace では手当が漏れ、漏れた場所でだけ混入が再発する。
- **サンドボックス側で shadow の置き場を workspace 外へ動かす** — `sandbox.filesystem` の設定スキーマに
  置き場を指定する手段が存在しない(2026-08-13 に確認)。
- **upstream への新規バグ報告** — 既報である(claude-code#17087 は一度「修正」後に回帰して auto-lock、
  追跡の本丸は sandbox-runtime#139)。新規 issue は立てず、#139 へ tidepool の観測(ext4/exFAT 両方での
  再現 = fmask 差、kill 時残留、`git add -A` 経由で PR に混入しうる実害)をコメントで足す。
