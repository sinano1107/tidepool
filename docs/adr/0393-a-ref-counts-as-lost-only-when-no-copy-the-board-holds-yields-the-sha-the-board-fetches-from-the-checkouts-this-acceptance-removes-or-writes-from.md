# ref が「失われた」のは盤面が持つどの写しからも sha が取れないときだけ —— 数える前に、この受理が消すか書く元にする checkout からも取る

2026-11-21 の grilling(issue #3533)で決定。give-up と「基準へ戻す」は、名前の場所に戻す先の object が無いことで ref を失われたと
数え(ADR 0373 決定5)、remote-backed では先に origin から取る(ADR 0380 決定4)。解放待ち(ADR 0369)の task の checkout には、その
sha の唯一の写しが残っていることがあり、判定はそれを見ずに、続く解放のやり直しが checkout を消し(完了の成果の最後の写し)、
人間の commit を keep-around せずに上書きしていた(実測は #3533)。0373 決定5 の「object が本当に失われた ref は、内容が回答の前に
失われている」は、盤面がまだ持つ写しを数えないと成り立たない。

## 決定

1. **ref が失われたのは、戻す先の sha が名前の場所・origin・決定2 の checkout のどれからも取れないときである。** 0373 決定5 と
   0380 決定4 はこの定義で読む。探すのは戻す先の全部で、`task/<id>` に限らない。
2. **探す checkout は、この受理が消すか書く元にするもの。** 着け先がこの workspace の task の最後の session の checkout のうち、
   解放待ちのもの(ADR 0369 決定2)と、解放済みで消されずに残るもの(同 決定7)。worker の repo の故障で残した checkout(同 決定5)、
   読み専用の checkout、決着した受験者の checkout(ADR 0276 決定4)は受理が消さず写しが残るので探さない。作業台(ADR 0371)は受理が
   取り込む元だが、名前の場所の object を借り(#3479)、戻す先になる取り込みの commit は盤面が名前の場所にだけ書く(推論、未実測)。
3. **取り方は解放の信頼しない写しの経路のまま**(ADR 0364、checkout で git を撃たない)。checkout の task branch の tip を盤面所有の
   写しへ取り、戻す先の sha がその閉包に在れば、写しから名前の場所へ sha で fetch し、ADR 0388 決定1・2 で確かめる。ref は書かず、
   取った後に全部の ref を調べ直す(0380 決定4 と同じ形)。
4. **失敗は段ごとに読む(ADR 0364 決定2、ADR 0367 と同じ線)。** checkout が読めない(git が即座に失敗する —— ADR 0084 決定2 /
   ADR 0357 決定3)なら「届かなかった」と読み、何も記録せずに数える —— 写しは決定7 が残す。**上限超過は数えずに回答を拒む** ——
   写しが無事なまま取り消せない失われた event(ADR 0375)を刻み、完了済みなら root の着地を終わらせうる。ADR 0357 決定2 からここだけ
   外れる。続くときの出口は、人間がその dir を別の場所へ移して「読めない」にすること。写しの host の失敗と名前の場所への fetch の
   失敗は、origin に届かないときと同じく回答を拒む。
5. **give-up と「基準へ戻す」の両方で、purely-local でも、checkout を先に、残った sha だけ origin に取りに行く。** 片方の選択肢だけが
   取ると、0380 決定4 の末尾と同じくどちらも1回目は通らない。
6. **checkout から取る sha は、名前の場所の保護ブランチ(`refs/heads/<branch>`)と共通の祖先を持つときだけ名前の場所へ入れる。**
   無関係な履歴の `task/<id>` は merge back も着地も `merge-tree` が道具の失敗として拒み(conflict でない)、回答のたびに詰まる。
   確かめは保護ブランチの tip を盤面所有の写しへ取ってから写しの中で行う —— 名前の場所へ入れると object の有無で戻され、写しが
   名前の場所を借りることには頼らない(面接室の写しは借りない、ADR 0364 決定1)。保護ブランチが無ければ取らない。同じ repo の
   clone し直しは、保護ブランチが進んでいても取り戻す。origin から取った sha には当てない(repo の同一性は ADR 0378)。
7. **盤面は、checkout を開いた後に失われた event が刻まれた task の、その checkout を消さない。** 解放済みの checkout を消す述語が
   読み、受理・後始末・解放の直後のどの呼び手にも効く。起点を開きに置くのは、give-up の回答では失われた event が解放のやり直しより
   先に刻まれるからで、「効いている」で読まないのは、子の pickup の固定(ADR 0372 決定3 / ADR 0392 決定1)が作り直すと効かなくなる
   からである。残した checkout は ADR 0369 決定5 と同じく盤面がもう触らず、失われた event を刻んだ回答の notice が1回だけ在り処を
   告げる。ADR 0388 が退けた「消す前に確かめる」は閉包の確かめで、盤面自身の記録を1つ読むこの述語はその理由に当たらない。
8. **ADR 0392 決定3 は完了済みの解放にも当てる。** 失われた event が効いている task のやり直した解放は、門の掛かる完了済みの task でも
   投げずに、`task/<id>` を書かず解放の失敗として刻む(負う解放から外れる)—— 0392 決定1 が ref と基準の行を消した後、門の側は
   「ref が動いた」で回答を拒み続け、出口が無い。checkout は決定7 が残す。0392 と 0393 は片方だけでは穴が残るので一緒に入る
   (#3480 は #3533 の実装に畳む)。

## 退けた形

- **盤面に残る checkout を全部探す** —— worker の repo の故障で残した checkout は出どころが壊れていて(ADR 0369 決定5)、この受理が
  消さないので写しを失わない。
- **checkout が読めなければ回答を拒む**(0380 決定4 の origin と同じ扱い)—— alternates で借りた祖先が gc で消えた checkout は直らず、
  workspace の Quarantine から抜ける回答が無くなる。
- **上限超過も「届かなかった」と数える**(ADR 0357 決定2 のまま)—— 一時的な上限超過で、写しの残る完了の成果が帳簿の上で捨てられる。
- **無関係な repo でも戻す** —— 戻した `task/<id>` は着地できず詰まる。
- **保護ブランチが基準の値と違えば checkout を探さない** —— 同じ repo を clone し直して保護ブランチが進んだだけの形で取り戻せない。
- **受理の削除だけで飛ばす** —— 削除の述語は1つで呼び手は3つあり、受理だけ塞いでも後始末と解放の直後が同じ記録を読まずに消す。
- **0392 と 0393 を順に入れる** —— 0393 が先なら give-up の後のやり直した解放が無関係な tip で人間の値を上書きし、0392 が先なら S2 で受理が
  どの回答でも拒まれる(独立レビューで code から確認、#3533)。
- **checkout の task branch の tip を丸ごと取る** —— 基準に無い worker の object を名前の場所へ持ち込む量が増え、判定に要るのは戻す先の
  sha だけである。

## 帰結

写しの保護は判定の精度に頼らない(決定7)。決定1〜6 の判定が外れても、壊れるのは記録(失われた event、root の着地の終わり)で、
最後の写しは消えない。判定の精度は、誤った記録と人間の commit の上書きを避けるために要る。

戻す先が消えるのは、盤面が基準の値を名前の場所で押さえず、人間の ref の移動と gc に任せているからで、同じ機構が checkout と作業台の
借りる元も消す(#3479)。押さえる側の設計は #3534 が持つ。押さえる ref も手で消せるので、この ADR の判定はその後も要る。
