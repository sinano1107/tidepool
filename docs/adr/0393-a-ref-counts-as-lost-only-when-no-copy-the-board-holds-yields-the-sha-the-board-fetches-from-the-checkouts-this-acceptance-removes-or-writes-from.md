# ref が「失われた」のは盤面が持つどの写しからも sha が取れないときだけ —— 数える前に、この受理が消すか書く元にする checkout からも取る

2026-11-21 の grilling(issue #3533)で決定。give-up と「基準へ戻す」は、名前の場所に戻す先の object が無いことで ref を失われたと
数え(ADR 0373 決定5)、remote-backed では先に origin から取る(ADR 0380 決定4)。解放待ち(ADR 0369)の task の checkout には、その
sha の唯一の写しが残っていることがあり、判定はそれを見ずに、続く解放のやり直しが checkout を消し(完了の成果の最後の写し)、
人間の commit を keep-around せずに上書きしていた(実測は #3533)。0373 決定5 の「object が本当に失われた ref は、内容が回答の前に
失われている」は、盤面がまだ持つ写しを数えないと成り立たない。

## 決定

1. **ref が失われたのは、戻す先の sha が名前の場所・origin・決定2 の checkout のどれからも取れないときである。** 0373 決定5 と
   0380 決定4 はこの定義で読む。
2. **探す checkout は、この受理が消すか書く元にするもの。** 着け先がこの workspace の task の最後の session の checkout のうち、
   解放待ちのもの(ADR 0369 決定2)と、解放済みで消されずに残るもの(同 決定7 —— 受理の最後で消す)。worker の repo の故障で残した
   checkout(同 決定5)と読み専用の checkout は探さない —— この受理はそれを消さず、写しは残る。作業台(ADR 0371)も、受理が取り込む
   元ではあるが探さない —— 名前の場所の object を alternates で借り(#3479)、戻す先になる取り込みの commit は盤面が名前の場所にだけ
   書く(推論、未実測)。決着した受験者の checkout(ADR 0276 決定4)も、記録として残り受理が消さないので探さない。
3. **取るのは object の無い戻す先の sha だけで、ref は書かず、取った後に全部の ref を調べ直す**(0380 決定4 と同じ形)。運ぶ手は解放と
   同じ信頼しない写しの経路と、ADR 0388 決定1・2 の確かめである。
4. **帰責は段ごと(ADR 0364 決定2、ADR 0367 と同じ線)。** checkout が読めない(git が即座に失敗する —— ADR 0084 決定2 / ADR 0357
   決定3 の線)なら「届かなかった」と読み、この段では何も記録せずに数える。帰責は続く解放のやり直しが今の経路で負う —— 未決着なら
   task の失敗、完了済みなら checkout を残す。ADR 0392 決定3 が受けるのはこの形である。**上限超過は数えずに回答を拒む** —— 写しが
   無事なまま失われた event(取り消せない、ADR 0375)を刻み、完了済みなら root の着地を終わらせうるからで、ADR 0357 決定2(上限超過は
   worker の repo の故障)からここだけ外れる。上限超過が続く checkout の出口は、人間がその dir を別の場所へ移して「読めない」にすること(写しは移した先に残る)。
   写しの host の失敗と名前の場所への fetch の失敗も、origin に届かないときと同じく回答を拒む。
5. **give-up と「基準へ戻す」の両方で、purely-local でも、checkout を先に、残った sha だけ origin に取りに行く。** checkout で揃えば
   origin に出ず、通信の失敗で拒まない。片方の選択肢だけが取ると、0380 決定4 の末尾と同じくどちらも1回目は通らない。
6. **checkout から取った sha は、名前の場所の今の保護ブランチと共通の祖先を持つときだけ取れたと数える。** 共通の祖先が無い sha を戻した
   `task/<id>` は merge back も着地も `merge-tree` が無関係な履歴として拒み(conflict でなく道具の失敗)、回答のたびに同じ所で詰まる。
   無関係な repo への `path` の差し替えと `git init` し直した履歴がこれに当たり、0373 決定5 の「全 ref が失われたと読んで通す」は
   そのまま残る。写しは決定4 と同じく、やり直した解放の失敗が残す checkout にある。同じ repo の clone し直しは、保護ブランチが
   進んでいても取り戻す。origin から取った sha には当てない —— repo の同一性は ADR 0378 が見る。確かめは盤面所有の写しの中で、
   名前の場所へ入れる前に行う —— 入れてしまえば object は在り、失われたかを object の有無だけで決める判定が戻してしまう。
7. **盤面は、解放の後に失われた event が刻まれた task の checkout を消さない。** 解放済みの checkout を消す述語は、その checkout の
   解放の event の後に失われた event があるかを読む —— 受理・後始末・解放の直後のどの呼び手にも効く。「効いている」で読まないのは、
   子の pickup の固定(ADR 0372 決定3 / ADR 0392 決定1)が fork 元から作り直すと失われた event が効かなくなり、旧い成果を持たない
   ブランチの横で写しを消すからである。盤面が自分で「成果は名前の場所から失われた」と記録した task の写しを、
   その記録に反して消さない。残した checkout は ADR 0369 決定5 と同じく盤面がもう触らず、受理の notice が在り処を告げる。ADR 0388 が
   退けた「消す前に確かめる」は閉包の確かめで外からの損傷の窓を守る形で、盤面自身の記録を1つ読むこの述語はその理由に当たらない。

## 退けた形

- **盤面に残る checkout を全部探す** —— worker の repo の故障で残した checkout は出どころが壊れていて(ADR 0369 決定5)、この受理が
  消さないので写しを失わない。
- **checkout が読めなければ回答を拒む**(0380 決定4 の origin と同じ扱い)—— alternates で借りた祖先が gc で消えた checkout は直らず、
  workspace の Quarantine から抜ける回答が無くなる。
- **上限超過も「届かなかった」と数える**(ADR 0357 決定2 のまま)—— 一時的な上限超過で、写しの残る完了の成果が帳簿の上で捨てられる。
- **無関係な repo でも戻す** —— 戻した `task/<id>` は着地できず詰まる。
- **保護ブランチが基準の値と違えば checkout を探さない** —— 同じ repo を clone し直して保護ブランチが進んだだけの形で取り戻せない。
- **受理の削除だけで飛ばす** —— 削除の述語は1つで呼び手は3つあり、受理だけ塞いでも後始末と解放の直後が同じ記録を読まずに消す。
- **checkout の task branch の tip を丸ごと取る** —— 基準に無い worker の object を名前の場所へ持ち込む量が増え、判定に要るのは戻す先の
  sha だけである。

## 帰結

写しの保護は判定の精度に頼らない(決定7)。決定1〜6 の判定が外れても、壊れるのは記録(失われた event、root の着地の終わり)で、
最後の写しは消えない。判定の精度は、誤った記録と人間の commit の上書きを避けるために要る。

戻す先が消えるのは、盤面が基準の値を名前の場所で押さえず、人間の ref の移動と gc に任せているからで、同じ機構が checkout と作業台の
借りる元も消す(#3479)。押さえる側の設計は #3534 が持つ。押さえる ref も手で消せるので、この ADR の判定はその後も要る。
