# 盤面の git の子は1つの起動口だけが作り、失敗の型はそこで1回だけ付ける —— 網に出る git は env だけを持ち込む

2026-11-28 の triage → grilling(issue #3999 の triage で、族の根として #2897 に寄せた)で決定した。盤面が git を起動する経路は3系統あった。
local の runner は失敗を「cwd が無い」「host の失敗(disk 満杯)」「git の道具の失敗」に分ける(ADR 0433 決定3・5)。網に出る git(ADR 0339 決定1)は
別に子を作り、この分類を通らない。ほかに、runner を通らない直接の起動もあった。失敗の分類を起動口ごとに書いていたので、分類を1つ足すたびに
写し漏れが出た。#2722 では cwd が無い失敗を2つの runner に別々に写し、直接の起動には写らなかった(#2782)。#3774 では disk 満杯の判定が
写す段にしか無かった。#3943 では型が local の runner にしか付かなかった(#3999)。直接の起動は、local の env を付け忘れても何も落ちなかった(#2897)。

## 決定

1. **盤面の git の子は、git の module の起動口だけが作る。** 失敗の型(cwd が無い・host の失敗・git の道具の失敗)は、そこで1回だけ付ける。
   直接の起動は残さない。
2. **網に出る git も同じ起動口を通り、env だけを github-auth から持ち込む。** env を組み立てる場所は ADR 0339 決定1 の1箇所のままにする。
   stall・ssh・`not our ref` のような網に固有の分類は、網に出る git が共有の型の上に足す。
3. **local の git が `file` だけで網に出ないことは、env を持ち込む口を github-auth の外から呼ばせない lint で守る。** あわせて、git の
   module の外で git を起動するコードも lint で落とす。今まで保証は、local の runner が env を固定することで成り立っていた。決定2 で env を
   受け取る口ができるので、保証は呼べる場所を絞ることに移る。lint は ref の読みを絞る plugin(#3913)とは別に立てる —— 落とす対象が違う。
4. **網に出る git の一般の失敗の型は、この ADR では決めない。** host の失敗と cwd が無い失敗は、決定1 の型のまま上に通す(ADR 0433 決定3・5 の
   適用)。それ以外は今の型のまま残し、どの型にしてどこへ送るかは #3999 が決める。一般の失敗を git の道具の失敗として通すと、pickup の
   catch(#3945)が修復案内付きの Quarantine で拾い始め、行き先を先に決めてしまう。

## Considered Options

- **lint だけで直接の起動を落とす** —— 今ある写し(網に出る git と直接の起動)が残る。分類を足すたびに、網に出る git に写す手間も残る。
- **起動口に寄せるだけで lint を置かない** —— 次の直接の起動が黙って増え、同じ写し漏れに戻る。
- **網に出る git を起動口に通さず、分類だけを共有の関数にする** —— 子を作る場所が2つのままなので、次の分類(上限・env の付け忘れ)が
  また片方にだけ入る。

## 派生

- Status 追記: ADR 0339 決定1(local の `file` だけを守る場所)、ADR 0433 決定3・5(出所での型が網に出る git にも及ぶ)。
