# 面接室が task の準備に提供するものと、面接室の項の並びは、それぞれ1つの持ち主から門と準備が読む

2026-11-20 の grilling(issue #3165)で決定。(task, 面接室) の項(ADR 0329 決定4 の Status 追記)は「準備がその task のために面接室から
fetch するもの」を写して書いていたが、準備は項の答えを読まず、fetch 元と切る元を自分で決めていた。写しは2点で欠けていた —— 記録された
面接室で root のブランチが無いとき、準備が切る元(面接室の保護ブランチ)の閉包を見る項が無い(#3163)。門の後に task のブランチの fetch が
落ちても項の文が付かない(#3161)。同じ形で、面接室の項の並びも pickup の門・答えの門・Quarantine の本文がそれぞれ組んでいて、答えの門
だけが未記録の面接室に「作る」項(`mkdir -p`)を撃ちうる順だった(#3160)。呼び手の一覧と `file:line` は #3165 に置く。コードの読みで
決めていて、盤面は走らせていない。

**Status 追記: 決定1 の理由の文「準備はその間にブランチを立てる」は、準備が複製を作ってからブランチを立てる順に変わる —— 準備はブランチを立てる前に、面接室が提供するものを fetch する。持ち主が1つで項と準備の両方が読む決定は変わらない([ADR 0414](0414-the-fix-moment-of-start-work-and-pickup-is-written-only-after-the-copy-has-been-received-from-the-named-place.md) 追記 決定6・7、2026-11-25、issue #3834)。**

## 決定

1. **面接室がその task の準備に提供するものの持ち主は1つ。** task ごとに「ブランチがあれば fetch するもの、無ければ切る元」を答え、
   項と準備の両方がそれを読む —— 受験者は自分のタスクブランチか出題の head、root は自分のタスクブランチか切る元(タスクブランチを切る
   sha と同じ読み方 —— 完了の門が人間しか書けない path を比べる fork 元とも同じ出所、ADR 0362 決定2)、読み手は読む出題の head(ADR 0361 決定1 の Status 追記)。準備から項の関数をそのまま呼ぶのではないのは、項が門の
   時点のブランチの有無で答えを変え、準備はその間にブランチを立てるからである。
2. **未記録の面接室の root は項を持たない。** 面接室を開く段が保護ブランチに空の commit を補う(ADR 0329 決定1)ので、門の時点で
   切る元の閉包を問えない。記録された面接室で root のブランチが無いときだけ、切る元の閉包が項になる。
3. **準備が面接室から fetch して落ちたら、その task の項の文で包む。** 面接室の性質として面接室の名前で止まり、読み専用の checkout と
   同じ形になる。checkout の番地を作れない失敗は今どおり host 側の失敗(ADR 0356 決定2)。
4. **面接室の項の並びの持ち主も1つ。** 面接室と開く task たちから「その面接室の受験者を含む項 → 面接室そのものの項 → 残りの task の項」と
   並べ、pickup の門・答えの門・Quarantine の本文がこれを読む。受験者の項は出口が同じ task の項とまとまる(ADR 0385 決定1)ので、
   並びの単位は受験者を含む項である。(task, 面接室) の項は面接室の repo が無ければ面接室が消えた理由で止まるので、未記録の面接室に
   「作る」項が撃たれない(ADR 0329 追記 決定7)。各項は面接室そのものの項か、どの task(RCA ならその id)の項かを
   持つ —— 答えの門が面接室そのものの項や倒す RCA の項を外すため(ADR 0385 決定2・6)。本文は撃つ順どおり、項の後に作業ツリーの clean を並べる。

## 考えた案

- **欠けた項と包み方を点で足す**: 同じ判断の写しが3つ目になり、次に準備が fetch するものを変えたときにまた項が遅れる。
- **答えの門の順だけ pickup の門に合わせる**: 並びを組む場所が3つのまま残り、本文の並びも撃つ順とずれたままになる。
- **準備の全段を「文・純粋な検査・操作」を持つ項目として宣言し、門と準備が同じ項目を撃つ**: 項が準備の写しであること自体を消す一般形で、この決定はその面接室の分にあたる。範囲が実環境の準備すべてに広がり、Interview の停止の欠陥の直しが遅れるので、#3459 に分けた。
