# 子は親と同じ workspace に居て、別の workspace への分解は文脈を運ぶ分解元つきの根になる

2026-11-19 の grilling(issue #1796)で決定。`parent_id` は性質の違う3つの仕事を1本で運んでいる —— ① 親の文脈を子の worker に渡す、
② 親が子を待ち、決着した子の成果を受け取る、③ 子の中身を親のタスクブランチへ返す。ADR 0372 決定4 の後、別の workspace の子には③が
成り立たず、子の中身は自分の保護ブランチへ着地する。子のまま残すと、中身について判断する読み手 —— 完了時レビューの根(#3225)、cancel が
捨てる範囲(#3270)、着地が待つ祖先の PR(`openPrRootAbove`)、親の着地の門 —— のすべてに例外が要る。別の workspace の子を許した根拠の
ADR 0031(委譲の木は場所を跨いでよい)は系譜(ADR 0053)より前の決定で、例に挙げた registry-edit の分解は帰り先の無い系譜では立たず
(ADR 0301 決定7)、別の workspace の子が使われた観測も無い。読み手の数え上げと `file:line` は #1796 に置く。コードと ADR の読みで決めていて、
盤面は走らせていない。

## 決定

1. **`parent_id` の子は、親と同じ workspace に導出される task だけである。** 子の列は pickup まで空で、明示は親の導出と同じかを確かめる
   ことにだけ使い、保存しない(ADR 0290 決定1・2 を全 type の子に広げる)—— 保存すると、既定の差し替えや未着手の親の Edit の後に子が親と
   別の workspace に残り、別の workspace の `parent_id` の子に戻る。親と違う明示は子にせず決定2 に回し(付帯子の review は今どおり拒む)、子の
   Edit で親と違う名前にすることは拒む。同じ workspace の中では、①〜③はこれまでどおり `parent_id` が運ぶ。
2. **親と違う workspace への分解は、分解元つきの根として登録される。** agent の分解は承認 question を経て(今ある `allowed_workspaces` 外と
   保護 workspace の承認と同じ扉)、approve で根になる。人間の分解は承認なしで、そのまま根になる。根は自分の workspace の保護ブランチから
   切られて自分で着地し、待ち・cancel・レビュー・着地・系譜のどの読み手にも根として扱われる。親はこの根を待たず、親の risk flag も引き上げない。
3. **分解元は、分解した task とその分解の判断を指し、文脈を運ぶことだけに使う。** 読むのは3つ —— pickup で凍結する親の文面(ADR 0321)、
   `get_current_task` が渡す親の `handoff_doc` と history(分解の理由と兄弟の結果、ADR 0045)、文面の書き手(帰責と学習の起草が分解した agent を
   書き手として読む)。分解元の task の側にも、ここから生まれた根を見せる。

## 帰結

- ADR 0372 決定4 の「別の workspace に固定された祖先を飛ばす」は、同じ workspace の子しか居ないので当たる場面が無くなる。系譜の規則は変わらない。
- 別の workspace への分解でできる根は自分の帰り先を持つので、ADR 0301 決定7 が理由に挙げた「帰り先を work 自身の workspace で読むか」は
  問う必要が無くなる。ただし帰り先の無い系譜の RCA の下では、その根を立てる承認 question 自体が登録の床で拒まれる(承認で work を立てる
  question は宛先がブランチに依存する、ADR 0301 決定2)。そこを開くかは #2510 が決める。
- 親は別の workspace の仕事の完了を待てない。順序が要るなら人間が、根の着地の後に続きを登録する —— 子の完了は着地ではないので、待っても
  「その変更が使える」は保証されなかった。

## 退けた形

- **子のまま残し、委譲の木と中身の行き先を読み分ける**(この grilling の最初の着地)—— merge back で中身を運んだ先を記録し、完了時レビュー・
  cancel・登録の床・着地の門をその記録と「導出が同じ祖先」の述語で読む形だった。独立の見直しを5回回すたびに、同じ「中身はどこへ行ったか」の
  読みに穴が出た(試行の全記録は #1796)。源の③を閉じれば読み手の例外は要らない。
- **別の workspace の子を分解元の無い根にする** —— registry-edit の worker が「なぜ直すのか」(親の文面・分解の理由・兄弟の結果)を失い、
  帰責の書き手が承認した人間になる。
- **人間の別 workspace の分解を拒み、根で登録し直させる** —— 登録し直すときに文脈が切れる。
- **子の明示を保存し、後で親と分かれたら ADR 0372 決定4 の「別の workspace の祖先を飛ばす」で受ける** —— 別の workspace の `parent_id` の子が
  残り、読み手の例外が戻る。
