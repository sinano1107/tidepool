# pickup の契機は「候補が増えたか slot が空いたかもしれない事象」のすべてであり、並べ替えは契機ではない

2026-09-12 の grilling(issue #536)で決定。ADR 0065 決定9 は「登録は即時ポーリングを撃たず、次の自然な契機(走行中タスクの終了、毎時のティック)を待つ」と決めたが、そのうち**走行中タスクの終了は契機として実装されていなかった**。`onQueueHeadChanged` は人間面の動詞(move / cancel / answer / complete / pace offset / spend-down / pause 解除 / triage close)にだけ配線され、後始末が slot を解放する経路は人間面を通らないので、単一 slot の盤面では1本走り終えるたびに次のタスクが最大1時間待つ。登録経路も WebUI・管理MCP の両方で撃たず、毎時のティックは `setInterval` なので起動直後にも走らない。Lima VM の実盤面で交絡を排した観測(解放から6分放置 → 契機を1つ与えて8秒で pickup)と `file:line` は issue #536 のコメントに置く。

## 決定

1. **契機の原理を1文に置く。pickable な候補が増えたかもしれない事象と、slot が空いたかもしれない事象はすべて poll を撃つ。候補集合の中の並べ替えは撃たない。「run now」は人間の明示的な例外である。** 契機の側は「pickup できるか」を判定しない —— 判定は poll が1点で行い、slot 占有中は同期の1チェックで終わる。列挙(halt の解除・throttle 判定の変化・親の unblock)は原理の適用例に位置づけ直し、「並べ替えが黙って pickup 要求を兼ねない」線(ADR 0065 / issue #299)は無傷のまま残す。

2. **登録は契機である。ADR 0065 決定9 のうち「登録は待つ」を改訂する。** 決定9 が退けたのは「登録経路によって急ぎ方が変わる非対称」であり、登録経路が**すべて**撃てば非対称は生じない。「セッションを閉じたときだけ」の残りの部分(閉じた時点で発火済み・何も止めていなかったなら撃たない)は無傷である。空 slot への登録で usage scrape が1回走る(約3秒、モデル呼び出しなし)のは、ADR 0028 が「稀な run now」に許したのと同じ負荷で、ADR 0077 が廃止したモデル呼び出しプローブとは別物である。 登録の扉を通らない登録も同じである —— triage の振り分け(`work` / `meta_review`)はセッションの有無に依らず適用され(ADR 0065 決定4)、セッション無しの close は今日「何も止めていない」として撃たないが、そこでタスクを1つでも作ったなら候補が増えている。

3. **slot の解放は契機であり、撃つ時点は後始末の完走後(landing の後)である。** 後始末は slot を空けた**後**に landing(push / PR 昇格)を走らせる(ADR 0109)。解放の瞬間に撃つと、次の pickup の fetch / checkout が前タスクの push と同じ checkout で並走する —— 今日も毎時のティックと並走しうるが、実質ゼロだった確率を毎回にはしない。callback は後始末の deps の**必須**フィールドとし、構築箇所(通常経路・watchdog・起動時復旧)の配線漏れを型に捕まえさせる —— 今回の欠落は optional な配線の漏れそのものだった。`slot.release()` 自体を landing の後へ動かす案は退けた: session の終わりは回収済み観測である(ADR 0109 決定2)。 保証は「**新しい**契機が並走を常態にしない」ことまでであって「並走が無い」ことではない —— landing の数秒に毎時のティック・登録・spend-down が届けば今日どおり並走しうる。これを閉じるために `slot.release()` を動かしたり pickup の門に landing を足したりはしない(前者は上記、後者は slot の意味を landing に漏らす)。

4. **起動完了は契機である。** 盤面の process が無かった状態からの遷移は、決定1 の原理の一例である。scheduler 生成後に1回撃つ。中断 session を抱えた再起動は決定3 で埋まるが、起動時復旧は scheduler より先に走りうるので、その配線だけは遅延束縛か生成順で解く。

5. **`inFlight` 中に届いた契機は捨ててよい。合体機構は作らない。** poll は最初の await より前に slot を読むので、「解放が poll 中に起きる」は構造的に起きない(poll が slot チェックを通過した時点で slot は空いている)。登録が poll 中に来ても、候補の読み取りは await の後なので取りこぼさない。この安全性は**順序の不変条件**なので、コメントとテストで固定する —— 順序を変えた将来の変更が赤くなる。

6. **名前は scheduler 自身の動詞に揃える。** 契機を運ぶフィールドは `onQueueHeadChanged` から `pollNow` に改める —— 中身は最初から `() => scheduler.pollNow()` であり、「先頭が変わった」は決定1 の原理と合わない。事象名を新設しない。

## 退けた案

- **登録は「候補が無かったところに現れた」ときだけ撃つ**(`pollIfParentUnblocked` と同じ形)—— slot 占有中・throttle 中の登録で「無かった」の意味が曖昧になり、契機の側が判定を持つ。判定は poll の1点に置く。
- **ADR 0065 決定9 を維持し、解放と起動だけ直す** —— 空キュー・空 slot への登録が最大1時間待つ残余が残り、その待ちに設計上の理由が無い。
- **`Slot.release()` にリスナーを置く**(配線1箇所)—— landing との並走を作る。配線数の懸念は必須フィールドで解ける。
- **`inFlight` 中の契機を持ち越す合体** —— 観測されていない痛みへの備え。不変条件のほうが安い。
