# CLI の版が model の最低版に届かない拒否は行の拒否であり、種の行は版上げの門で確かめる

2026-10-02 の triage / grilling(issue #1267)で決定。ADR 0184 は Claude CLI を喋る Provider の行の拒否を 404 だけで判定
したので、CLI の版が model の最低版に届かず断られた行(400)は「報告なき exit」(ADR 0145)に落ちていた。決定1 は
「CLI の版の古さを、どちらの CLI も区別して返さない」としたが、Anthropic の API は 400 の本文に
`details.error_code: "claude_code_version_too_old"` を載せており、版を固定する CLI(ADR 0186)はそれを result 行の
`api_error_code` に写す。実測(debug 出力の本文、field が現れる版の境界)は #1267 のコメントに置く。

## 決定

1. **result 行の `api_error_code` が `claude_code_version_too_old` なら、404 と同じく行の拒否である。** ADR 0184 決定3 の
   証拠に足す。CLI が自分の enum へ写した `api_error` ではなく、サーバの識別子をそのまま写した `api_error_code` を読む ——
   判定の元はサーバの門で、間に CLI の対応表を挟むと、版によって値が変わりうる場所が1つ増える。`@internal` の field
   である揺れは、版の固定(ADR 0186)が押さえる。
2. **最低版が model のものか組織ポリシーの下限かは区別しない。** どちらも同じ code で、区別は文言にしか無い
   (ADR 0104 決定2 の線で文言は読まない)。組織の下限なら anthropic の行が使われるたびに1本ずつ外れ、行の数だけ
   question が立つ。それでも間違った行は走らない。個人のサブスクリプションでは観測されていない。
3. **この証拠の question は、原因を運用者の言葉で名指す。** 「この盤面の Claude Code CLI が model の要求より古い」と書き、
   先頭は ADR 0184 決定6 と同じく行の差し替えを促し、行を残すなら tidepool を更新してから答えるよう書く。運用者は
   固定の版を変えられない(版は checkout が宣言する。ADR 0186 決定5)ので、「固定の版を上げる」は運用者の文面に
   書かない。決定1 が原因を断言しなかったのは区別できなかったからで、構造化された証拠が区別した場合はこの限りでない。
   選択肢・解除の門・回答時の1ターンの再検査は 404 と同じで、再検査もこの証拠を「まだ走れない」と読む。
4. **種の行は、その Harness の固定の版で走ることを、版上げの門で確かめる。** Claude も Codex も同じである。種が DB に
   入るのは盤面を新しく作るときだけで、そこで行の Quarantine が立つのは出荷物の欠陥である(#1249 の確認では
   `claude-fable-5-1` と `gpt-6-astra` の両方が立った)。
5. **この面は版上げの適合試験で再現できない。** 固定の版より新しい CLI を要求する model は、版を上げる時点では
   ふつう手元に無い。手順書は 429 と並べて未確認の面として名指す。field が消えたら「報告なき exit」に落ちる ——
   行が走らないだけで、間違った行は走らない。

## 帰結

- ADR 0184 決定1 の「CLI の版の古さを、どちらの CLI も区別して返さない」は、Claude CLI については誤りになった。
  Codex は文言しか無いままだが、版の古さは `model/list` の照合(ADR 0184 決定3)で拾われている。

## 退けた案

- **Harness の版の資源(ADR 0186 決定2)に落とし、`claude-code` の pickup を止める** —— 新しい model の行を1本足した
  だけで盤面全体が止まる。
- **`api_error` を読む** —— 決定1。
- **古い CLI を一時的に入れて適合試験で再現する** —— 確かめられるのは古い版の振る舞いで、固定の版ではない。
