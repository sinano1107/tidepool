# 人間は無効化済みのエントリを本文の側ごと写して復元でき、後継が生きている間は復元できない

2026-09-28 の grilling(issue #1050)で決定。meta-review の直接適用(畳み・移動・定義の書き直し・candidate の引退)には逆操作が無く、
ADR 0083 追記4 の「人間は異議で戻す」は将来の meta-review を直すだけで店は戻らない。直接適用で復元不能な損失は1つ —— 畳まれた
Knowledge の commit / event 出所で、人間が書き直すと自身の宣言(ADR 0083 追記5)に変わる。今の実装の walk-through は #1050 のコメントに置く。

## 決定

1. **復元は人間の面(settings / 管理MCP)だけの操作で、無効化済みのエントリの本文の側 —— title・text・原文・出所・書き手・状態・
   宛先・注釈 —— を写して新エントリにする。** 移動の複製(ADR 0162 決定5)と同じ形で、新規の書き込みの門は掛けない。4種別すべてが
   対象で、状態は継ぐ(approved → approved、candidate → candidate)。無効化の理由は問わないが `path_moved` だけは拒む —— 複製が
   生きていれば移し戻し、複製が畳まれていればその複製を復元する。名指した行そのものを復元し、鎖はたどらない。
2. **後継が生きている間は復元できない。** 「A は C に置き換えられた」と「A の本文が生きている」を同時に記録に立てない。人間はまず
   後継を落とす。人間の編集(A → A')の取り消しも同じ手順。「生きている」は後継の `path_moved` の鎖を末尾までたどって見る(提案 question の pin と
   同じ、ADR 0162 決定6。`superseded` はたどらない)—— 畳んだ後継が移されていれば、その複製が生きている間は復元できない。
3. **復元は作成 event 1つで、旧の行は触らない。** payload に復元元の id と復元した者の activity を刻む。旧の無効化の理由と後継 id は
   そのまま(削除は無く追記のみ、ADR 0083 決定5)。復元前に旧を pin していた提案 question は陳腐化したままで戻さない。
4. **置き場は旧と同じ scope / path に固定。** 移すなら復元後に移動する。Definition の復元は同じ枝に生きた Definition があれば拒む
   (移動と同じ門)。

## 退けた案

- **人間の Knowledge に出所欄を足す(ADR 0083 追記5 の見直し)** —— 復元では盤面が出所を写すので、人間に「どの記録の事実か」を
  書かせる理由は生まれない。
- **逆操作は置かず、異議 → 帰責 → Behavior(meta-review 宛)で足りるとする** —— 記憶の書き込みへの異議(ADR 0122 決定3、#632)が
  着地しても直るのは今後の振る舞いで、店は戻らない。役目が別。
- **meta-review にも復元の verb を与える** —— 自分の畳みを自分で戻す経路は「直接適用 → 決定ログ → 異議」の門を迂回する。
- **後継が生きていても復元を許し、重複は健全性検査に任せる** —— 決定2。
- **復元に置き場の引数を持たせる** —— 移動と二重になる。
- **approved だけを対象にする** —— 理由コードや状態で対象を選り分ける規則を増やさない。
