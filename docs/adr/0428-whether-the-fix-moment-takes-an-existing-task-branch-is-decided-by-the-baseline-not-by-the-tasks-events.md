# 固定の瞬間が在る `task/<id>` を採るかは基準が決める —— task の event の有無を書き手の証拠にしない

2026-11-26 の triage と grilling(issue #3877。#3539 を畳む)で決定。

固定の瞬間(pickup と `start_work`)は、在る `task/<id>` を2通りに読んでいた。`task_branch_created` が無ければ、作成の途中で落ちた後と読んで event だけ足す(ADR 0414 決定10 が引く ADR 0329 決定2 の形)。失われた event が効いていれば、give-up の後に人間が置いた ref と読んで、その task を cancel だけの failure question で止める(ADR 0392 決定2)。どちらも書き手を task の event で推し量るが、盤面は ref を書いてから event を書くので、event は ref より必ず遅れる。そのため、失われたブランチの作り直しが ref と event の間で落ちると、盤面自身が書いた ref が「人間の ref」と読まれ、task は cancel しか出口を持たない(実測は #3877)。一方、盤面が書いた ref かどうかは、書く前に予告する基準(ADR 0351)が既に知っている。give-up の後に人間が置いた ref は基準に無く、固定より前の比較が workspace の Quarantine に回し、「基準へ戻す」が消す(ADR 0373 決定3・5、ADR 0392 決定1)。測定と、届く経路の調べは #3877 に置く。

## 決定

1. **固定の瞬間は、固定する集合の全員について、在る `task/<id>` の値が基準(予告中の2値を含む)に在るかを確かめる。** 在れば、盤面が書いて event の前に落ちた作成と読み、`task_branch_created` だけ足して通る。初回の作成も、失われた event が効いている task の作り直しも同じ規則で、失われているかどうかで分けない。
2. **基準に無ければ、ref が動いた形(`RefsMovedError`)として workspace の Quarantine で止まる。** 比較と固定の間の await に置かれた ref も、ここで止まる。黙って採る分岐は作らない。ADR 0414 決定9 のとおり、確かめは書く前に全員について行う。
3. **task の event の有無は、在る ref の書き手の証拠にしない。** ADR 0392 決定2 の止まり(その task の cancel だけの failure question)は置き換えられ、その拒否の型も無くなる。

## 退けた形

- **守りを残し、作り直しの前に意図の event を足す** —— 基準と同じことを2つ目の帳簿で言う。2つの帳簿が食い違う形を、また1つずつ避けることになる(ADR 0392 の背景と同じ形)。
- **今のまま** —— 盤面のクラッシュ1回で task が cancel しか出口を持たない。

## 帰結

- ADR 0392 決定2 は決定1・3 で置き換えられる。決定1・3・4 は残る。
- 決定1 は、give-up の後に失われた task の `task/<id>` を盤面が作るのは固定の瞬間だけ、という前提に乗る。この前提は ADR 0392 決定3(受理の解放は失われた task の ref を書かない)と、give-up が走行中の失われた task を拒むことで保たれる。ほかの書き手が増えれば、その値も黙って採られる —— 決定3 を外す変更はこの ADR を見直す。
- ADR 0414 決定10 のクラッシュ後の回復は、初回の作成と作り直しの両方で、基準に在る値だけに成り立つ。決定9 の型付きの拒否から、失われた event が効いたまま在る ref の拒否が抜ける。
- #3539(祖先の ref で拾った子に question を立てる)は、止まりそのものが無くなるので残る作業が無い。
