# start_work と pickup の固定は、名前の場所から複製を受け取った後に書く

2026-11-25 の grilling(issue #3788、#3763 の実装の派生)で決定。ADR 0374 決定2 は `start_work` を「固定(列・`task/<H>`・`task_branch_created`、祖先の分も)→ 作業台を開く」の順に置き、開けない失敗を「人間が壊した作業台か host の事情で、開き直せば直る」ものとして、名前の場所を止めずに拒んだ。その後 ADR 0411 決定5 が「branch の閉包が全部読める」を名前の場所の条件にしたが、この条件を確かめるのは複製を作る fetch で、固定の後に走る。開き直しでは直らない名前の場所の側の失敗が、記録を書いた後に起きるようになった —— 拒まれただけの task が「タスクブランチを持つ」と読まれる。pickup も同じ順だった。測定と経路の読みは #3788 に置く。

## 決定

1. **`start_work` と pickup は、名前の場所の側の理由で落ちるなら、固定を何も書かずに落ちる。** 名前の場所の側の理由は、shallow・書く先の閉包が strict な検査で読めない・作業台が `board/*` として受け取る branch がその検査を通らない(ADR 0411 決定5 と追記)。固定は task の列・`task/<id>` の ref・`task_branch_created` で、同じ瞬間に固定する祖先の分を含む。ADR 0374 決定2 の順を、この範囲で置き換える。
2. **機構は、複製を先に作ること。** fork 元の commit を読み、そこから複製(`start_work` は作業台と `board/*` の受け取り、pickup は task の checkout)を作り、通ってから固定を書く。固定が書く `task/<id>` は、複製が受け取った commit である。タスクブランチを既に持つ task(2回目以降の `start_work`、再 pickup)でも順は同じで、複製の元はそのブランチ —— 同じ瞬間の固定が祖先を作り直しうる。固定が拒むか落ちたら、この呼び出しが作った複製は消す —— 前から disk にある作業台は消さない(人間の commit を持ちうる)。前から作業台がある `start_work` では、`board/*` の受け取りが固定の前の確かめになる。
3. **固定の後に残る失敗は、作業台と host の側だけ。** 固定の後に `board/*` へ `task/<H>` と祖先のブランチを足す手が落ちるのは、ADR 0374 決定2 が置いた「開けない」拒否のまま(開き直しで直る)。
4. **基準の行は、落ちた扉が残してよい。** 基準は ref の写しで、task の状態を変えない。残さない形は閉包の確かめを準備の前に置くことになり、閉包を2回読む。shallow の確かめだけは1コマンドなので、`start_work` と `open_workbench` でも pickup と同じく準備の前に置く。
5. **失敗の扱いは変えない。** 人間の扉は拒否(ADR 0374 決定2、文は ADR 0411 の名前の場所の拒否)、pickup は名前の場所の Quarantine(ADR 0411 決定5)。

## 退けた形

- **門の項で閉包が在ることを先に確かめる**(面接室の (task, 面接室) の項と同じ読み)—— object が在るかしか見ず、破損と strict な検査の warning では今と同じく固定の後に落ちる。
- **strict な検査を事前に別の fetch で撃つ** —— 決定1 は満たすが、閉包を毎回2回読む(ADR 0411 決定6 の費用が倍になる)。
- **shallow の確かめだけを前に移す** —— 閉包の欠けと `board/*` の branch で同じ形が残る。

## 範囲の外

- **面接室で走る task の pickup。** ブランチを立てた後に面接室が提供するものを読んで fetch する(ADR 0386 決定1)ので、この順に乗らない。閉包が在ることは門の項が固定の前に確かめている。破損で固定の後に落ちる形は派生 issue が持つ。 **Status 追記: 下の追記(issue #3834)が範囲に入れた。**
- **拒否や停止の文の中で作業台を開く扉**(封じ込めの組の停止、conflict の拒否、完了の text C2b)。停止と拒否は作業台を開けたかに依らない事実で、固定を書かない。

## 残る穴

複製を作ってから固定を書くまでに盤面の process が死ぬと、タスクブランチの無い task の作業台が disk に残る。途中で止まった盤面が残した置き場の族(#3617)に寄せる。

## 追記(2026-11-25 の grilling、issue #3834)

「範囲の外」に置いた面接室で走る task の pickup は、面接室の object が壊れているか strict な検査を通らないと固定の後に落ちた。同じ形が読み専用の checkout にもあった —— 面接室の外の task を含む読み手が、実環境に固定を書いた後で面接室からの fetch に落ちる。門の項は object が在るかしか見ない。測定は #3834 に置く。

6. **決定1・2 は、pickup が作る複製すべてに及ぶ。** task の checkout(面接室で走る task を含む)と、どの役でも読み専用の checkout を全部作り、通ってから固定を書く。作る手が落ちるか固定が拒んだら、この呼び出しが作った複製を全部消す。面接室で走る task だけを直すと、読み手の分が残る。
7. **面接室で走る task の複製の元は、面接室が提供するもの**(ADR 0386 決定1)—— タスクブランチがあればそのブランチ、無ければ切る元を面接室で解いた commit で、固定はその commit を `task/<id>` に書く。固定が切る sha と準備が fetch するものは同じ持ち主の答えなので、順を入れ替えても決定2 の「固定が書く `task/<id>` は、複製が受け取った commit」が保たれる。解けない切る元は、fetch の前に今の文で落ちる。
8. **失敗の扱いは変えない。** 面接室からの fetch の失敗はその task の項の文で面接室の名前の Quarantine(ADR 0386 決定3)、番地を作れない失敗は host の側(ADR 0356 決定2)。読み専用の checkout の fetch に strict な検査は足さない —— 読み手は出題の head の tree を読むだけで、完了の門に閉包を出さない(ADR 0411 決定1 の理由に当たらない)。

「残る穴」の残骸には読み専用の checkout も入る(#3617 のまま)。門で strict な検査を撃つ形は、上の「退けた形」のとおり採らない。

## 追記(2026-11-25 の triage、issue #3841)

決定1 の「固定を何も書かずに落ちる」は名前の場所の側の理由だけを範囲にしていた。固定そのものが持つ task の側の型付きの拒否 —— 失われた event が効いたまま `task/<id>` が在る(ADR 0392 決定2)—— は、祖先を上から1つずつ書きながら判定していたので、下の祖先か task 自身で拒むと、それより上で作り直した祖先の `task/<id>` と `task_branch_created` が残った(拒んだ扉が、その祖先の失われた event を効かなくする)。測定は #3841 に置く。

9. **固定の瞬間は、書く前に拒否を全部確かめる。** 固定する集合(同じ瞬間に固定する祖先を上から、最後に task 自身)の全員について型付きの拒否を確かめ、通ってから書く。確かめは上から順で、名指す持ち主は今までどおり最初に拒む task。拒否の後には、この呼び出しが書いた ref・event・列が無い。確かめは決定2 の複製の後・固定の直前に置き、名前の場所の側の確かめとの順は変えない。event は append-only なので、書いてから巻き戻す形は採らない。
10. **書く途中の git や DB の失敗は範囲の外。** 次の作成が event だけ足して通るクラッシュ後の回復(ADR 0329 決定2)のまま。
