# エージェント定義は専門性のみを運ぶ — ワーカープロトコルは盤面が注入する

初代エージェント deckhand の system prompt は、MCP verbs の使い方と rules of the road(盤面のワーカーとしての振る舞い方)を運んでいた。しかしこれは全ワーカー共通のプロトコルであり、agent ファイルに書くと複写 drift を生む — 全ワーカー共通の教義を registry の各所へ複写しない、という ADR 0010 の論拠がそのまま当てはまる。しかも verb の意味論は MCP ツールの description が接続時に既に運んでおり、盤面の掟(subagent 密輸禁止等)は BOARD_DOCTRINE として spawn 時に注入済みだった。プロトコルは3箇所に分散していた。

決定: **agent 定義ファイル(registry の `agents/<name>.md`)は専門性 — 人格・観点・そのエージェント固有の手順 — のみを運ぶ。** ワーカープロトコルの散文は adapter のコード側注入(BOARD_DOCTRINE の拡張)へ全面移管する。この帰結として、専門性を持たない既定エージェントの正規の姿は**本文が空**の定義(frontmatter のみ)になる。deckhand は削除し、まっさらな既定エージェント **tako** 🐙 に置き換える(命名の世界観は「船員」ではなく「潮だまりの住人」— エージェント名は海の生き物のローマ字和名を優先する)。

帰結:

- **エージェントを増やすのは、人格・観点・権限・モデルが frontmatter/本文の差として現れるときだけ**(例: レビュー専門の auditor、戦略思考特化)。手順知識はまず担当エージェントの instructions(本文)に閉じ、他エージェントと共有したくなった時点で workspace の skill へ昇格する — 「まず inline、共有で抽出」。
- 定型作業のためにエージェントを増やさない。デプロイ等は既定エージェント + skill で足りる。
- 空本文が正規形になることで、WebUI からのエージェント作成の最小操作が「frontmatter を埋めるだけ」になる。

Considered options:

- **プロトコルを各 agent ファイルに書き続ける(deckhand 方式)** — エージェントが増えるたびに複写され drift する。「まっさらなエージェント」が定義できず、作成の敷居が本文執筆になる。
- **deckhand の名前を維持して本文だけ空にする** — 操作としては同じで移行も最小だが、「甲板員」は船の世界観を引き込む。マスコット級の名前は tidepool の住人(海の生き物)から採る、という世界観の決定を優先した。
