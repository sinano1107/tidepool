# task の checkout と作業台は名前の場所の objects を借りない —— 閉包を全部持つ複製で作り、帰責は落ちた手でなく段で決まる

**Status 追記: 決定1 の「worker は名前の場所の objects を読めない」は Interview の root が読む実環境にも成り立つ —— root は実 workspace の名前の場所でなく休止位置の head の読み専用の checkout を読む([ADR 0426](0426-the-interview-root-reads-a-checkout-of-the-resting-head-not-the-real-workspaces-named-place-and-the-real-environment-it-is-told-is-a-place-it-can-read.md) 決定2、2026-11-26、issue #3865)。**

**Status 追記: 決定4 の「閉包の中は守る」は、運ぶ手が読む object(tree・commit)と、運ぶ commit が名前の場所に既にある運び直しにも成り立つ —— 運ぶ手は損傷で落ちる前に入れ直しへ届く([ADR 0425](0425-carrying-reaches-the-reinsertion-before-damage-inside-the-closure-in-the-named-place-fails-it-even-when-the-carried-commit-is-already-there.md) 決定1・2、2026-11-26、issue #3862)。**

**Status 追記: 決定4 の「確かめが上限を越えたときは名前の場所の側で拒む」の帰責は worker の故障に置き換わる —— 読むのは運んだばかりで確かめ終えていない閉包である。入れ直しに進まないことは保つ。決定3 の段の帰責は上限超過には当たらない([ADR 0423](0423-a-bounded-git-call-reads-bytes-not-yet-verified-into-the-record-and-what-reads-only-the-record-runs-unbounded.md) 決定1・5、2026-11-26、issue #3855)。**

2026-11-24 の grilling(issue #3734、#3588・#3589・#3501 の族の根)で決定。ADR 0356 決定2 は、work / review の task の checkout を「alternates で名前の場所の objects を借りる」形で作った。理由は「今日と同じ可視性」の1句で、複製と比べていない。借りると、盤面が tip を検証する写しに checkout の byte と名前の場所の object が混ざり、検証の git が落ちたとき、盤面はどの手が落ちたかからどちらの故障かを推すことになる。この推しは両方の向きに外れた —— worker が借りている tree の id に偽の loose を1つ書くと名前の場所の Quarantine が立ち、名前の場所で壊れた借りている blob は checkout の故障になる。ADR 0364 の追記(#3495)の確かめ直しも同じ形で騙された。借りない役(Interview の2役)にはこの族の問題が1つも無い。実測と費用の表は #3734 に置く。

1. **task の checkout は、どの type でも、自分の branch の閉包を全部持つ複製で作る。** ADR 0356 決定2 の「work / review は alternates で借りる」を置き換える。検証(ADR 0364 決定1)は4つの役とも「閉包が全部写しの中で解ける」の1つの手になり、名前の場所の ref から届く閉包を除外する形と、ADR 0364 の追記(#3495)の確かめ直しは要らなくなる。worker は名前の場所の objects を読めない —— sandbox の読み path からも外れ、名前の場所にあるだけの commit を親にした tip は checkout の故障になる(ADR 0364 決定1 の「worker が読める object だけで作れる」は、読める範囲が自分の閉包に狭まる)。
2. **作業台も複製で作る。** tip の検証は借りない写しの中で済ませ、名前の場所の値と比べる手(祖先か、どの commit が先にあるか)は、検証を通った盤面所有の写しに名前の場所の objects を借りさせて撃つ —— 出題の写しが既に採っている形(ADR 0364 決定1)。借りるのは盤面所有の写しだけで、人間の作業台は借りない。
3. **帰責は段で決まる。** 借りない写しの中の検証が落ちれば checkout か作業台の故障、比べる段と名前の場所へ運ぶ段が落ちれば名前の場所の側。ADR 0364 決定2 の線はそのままで、「stderr でも名前の場所への問い合わせでも分けられない」は、分ける必要が無くなる。
4. **運んだ後は、tip の閉包の全部が名前の場所で読めることを確かめ、欠けは入れ直す。** ADR 0388 決定1 の集合「運んだ場所の自前の store にある object」は式を変えず、複製では閉包の全部になる。ADR 0398 決定2・3(借りている tree の下の object と、運ぶ前に名前の場所で起きた損傷は守らない)は、tip の閉包の中については守る側に置き換わる。運び終えた後の損傷(ADR 0388 決定4)は今どおり守らない。確かめが上限を越えたときは入れ直しに進まず、名前の場所の側で拒む(#3735)。
5. **盤面で使う名前の場所は、branch の閉包が全部読めることを条件にする。** 複製を作る fetch は閉包を全部読むので、古い履歴の object が1つ欠けていても pickup は止まる —— 読めない object を名指す名前の場所の Quarantine。shallow な名前の場所も同じ条件で拒む。**今は使えているものが使えなくなる**: 借りる形では、触らない履歴が欠けていても仕事は進んだ。写しがどこにも無い object を失った local だけの repo は、盤面では使えない。閉包が読めない repo は git 自身も clone できず、盤面の外でも壊れている。ADR 0398 決定4(盤面は名前の場所の健全性を確かめない)は、pickup と運ぶ手が閉包を読む範囲で置き換わる。
6. **費用は閉包の大きさに比例し、今は受け入れる。** 借りる形の誤りは記録に誤った帰責を書き、人間に作業台を手で消させる。複製の費用は遅さで、後から縮められる。検証の段の上限(ADR 0357 決定5)は変えない —— 閉包の大きさから導くか、差分で検証するかは #3764。
7. **封じ込めの検査の使い捨て checkout(ADR 0379 決定2)も複製で作る。** 盤面はその tip を読み戻さないので帰責を推す箇所は無いが、ADR 0379 決定2 は「task の checkout と同じ作り方」と決めていて、決定3 は同じ検査を2つの checkout に当てて比べる。借りる形を残すと、作り方が2つになり、名前の場所を借りる checkout がこの1箇所のためだけにコードに残る。checkout を作る手から「借りる」が無くなる。

## Considered Options

- **借り続け、帰責に「分からない」を足す**(ADR 0409 決定1・4 の形)—— 費用は新しい object の量で済むが、どちらの故障か決められない失敗の組と、確かめ直しの手が残る。
- **閉包が読めない名前の場所(shallow を含む)だけ借りる形に落とす** —— その workspace にだけ帰責の誤りが残り、検証の手が2つになり、どちらで走ったかの記録が要る。
- **運んだ後の確かめを、fork 元の閉包を引いた集合に絞る** —— 引く元を checkout の byte から読むので、除外の機構が戻る。
- **作業台だけ借りる形を残す** —— 取り消せない害(人間に未取り込みの commit を手で消させる)は作業台で起きる。
- **盤面の記録を人間の repo(名前の場所)に置くこと自体を問い直す** —— ADR 0356 が bare と clone の強制を退け、ADR 0388 決定4 が理由つきで受け入れている。基準の値を押さえる話は #3534。

## 追記(2026-11-24 の実装、issue #3734)

決定1 の後、完了の門と未決着の解放の検証は、tip の閉包全体を `index-pack --strict` に掛ける。fsck の warning も拒む検査で、名前の場所の ref から届く閉包はもう除外されない。そのため、名前の場所の履歴に fsck の warning に当たる object(mode を 0 埋めした古い tree など)が1つでもあると、pickup は通るのに、すべての task が task の checkout の故障で落ちる。worker には直せず、記録は worker を責める(#3734 の ponytail-review で実測)。

決定5 の条件に「branch の閉包が strict の検査を通ること」を足す。pickup で task の checkout を作るとき、作った複製の閉包に同じ strict の検査を1度撃つ。落ちれば、その object を名指す名前の場所の Quarantine で止まる。帰責は段で決まる(決定3)。名前の場所の履歴が理由の失敗は、checkout の故障になる前に名前の場所の側で止まる。そうした repo を盤面で使えるようにするか(fsck の個別の msg-id を warn に戻すか)は #3128 が持つ。

## 追記(2026-11-24 の実装、issue #3763)

決定2 で作業台を複製にすると、作業台は名前の場所の branch を `board/*` として fetch で受け取る(ADR 0371 決定7)。この fetch に strict の検査が無いと、書く先でない branch(人間が `git merge board/<x>` する相手)の履歴にある fsck の warning に当たる object が作業台に届く。人間が盤面の拒否文どおりに merge すると、借りない写しの中の検証(決定3 の段1)が落ちて作業台の故障になり、workspace の削除の扉は作業台を手で消せと言う —— #3589 と同じ害である(#3763 の試作で実測)。借りる形では、名前の場所の ref から届く閉包を除外していたので起きなかった。

決定5 の条件を、作業台が `board/*` として受け取る branch すべてに広げる。`board/*` の fetch にも task の checkout と同じ strict の検査を当て、落ちれば名前の場所を名指して拒む(決定3 の運ぶ段の帰責)。書く先でない branch に1つでもそうした object があれば、その workspace では作業台を開けない —— 決定5 の「branch の閉包」より厳しい。名前の場所の履歴が理由の失敗は、人間が作業台で merge する前に名前の場所の側で止まる。そうした repo を盤面で使えるようにするかは、今どおり #3128 が持つ。
