# 未開始(Idle)ウィンドウは「観測できた不在」であり観測の失敗ではない — fail-closed に落とさない

アカウントのセッション窓がアクティブでないとき、`/usage` パネルの session ブロックは「0% used」だけを描き **Resets 行を描かない**(issue #287。Pi の実機キャプチャを ADR 0074 の画面合成に通して確定 — 初期フレームは spawn 時刻+5時間の仮アンカー「Resets 12:10am」を合成描画するが、直後のパネルリフレッシュがこれを消し、本番 checkUsage の quiet debounce は必ずリフレッシュ後の画面を読む。issue コメント欄の目視判定 (c) は初期フレームの残像を読んだ誤りで、実態は (b) だった)。従来のパーサは percent と Resets の**両方**を要求するため、この正当な状態が「観測不能」に潰れて fail-closed(throttled、resetsAt = null)に落ちる。fail-closed はタイマーを張らないので復帰手段は人間がセッションを開始することだけになり、**人間の最後の利用から5時間後〜次の利用まで盤面が遊休する** — tidepool が価値を出すはずの AFK 時間帯そのものが失われ、UI には「観測不能」という真逆の顔(予算まっさらなのにスクレイパー破損の表示)が出る。

そこで観測語彙に**未開始(Idle)** — 「ウィンドウの不在を観測できた」状態 — を追加し、観測の失敗(unobservable)と型で区別する。判別は描画からの3分法で、session / week / fable の3ウィンドウに一様に適用する:

- **percent が 0 かつ Resets 行なし → 未開始(Idle)。** 正当な状態であり、そのウィンドウの線は絞らない(盤面は即 pickup してよい)。
- **percent が 0 より大かつ Resets 行なし → fail-closed。** アクティブな窓は必ず Resets を描くので、これは破損の疑い。
- **percent 自体が読めない(unavailable 表示・ラベル不在)→ fail-closed。** 従来どおり。

この3分法には**自己制限性**がある: 書式変更で Resets が恒久的に読めなくなっても、「未開始」と誤読できるのは使用率が 0% の間だけで、盤面が pickup して使用率が付いた瞬間に「>0% + Resets なし」= fail-closed に落ちる。#79 型の「書式変更でサイレントに絞りが外れる」被害は 0% 近傍に閉じる。

**ADR 0030 の予約(人間の取り分)の意味論は変えない。** オフセットは「アクティブな窓の中で経過ペースから遅れて走る」ことであり、窓が無い状態には遅れる対象のペース線が存在しない。pickup が窓を開けた後は、just-in-time の次回観測から従来どおりペース線(オフセット込み)が効く — 序盤に 1% でも使用率が付けばペース線超過で catch-up まで絞られるので、人間の予約は窓が開いた直後から機能する。逆に未開始にも予約相当の待ちを課すと、待ち明けの再観測がまた未開始を見る「滑る livelock」として同じ遊休が再発する。

**永続状態・UI は変えない。** 未開始は throttle_state 上「throttled = 0」に畳む。未開始は本質的に過渡状態で(候補タスクがあれば盤面が即 pickup して窓が開き、無ければ scrape 自体が走らない)、人間にとって行動可能な真実は「絞られていない」— それは正確に表示される。ADR 0028 の「fail-closed は可視化とセット」は観測不能側の原則であり、未開始はもう観測不能ではない。

Considered options:

- **fail-closed の維持(wontfix)** — ADR 0028 の fail-closed はスクレイパー破損・認証落ち向けの設計で、「セッション未開始 = 予算まっさら」という正当な状態の誤分類は設計意図の外。タイマーの張れない恒久停止であり自己回復の道が構造的に無い。
- **0% ウィンドウの合成(未開始を「今開始した 0% の窓」と読み替える)** — 既存の evaluateWindow にそのまま流せるが、アンカーが観測のたびに now へ滑るため、オフセット予約時間(session 20pt = 1時間)を毎 poll 引き直す滑り livelock になり直らない。
- **percent だけで判別(>0% + Resets なしも未開始扱い)** — 自己制限性を失う。Resets の書式変更ひとつで session の絞りが全域サイレントに外れる(#79 の形の再現)。
- **未開始を第3状態として永続・UI 表示** — スキーマ拡張(窓別カラムの 0/1/NULL に第4値)に見合う診断価値が無い。過渡状態ゆえ人間が目撃する時間はほぼなく、鮮度表示(ADR 0058)が既に観測時点を伝えている。

Consequences:

- ADR 0008 / 0028 の「観測不能はすべて fail-closed」は維持されるが、**「観測不能」の範囲が狭まる** — 観測できた不在はもう観測不能に含まれない。
- `tests/usage.test.ts` の既存 fail-closed 固定(unavailable 表示・ラベル不在・% 不読)は3分法でも全て fail-closed 側なのでそのまま残る。追加は4本: 実キャプチャ由来の合成画面 fixture(session 未開始・week は読める)、未開始 → throttled しない、「>0% + Resets なし」→ fail-closed、week 側の未開始も同じ読み。
- week の未開始レンダ(アカウントが7日以上静かな場合)は未観測のまま一様適用する。判別規則がブロック単位で同一なため session だけ特別扱いする理由が無く、誤読の被害は自己制限性が同様に閉じる。
- 実装は issue #287(Codex 委任)。
