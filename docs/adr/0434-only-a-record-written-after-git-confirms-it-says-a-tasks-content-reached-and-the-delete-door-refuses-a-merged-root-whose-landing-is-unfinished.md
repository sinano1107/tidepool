# 内容の到達を言うのは着地が終わったことを確かめた記録だけ —— PR の merge の記録は数えず、削除の扉は merge 済みで着地の終わっていない根を拒む

2026-11-27 の triage → grilling(issue #3921、扉の側は #3949)で決定。ADR 0421 の Status 追記と ADR 0380 決定1 は、PR の merge の記録
(`pr_merged` / `pr_merge_observed`)を、根のブランチの内容が保護ブランチに届いた記録(到達の記録)として種類だけで数えていた。だが
merge で届くのはその時点の PR の head までで、収束が push する前に根へ merge back した修理の内容は届いていない(ADR 0241 決定1 の
「merge 済みでまだ運ぶ内容がある」)。盤面の merge は撃つ前に積み残しを git で確かめるが、gh の merge を待つ間の子の解放の merge back
は止めず、観測の merge は何も確かめない。merge back は記録を残さないので、merge の時点でブランチが head より先に進んでいたかは記録で
決められない。#3921 の実測では、merge を観測した後に削除の扉が通り、同じ checkout で登録し直した根の下の修理子が根のブランチから
分かれて根へ merge back し、誰も運ばないまま done に見えた。読み手の表と実測は #3921 に置く。

## 決定

1. **到達の記録は、着地が終わったことを確かめた記録だけ** —— 収束が根に運ぶ内容が無いと確かめた後の `landing_finished` と、local 着地の
   執行(`local_merge_executed`)。PR の merge の記録は、盤面の merge でも観測でも数えない。読む側(削除で着地が終わった task の帰り先なし、
   系譜の「着地済み」、失われた task の透明)はどれも記録だけで読むまま、この集合を読む。ADR 0421 Status 追記の「記録で決められない
   側は拒む側に倒す」を、子の内容だけでなく根自身のブランチの内容にも当てる。
2. **削除の扉は、PR の merge を記録したが着地がまだ終わっていない根が在る間は拒む** —— 運ぶ内容が残るかを問わず、記録だけで読む。
   待てば通る: 収束は次の回で merge 済みの根を必ず読み終える(内容が無ければ `landing_finished`、残れば失敗の question)。断念が効いている
   根は ADR 0421 決定4 と同じく数えない。これで、削除で着地が終わる merge 済みの根は、内容が届いていないと人間が答えたものだけになり、
   決定1 がそれを帰り先なしに数える。
3. **削除の確認の一覧は、扉を通る merge 済みの根も、GitHub の merge が内容を欠くと名指す。**

## 退けた形

- **merge の記録に届いた head を持たせ、読むときにブランチと git で比べる** —— ADR 0421 決定3 の「git を当てず」と食い違い、
  `landing_finished` が既に同じ比較を git で済ませている。
- **merge back に sha 付きの記録を足す** —— 新しい event と書き手が要り、得るものは決定1 と同じである。
- **扉が、merge 済みで内容の残る根だけを拒む** —— 内容の届いた merge 済みの根が観測の直後に扉を通ると、決定1 の下では永久に帰り先なしに
  なる。
- **本番の scheduler で観測と収束の間の窓が開くかを測る** —— どちらの結果でも直す形が変わらず、人間の回答(断念)からも同じ形に届く。

## 帰結

- 失われた task の透明は、数える祖先の PR の merge の記録では成り立たなくなる。merge から収束の次の回までの間に失われて give-up した
  task は死んだと読まれる。
- 観測の直後に叩いた削除の扉は、収束が根を読み終えるまで拒む。
- ADR 0380 決定1・ADR 0421(決定3・4・5 と Status 追記)に Status 追記を置いた。
