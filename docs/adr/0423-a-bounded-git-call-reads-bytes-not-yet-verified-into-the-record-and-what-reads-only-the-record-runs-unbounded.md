# 上限を持つ git の手は記録として確かめ終えていない byte を読む手であり、記録だけで読める部分は上限を持たない手に分ける

2026-11-26 の triage → grilling(issue #3855、#3814 の派生)で決定。ADR 0357 決定2 は上限で止まった手を worker の repo の故障とし、
それは上限を持つ runner の型でそのまま決まる。一方、上限超過以外の失敗は段で帰責する(ADR 0411 決定3)。そのため上限を持つ手が
名前の場所の byte も読むと、名前の場所の遅さが worker の時間切れとして刻まれる —— 出題の写しは面接室にしか無い親の tree を worker の
tree と上限つきで比べ、遅ければ root を回収する。同じ読みの損傷は面接室の側の拒みに落ちる(#3814 の固定)ので、同じ手が壊れれば
面接室、遅ければ root と割れていた。逆に、運んだ後の確かめ(#3735)は上限超過だけを手で名前の場所の側に付け替えていた。上限を持つ
手の一覧と帰責の表は #3855 のコメントに置く。

## 決定

1. **上限超過の帰責は、手が読む byte で決まる。段では決めない。** 比べる段・運ぶ段の手間は worker の中身と履歴の大きさで増やせるので、
   段で帰責すれば worker は大きさだけで帰責を名前の場所へ押し付けられる —— 決着していない解放なら名前の場所の quarantine になりうる(コード読み、未測定)。
2. **上限を持つ手が読む「worker の byte」は、その時点で記録として確かめ終えていない byte である。** worker が今書いた byte と、今運んで
   いる途中の byte。確かめ終えて記録に入った byte は、誰が書いたものでも名前の場所の byte である —— 前の出題で運んだ面接室の tree も
   そう。上限は凍結(worktree の FIFO、ADR 0357)を防ぐためにあり、object store の確かめ済みの object は凍結の形を取れない。名前の場所の
   plumbing を上限なしにする ADR 0357 決定1 と同じ線である。
3. **記録の byte だけで読める部分は、上限を持たない名前の場所の側の手に分ける。** 失敗は型の無いまま名前の場所の側に落ちる(verb の
   時点では拒むだけ、ADR 0359 決定4)。
4. **記録の byte と確かめていない byte を1度に辿る手は上限を持ち、止まれば worker(作業台の流れでは作業台)の故障のまま。** 履歴の
   比較(祖先か、他 task の commit を含むか)、名前の場所への fetch(ADR 0364 決定2)、入れ直しがそれにあたる。名前の場所の遅さを
   worker の故障と刻む余地はここに残り、受け入れる —— 分ければ一方の側の読みで比べられない。
5. **運んだ後の確かめの上限超過は worker の故障である。** 読むのは運んだばかりで確かめ終えていない閉包である。ADR 0411 決定4 の
   「名前の場所の側で拒む」の帰責を置き換え、「上限超過は損傷を見つけたことにならない —— 入れ直しに進まない」は保つ。
6. **「worker の repo の故障」の語は残す。** 意味は原因の断定でなく、止めるのは session で名前の場所ではないという分類である(繰り返しの
   凍結を断つ、ADR 0357 決定2)。回収される worker に言う文は原因を言い切らない。

## 退けた案

- **段で帰責する** —— 決定1 の穴。
- **混ざった手の上限超過はどちらの故障にもせず拒むだけ** —— 拒めば凍結を繰り返せる(ADR 0357 決定2 の理由)。
- **「byte の出所」(書いたのは誰か)で線を引く** —— 面接室の親の tree は前の出題で運んだ root の byte なので今の挙動が正しくなり、
  運んだ後の確かめと同じ軸で逆の答えを出す。
