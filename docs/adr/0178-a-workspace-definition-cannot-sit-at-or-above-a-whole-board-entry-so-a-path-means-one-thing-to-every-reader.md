# workspace の定義は盤面全体のエントリがある path とその上位に置けず、影は作れない —— 重ねた1本の木を門で守る

2026-09-30 の triage / grilling(issue #1212)で決定。ADR 0083 追記4 は「同じ枝で重なれば workspace が勝ち、盤面全体は影に
入る」と置き、影の定義を「他の workspace でその枝が何を受け持つか」と読んだ。だが盤面全体の leaf は影の枝の下にも届き、
workspace の定義の下に並ぶ。影が無くても同じ形が出る —— 盤面全体の定義が無い path に盤面全体の leaf があり、workspace が
それぞれその path を定義していると、1件の leaf が workspace ごとに別の定義の下に出る。実測は #1212 のコメントに置く。

## 決定

1. **読み手の INDEX は盤面全体と workspace を重ねた1本の木のまま。** 盤面全体の定義は、自分の定義を持たない workspace の
   枝も定義する。ADR 0176 決定7 と ADR 0177 決定5 は変えない。
2. **盤面全体のエントリがある path とその上位に、workspace は Definition を持てない。** 門は両側に掛かる —— workspace の
   Definition を置く操作にも、盤面全体のエントリを置く操作にも(書き込み・1件の移動・枝ごとの移動・復元)。workspace の leaf は
   どこにでも置け、workspace は盤面全体の枝の下に自分の子の枝を定義できる。
3. **門が見るのは、無効化されていない盤面全体のエントリすべて。** 種別・状態(candidate も)・宛先を問わない。
4. **盤面全体の leaf は、盤面全体の定義が無い枝にも置ける。** 追記4 の「定義の無い枝への書き込みは拒否しない」は盤面全体でも
   同じで、その枝は全 workspace で未定義と出る。
5. **門は操作が残す状態に掛かる。** 同じ操作で畳まれる workspace の定義は当たらない —— 盤面全体の定義を書いて、その path の
   workspace の定義を `supersedes` で畳むのは1手で通る。枝ごとの移動は1組でも当たれば全体を拒み、当たった組をすべて名指す
   (ADR 0177 決定2 と同じ形)。`merge` は同じ scope の定義どうしの畳みのままで、scope を跨ぐ畳みは足さない。
6. **影は作れない。** 追記4 の「workspace が勝ち、盤面全体は影に入る」、追記7 の「`read_memory` は影の Definition を省く」、
   ADR 0161 追記7 の「`supersedes` なしで書けば影として覆える」を改める。workspace 固有の意味は別の path か子の枝に置く。
   `search_memory` が Definition を返さない(追記7)は変えない。
7. **leaf の行に scope の印は出さない。**
8. **構造検査の「workspace と盤面全体の定義の矛盾」を落とし、「複数の workspace が同じ path を定義している」を足す。** 同じ
   意味なら盤面全体の定義1つに畳み、違う意味ならどちらかの枝を改名する。運ぶ場所は memory meta-review の purpose(追記8)。

## なぜ重ねたままか

盤面全体と workspace の path を別の名前空間に分ければ、影も門も要らない。だが meta-review の workspace を跨ぐ仕事(枝を跨ぐ
重複、全 workspace に要るエントリを盤面全体へ広げる)は「同じ path は同じ話題」を鍵にする。分けると同じ事実が workspace ごとに
別の path に育ち、盤面全体へ広げても workspace の木は揃わない。重ねた木では、盤面全体へ広げた path を以後どの workspace も別の
意味で定義できず、共有の語彙は広げるたびに増える。これは仕組みからの推論で、複数 workspace の盤面で meta-review を走らせて
測ってはいない。

## なぜ上位にも掛け、leaf も数え、見えないエントリも数えるのか

枝の意味は上位の定義の中で読まれるので、上位が workspace ごとに違えば同じ path が同じ意味にならない。定義だけを数えると、
盤面全体の leaf を書く前に定義が要り、追記4 の例外が盤面全体にだけできる。見えるものだけを数えると、candidate が承認された
瞬間に禁じた形ができ、人間の approve を拒む門が要る。

## なぜ検査を入れ替えるのか

矛盾は門で作れないので、周期で見るものが無い。残るのは workspace どうしの重なりで、互いに見えないので worker の読みは
壊さない。だが門が構造を揃えるのは誰かが盤面全体へ広げたときだけで、放置した重なりは広げるときに必ず門に当たる。

## 退けた案

- **盤面全体と workspace の木を分ける** —— 上のとおり。ADR 0177 決定5 は理由ごと不要になるが、構造を揃える力が無くなる。
- **定義どうしだけを排他にする** —— 盤面全体の定義が無い path の盤面全体の leaf を塞げない(実測した形)。
- **影を残し、leaf の行に scope の印を出す** —— 1つの path に意味が2つ載る状態を残し、周期の検査で補う形になる。門で守った
  後の印は、worker の行動を変えない。
- **定義は盤面全体にしか置けない** —— 構造は書く時点で揃うが、1つの workspace の worker の1行が審査なしで全 workspace の
  注入に入る。workspace で育てて meta-review が盤面全体へ上げる向きが、candidate から approved へ上げる記憶全体の作りと揃う。

## 帰結

人間の盤面全体への書き込みが、worker の書いた workspace の定義で拒まれうる。出口は盤面全体の定義を書いて畳む1手で、拒否の
文言が当たった組を名指す。塞いでいる定義を見て畳む面は #1219。
