# 同じ名前の登録し直しは前の登録の続きであり、名前の repo は、名指す task が残る間は削除をまたいで残る

2026-11-22 の grilling(issue #3500、族に #3390)で決定。削除の扉 → 登録し直し は2つの役を兼ねていた。path の差し替え(ADR 0373
決定14)では、削除を生き残った根が再登録した checkout を信じて着地を続ける(ADR 0370 決定1)。repo を移す道(ADR 0378 決定9)では、
削除の扉が覚えた repo を行ごと消し(同 決定10)、新しい repo を覚え直す。記録はどれも名前で引くので、盤面は新しい登録が続きか別物かを
区別できない。PR を開いた done の根は削除の扉を止めず、別の repo で登録し直すと、着地はその根の PR 番号で新しい repo の無関係な PR を
読み、決着を旧い根に刻む。新しい repo で同じ番号が振られると、番号から根を引く読み手が旧い根を返す(どちらも実測、issue #3500 の
コメント)。

## 決定

1. **同じ名前で登録し直したものは、前の登録の続きである。** 別の repo には別の名前を付ける。世代を持たせて「別物」とする形は退けた
   —— 世代の列と前の世代の根の出口が要るのに、同じ名前で repo を移したい運用は1つも挙げられなかった。
2. **名前の記憶を、正体と場所の状態に分ける。** 覚えた repo と覚えた出元 repo(purely-local であることを含む)は名前の正体で、削除を
   またいで残る。基準の ref と sparse の写しは場所の状態で、今どおり削除で消す —— 基準を残すと path の差し替えで古い基準と新しい
   checkout を比べてしまい、ADR 0373 決定14 が壊れる。
3. **削除の扉は、その名前を名指す task が状態を問わず1つでも残る間、正体を消さない。** 名指す task が無いときだけ消す(間違えて登録した
   名前は今どおり別の repo へ向け直せる)。判定は消す処理と同じ同期区間で行う(#3372 / #3322 の穴を受け継がない)。「着地を終えた根」
   の一般の述語で線を引く形は退けた —— 今は無く(ADR 0397 決定1 は失われた根だけ)、作ると PR の決着・hold・断念・失われた根を1つに
   まとめる仕事になる。
4. **違う repo は登録の扉が拒み、扉を通らない行は行き先の入口の照合が workspace の Quarantine にする。** 扉は checkout の origin から
   書く宣言を覚えた repo と ADR 0378 決定4 の比べ方で比べ、文は両方を名指して別の名前を案内する。扉を経ない行(ADR 0373 決定13)は
   ADR 0378 決定6〜8 のまま止まる。覚えた値は基準の行が無くても比べる —— 「行が無ければ覚えた値も無い」が決定2・3 で偽になる。
5. **登録の扉は、覚えた出元 repo を新しいエントリに書く。** 続きなので受け継ぐ。書かなければ、fork を持つ workspace は登録し直した
   直後に覚えた値と宣言の食い違いで Quarantine になる。
6. **改名だけは、GitHub が同じ repo と答えたときに扉が受け入れる。** 覚えた値と宣言が食い違ったときだけ両方の repo の id を問い、
   同じなら覚えた値と、その名前の根が記録した PR の repo(決定7)を同じ transaction で書き換える。違う id か読めなければ拒む。出元
   repo の改名は settings の扉で同じ扱いにする。GitHub へ出るのは食い違ったときだけである。
7. **PR は repo と番号の組で記録し、番号から根を引く読み手は repo も鍵にする。** 決定3 で正体が消えた後に同じ名前を別の repo へ
   登録し直すと、番号の衝突は決定1 の下でも残る。
8. **出元 repo の差し替えは、PR を記録していて merge も close も記録されていない根が残る間は拒む。** 開いた PR の head は古い fork に
   あり、差し替えた後の push と自分の PR の探索は新しい fork を見る。一度使った出元 repo を永久に固定すると fork を作り直せないので、
   線は開いた PR に置く。
9. **着地の最初の撮りも、pickup の開く前の項を通す。** 最初に触れる4つの入口のうち着地だけが外れていた(issue #3390)。決定4 の扉は
   登録の後に名前の場所で origin を向け替える形を塞がない。落ちれば workspace の Quarantine で、受理が同じ述語を撃ち直す。

## 帰結

- ADR 0378 決定9 の「repo を移す正規の道は 削除の扉 → 登録し直し」と決定10 の「登録し直しで新しい repo が覚え直される」は偽になる。
  同 限界の「改名は 削除の扉 → 登録し直し だけ」は決定6 に置き換わる。ADR 0383 決定2 の「開く前の項を求めるのは作業台を開く操作」
  は着地の最初の撮りに広がる。どちらにも Status 追記を置いた。ADR 0370 決定1 と ADR 0373 決定14 は変えない。
- 名前を別の repo に向け直す道は、名指す task が無い間に限られる。一度使った名前は、同じ repo(改名を含む)にしか登録し直せない。
- `branch:` を登録し直しで変えたとき開いた PR の base と食い違う疑いは、この ADR の外に起票した。
- 改名で自分の PR の探索が取りこぼす疑い(#3578)は、登録し直しが無くても起き、この決定に依らない。
