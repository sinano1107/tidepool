# episode は走った段を持ち、学習器は行のいまの段の観測だけを数える

2026-10-07 の grilling(issue #1414)で決定。学習器のセルは (provider, model, effort, advisor) で段を持たず、spawn の記録も
出所(`source.tier`)しか持たないので、行を段の間で動かすと、元の段の task で得た受理・却下が移った先の候補どうしの比較に
そのまま数えられていた。ADR 0110 決定2 が「学習の文脈変数」とした要求ティアは、候補が要求ティアの行に限られることで
セルに暗黙に入っているだけで、行が段を移らないあいだしか成り立たない。effort の書き換えはセルが変わるので実績が切れ、
漏れるのは tier の書き換え(人間の編集、行の提案 —— ADR 0150、段を足して行を移す提案 —— ADR 0200 決定8)だけだった。
コードの照合と実装の割り付けは #1414 のコメントに置く。

## 決定

1. **すべての `worker_spawned` が、解決した段の id を持つ。** work / review、claude / codex の書き手を問わない。候補は要求
   ティアの行だけなので、走った段 = pickup が解決した段である。名前でなく id で持つ(ADR 0200 決定2)—— 消した段の名前は
   id から引ける。既存の episode は埋め戻さない(盤面は作り直す)。
2. **学習器は、候補の段で走った episode だけを集計する。** 盤面の段と workspace の段の両方を段で絞る。行を T から T' へ
   移すと T' では未観測になり、先頭なら未観測のまま走る(ADR 0181 決定2)。T へ戻せば T の観測がまた数えられる。段を
   論理削除して同名で足し直すと id が変わり、旧い観測は二度と数えられない —— 段をまたいだ episode は申告された仕事が違う
   (ADR 0200 決定8)という線のとおりである。
3. **セルは4欄のままで、段は workspace と並ぶ episode の文脈である。** pickup の候補は1つの段に揃うので、推薦の結果は
   段をセルに入れても同じ。入れると shadow 行の両セルと `list_routing_cells` の「初観測のセル」の形が変わり、「セルは pin の
   綴り」が崩れる(pin に段は無い)。行の移動は `list_routing_cells` が既に並べる行の編集で見える。
4. **Interview の観測は、同じセルの、同じ段の観測としてだけ数える。** ADR 0181 決定4 の「同じセルの観測」をこう読み替える。
   対象を段 T で測った結果は、T に行が足されたときだけ数えられ、T' に足した行は未観測で始まる —— Interview の問いは
   「この model は段 T の品質を満たすか」で、T の結果は T' を語らない。
5. **`list_allocations` は、すべての出所の配分評価に解決した段を付ける。** これまで `task` 出所だけに付いていたのは、spawn が
   段を持たなかったからである。段の説明の書き換えを `task` 出所からだけ提案する線(ADR 0200 決定7)は変えない。

## 退けた案

- **何もしない** —— ADR 0110 決定2 と ADR 0200 決定8 が「比べられない」とした episode を、推薦の中で比べ続ける。
- **移した時点で実績を切る** —— 行ごとに切った点の印(移した event の id)が要り、行を元の段へ戻しても実績が戻らない。
- **段をセルの5欄目にする** —— 決定3。
- **Interview の観測は段を問わず数える** —— 決定4。rubric 採点の probe が、別の段の本番 episode と並ぶ。
