# 人間の畳みは書き込みの supersedes と既存の後継への畳みに分かれ、移動の複製は本文の側を継ぐので pin は path_moved をたどる

2026-09-28 の grilling(issue #1037)で決定。ADR 0161 決定4 が人間の面に畳むと移動を作ると決めたので、その形を決めた。
今の人間の口と domain の関数の調査は #1037 のコメントに置く。

## 決定

1. **新しく書く後継は各種別の書き込みの `supersedes`(1件以上)、既にある後継は畳む口が受ける。** 4種別すべての書き込みが
   `supersedes` を持ち、approved の編集はその1件の場合。既にある後継への畳みは replaces と successor_id を取る。
2. **置き換えられるのは、新しく書く後継なら approved だけ、既にある後継なら candidate も。** candidate を新しい文言で
   置き換えるのは question の外で直すこと(ADR 0152 決定3)。既にある approved へ畳むのは覆われた candidate の引退で、
   文言を承認しない。
3. **新しく書く Behavior の出所は、`source_event_id` があればそれ、無ければ supersedes の出所が1つに揃っていればそれを継ぎ、
   揃っていなければ自身の作成 event。** 1件の編集は「揃っている」の特別な場合で今の挙動のまま。meta-review の `consolidate` と
   同じ規則で、違いは揃わないときの出所が人間は自身の宣言、meta-review は推論の decision であること(ADR 0153 の書き手の線)。
   何を畳んだかは置き換えられた側の `successor_id` が持ち、出所(本文の証拠)とは役目が別。Exemplar は出所が必須、Knowledge と
   Definition は出所を持たないので、この規則は Behavior だけのもの。(2026-09-28 に改訂: 当初は「2件以上は継がない」としたが、
   揃った出所を継がない理由は無かった —— #1038 の見直し)
4. **移動は4種別すべてが受け、単位はエントリ1件と枝ごと。** 枝ごとは1つの scope の中でその枝と配下の生きたエントリを
   1 transaction で写す。移動元と移動先の両方に Definition があれば拒否する —— 2つの定義をまとめるのは畳む。宛先の変更は移動でなく編集。
5. **移動の複製は本文の側 —— 書き手・状態・出所・承認(版)—— を継ぎ、移した者は移動のイベントに残る。** candidate は
   candidate のまま移る。meta-review の `move_memory` も同じ規則に揃える。
6. **移したエントリを pin する提案 question は陳腐化させず、pin の解決が `path_moved` の鎖をたどる。** question の pin は
   見せた時点の id と版のまま残し、照合と適用は生きた複製に対して行う。`superseded` はたどらない。

## なぜ畳む口を書き込みと既存の後継で分けるのか

新しい後継の欄は種別ごとに違う(Exemplar の注釈、Behavior の宛先と出所)。1つの口にすると4種別の書き込み schema を畳む口が
もう一度持つ。「この新しいエントリが X を置き換える」は既に `supersedes` の意味。

## なぜ移動の複製は移した者の名義にしないのか

`path_moved` は本文が同じことを言い、書き手と承認は本文に属する。移した者の名義にすると、question で承認された AI の文言が
人間の文言として記録され、人間の Knowledge は出所を持たないという線とも衝突する。

## なぜ pin を陳腐化させずにたどるのか

移動は本文が同じことを盤面が保証するので、見せた前提は崩れていない。陳腐化させると提案が次の meta-review まで消える。
question の列を新しい id に書き換える案は、見せた前提の記録を後から変えるので退けた。

## 退けた案

- **新しく書く後継と既にある後継を1つの口で受ける** —— 決定1の理由。
- **移動は Knowledge と Definition だけ** —— Behavior / Exemplar の置き場の変更が本文の変更(`superseded`)として記録され続ける。
- **移動はエントリ1件だけ** —— 枝の改名が途中で止まると枝が割れて残る。ADR 0161 が畳むで退けた N+1 手と同じ欠陥。
- **枝の下に candidate があれば枝ごとの移動を拒否する / candidate は元の path に残す** —— 本文が同じなので candidate のまま移せる。

## 追記(2026-09-28 の grilling、issue #1047)

**決定5 の「出所を継ぐ」は、出所が自身の宣言(自身の作成 event)なら複製も自身の宣言、と読む。** 対象は人間の Knowledge・
Definition(書き手を問わず)・出所の Episode を添えない人間の Behavior。旧エントリの作成 event を複製の出所に写す形は退けた —— それは
どの書き口も作れず(事例の引用は decision_logged / worker_spawned の event だけを受ける)どの読み口も描けない出所であり、旧との
結び付きは `path_moved` の後継 id が既に持つ(出所と役目が別、決定3)。「自身の宣言」の判定は出所が自身の id を指すことのままで
よい —— worker の Knowledge は任意の event を引用できるので、作成 event を指すことを自己宣言と読むと正当な引用を誤分類する。
今の実装の walk-through は #1047 のコメントに置く。

## 追記(2026-09-28、issue #1041 の実装時)

**決定3 の「この規則は Behavior だけのもの」を改め、Exemplar も `supersedes` があれば出所を省いてよく、省いたときは
supersedes の出所が1つに揃っていればそれを継ぐ。** 揃っていなければ拒否する —— Exemplar は出所が必須のまま。注釈はその出所の
case で検査する。RCA 起草の Exemplar candidate は出所が帰責(`objection_attributed`)のまま承認されるが、事例の引用はその
event を受けないので、出所を転記し直す編集ではその approved Exemplar を書き直せなかった。
