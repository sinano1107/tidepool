# 正準テキストは英語、翻訳は表示時の導出

UI を日本語で読めるようにするにあたり、エージェントに日本語で直接出力させる案(system prompt での言語指示)を退け、記録される正準テキストは常に英語のまま、日本語化はすべて表示層の導出として実装すると決めた(2026-07-13 の grilling)。

根拠: tidepool では「人間向けに見える出力」がほぼすべて後段でエージェントの入力になる — meta-review はログ全体を読み、Auditor の独立レビューは成果物と判断ログを読み、handoff doc は統合復帰セッションが消費し、question の選択肢は選ばれた回答としてエージェントのコンテキストに還流する。エージェント消費テキストは英語という既存の不変条件(`src/tasks.ts` 冒頭に明文化)を保つには、正準を日本語にする余地がそもそもない。また「保存値に焼き込まず表示の瞬間に解決する」という盤面の一貫した導出哲学(blocked / held / workspace 帰属と同型)にも一致する。

退けた代替案: system prompt への出力言語指示は、将来の出力の言語切替こそ1行で済むが、過去の不滅の記録が出力時の言語で固定され、レビュー機構が読む記録の言語が人間の表示言語設定に従属してしまう。

精密化(同日の追記): 「英語」の不変条件が覆うのは**地の文(scaffolding)** — 盤面とエージェント自身が発するテキスト(system prompt、tool 記述、handoff の見出し、エージェントの記録) — のみ。**人間が書いたペイロード**(登録した title / purpose / 完了基準、question への自由記述回答、異議の steering、scratchpad)は書かれた言語のまま保存し、翻訳も英訳正規化もしない — 入力時に英訳して焼き込むと、異議やレビューが読む人間の意図の一次資料が機械翻訳になり、記録は不滅・無改変の哲学に反する(エージェントは日本語ペイロードをそのまま読める)。registry の識別子(workspace 名・agent 名)は機械照合に使われるため従来どおり英数字。帰結として、人間登録の日本語 title とエージェント登録の英語 title が Board / Queue 上で混在することは許容する。

再精密化(2026-08-14、issue #298 の grilling): この不変条件は盤面の実装者に向けてしか書かれておらず(`src/tasks.ts` 冒頭のコメント)、**ワーカー自身には一度も届いていなかった**。日本語ペイロードのタスクを実行したエージェントが、記録(判断ログ、decompose の子のフィールド、handoff doc、result)を日本語で焼き込む事象が実機で2回観測され、どのフィールドが日本語に倒れるかはタスクごとに変わり安定した分かれ目は無かった(issue #298)。対応として、WORKER_PROTOCOL に「盤面に書くものはすべて英語、引用する人間ペイロードは原語のまま」の横断1文を置く。これは本 ADR が退けた「system prompt での言語指示」と矛盾しない — 退けたのは記録の言語を人間の表示言語に従属させる指示であり、英語指示は正準を固定する側に立つ。置き場所が per-verb の tool 記述ではなく WORKER_PROTOCOL なのは、横断的な作法は protocol・動詞ごとの意味論は tool 記述という線(ADR 0017)に加え、倒れ方が非決定的である以上フィールド単位の対処では覆えないため。PR 本文は handoff の派生値なので地の文として英語側に入る(外部面を人間の言語で見せたくなったら、保存値ではなく表示・派生の問題として別途扱う — handoff→PR の時差を扱う issue #303 と交差する)。verb 境界での言語 enforcement は入れない — 原因は指示が届いていないことなので、まず届いた状態での再発率を観測してから検討する。

三度目の精密化(2026-08-21、issue #415 の grilling): 再精密化の1文(WORKER_PROTOCOL)が届いた状態でも再発した — 英語ルールを含むブランチ(commit 5295f94)で日本語ペイロードのタスクを盤面の既定(sonnet / medium)の tako に任せ、判断ログと handoff doc がともに日本語で焼き込まれた。Claude CLI の user 層 `language` 設定は原因ではない(worker spawn は `--setting-sources project` で user 層を遮断しており、実測でもその形では言語指示が届かない)。残る原因は指示への不追従で、system prompt 前方の1文が `get_current_task` 以降の日本語ペイロードに負ける。よって**置き場所を盤面に書く verb の tool 記述に移す** — `log_decision` / `complete_task` / `decompose` / `escalate` の4つ(worker session が届く書き込み面の全部。読取の `get_current_task` / `list_agents` と人間側の管理MCP は対象外)— 共通定数1つを各 description に連結し、「引用する人間ペイロードは原語のまま」の半文も一緒に運ぶ。WORKER_PROTOCOL の1文は**外す**(移す、複製しない): 規約の綴りを1箇所にするのが ADR 0017 の趣旨であり、外すことで「verb 記述だけで足りるか」を直接測れる。これは再精密化が置いた線「横断的な作法は protocol、動詞ごとの意味論は tool 記述」を精密化する — 違反が書き込み点で起きる規約は、横断的であっても書き込み点に置く。「倒れ方が非決定的なのでフィールド単位では覆えない」は根拠として退ける(verb 単位なら書き込み点は全て覆える)。verb 境界での enforcement は引き続き入れない: 引用ペイロードを原語のまま許す以上、非 ASCII 比率のような閾値では引用と違反を区別できない。再開条件を明文化する — 移設後、issue #364 の手順で日本語タスクを既定モデルで2回回し、1回でも倒れたら次手は `-p` 本文への再掲、それでも倒れたら enforcement を設計する。
