# 資源を止めるのは型で名指された資源の故障だけ —— 無人の過程の盤面のバグは、その段が帰属の分からない失敗を送る先へ行く

**Status 追記: 決定3・5 の出所での型は、網に出る git にも及ぶ —— 盤面の git の子は1つの起動口だけが作り、cwd が無い失敗と host の失敗はそこで型になる。網に出る git の一般の失敗の型は #3999 が決める([ADR 0441](0441-the-board-starts-every-git-child-at-one-place-that-types-its-failure-once-and-network-git-only-brings-its-own-env.md) 決定1・4、2026-11-28、issue #2897)。**

2026-11-27 の triage → grilling(issue #3938、#3903 の triage で族の根として分けた)で決定。無人の過程(後始末・pickup・着地・worker の
準備)の catch は、型の付いた失敗を ADR の決めた行き先へ送り、残りを全部名前の場所の Quarantine にしていた。名前の場所に撃つ git の
失敗は素の `Error` なので、この既定は git の失敗には偶然当たる。だが盤面のバグ(`TypeError`・不変条件の門)と host の失敗も同じ所に
落ち、人間に「名前の場所を直せ」と出る。この既定は誰も決めていない写しで、ADR 0403 決定2 / ADR 0427 決定2(出口は失敗の中身で決まる)、
ADR 0294 決定3、ADR 0342 決定1 と食い違う。箇所の表と読んだ経路は #3938 に置く。

## 決定

1. **範囲は無人の過程の catch である。** 人間が叩く扉は拒否文で返し(ADR 0427 決定3)、worker の verb は ADR 0424 のまま。
2. **盤面のバグは資源を止めず、その段が帰属の分からない失敗を送る先へ行く。** 後始末の中なら落ちた後始末(ADR 0342 決定1)、
   slot を握った後の pickup と worker の準備なら `spawn_failed`(ADR 0294 決定3)、着地なら昇格失敗 question(ADR 0403 決定3)。
   新しい行き先は作らない。後始末の盤面のバグは、名前の場所1つの停止から盤面全体の停止へ重くなる —— ADR 0112 決定3 の
   「直るまで動かないのが正しい」の代償として受け入れる。
3. **盤面が起こす git の失敗は、出所で「git の道具の失敗」の型を持つ。** catch はこの型を、名前の場所に撃つ段の失敗に限って
   名前の場所の Quarantine にする。型は失敗した git の path を持たない —— どの場所かは段の帰責(ADR 0367 / 0370 / 0403 決定4)が
   決める。1つの git が worker の worktree と名前の場所の objects を同時に読む段があり、path では場所が一意に決まらない。
   同じ catch の中で名前の場所以外(worker の checkout・盤面所有の写し・view の一時 dir)に撃つ git は、その段の型
   (worker の repo の故障・写しの host の失敗・ADR 0427 決定2 の写しの資源)で名指す。名前の場所の git の失敗を Quarantine にする
   既存の決定は動かさない。
4. **盤面が名前の場所の状態を観測して投げる失敗も、名前の場所の型を持つ。** 保護ブランチの diverge・ahead、merge back の
   conflict、記録した親が commit でない、など。名前の場所を直せば通る故障で、型が無いと決定2 で盤面全体の停止に倒れる。
5. **disk が満ちた git の失敗は、出所で host の失敗の型にする。** 行き先は段ごとの host の線(ADR 0356 決定2 / ADR 0364 決定2)。
   今の判定は写す段にしか無く、その外の fetch が名前の場所の Quarantine になっていた(#3774)。
6. **名前の場所を直しても通らない不変条件の門は型を付けない。** alternates の門(ADR 0412 決定2)・task の checkout の検査・
   記録の task ref が無い、は決定2 の行き先へ行く。旧版の完了の tip を確かめられない失敗が盤面のバグか名前の場所の故障かは
   spec が判定する。
7. **例外は1つ: 人間担当の work の完了の後の merge back。** `done` を書いた後なので拒否で返せず(ADR 0401 決定1 の (3))、
   後始末の中でもないので撃ち直す runner が無い。撃ち直しの経路が workspace の Quarantine の受理(ADR 0369)しか無いので、
   盤面のバグでもその Quarantine に残す。理由の文は名前の場所の故障でなく盤面の失敗と名指し、答えればやり直すと告げる。
8. **無人 merge の最後の同期区間の盤面のバグは、`merge_failed` でなく ADR 0403 決定3 の昇格失敗 question にする。**
   `merge_failed` は gh の merge が落ちたことを言う question で、盤面のバグを「merge を直せ」と読ませる(#3771)。

## Considered Options

- **盤面のバグの側に型を付ける(門ごとの型)** —— `TypeError` のような想定外のバグは型を持てず、既定が名前の場所のまま残る。
- **git の型に path を持たせる** —— 場所が一意に決まらない段があり、段の帰責と二重になる。
- **人間担当の work の merge back も盤面全体の停止にする** —— 撃ち直す step が無く、受理が再起動まで通らない。
