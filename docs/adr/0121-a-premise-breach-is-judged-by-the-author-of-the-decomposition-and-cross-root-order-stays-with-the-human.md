# 前提の破綻は分解判断の書き手が判断し、root 間の順序は人間に残る

2026-09-15 の grilling(issue #629)で決定。worker があるタスクの途中で、後続のタスクにも効く不具合を見つけたとき、
今の盤面に打つ手が無いのではないか、が発端。答えは場合で割れた。同じ分解判断に乗る兄弟に効く発見は、Decompose の
節が「escalation で人間を呼ぶ」と処方しながら、一般 question の held が自分のサブツリーしか凍らせないため兄弟を
止められない — 既存挙動の導出上の穴で、痛みの観測を待つ種類ではない。別の root タスクに効く発見は、worker が任意の
タスクを引けない以上、原理的に人間の判断である。実装の現状と `file:line` は issue #629 のコメントに置く。

## 決定

1. **前提の破綻は、その分解判断の書き手が判断する。** 子は「自分が乗っている分解判断の前提が壊れた」を宣言する専用の
   verb を持つ(escalation ではない — escalation の「宛先は常に人間」の線は無傷)。宣言の効果は、同じ分解判断に乗る
   未決着の子(宣言者を含む)のサブツリーが書き手の判断まで held になること — ADR 0048 の abandon の範囲と同じで、
   held と cancel されうる範囲を一致させる不変条件も同じ。書き手が agent なら親が**早期統合復帰**する: blocked のまま
   slot 候補になり(blocked の行が候補に入らない線のこの1点だけの例外 — 導出そのものは変えない)、記録だけを持って
   別セッションで復帰する — 親の知識が記録で足りることは統合復帰が既に前提にしているので、ADR 0045 が却下した
   「子1つごとの checkpoint」とは別物である。
   帰結は2つだけ: **続行**(判断ログ1行で held を解き、宣言した子は親の判断を時系列で受け取って再開)と**再分解**
   (古い判断の破棄 + 新しい decompose を1回の呼び出しで行う)。破棄だけして再分解しない形、未決着の子を残したまま
   新しい判断を書く形は作らない(ADR 0047 の出自の読み取りが濁る)。書き手が人間(人間 decompose)なら Tidepool 名義の
   同じ2択の question、root タスク(親なし)には兄弟が無いので従来の escalation。同じ分解判断への2度目の宣言は Tidepool 名義の
   question(続行 / 判断ごと破棄)へ格上げする — 親の続行はその前提について最終で、親子の往復で slot を燃やす形を
   閉じる。宣言は失敗ではなく(failure question も失敗統計も無い)、子の宣言と親の判断は判断ログに並び、異議が打てる。
   誤宣言の是正は異議 → 帰責(`capability`)が拾うので、別の統計は作らない。

2. **root 間の順序は盤面が持たず、人間に残る。** 自分のタスクの外に効く発見はタスクにならず、「直さない」という権限内
   判断として `log_decision` に置く。流し読む人間が scratchpad → 登録 → 並べ替えで扱い、直させたければ異議 → 修理子
   — principle 6 のセンサ(朝の「またこれか」)そのものが既に経路である。`depends_on` の辺、発見を受けた盤面名義の
   影響範囲 review、下書き時の影響先提案のいずれも入れない。順序を並べ替えから守る必要が本当にあるときは、既存の
   人間 decompose(発見の修理を影響先の子にする)が blocked の導出で守る。観測条件と退けた形の設計は issue #630。

## 退けた案

- **宣言した子が自分で escalation し、held の範囲だけ abandon の範囲に広げる** — 判断の質を上げる材料を持つのは
  分解の書き手であり、人間の question を毎回燃やす。宣言の誤りのコストは「親の spawn 1回 + 遅延」で足りる。
- **すべての escalation が兄弟を held にする** — 局所的な判断の question まで木を凍らせる。
- **現状維持(子が handoff に書き、後続の兄弟が spawn 時の時系列で読んで各自 escalate する)** — 兄弟の数だけ
  spawn と question を払う。
- **親が一部の子だけ差し替える** — 「破棄 → 新 decompose」で表現でき、未決着の子と新判断の混在を作らない。
- **handoff に「タスクにすべき発見」欄を足し、Register の仕上げ待ちへ落とす** — 発見の「これより先」は worker の
  単独主張で、判定は人間。写す手間だけのために欄と受け口を足すより、判断ログ + scratchpad の既存経路で足りる。
