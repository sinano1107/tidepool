# 基準との比較は名前の場所の ref を読んで書く操作すべての最初に置き、Quarantine の受理は見せた移動だけを受け入れる

2026-11-11 の grilling(issue #3151、#3147 の派生)で決定。ADR 0351 決定2 は「基準は切れない」を pickup と解放の2つの時点の比較に
載せたが、名前の場所の ref を読んで運ぶ操作はその外にもあった。Quarantine の受理は比べずに今の `task/<id>` を merge back し、全撮りで
基準を上書きする —— 別の理由で立った Quarantine に回答すると、門を通っていない commit が親のブランチに入り、本文には移動が出ない。
着地の収束も比べずに今の `task/<id>` を push し、Quarantine も回答も無いまま PR に届く —— poll は収束を pickup より先に走らせるので、
pickup の比較が気づくのは push の後である。ADR 0351 決定4 の「回答は『動いた ref のほうが正しい』の受理」は、移動が Quarantine の理由
として名指しされたときしか中身を持たない。`done` の task の `task/<id>` は門の後も正当に動く(子孫の merge back、追いつき、ADR 0240
決定4 の手の merge が帰り先に書き、帰り先は `done` の work でありうる)ので、基準の行は門の tip ではなく「盤面が最後に書いたか受理した
値」である。実測の表と読み手の一覧は #3151 のコメントに置く。

## 決定

1. **基準との比較は時点ではなく操作に置く。** 名前の場所の ref を読んで repo か記録に書く盤面の操作 —— pickup、解放、Quarantine の
   受理、着地の収束、着地の回答と無人 merge の tick、workspace の publish —— は、それぞれ最初に全 ref を基準と比べ、動いていれば動いた
   ref を名指して workspace の Quarantine に落とす。比較器は1つ、範囲は全 ref のまま(ADR 0351 決定2、ADR 0064 決定1)。表示だけの
   読みは比べない。
2. **ref の値の出所は比較の戻り値である。** 名前の場所の ref を読む手は比較の戻り値を受け取って値を引く(完了済みの解放が既にこの形
   —— ADR 0359 決定2)。比べずに読める道は、表示用と名指しした1つだけにする。決定1 の操作の一覧を、数え上げではなく形で守る。
3. **受理は比べてから受け入れる。** 受理の検査は全 ref を基準と比べ、まだ見せていない移動があれば旧値と今の値を名指して回答を拒み、
   その値を**見せた値**として workspace の行に書く。今の値が見せた値と同じ回答だけを受け入れ、merge back のやり直しと全撮り
   (ADR 0351 決定4)へ進む。見せた後にさらに動いていれば、もう一度拒んで見せ直す。本文には「見せていない移動があれば1度拒んで
   名指しする」の固定の文だけを置く(ADR 0369 決定6 の線)。
4. **見せた値を書くのは、名指しの文が人間に届く2箇所だけ** —— 比較の失敗が Quarantine の question を新しく立てたとき(理由が名指し
   する)と、受理が拒否文で名指ししたとき。question が既に開いていて登録が何もしなかった観測(ADR 0366 決定1)は書かない: 人間に
   届いていない移動が次の回答で通ってしまう。見せた値は盤面の予告の2値行(ADR 0243 決定1)とは別の欄に持つ —— 予告は盤面の書き込み、
   見せた値は人間の同意待ちで、持ち主が違う。
5. **完了の門を通った `done` の task の `task/<id>` は、基準の値に「今の値にも帰り先にも届いていない内容」がある移動を、見せた後でも
   受理しない。** 門を通った内容がどこにも届かないまま記録から外れる移動だけを拒む —— `done` ⇔ tip が記録にある(ADR 0359 決定1)を
   1択の回答で破らない。測るのは盤面が「届いていない」を測る既存の述語(merge すると tree が変わるか)で、測れなければ拒む。拒否文は
   この移動を追加の移動と分けて名指す。意図して捨てる出口は `merge -s ours` で基準の値を祖先に残す(ADR 0239 帰結、ADR 0240 決定4)。
   ADR 0242 決定4 の「捨てる」出口だけが、`reset --hard` の後に子孫のブランチを記録する形で基準の値を落としていたので、旧い tip を
   `merge -s ours` で記録する形に直す。着地済みの task のブランチを欠く移動は、内容が届いているので通る。`done` でない task の
   ブランチは、見せたうえで巻き戻しも受け入れる —— 退避した WIP を人間が捨てて retry させる修理を塞がない。ADR 0369 決定3・7 の確認
   (門の記録した tip が今の `task/<id>` から辿れる)は checkout を消す手前のもので、そのまま残る。
6. **門の tip を基準の行と別には記録しない**(ADR 0359 の退けた形のまま)。門の tip そのものを要る読み手は ADR 0369 の確認1つで、
   基準の行で足りる。どの commit が門の tip だったかを名指す記録を残すかは別の問い(#3156)。
7. **手の書き込みを指示する文面は、確認の question を経ることを告げる。** 着地の拒否文(積み残しの merge back、追いつきの conflict、
   local 着地の conflict)と ADR 0242 決定4 の文面に従った手の merge は、決定1 の後は retry の時点で比較に当たり、workspace の
   Quarantine を1枚経る。

## 根と、この決定の位置

根はもう一段下にある: 人間が書いた内容を記録に入れる正規の扉が無く、Quarantine の受理 —— 故障の封じ込めの解除 —— がその入口を
兼ねている。手で書かせる決定(ADR 0064 決定7、ADR 0239 帰結、ADR 0240 決定4、ADR 0242 決定4 ほか)は、名前の場所が盤面の記録に
なる(ADR 0356)より前のものである。決定3〜5 はその入口に同意の中身を与える手当てで、扉の設計(#3158)が決まれば見せた値は外す。
決定1・2 は残る。

## 退けた形

- **受理の範囲から `done` の task の `task/<id>` を外す** —— ADR 0240 決定4 の手の merge は帰り先に書き、帰り先は `done` の work で
  ありうる。ADR 0351 が退けた「範囲を狭める」と同じ形。
- **受理の merge back を門の tip に固定する** —— 門の後に子孫から届いた内容を落とす。
- **運ぶ読みの直前で、読む ref だけを比べる** —— 着地は運ぶ前に、今の ref から `nothing_to_land` / `landing_finished` を1度きりの event
  として書く。運ぶ手前だけ守ると、比べていない ref で決めた記録が残る。
- **question を読むたびに差分を描き、回答に digest を載せる** —— 回答の扉すべての payload が変わる。
- **拒否のたびに question の本文を書き足す** —— 受理が散文を読み戻すことになる。
- **内容を落とす移動も、見せた後は受理する** —— 回答は意図を運ばないので、盤面が指示した巻き戻しと事故を同意で区別することになり、
  門を通った内容が1択の回答で記録から外れる。ADR 0369 決定3 が立てた順(`done` ⇔ tip を先に)と逆になる。
- **基準の値が今の値から辿れるかだけで測る** —— 着地済みの task のブランチを欠く checkout(ADR 0351 決定7 の path の差し替え)まで
  永久に拒む。
- **操作の一覧を test だけで守る** —— 今ある読み手を全部数えたという主張に乗る(ADR 0369 が退けた形と同じ理由)。
