# 入力の規則は leaf の理由関数に置き、サーバーの zod と WebUI の両方がそれを呼ぶ

2026-10-08 の grilling(issue #1551、派生 #1585 / #1586)で決定。ADR 0209 で、WebUI はサーバーの leaf の実行時の関数を
呼べるようになった。それでも WebUI には、送る値の規則の写しが残っていた。pacing offset の範囲、正の整数、provider rank の順列、
registry 名、skill の文法である。写しは「送れる値でだけ Save を押せる」ようにするためのもので、押せない理由は画面に出ない。
写しを消して往復に回す案も検討したが、そうすると zod の 400 は「Bad Request」としか出なかった(#1585)。WebUI のどの欄が
zod の 400 に届くかの実測は、#1585 のコメントに置く。

## 決定

1. **サーバーが入口で断る値の規則は、理由を返す関数(`string | undefined`)として leaf に置く。** サーバーの zod は
   `superRefine` でそれを呼ぶ。WebUI は `TidepoolRules`(ADR 0209)経由で同じ関数を呼び、欄の横に理由を出して送信を止める。
   規則の理由文は1つになる。leaf は概念ごとに分ける(ADR 0204 決定5)。ただし、zod の外側の型の門
   (`z.number()` が `null` を断る、など)は、サーバー側では zod の文のまま残る。WebUI はそこへ届く値を送らない。
2. **数値欄の空欄を、WebUI は「値なし」として読む。** 空欄を `NaN` にして理由関数に断らせる。`Number("") === 0` を経由して、
   空欄が黙って `0` として受け入れられる経路を作らない。
3. **空を許さない欄の空白は、leaf の関数1本で扱う。** 入口で前後の空白を取り、空になれば断る。HTTP と MCP の入口、domain 層の
   検査、WebUI の空欄判定が、すべて同じ関数を呼ぶ。今は `min(1)`、`/\S/`、`=== ""`、trim してから判定、の4通りに割れている(#1586)。
   前後の空白を拒否せずに取るのは、エージェントが送る複数行の文(末尾の改行など)を、見えない差で断らないためである。
   保存される値に前後の空白が残らない点は、拒否しても取っても同じである。
4. **ADR 0138 決定6 を、値の規則についてだけ狭める。** 送信側の body の**形**は、今までどおりサーバーから引かない。
   値が受け入れられるかの**規則**は、決定1の経路で引く。

## 退けた代替案

- **写しを消し、送ってからサーバーの 400 を見せる。** 「押してから理由が分かる」止まりになる。#1585 で 400 を読める文にしても、
  押す前に理由が出る形には及ばない。
- **欄単位の zod schema を leaf に置いて bundle する。** 理由文の共有という効果は決定1と同じだが、zod が丸ごと bundle に入る。
  `public/app.js` が 282KB から約 850KB になり(zod 分は約 570KB、minify なし)、zod の版を上げるたびにコミット済みの成果物に
  大きな差分が出る。
- **真偽値の述語を leaf に置き、Save を押せなくする。** 写しは消えるが、押せない理由は今と同じく出ない。
- **前後の空白を拒否する。** 人間は WebUI が trim してから送るので困らない。困るのはエージェントで、見えない差で tool の呼び出しが
  断られ、やり直しに slot と token を使う。
