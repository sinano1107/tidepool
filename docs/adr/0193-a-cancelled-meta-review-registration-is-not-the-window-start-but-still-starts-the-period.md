# 取り消された meta-review の登録は材料の窓の起点にならないが、周期の起点にはなる

2026-10-02 の triage / grilling(issue #1237)で決定。材料の窓の起点(ADR 0180 決定1 の「前回の登録」)と due の判定は、同主題の
最新の登録を task の status を見ずに取っていた。meta-review が abandon で取り消されると、その登録が次の review の「前回」になり、
その前の材料はどの完了した review の窓にも入らない。現状の読み口と実測は #1237 に置く。

## 決定

1. **材料の窓の起点は、同主題で完了(`done`)した最新の登録の watermark。** 取り消された登録は数えない。読み口の既定、
   spawn 時の注入、routing の読み口はすべてこの起点を共有する。abandon された回が途中で直接書き込みや決定ログを残していても、
   それは窓を読み終えた証拠ではない。次の回が同じ窓を読み直しても、直接書き込みは自分の産物として材料から外れ(ADR 0151)、
   既に直された箇所を店で見直すだけで済む。
2. **周期の起点は、status を問わず最新の登録。** 取り消しの直後に次の回を登録しない。「すぐもう一度」は failure question の
   retry が担い、retry は同じ登録のまま走り直す。abandon を即時の再登録に化けさせると retry と abandon の区別が消え、失敗が
   続く原因が残っていれば、登録と失敗 question が人間の前に繰り返し出る。取りこぼした窓は、次の周期の窓に含まれて読まれる。
3. **due の材料の判定は、決定1 と同じ起点から数える。** 最新の登録(取り消しを含む)から数えると、abandon された回の窓にだけ
   材料があったとき、無関係な変更が来るまで due にならず、決定1 で塞いだ穴が due の側から開き直る。

## 帰結

- 窓の起点と周期の起点が別の登録を指しうる。abandon の後の回は、周期は取り消された登録から数え、窓は完了した登録から読む。
- issue が挙げた「完了したが材料を読み切らなかった review」は扱わない。材料は spawn 時に上限なしで prompt に入り
  (ADR 0180 決定2)、1 session に収まらなくなる場合は #614 の話である。
- 今 meta-review が取り消される経路は abandon だけで、人間の直接 cancel は盤面登録の root に届かない(#1348)。決定は
  経路を問わず取り消された登録に当たる。
