# Board call の 401 は共有の一歩で Provider 認証の証拠にし、その呼び出しは失敗に数えない

2026-10-06 の triage / grilling(issue #1457)で決定。result envelope の 401 を Provider 認証の Quarantine に回していたのは
AI 下書きの呼び手だけで、振り返りの3用途(帰責・配分評価・behavior draft)は同じ一発呼び出しの同じ `CliAuthError` を受けながら
`*_failed` event に畳んでいた。除外の決定はどこにも無く、振り返りが AI 下書きより後に足されたときの取りこぼしである。経路の
`file:line` と再現は #1457 のコメントに置く。

## 決定

1. **振り返りの Board call の 401 も Provider 認証の Quarantine の証拠である。** 証拠と述語は AI 下書きと同じで、確度の線
   (構造化された証拠だけ)は動かない。振り返りは常に anthropic で撃つので、帰属は anthropic。
2. **401 の分類は、行の拒否と同じ共有の一歩で行う。** 表の行で撃つ Board call の呼び手は1つの一歩を呼び、それが行の拒否と 401 の
   どちらの Quarantine も立てる。呼び手ごとに2つを呼ぶ形は、今回の取りこぼしをもう一度起こしうる(ADR 0202 決定1 と同じ理由)。
   表の行で撃たない表示時翻訳は従来どおり 401 だけを分類する。
3. **401 で終わった Board call は撃ち直しの失敗に数えない。** 1ターンも走っておらず直す判断が存在しない、という ADR 0202 決定3
   (ADR 0184 決定4)の理由がそのまま当たる。数えると、環境の事象が対象ごとに3回の枠を1つ食い、失効1回で打ち切りの一覧に
   落ちる対象が出る。数えなくても撃ち直しがループしないのは、Provider 認証の Quarantine の間はその provider の Board call を
   撃たないから(撃てなかった)で、これは #1466 が成り立たせる —— #1466 が入るまでこの決定は実装しない。
4. **事実は Provider 認証の確認 question にだけ残す。** 理由は、どの用途の Board call が(対象の task があればどの task で)401 を
   受けたかを名指す(ADR 0202 決定5 に揃える)。pickup の使用量観測の分類と worker exit の経路の理由は変えない。対象の側には
   何も書かない。

## 帰結

- ADR 0164 決定3 の「CLI の認証」は数える側から外れ、「その provider が認証の Quarantine 中」が撃てなかったに加わる(0164 追記3)。
- 認証を直せば、保留中の対象は次の sweep で撃ち直される —— 人間が対象ごとに Retry する必要は無い。

## 退けた案

- **0164 決定3 のまま数える** —— 揃えて壊れるものが無いのに 0202 との非対称が残り、上の枠の消費が起きる。
- **隣に 401 用の関数を置く** —— 呼び手が2つを呼ぶ形が続く。
- **理由に用途を名指さない** —— 直し方は用途によらないが、撃てなかった事実の置き場所が question だけになったので、0202 と揃えて残す。
