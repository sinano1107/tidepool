# workspace の列は場所が固定された事実だけを持ち、pickup は未着手の祖先も固定し、系譜はタスクブランチを持つ同じ workspace の祖先だけを数える

2026-11-14 の grilling(issue #1796 の族。map #3178 の ticket #3213 の中で一緒に決めた)で決定。木を先に登録すると、盤面は必ず子を先に
pickup する。子の系譜は未決着の親を無条件に候補に数える(ADR 0053 決定1)ので、まだ作られていない `task/<親>` を読み、workspace を
Quarantine に落とす(#1796)。同じ根から3つの形が出ていた —— 登録時に親の列を写した子が、既定の差し替えの後に pickup された親と別の場所に
分かれる(#1788)、別の workspace の祖先のブランチを自分の checkout で探す(#2033)、ブランチを持たないまま決着した祖先を読む(#1827)。
ADR 0290 決定6 は、これを「列は固定の事実か写しか」という前提の問いとして範囲外に置いていた。再現・読み手の一覧・`file:line` は #1796 と
#3213 に置く。コードと ADR の読みで決めていて、盤面は走らせていない。

この ADR が持つのは、列の意味・祖先の固定・系譜の規則・workspace の Edit の凍結までである。祖先が人間担当のときの固定、人間の「書き始める」が
同じ固定の瞬間になること、assignee の凍結に足される鍵は、同じ map の人間担当の work の ADR が持つ。`task_branch_created` が運ぶほかの値と、
ブランチが失われた後の系譜の読みは、失われたブランチの後始末の ADR が持つ。

## 決定

1. **`tasks.workspace` の列は「この task の場所が固定された事実」だけを持つ。** 列を書くのは明示と固定の瞬間だけで、登録時に親の列を写す
   2箇所(分解の子、異議由来の修理子)はやめる。空の列は「列が埋まっている最も近い祖先 → 無ければ既定」と読む —— ADR 0290 が付帯子の
   review に入れた導出を、全 type に広げる。固定が書くのは空の列だけで、埋まっている列は書き換えない(ADR 0233 決定2 のまま)。親を持たない
   task に盤面が登録時に名前を渡す箇所(受験者、retry の Interview の root、`pr_merge` の question)は、導く相手が無い明示なので変えない。
   写しだと、pickup 前の親の Edit が子に効かず、既定を差し替えると兄弟が別々の場所に分かれる。
2. **「タスクブランチを持つ」は event `task_branch_created` で読む。** 盤面は `task/<id>` を作ったら、契機を問わず、ref を書いた後にこの
   event を残す(「開いた event は repo ができた後に書く」—— ADR 0329 と同じ順)。読むのはこの event で、branch が在ることでも pickup の event
   でもない。pickup は event と列を先に書いて ref を後で作るので、間で門が落ちて `todo` に戻った task(ADR 0274)は pickup の event を持つが
   ブランチを持たない。git でブランチの有無を読むと、手で消されたブランチで経路が黙って変わる。固定が空の列を書いたなら、書いた名前と出所
   (既定か、どの task の固定からか)を event に残す —— 登録の event は workspace を記録しないので、残さないと「未指定で登録された」事実が
   消える(ADR 0233 決定4 の線)。
3. **自分のタスクブランチを切る task の pickup は、未着手の祖先も固定する。** 同じ workspace に導出される未決着の work の祖先のうち
   タスクブランチを持たないものを、上から順に固定する —— 空の列にその workspace を書き、祖先自身の系譜から `task/<祖先>` を作り、event を
   残す。列・ref・event は揃って書く。子は `task/<親>` から切られて `task/<親>` へ帰り、親は後で同じ場所で pickup されて統合する。review の
   pickup は固定しない(系譜に透明で、親のブランチが在れば読むだけ)。祖先のブランチを作れなければ、pickup の準備の今ある失敗に乗る。
4. **系譜に数える祖先は「タスクブランチを持ち、列が自分の workspace と同じ」work の祖先だけである。** それ以外 —— タスクブランチを持たない
   祖先と、別の workspace に固定された祖先 —— は、決着済みでも未決着でも飛ばす。数える祖先が残らない task は、自分の workspace の保護
   ブランチから切られ、そこへ自分で着地する。タスクブランチを持たないまま決着した祖先も、この規則で飛ばされる。導出した workspace ではなく
   書かれた列を比べる —— 未固定の祖先の導出は Edit や既定の差し替えで変わり、既に走った子の系譜に後から入って、存在しない `task/<祖先>` を
   読ませる。書かれてタスクブランチを持つ列は動かない(決定5)。
5. **workspace の Edit は、pickup の event か `task_branch_created` を持つ task では拒む。** 空に戻すことも含む。列を明示しただけの task は
   今どおり Edit でき、空に戻せば決定1 の導出(祖先 → 既定)に従う。assignee の鍵にこの event は足さない —— 足すと、木を登録して子が1つ
   走った時点で、まだ誰も走らせていない親の担当を替えられなくなる。

## 退けた形

- **登録時の写しを残し、書き込み点を足して揃える** —— 後から pickup される兄弟が別の既定を引く穴が残る。
- **分解の子を親と同じ workspace に限る** —— review の発見を registry の編集として出す、workspace を越える経路(ADR 0031)を塞ぐ。
- **`task_picked_up` を使い回す** —— slot・後始末・学習器・routing review が session の始まりとして読んでいる。
- **実使用の記録の上に入れる** —— 既存の task はブランチを持つのに event を持たず、木が「祖先は居ない」と読まれる。埋め戻しを書かずに済む
  よう、門の前に入れる(#1796)。

## 帰結

- 「既定への参照は pickup で終わる」(ADR 0233 決定1)は、workspace の側では「場所の固定で終わる」になる。一度も pickup されていない task
  にもタスクブランチが在りうる。既定 agent の側は変わらない。
- 「人間の手は分解ツリー1本につき1回」(ADR 0053 決定3)は、木1本でなく、同じ workspace でつながる系譜につき1回になる。別の workspace の
  子は自分の保護ブランチへ自分で着地する。
- ADR 0301 決定7 が理由に挙げた欠陥(系譜の読みが workspace を見ない)は決定4 で無くなる。決定7 そのものは変えない(#2510)。
- 記録だけで系譜を近似している述語(PR が開いている祖先の下の子孫を `parent_id` だけで外す、ほか)と、列を生で読む箇所を、この規則に
  合わせる。全件の列挙は spec が持つ(#1796)。
- 確かめていない: Interview の受験者と root が系譜に持つ専用の枝(ADR 0263・0273・0276)との噛み合わせ。別の workspace に飛ばされた子が、
  根として完了時レビューを受けるか(#3225)。
