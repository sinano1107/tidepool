# 応答予算の床の記録は Settings の Board に消せない行で出し、一覧の Board 行が印を出す

2026-10-09 の grilling(issue #1386)で決定。ADR 0195 決定5 の出口の床は、予算を超えた応答を切り、盤面スコープの
`response_truncated` を1件残す。床は読み口の欠陥で、予算を超えうる読み口が床に落ちないことは不変条件である。それなのに、
記録はどの人間の面にも出ていなかった。管理MCP で落ちたときは目印が人間の session に届くが、Worker MCP で落ちたときは
worker にしか届かない。直すのは tidepool のコードの変更で、盤面の中に直す手は無い。盤面は止まらず、何も塞がない。
盤面スコープの event が人間の面に出るのは、これが最初の例になる。

## 決定

1. **床の記録は WebUI の Settings > Board のカードに出す。記録があるときだけ出す。** この画面はもともと盤面の状態を
   出す場所で、行があるときだけ出る打ち切った撃ち直しのカード(ADR 0164 / 0172)が先例になる。
2. **行は (surface, verb) ごとに1つで、events から導出する。** 新しい状態は持たない。行には回数、最後の時刻、
   切る前の最大の大きさ、最後の task(worker の面のとき)を出す。同じ名前の verb でも、管理MCP と Worker MCP では
   実装が別なので、surface も鍵に入れる。
3. **行を消す操作は置かない。** 打ち切った撃ち直しの Dismiss には「二度と撃たない」という盤面への効果がある。床の行を
   消しても盤面は何も変わらず、「直した」と「見なかったことにした」を区別できなくなるだけである。盤面は自分の版を
   知らないので、直ったかどうかは版を上げたあと最後の時刻が進まないことで読む。
4. **行があるあいだ、Settings の一覧の Board 行を注意の色にして件数を出す。** 開かない画面の2階層目に置くだけでは、
   この issue の「誰も気づかない」がほとんど残る。
5. **同じ印を、打ち切った撃ち直しにも出す。** 床だけに印を付けると、人間の Retry / Dismiss を待つものに印が無く、
   何も塞がない床にだけ印がある逆転になる。

## 退けた案

- **盤面が human 宛ての task を立てる。** push の対象は「人間がボトルネックで親を塞ぐ」ものに限られる(CONTEXT.md の
  Quiet hours)。答える判断が無いので、人間に意味の無い完了操作をさせることにもなる。
- **管理MCP に読み口を足す。** 管理MCP は settings を痛みが観測されたときにだけ広げる。管理 session で落ちた分は、
  人間がすでに目印を読んでいる。
- **記録だけに留める。** 気づく経路が無いまま欠陥が残る。#1393 は観測をこの面に頼っている。
- **Settings タブにバッジを付ける。** タブのバッジという新しい仕組みになる。しかも、何も塞がない床に、人間を呼ぶ扉に
  近い強さを与えてしまう。
