# WebUI は連結方式のまま TypeScript にする

2026-09-18 の grilling(issue #245)で決定。ADR 0027 は `public/index.html` の React 配線層を「自動テストで
守られない唯一の層」と名指し、その理由に「in-browser Babel のビルドレス React で**型検査も効かない**」を置いた。
ADR 0055 は前半を偽にしたうえで、後半について「埋めるのは本 ADR ではなく派生 issue の仕事になる」と先送りした。
本 ADR がその仕事である。実測(無編集で `.tsx` に改名した tsc の全結果、エラーの内訳、モジュール境界の挙動)は
[#245 のコメント](https://github.com/sinano1107/tidepool/issues/245#issuecomment-5727402766)に置く。

## 決定

1. **`.tsx` にするが、モジュールにはしない。** `import` / `export` を書かず、全ファイルがスクリプトスコープで
   グローバルを共有する今日の形を保つ。tsc はスクリプトのファイル群を1つのグローバルとして見るので、
   `app` から `BoardScreen` を引く参照はそのまま解決される。ADR 0055 の「連結方式であって bundle ではない」は無傷。
2. **strict はルートと同水準。** webui 用の設定を `webui/tsconfig.json` として独立に持ち(ルートは `types: ["node"]`・
   DOM lib 無し・`jsx` 未設定なので `include` の追加では通らない)、`npm run typecheck` は `tsc -p` 2本になる。
   置き場所が webui 直下で名前が `tsconfig.json` なのは、tsserver が自動で探すのがその名前だけで、別名だと
   エディタ診断が webui を inferred project で検査して偽のエラーを出すため(issue #975)。水準を2つ持たない —
   下げれば「webui は緩い」が既定になり、締め直す契機が構造的に来ない。
3. **サーバの語彙はインライン `import(...)` 型で leaf module から引く。** `import type` **文**はファイルを
   モジュールにし、そのトップレベルがグローバルから消えて参照側が壊れる。`type S = import("../src/x").S;` は
   スクリプトのまま引ける唯一の形である。引く先は依存ゼロの leaf vocabulary module —— `src/cause.ts`(ADR 0115
   決定1)と `src/provider.ts`(issue #545)が既に持つ型で、集合を持つ module が import を抱えていると
   ブラウザ側のプログラムに node の世界が流れ込むため、抽出して re-export する。
4. **design-system の型は既存の `.d.ts` から取る。** `design-system/components/**/*.d.ts` は22件すべて揃っており、
   `window.TidepoolDesignSystem_8a0ead` の宣言はそこを参照する **生成物**にする(`scripts/build-ds-bundle.mjs` が
   既に持つ名前→パスの表から導出し、`--check` で鮮度を守る)。手書きの宣言は写しをもう1枚作るので採らない。
5. **移行はファイル単位で刻む。** `allowJs` が真の間は `.jsx` が素通しになるので、残件は tsconfig が持つ ——
   `allowJs: false` を最終状態として書き、緑が部分的であることを人間の記憶に預けない。

## 根拠

**ESM 化は前提ではなかった。** issue #245 の本文は「分割 → ESM 化 → `.tsx` 化」の3段を置き、前2段を
「段3の手段として初めて正当化される」と書いた。実測はこれを裏返した —— 5本を無編集で `.tsx` に改名するだけで
React は UMD グローバルとして解決され、ファイル跨ぎの参照も `Cannot find name` を1件も出さない。残るエラーの
65% は implicit any、すなわち「props に型を書け」であって、構造の問題ではない。前2段は段3から見た理由を失う。

**型検査が守るのは e2e が撃たない分岐である。** `e2e/` には CI 常駐の spec が19本あり、配線の主要な導線は
既に実物で撃たれている。型検査の固有の価値はその外側 —— 撃っていない分岐の `undefined` 参照や props の付け忘れ ——
にある。サーバ語彙の写し(issue #352)の一致は、型を共有した副産物として後から乗るものであって、本 ADR の主題ではない。

**モジュール化は all-or-nothing で、しかも安くない。** 1ファイルを module にすると、そのトップレベルが
グローバルから消えるだけでなく `React` の UMD 参照も禁じられ、`import React` が抱き合わせで要る。5本(段1後は7本)
すべてを同時に移す以外の道が無く、その対価は抑制コメント数行である。

## ADR 0027 / 0029 の前提はどう変わるか

どちらも改訂しない(既存 ADR は不変の歴史)。ただし理由づけに使われた記述が2つ偽になる:

- ADR 0027 の「**型検査も効かない**」と ADR 0029 の「**型検査なし**の React 配線層」は、本 ADR で偽になる。
- 両者が言う「**自動テストで守られない唯一の層**」は、本 ADR とは無関係に**すでに偽である** —— `e2e/` の CI 常駐
  spec は19本ある。ただし ADR 0027 の線そのもの(スモークは網羅を狙わず数本に限る)の再評価は本 ADR ではしない。

## 失うもの

design-system の型は React 18 の UMD の姿に固定される。22件の `.d.ts` は `React.CSSProperties` / `JSX.Element` を
素のグローバルとして参照しており、`jsx: "react-jsx"` へ移ると大域 `JSX` 名前空間が消えて全件が書き換えになる。

## Considered options

- **ESM 化してから TypeScript にする(issue #245 本文の3段構成)** — 上記のとおり前提が実測で崩れた。連結方式を
  捨てる判断を、型検査という別の用件のついでに引き受けることにもなる(ADR 0055 が `ui_kits/` について断った形と同じ)。
- **`noImplicitAny: false` で入れて後から締める** — 床の281件だけ先に潰せる。採らなかったのは、締め直す契機を
  持たないため。ファイル単位の刻み(決定5)が、水準を下げずに1回あたりの量を制御する。
