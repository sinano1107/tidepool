# `parent_id` の木は委譲の木で、系譜は中身の行き先 —— 中身についての述語は系譜で読む

2026-11-19 の grilling(issue #1796)で決定。ADR 0372 決定4 の後、別の workspace の子は親のブランチに帰らず、自分の保護ブランチへ根として
着地する。一方で `parent_id` の上では親の子のままなので、同じ task の集合に形の違う木が2本できる。今の読み手はどれも `parent_id` を読むので、
中身について判断する述語が食い違う —— 親のレビューに載らない子がレビューされない(#3225)、cancel が「捨てる」と出した子が着地する(#3270)、
運ばれない祖先の PR を着地が待つ(`openPrRootAbove`)。読み手の一覧と `file:line` は #1796 に置く。コードと ADR の読みで決めていて、盤面は
走らせていない。

## 決定

1. **`parent_id` は委譲の木である(ADR 0031)。系譜は中身の行き先である(ADR 0053 / ADR 0372 決定4)。** 別の workspace の子も子のままで、
   親は未決着の子を待ち、子が決着するまで完了できず、決着した子の成果を文脈に受け取る。祖先の cancel は未決着の子孫を workspace を問わず
   一緒に倒し、走っている子孫があれば cancel 全体を拒む(ADR 0304)—— これらは委譲についての読みなので `parent_id` で読む。ブランチの中身を
   判定・運搬する述語は系譜で読む。2本が分かれるのは workspace を跨ぐところだけではない —— 透明な review、着地済みの祖先(ADR 0105)、
   失われたブランチ(ADR 0380)、固定されていない祖先でも分かれる。
2. **盤面は、完了した work の中身を運んだ先を記録する。** merge back のとき、運んだ先が祖先の `task/<id>` か、自分で着地する保護ブランチかを
   event に残す。「X の中身が祖先 P のブランチに入ったか」は、この記録を P までたどって読む。列や導出から後で推し量らない —— 祖先の Edit や
   既定の差し替えで列が動いても、既に運んだ中身の行き先は動かない。pickup で切った元は記録の代わりにならない —— 切った元の祖先が後で
   着地済みになると、子はそれを飛ばして帰る(ADR 0105)。
3. **完了時レビューの根は2段で読む。** 列で計算する述語(ADR 0209 で WebUI と拒否が共有する)は、「`parent_id` を持ち、自分の workspace の
   列が親の導出と違う work」を根と同じに扱い、その子への `review_flag` を不発の値として拒む(ADR 0111 追記7・8)。述語は親の導出 —— 祖先の
   列と今の既定 —— を入力に要する。完了の扉は、その時点の系譜で運ぶ先を計算し、保護ブランチなら述語が子と読んでも完了時レビューを立てる。
   述語と扉が食い違う形は許す —— 述語が子・扉が根なら flag 無しでもレビューされ、述語が根・扉が子(G(B) → P(A) → C(B) の C)なら C の中身は
   G のレビューに載る。親の Edit や既定の差し替えで述語の答えが変わっても子の値は検査し直さない(子の Edit ではないので、追記8 の「変わる
   たびに検査し直す」が届かない)。残った値は効かなくなるだけである。
4. **「成果が捨てられた」の cancelled の項(ADR 0271 決定1)は、二つの問いに分ける。** 完了済みの work の成果が捨てられたか —— cancel の面に
   出す、その完了時レビューを倒す —— は、決定2 の記録で、中身が cancelled の祖先のブランチに入ったときだけ数える。別の workspace の完了済みの
   子は捨てられず、レビューも倒れず、自分の保護ブランチへ着地し、cancel の面はそれを独立して着地するものとして見せる。cancelled の祖先の下に
   新しく立ってよいか(ADR 0301 の登録の床)は、今どおり `parent_id` で読む(ADR 0380 決定6)。帰結として、捨てられずに着地する別の
   workspace の子の下にも修理子は立たない —— 異議は帰責と RCA になる(ADR 0301 決定6 の予告と同じ)。
5. **親の着地の門が数える未決着の付帯子は、決定2 の記録で中身が親のブランチに入った子孫のものに限る。** 親の中身に入らない別の workspace の
   子孫のレビューは、親の着地を止めない。親がその子の成果を受け取って完了していても、子の修理を待たずに着地する —— 子の完了は子の着地では
   ないので、今の設計も親が子の着地に乗ることを保証していない。
6. **ほかに `parent_id` を読む述語は、委譲と中身のどちらについての述語かで仕分ける。** 全件の仕分けは #1796 の spec が持つ。

## 退けた形

- **別の workspace の子を根として登録し、出所のリンクだけ残す** —— 委譲の木が場所を跨いでよい(ADR 0031)ことを崩し、親の待ちと成果の
  受け渡しを失う。
- **1本の述語で系譜を読む** —— 系譜は決着済みの祖先について git を読むので、列の述語(ADR 0209)に入らない。
- **cancel も委譲で読み、別の workspace の子の着地を止める** —— 項の理由が中身についてのものなので、理由の当たらない子を巻き込む。止めたい
  人間には着地の question がある。
- **cancelled の祖先の列と自分の列(または導出)を比べる** —— 祖先の Edit や既定の差し替えで列が動くと、中身が一度も入っていない子が捨てられた
  ことになる。cancel で空の列を焼き付けても、cancel の前の Edit は防げない。
- **子が親の導出と同じ名前を明示したら保存しない** —— 親が既定に従うとき、既定の差し替えで子が人間の打っていない名前で走る。親に従わせたい
  人間は欄を空にする。空と明示の違いは画面の文言で見せる(#1796)。
