# Interview は、実環境を読む root が面接室に組んだ環境で測る —— root は第5の task type `interview` で、採点は学習器の観測ではなく事前分布の種である

2026-10-18 の grilling(issue #2184 —— #2011 / #2091 / #921 の根、#1898 もここで決着)で決定。Interview は盤面全体の主張
「この model はこの段の品質を満たすか」を測るのに、乗り物は本番の workspace 1つで、受験者は root の workspace を写して走って
いた(ADR 0253 決定1 / ADR 0267 決定5)。門の盤面では本番の workspace が tidepool 自身1つしか無く、受験者は checkout から測られて
いると読め(#2011)、別の workspace を選ぶ材料も盤面に無かった。「root は受験者と同じ場所にいる」はどの ADR の決定でもなく、
コードの写しだった。実装の照合と読み口の表は #2184 のコメントに置く。

## 決定

1. **受験者は面接室で解く。** 面接室は Interview ごとに盤面が作るまっさらな git リポジトリで、registry の Workspace ではない。
   root の workspace は実環境のまま(ADR 0258 は保つ)で、root は実環境を読み、probe に過不足のない環境を面接室に組む ——
   実環境の写しではなく、盤面の語・盤面を説明するファイル・実環境を名指す名前を含まない匿名化した再現。過不足と匿名化は
   Interviewer の本文(ADR 0269)が持つ規律で、盤面は検査しない。面接室は root の決着後も消さない(監査・異議・retry が環境を読む)。
2. **root は第5の task type `interview`。** 権限面は「実環境について盤面が持つものを読める(読めないのは答案と対象の結びつきを
   明かすものだけ)、書けるのは面接室だけ」で、review(読むだけ)とも work とも違う(ADR 0272 の基準)。登録は人間の扉と提案の
   approve だけ。組み込み agent は review と interview を走らせる。床は OS レベル —— cwd を面接室にし実環境を読みに開ける ——
   で、Claude / Codex とも組み合わせは未実測なので最初の ticket で Lima VM で測り、崩れたら退けた案3に落とす。
3. **出題は、面接室の写しを盤面名義で commit して分岐元の head にし、監査の review を立てる。** root の session の HEAD と作業
   ツリーは動かさない(ADR 0064)。受験者を登録するのは監査の受理で、却下なら root は findings を受けて出題し直す。受験者が
   1人も立っていないあいだは出題をやり直せ、立った後は1回(ADR 0245 決定3 / ADR 0253 決定1 を改める)。#2182 はこれで消える。
4. **監査は `review` type の1種別(RCA と同じ位置)。** 既定は Auditor が root と同じ段で走り、実環境と面接室を読んで、環境・probe・
   rubric がその段の説明の言う仕事を1つ下の段では足りない形で問うているかを判定し、値で残す。付帯子の review は親の読みの面を
   継ぐ、という1規則で読める。監査が review の床(読み + task temp)の外の書きか読みを要したとき、`interview` 側の type に分ける。
5. **採点の後の review は置かない。** 採点の重みは種1件分(決定7)で、行を足す判断は findings を読む人間が持つ(ADR 0199 決定6)。
   「分けたか」は採点の分布として結果に出し、採点の誤りは root の採点の行への異議で受ける。
6. **段は Interview 1件の属性。** 対象は (provider, model, effort) の3欄で、同じ probe で比べられるのは同じ段の対象だけ(段違いは
   Interview を2件)。root と監査が走る段は、盤面の判断の段(ADR 0200 決定4)と測る段の高い方で、人間は登録時に測る段以上へ上げ
   られる —— 対象より下の段の採点者は構成で付かない。表の形が変わる(対象の段の列を root へ)。
7. **採点は観測ではなく事前分布の種。** 表の事前分布(受理1件分)をそのセル・その段で置き換え、学習器が移れる「観測あり」にする
   が、本番の episode と同じ重みでは足さない(ADR 0181 決定4 / ADR 0210 決定4 を改める)。種は受理1件分と出所の event で、却下は
   種にならず、強さのノブは出さない。**人間も行を足す扉で種を置ける**(明示、根拠は編集の記録)。段をまたいで種は写さない。
8. **受験者の `workspace` 列は実環境の名前で、層と許可ドメインの出所。走る場所は面接室。** quarantine と封じ込めの検査は走る
   場所の単位で、受験者は面接室だけ、root は両方を見る。slot は盤面に1つのまま。
9. **登録の欄は仮説(必須)・測る仕事(任意)・根拠の task(人間は任意、提案は必須)で、free text の purpose は持たない。** 人間の
   面では workspace の欄を「実環境(root が読む workspace)」と呼び、受験者の行は「面接室」と出す。root の詳細に面接室の在り処と
   出題の head を出す(ADR 0082 の線)。retry の新しい root は旧い面接室も読める。root の読み口の verb 一覧は spec で応答の形を
   実測して決め、段の説明と実環境の宣言のうち受験者に効く部分は注入する。
10. **流し読みは Interview ごとのグループに root と監査の行を束ね、workspace のグループには出さない。** 見出しは probe の題と実環境の
    名前。グループの単位は判断の産物がある場所で、本番の work は workspace、Interview は面接室である。異議の意味と効果は変えず、
    ADR 0268 決定6 の印は見出しに昇格する。受験者の行は出さないまま(ADR 0268 決定1)。

## 退けた案

1. **人間が用意した固定 repo を土台にする** —— root が実環境を見ずに probe を書き、環境に合った問題が作れない。土台の中身の選択が人間に残る。
2. **本番の workspace のまま、選ぶ材料と移る根拠を足す** —— 門の盤面では結局 tidepool でない workspace を1つ足すことになり、それは面接室である。
3. **空の土台に、scaffold を出題の verb の payload で運んで盤面が commit する** —— root が scaffold を動かして確かめられず、分量が verb に縛られる。床の実測が崩れたときの代案として残す。
4. **cwd を実環境のまま、面接室への書きを権限で足す** —— review の床は permission 層の `manual` で、Bash を自動許可に戻した瞬間に cwd も書ける(ADR 0033 追記 / ADR 0035)。
5. **採点を同じ重みの観測として数え続ける** —— 匿名化した再現環境の rubric 採点を本番の受理と並べる根拠が無い。数えないと死に行の穴(ADR 0181 決定1)が戻るので種にした。
6. **監査を別の type にする / 採点の後にも review を置く / 面接室に実環境と byte 同一のファイルがあれば出題を拒む / 複数の段を1回の登録で展開する** —— いずれも今日の差や観測が無く、条件は派生 issue に置く。
7. **Interview 専用の別盤面** —— 学習器が別 DB になり知見が戻らない(#2011 のコメント)。

## 帰結

- ADR 0258 決定1〜4 はそのまま。「probe はその checkout の上で解かれる」の一文だけが面接室に移る。
- ADR 0263 決定2 の前提「checkout が盤面自身を説明しない」は面接室と規律に置き換わり、決定6 / 追記4 の head の読み方は面接室の出題の commit になる。ADR 0266 の答案の後始末は面接室の中で同じく要る。
- #2091 は決着(採点は実環境の層と盤面全体の層の種)。#1898 の3つの問いはここで決まった(段の移動、root の段、段の説明の注入)。
- 実装は `/to-spec` → `/to-tickets`。表の形が変わるので priority:high のまま。

## 追記(2026-10-18 の grilling、issue #2209 / ADR 0275)

決定1 の「過不足と匿名化は Interviewer の本文が持つ規律」は、運び手が `interview` type の spawn 注入に変わる(ADR 0275 決定3)。
「盤面は検査しない」はそのまま。決定2 の「組み込み agent は review と interview を走らせる」に memory_repair が加わる(ADR 0275 決定1)。
