# プロダクト WebUI のソースは webui/ に置き、Design 側に常設の写しを持たない

2026-09-18 の grilling(issue #246)で決定。盤面が出荷する画面 4 本(queue / triage / single-question / board)は
`ui_kits/tidepool-webui/` にあり、同じファイル群がキットのデモ面(`/kit`)と Product Design 側のコピーの元でもあった。
ADR 0051 と ADR 0055 はこの配置を「Design 側と紐づくので別途判断する」と2度先送りした。本 ADR がその判断である。
実測(依存関係、`/kit` の利用者、起票後の編集履歴、押し戻しの記録)は #246 のコメントに置く。

## 決定

1. **出荷する画面のソースはプロダクト側(`webui/`)に置く。** ADR 0051 が `design-system/` に出した答えと同じ向きで、
   ADR 0055 の「`ui_kits/` は動かさない」をここで引き取る。
2. **`ui_kits/` とキットのデモ面(`/kit`)は畳む。** デモ専用の画面・mock データ・デモの殻も一緒に消える。
   画面の側に残っていた「mock でも動く」ための振る舞いも、利用者がいなくなるので除く。
3. **Design 側に画面の常設の写しを持たない。** Product Design 側の既存コピーは削除する。探索を実画面に接地させる
   必要が出たら、その時点の実ソースから DesignSync で届ける。

## 根拠

**往復は片道しか実在していなかった。** 起票後の画面の編集はすべてリポジトリ側の実装が起点で、Design 側から戻ってきた
変更は記録上ひとつも無い。「Design と往復する正本」として `ui_kits/` を認める案は、実在しない往路を設計に書き込むことになる。

**常設の写しは、保たれているという前提が崩れていた。** Product Design 側への押し戻しの記録は 2026-08-07 が最後で、
その後の画面の変更は届いていない。デモ面の中でも、本番に別実装がある画面の写しは古いまま残った(#206)。
ずれた写しに接地した探索は、写しが無い探索より悪い。都度届ければ、届いたものは必ず新しい。

**画面の編集が1つの提供元で完結する。** 写しを保つ限り、画面を触る実装はすべて「実装」と「Design 側への押し戻し」に
割れ、後者は DesignSync を持つ側にしかできなかった。写しを持たなければ、割れるのは探索を始めるその時だけになる。

## 失うもの

Claude Design の中で実画面のコードが動く状態。キットのデモ面は、サーバ無しで画面を動かせる唯一の形だった。
リポジトリ内の authoring 面は ADR 0050 の preview board が担っており、こちらは無傷である。

## Considered options

- **`ui_kits/` を Design と往復する正本として認め、プロダクトがそれを読むことを明文化する。** 上記のとおり往路が実在しない。
- **4 本だけ `webui/` へ移し、デモの殻は非出荷物と明示して残す。** Design 内で動く写しは保てる。だが mock 許容の
  振る舞いが画面に残り続け、画面の意味が変わるたびにデモ側の追随が要る —— #206 に積まれたずれと同じものを作り続ける。
