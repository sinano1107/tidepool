# 記録された場所の開いた event は repo ができた後に書く —— 面接室と受験者の checkout は1つの開く手順で開き、面接室の名前の quarantine は、その名前を立てうる門の述語をすべて撃ち直して解く

2026-10-30 の triage → grilling(issue #2724 —— #2705 の code-review の残り)で決定。面接室の名前(root id)の quarantine は3つの門から
立つ —— root 自身が面接室を開く手順、読む task の pickup の門(ADR 0277 追記 決定1)、受験者が自分の checkout を開く手順(ADR 0276 決定3)。
解除の門(ADR 0137 決定5)は開く手順を撃ち直せない(event を書き repo を作る副作用そのもの)ので、開いた event・ディレクトリ・repo の有無から
**どの門で止まったかを推定**して検査を選んでいた。開いた event を `git init` の前に書く順では「event あり・repo 無し」が盤面の正常経路
(init の途中で落ちた)として残り、外部で壊された記録と見分けられない —— 本 issue の「`mkdir -p` だけ予告し `git init` が要ることを言わない」
はこの推定の綻びで、同じ推定が root 自身の再 pickup では壊れた面接室を黙って空 repo で作り直し、受験者の再開では checkout を作り直して答案の
記録を失わせていた。門の表・code の読み・テストの釘は #2724 のコメントに置く。

## 決定

1. **記録された場所(面接室・受験者の checkout)の開いた event は、repo ができた後に書く。** 面接室は `git init` と空コミットの後、受験者の
   checkout は出題の head の fetch と `main` の checkout の後。実体の綴りは mkdir 直後の realpath で取るので、event が実体の綴りの記録である
   こと(ADR 0277 決定1)は変わらない。これで **開いた event がある ⇔ 盤面が repo まで作った記録がある** が不変になり、event があって repo が
   無い場所は壊れた記録、event が無い場所はまだ作っていない場所、の2分岐だけになる。ADR 0277 決定1 の「次の pickup が event を書く」と
   追記 決定2 の3分岐(消えた・ディレクトリだけ・repo あり)はこの2分岐に置き換わる。在り処を規約から導く(ADR 0277 決定1)以上、
   event を git の前に書く理由(途中で落ちても在り処を引ける)は無かった。
2. **面接室と受験者の checkout は1つの開く手順で開く。** event があれば在り処に repo があることを確かめ、無ければ投げる(壊れた記録、
   作り直さない)。event が無ければ規約の番地に mkdir → realpath → 作る → event。違うのは「作る」の中身だけ(面接室: init + 空コミット、
   受験者: init + 面接室から出題の head を fetch + `main`)。作る枝は冪等である —— 作った後・event の前で落ちた場所(repo あり・event 無し)
   は次の pickup が同じ番地で作り直して通る。ADR 0276 決定1 の「面接室と同じ順」は、写しではなく同じ手順になる。
3. **root 自身の再 pickup も受験者の再開も、event があって repo が無ければ同じ述語で止まり、作り直さない。** 面接室が記録で盤面が作り直さない
   (ADR 0277 追記 決定2)のに、自分の pickup だけを例外にする理由が無い。受験者の再開判定は「event があり、タスクブランチがある」。
   repo はあるが HEAD が未生の面接室(人間が `git init` だけした)は、開く手順が空コミットを置く —— 失うものが無く、root の準備が `main`
   を要るのは ADR 0273 決定1 のままである。
4. **面接室の名前の quarantine の解除の門は、その名前を立てうる門の純粋な述語をすべて撃ち直す。** 面接室(決定1 の2分岐)に加えて、
   **未決着の**受験者ごとに「event が無ければ番地を作れる / event があれば repo がある」と、出題済みなら「出題の head が面接室で引ける」。
   どの受験者のどの述語が落ちたかを拒否の理由に書く。決着した受験者の checkout は記録だが、開く pickup が無いので門に掛からない。
5. **予告する出口は撃つ述語に従う。** 「手で `git init` して空のまま走らせる」は、出題の head の述語が並ぶ名前(出題済みで受験者が未決着)
   では通らないので予告しない —— 復元か cancel だけ。受験者の checkout を手で作る出口も書かない: init だけでは準備が `main` から切れず、
   手順を写させても答案の記録(WIP)は戻らないので cancel と同じ結果である。

## 退けた形

- **順序を触らず、検査の述語だけ event の有無で切る** —— 「event あり・repo 無し」を正常経路に残したまま検査を締めるので、init の途中で
  落ちた root 自身も人間の `git init` 待ちになり、予告に説明が1段残る。
- **決着した root の面接室だけ `git init` を要求する** —— 未決着の root の面接室を監査が読んで止まるとき、root は監査の決着まで todo で
  待つので root 自身の pickup は来ない。「決着」は述語として足りず、event の有無で切るのが正しい線だった。
- **回答時に盤面が作り直す / 受験者の checkout を出題の head から作り直す** —— 記録の欠落を盤面が既定で埋める形(ADR 0277 追記 決定2 と同じ理由)。
- **受験者の開く失敗の解除を兄弟 issue に分ける** —— 主題は「解除の門が止めた門を推定する」ことで、受験者の門はその3つ目の実例。述語は
  どれも今ある純粋関数で足りる。

## 追記(2026-10-30、issue #2732)

決定4 の「撃ち直す」は、解除の門と予告の文が pickup の門の述語を各自で手で列挙する形で実装され、受験者の checkout では pickup が
撃つ `.git` の形の検査(ADR 0146)が解除と予告の列挙から漏れた —— 隔離した盤面で、gitfile の checkout への修復回答が受理され、
次の pickup が同じ理由で再停止した。決定4 は述語の集合を決めたが列挙の持ち主を決めていなかったので、ここで決める。

6. **場所の種類ごとに pickup の門の純粋な前半を1つの一覧として持ち、撃つ門(pickup)・撃ち直す門(解除)・予告の文はその同じ一覧を
   読む。** pickup はその一覧を撃ってから不純な段(開いた event・fetch・休止位置・タスクブランチ・ref の基準)に進み、解除は同じ一覧を全部
   撃ち、予告は一覧の各述語の説明を並べる。一覧は記録の状態で分岐する(決定4: event が無ければ番地を作れる、あれば repo がある)ので、
   pickup は開く前に撃てる。解除の門だけが上乗せする検査 —— clean tree(issue #21)・盤面の状態 path との重なり・GitHub repo アクセスの
   修復(ADR 0067 決定2)・merge-back のやり直し —— は pickup の述語ではなく解除の上乗せのままで、clean tree は受験者の checkout には
   当てない(WIP を残す、ADR 0276 / 決定2)。実環境の pickup が撃つ registry の役割の照合と remote 宣言と clone の照合は、今日の解除と
   予告の列挙にも無い同じ写し漏れで、一覧の共有でそのまま解除と予告に入る。pickup の門に述語が増えれば解除と予告は追随し、3つの面の
   列挙がずれる形は構造として無くなる。

## 追記(2026-10-30、issue #2737)

追記 決定6 は一覧の持ち主(場所の種類ごと)を決めたが、pickup が**どの場所に**一覧を撃つかの持ち主を決めていなかった。停止の門は task が開く
場所すべての名前を1本の SQL で数える(ADR 0273 決定8)のに、撃つ側は同じ集合を手で経路に分け、経路ごとに撃つものを各自で決めていた ——
読む面接室は一覧の外の綴り(`.git` の有無だけ、ADR 0277 追記 決定1)で、読む実環境は fetch が要るもの(remote 正本あり)だけ一覧を撃ち、
remote 正本を持たない実環境は読む側では何も撃たれなかった。本文の2つの決定が張り合い(0277 追記 決定1 と決定6)、code は古い側に従っていた。
code の読みと釘は #2737 のコメントに置く。

7. **pickup の純粋な一覧を撃つ場所の集合は、停止の門が数える「task が開く場所すべて」と同じである。** 走る場所・`workspace` 列・読みだけ開く
   場所。列挙は走る場所を開く**前**に行い(番地は記録があれば event の綴り、無ければ規約の番地 —— 決定4 の2分岐が既に組んでいる形)、
   全場所の一覧が通ってから走る場所を開き、不純な段(fetch・休止位置・タスクブランチ・ref の基準)へ進む。どの門も通る前に盤面は記録を
   書かない —— 根拠の面接室が消えた root は自分の面接室を作らずに止まる(旧: 開いた後に読む場所を門に掛けていた)。落ちた場所の名前で
   止まり、remote 正本を持つ場所の失敗は純粋・不純を問わず修復案内込み(ADR 0067 決定2)なのは今のまま。
8. **場所の種類は列挙が付け、門は判別し直さない。** 受験者の走る場所は名前が root id で在り処が受験者の checkout なので、名前からの再判別は
   列挙の知識の写しになる。読みだけ開く面接室は走る面接室と**同じ種類**で同じ一覧を撃つ —— `.git` がディレクトリであること(ADR 0146)は
   「誰の repo か」の検査で、書くかどうかとは無関係。ADR 0277 追記 決定1 の述語(`.git` の有無、sparse snapshot の掃除と揃える)は面接室の
   一覧の第1項(記録分岐の「repo がある」)に移り、失われない。解除の門の「名前に掛かる場所すべて」(決定4)は名前 → 場所の逆向きの軸で、
   別の列挙のまま。
9. **不純な段の条件は一覧に掛けない。** remote 正本の有無は fetch と休止位置の要否であって、`.git` の形・registry の役割の照合・remote 宣言と
   clone の照合を撃つかどうかの条件ではない。remote 正本を持たない実環境に origin が残る形は、その実環境の自分の task と同じ条件で root の
   pickup でも止まる。

退けた形: **読む側だけの薄い一覧**(種類が4つになり、読む側に別の綴りが戻る)、**fetch の条件で純粋な一覧を絞る今の形**(purely-local の
実環境が読む側で素通りする)、**各門が名前から種類を判別する**(3綴りが残る)、**停止の門の SQL と撃つ門の列挙を1本にする**(軸は同じだが
SQL は候補全件の述語、TS は拾った1件の場所の組で、ADR 0273 決定8 の「門の側の対」のまま —— 本件では広げない)。

## 追記(2026-11-01、issue #2730)

追記 決定6 は一覧の持ち主を「純粋な前半」で切ったが、解除が撃ち直せるかを決める性質は純粋さではなく「場所の段で、冪等で、記録(開いた
event)を書かない」ことだった —— 開く手順を一覧から外す理由がそれで、純粋さはその代理である。代理で切ったので鮮度の段(fetch・休止位置)が
一覧の外に残り、pickup の停止の生産者が2つ(一覧の述語と、action の失敗)になり、2つ目には持ち主も説明文も無かった。隔離した盤面で、
保護ブランチが無い(面接室 #2730・実環境 #2775)、ローカルの先行、分岐、fetch 不達の4つの停止がどれも回答を受理され、次の pickup で同じ
理由で止まり直した。人間が出口どおり `git init` だけした面接室はホストの `init.defaultBranch` が `master` だと空コミットが `master` に
乗り、`main` が生まれない。測定の表と code の読みは #2730 のコメントに置く。

10. **一覧は記録を書かない場所の段すべてを持ち、前半(開く前・純粋な述語)と後半(開いた後・fetch と休止位置)に分かれる。** pickup は
    前半を全場所に撃ち、開き、後半を全場所に撃ってから task の段(タスクブランチ・ref の基準 —— 場所の項ではないので一覧の外)へ進む。
    解除は両半分を撃ち、予告は両半分の説明を並べ、停止の理由は pickup も解除も落ちた項の説明を載せる。追記 決定7 の「どの門も通る前に
    記録を書かない」は前半を縛る線で、後半は書き込みそのものなので開いた後に来るのが構造である。
11. **後半は役(走る / 読む)で絞らない。** 読むだけ開く場所にも fetch と休止位置を撃つ —— root が読む正本は保護ブランチの状態で、休止は
    それを worktree に出す行為である。remote 正本の有無は fetch 項の内側の no-op になり、追記 決定9 の「休止位置の要否」の句は消える。
    slot は1つなので、読む場所の休止が走行中の session と重なることは無い。
12. **解除が後半を撃つ集合は前半と同じ(決定4)**: 名前の場所と未決着の受験者の checkout。受験者の checkout に clean tree は当てないが
    後半は当てる —— `checkout` は `-f` 無しでは dirty を捨てず拒むので WIP は失われず、`main` に休止済みなら no-op である。
13. **未生の HEAD は、開く手順が `main` に向け直してから空コミットを置く(決定3 の補いの前段)。** 判別は「HEAD が未生」で、生まれた HEAD
    には触らない。面接室の種類の休止の項は未生の HEAD を通す(次の pickup の開く手順が補う)—— 解除が面接室に commit を書く形は採らない。
    実環境と受験者の checkout の未生は通さない(決定5)。決定3 の「root の準備が `main` を要るのは ADR 0273 決定1 のまま」は引用先が違う
    —— 要るのは保護ブランチの既定名と休止位置・fork 元の機構で、ADR 0273 決定1 は ADR 0276 で撤回済み。
14. **解除の順序は、前半(全場所)→ 読みだけの上乗せ(clean tree・状態 path、名前の場所だけ)→ 後半(全場所)→ merge-back のやり直し。**
    後半の token は fresh で取り(持っている token を答えにしない)、失敗経路は pickup と同じ repo アクセスの案内を連ねる。回答時に無条件に
    仲介へ訊く段は畳む(ADR 0067 決定2 の解除の扉はこの形になる)。後半の ff の書き手は呼び手が渡す —— pickup は口の外のまま(#2459 は
    動かさない)、解除は口。

退けた形: **解除が鮮度の段の関数を別に呼ぶ**(生産者2つのまま、予告が追随しない)、**停止ごとに純粋な写しの述語を一覧へ足す**(追記
決定6 が消した2面の列挙が戻る)、**撃ち直さず本文で止まり直しを予告する**(fail-closed に反する)、**出口の文を `git init --initial-branch=main`
に書き換える**(ホストの既定を人間に意識させる)。
