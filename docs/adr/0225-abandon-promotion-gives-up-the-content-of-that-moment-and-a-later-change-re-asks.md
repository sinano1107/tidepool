# abandon promotion が断念するのはその時点の内容の昇格であり、後の内容の変化は昇格の question を立て直す

2026-10-09 の grilling(issue #1642、発端は #1630 の spec review / ADR 0217 決定4)で決定。PR 昇格失敗の question に
`abandon promotion` と答えたタスクは、どの着地済みの記録も刻まれないので、その木の付帯子が後で決着すると
`relandAncestors` が着地し直していた。内容が何も変わらない決着(何も見つけない review)でも PR が開き、profile が読めな
ければ agent 名の quarantine がまた落ちる。後者は、quarantine の解除が付帯子の走っている間だけ通ってしまう、ADR 0217
決定4 が塞いだはずの繰り返しになる。実測と経路は #1642 に置く。

## 決定

1. **abandon promotion が断念するのは、その時点の内容の昇格である。** 回答の時点のタスクブランチの head を、盤面名義の
   event としてタスクに刻む(断念は人間の判断として decision log に、断念した内容は事実として event に — ADR 0073 決定2
   の区別)。付帯子の決着による再発火は、刻んだ head から内容が変わっていなければ何もしない。内容の比較は「着地済みは
   内容で測る」(ADR 0105)と同じ比較で行う。head を刻めなかったときは「変わった」と扱う — 修理を捨てない側に倒す。
2. **内容が変わっていれば、PR を開かずに昇格の question を立て直す。** 立てるのは門が開いてから(ADR 0092)で、形は
   PR 昇格失敗の question と同じ(retry / abandon promotion、推奨は retry — 変わった内容は修理として求められたもの)。
   abandon は、このタスクについて人間が下した最新の明示の判断である。ADR 0196 決定2 が無人 merge の根拠を常設の
   設定に限ったのは、個別の判断が無い場合の話で、常設のダイヤルでその断念を覆す根拠にはならない。直接昇格すれば、
   `auto_if_ci_green` の下で断念した内容ごと無人で merge されうる。もう一度 abandon と答えれば、その時点の head が刻み直される。
3. **着地を待つ完了タスクの数え(ADR 0217 決定4)は変えない。** 立て直しは profile を読まないので、付帯子が走っている
   間に quarantine の解除が通っても、決着で落ちることはない。立った question は、開いている失敗 question の条件で数えられ、
   retry の回答で profile を読むのは今の retry と同じである。

## Considered options

- **いつでも着地し直す(今の挙動)** — 内容が変わらない決着でも、人間が断念した PR を盤面が新しい判断なしに開く。
  数えの述語に「abandon 済みで、門が閉じている」を足す必要も残る。
- **abandon を着地済みとして扱い、着地し直さない** — 後から来た修理が、断念したブランチに merge back されたところで
  止まる。ADR 0105 決定3 の「修理が無言で消える経路は残さない」に反する。
- **内容が変わったら `land()` で直接昇格する** — 決定2 の理由で退けた。
- **内容の変化を履歴で近似する(abandon の後に木の work タスクが done になった)** — 空の修理でも question を立てる。
  ADR 0073 が退けた答え合わせの question になる。
