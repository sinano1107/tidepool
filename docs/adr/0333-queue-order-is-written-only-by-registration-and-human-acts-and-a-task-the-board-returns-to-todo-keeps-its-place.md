# キュー順を動かすのは登録(末尾)と人間の行為の帰結だけで、盤面の都合で todo へ戻る task は位置を変えない

2026-10-31 の grilling(issue #2780)で決定。盤面が自分の都合で `todo` へ戻す task —— 上限到達による中断(ADR 0007 / 0104 決定1)、行の拒否(ADR 0184 決定4)、盤面の記録の器が書けない pickup(ADR 0266 決定3)、資源の停止で worker が走らなかった pickup(ADR 0274 決定1・4)、0ターンで終わった session(ADR 0331 決定2・4)—— は `todo` の**先頭**へ動いていた。先頭にする理由はどの ADR にも無い: ADR 0007 が failure question の retry 回答の先頭復帰を「同じ操作」として借用し(#467)、後続の ADR はその形を写していた。キュー順の持ち主を決めた ADR が無かったので、人間の操舵の verb(run now)が盤面の「判断なしに戻す」の実装になった。

pickup はキュー順に触らないので、何もしなければ task は拾われる前の位置に居る。先頭へ動かして順が変わるのは、拾われた時点で走れなかった行(skipped / blocked / held)か、走行中に人間がその上へ動かした行がある場合で、どちらも盤面が人間の並べた順を黙って書き換える。GLOSSARY「Pickable head」は資源で skip された行を「資源が回復すれば元のキュー順で再び候補になる」と書いており、pickup の後に止まった行だけが先頭へ行くのは、同じ資源回復の話の中の食い違いだった。実測の表と `file:line` は #2780 のコメントに置く。

## 決定

1. **キュー順は pickup で変わらず、盤面の都合で session が終わっても変わらない。** 盤面が自分の都合で `todo` へ戻す task は status だけが変わり、位置は変わらない。上の5つの ADR の「先頭へ戻す」はすべてこの決定で置き換える。盤面は判断していないものを「次に走れ」と言わない。
2. **キュー順を動かすのは、登録(末尾)と人間の行為の帰結だけ。** move(run now を含む)、failure question の retry / abandon の回答、回答で unblock された親の front-insert。これらは今のままで、本 ADR は触らない。釘は「task の移動の event の actor は常に人間」。

## 退けた案

- **5つの kind を個別に直す** —— 持ち主を決めないと、次に「todo へ戻す」ADR を書くときにまた retry の形を写す。
- **上限到達による中断だけ先頭に残す** —— 途中の成果は task branch に退避され他を塞がない(ADR 0064)。ADR 0007 の2つの理由(判断価値の無い question を立てない、自動で再開する)はどちらも位置に依らず、先頭でないと壊れる運用を1つも挙げられなかった。

## 帰結

- ADR 0184 決定4 の「次の pickup は別の候補で走る」は位置を変えなくても成り立つ —— 戻った行がまだ Pickable head ならそのまま拾われ、資源で外れていれば次の候補が走る。
- Interview の受験者(pin の子)の順序も同じ規則に乗る。#2750 の判断(受験者の順序に欠陥は無い)は変わらない —— ADR 0264 決定4 で結果は順序に依らない。
- 人間向けの文(containment question、Quarantine の理由)から「queue head」が消える。retry の回答の文は人間の行為なので残る。
