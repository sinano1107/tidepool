# 運ぶ手は、名前の場所の閉包の中の損傷で落ちる前に入れ直しへ届く —— 運ぶ commit が名前の場所に既にあっても同じ

2026-11-26 の triage → grilling(issue #3862、#3814 の ponytail-review の派生)で決定。ADR 0411 決定4 は、運ぶ tip の閉包の中の損傷を、
運ぶ前に名前の場所で起きたものも入れ直す(ADR 0388 決定2)と決めた。ところが運ぶ手は名前の場所への fetch を先に撃ち、入れ直しはその後にしか
走らない。fetch は受け取った commit から届く tree を読むので、閉包の中の tree の壊れた loose で落ちて入れ直しに届かず、保証は fetch が開かない
blob にだけ成り立っていた。守るか止めるかが、決定でなく、どの git の手が先にその object を読むかで決まっていた。面接室では、前の出題の写しの
tree を再現する出題し直しが毎回拒まれ、面接室は直らない。測定と入口の表は #3862 のコメントに置く。

## 決定

1. **ADR 0411 決定4 の保証は、運ぶ手が読む object(tree・commit)にも成り立つ。** 運ぶ手は、閉包の中の名前の場所の損傷で落ちる前に入れ直しへ
   届く。閉包の外の損傷は今どおり守らない(ADR 0398、ADR 0411 決定4)。
2. **運ぶ commit が名前の場所に既にあっても同じ。** 出題の写しと退避の WIP は、同じ秒・同じ tree・同じ親なら前の写しと同じ commit になり、
   自前に確かめる object が無いので、その閉包の中の損傷を見つけなかった(ADR 0412 の追記の限界)。その閉包の中の損傷も入れ直す。
3. **運ぶ入口の全部が同じ1つの規則に従う** —— 門の取り込み、退避の tip、退避の WIP、作業台の取り込み、Interview の出題の写し。
4. **入れ直しても揃わなければ、今どおり各入口の「名前の場所へ運ぶ段が落ちた」扱い**(ADR 0388 決定2)。

入れ直しへ届かせる形 —— 確かめを運ぶ前に置くか、運ぶ手が落ちたら入れ直して撃ち直すか —— は spec で決める。前者は閉包の確かめが1回の運びで
2回になる(ADR 0411 決定6 の費用の倍)。壊れた tree の入れ直しと、決定2 の形で受験者の fetch が落ちることは未測定である。

## 退けた案

- **保証を blob に狭め、運ぶ手が読む object の損傷は名前の場所の故障として止める** —— 直す手は盤面が既に持ち、届かないのは順序だけである。
  狭めると、同じ閉包の中で object の種類ごとに守るかが割れる。2日前の ADR 0411 決定4 を戻す理由も観測されていない。
- **入口ごとに直す** —— どの入口も同じ順序を写した形で、1つだけ直すと残りに同じ穴が残る。

## Consequences

- Status 追記: ADR 0388 決定1・2(「名前の場所へ入れた直後に」確かめる)、ADR 0411 決定4、ADR 0412 の追記(同じ秒の出題し直しの限界)。
- 面接室で失敗した出題を後始末が観測しない問題(ADR 0424 の前提)は #3904 に置く。閉包の中の損傷は決定1 で次の出題が直すので、#3904 に残るのは閉包の外の損傷である。
