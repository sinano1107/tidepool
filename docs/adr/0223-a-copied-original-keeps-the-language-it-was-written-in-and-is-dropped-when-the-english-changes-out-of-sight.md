# 写した原文は書かれたときの言語を継ぎ、原文が見えないまま英語が変わったら落とす

**Status 追記: 決定2 は管理MCP について ADR-0230 決定2 で改訂済み** —— 管理MCP の呼び手は原文の言語を申告し、申告は写しの一致に勝つ。一致で継ぐのは申告を送らない WebUI の書き込みだけになる。

2026-10-09 の grilling(issue #1680)で決定。人間の書き込みは、送られた原文に書き込み時点の表示言語を付けていた。Edit・
一つの木の門の欄の出口(広げる・Write)・Exemplar の Edit は既にある原文を写して送り直すので、表示言語を切り替えたあとに
写すと原文の言語が付け替わる。また English の盤面のフォームは原文の欄を出さないまま写した原文を送り直すので、人間が英語を
書き換えると、見たことのない原文が新しい英語の一次資料として残る。観測と経路の一覧は #1680 のコメントに置く。

## 決定

1. **言語は原文の文字列の性質で、写しに付いて回る。** 今の表示言語を付けるのは人間が新しく打った原文だけ。移動・復元が
   原文を言語ごと写す(ADR 0162 決定5 / ADR 0163 決定1)のと同じ扱いを、フォームを経る写しにも揃える。いま言語を読む側は無いが、
   表示言語の候補は増える予定で、そのとき過去の原文が何語かを後から復元する手段はこの値しかない。
2. **継ぐかどうかはサーバが原文の一致で決める。** 送られた原文(title と text の組、Exemplar は注釈ごと)が `supersedes`
   の相手の原文と完全に一致すればその言語を継ぎ、一致しなければ今の表示言語を付ける。何を写したかを知っているのはサーバ
   なので、wire に言語を足してクライアント(WebUI と管理MCP の呼び手)に申告させない。原文を1文字でも直せば、人間が今の
   表示言語で打ち直したとみなす —— 新しく打った原文の前提(ADR 0175 決定3)と同じ線である。
3. **原文がフォームに見えないまま英語が変わったら、原文を保存しない。** English の盤面の Edit / Write がこれに当たる。
   英語が写したままなら原文も写したまま残す。落とすときは保存の前にフォームがそう言う。原文が見えていた場合は、英語を
   手で直しても原文を残す —— ADR 0015 四度目の精密化のとおり英語欄は常に編集可で翻訳は補助、英語が原文と同じことを
   言っているかは人間が逆翻訳で確かめる。
4. **管理MCP の呼び手が添えた原文は、それが英語の訳元だという申告として受ける。** 盤面に Translate の無い面で、訳した
   かどうかは確かめられない。写して送った原文の言語は決定2 で継ぐ。

## 退けた代替案

- **言語の列を消す** —— 読む側が無く v1 の原文は事実上 Japanese だけだが、言語が増えた日に復元できない。
- **英語が原文から訳されたままのときだけ原文を残す**(手直しも throttle 中の手書きも原文を落とす) —— 決定3 の場面は
  直せるが、訳したあと1語直しただけで一次資料が消え、ADR 0015 が原文を残す理由そのものを捨てる。直すべき欠陥は
  「人間が原文を見られない」ことで、決定3 で足りる。
- **言語が違えば写さない**(Edit を原文なしで開く) —— 一次資料を落とす。
- **新しく打った原文の言語を人間に選ばせる・判定する** —— この issue の主題(写し)の外。前提の崩れ(管理MCP で表示言語と
  違う言語の原文を添える等)は派生 issue で扱う。
