# 盤面は登場人物だが住人ではない — 記号の語彙が種別を言う

issue #222 で決定。盤面自身が登録した question(PR 昇格失敗、issue #220)が、UI で発行元の
アイコンも名前も出さず「-」と表示された。盤面の名前は `tidepool` に決まっており
(`BOARD_WORKER_ID`、`src/tasks.ts:38`)、イベントには正しく記録されているのに、**盤面には
見た目の表現がそもそも無い** —— アイコンマップは registry 由来(`GET /api/registry/candidates`、
issue #52)であり、registry は agent の定義であって盤面の定義ではないため、盤面の名前は原理的に
そこへ載らない。

素朴な直し方は2つあり、どちらも `HUMAN_ROSTER_AGENT`(`src/tasks.ts:27`)という前例に引かれる ——
「registry の agent ではないが roster には出る」という同型の枠を盤面にも作るか、アイコンマップに
`tidepool → 🌊` を1行足すか。**どちらも採らない。**

## 決定

**盤面は Roster に入らない。代わりに「登場人物(Cast)」を用語として立て、視覚的身元はそこに属させる。**

Roster の行の意味は「**この相手に振れる**」である(CONTEXT.md)。`human` がそこに居るのは実際に
human へ委譲できるからで、盤面には委譲できない —— 盤面は assignee にならず、slot に入らない。
盤面を roster に入れると、行の意味が「振れる相手」から「盤面に出てくる名前」へ薄まり、agent が
委譲判断の材料として読む一覧に、決して振れない行が1つ混ざる。

#222 が実際に要求しているのは委譲候補の一覧ではなく、**記録に名前が残りうる主体すべてが視覚的
身元を持つこと**である。これは Worker(assignee になれる主体)より1つ広く、Roster とは行の意味が
違う、3つ目の集合であり、CONTEXT.md に `登場人物` として立てた。3種 —— registry の agent、
`human`、盤面自身。

**盤面の記号はアプリのマークであり、絵文字ではない。**

絵文字は**住人の語彙**である。アイコンピッカーの既定リストは海の生き物から始まり、そのコメントは
「the fixed order is the worldview convention (tidepool dweller naming), not cosmetic」と
明言している(`webui/app.jsx:800-804`)—— ADR 0017 が「エージェント名は海の生き物のローマ字和名を
優先する」と決めた命名の世界観の、視覚側の現れである。盤面に絵文字を与えると、たとえピッカーの
リストの外から選んだとしても、**住人の語彙で綴られた非住人**になる。

盤面はアプリのマーク(`public/favicon.svg`)で描く。マークは生き物ではなく、場そのものの記号で
あり、`#1d6a66` = `--tide-4` / `#f4f9f7` = `--tide-0` と、既にデザイントークンで描かれている。
**語彙を分けることで、盤面が住人ではなく場であることを見た目そのものが言う。**

## 帰結

- **アイコンマップは無傷。** `GET /api/registry/candidates` の `icons` は registry の agent だけを
  載せ続ける —— マークは `name → 絵文字` のマップに乗らないので、合流させる先が無い。この決定は
  サーバ側のコードを1行も変えない。
- **`AgentChip` が3つ目の分岐を持つ。** 既に `human` boolean が 🧍 グリフと二人称ラベル "you" を
  切り替えており(`design-system/components/board/AgentChip.jsx:16,20,26`)、`board` boolean が
  同型の3つ目として並ぶ。`icon` prop は単一書記素チェックを通る文字列専用なのでマークは通せない。
  design-system の改修なので `/design-sync` の往復を伴う。
- **マークのパスはリポジトリ内で3枚目になる**(`public/favicon.svg` / `public/icon.svg` に既に2枚)。
  design-system がアプリのアセット経路(`<img src="/favicon.svg">`)に依存すると、`ui_kits` の単体
  表示と Claude Design のプレビューで壊れる —— ADR 0050 が「プレビュー面はオーサリング用」と
  決めた前提が成立しなくなる。自己完結を取り、複製にはコメントで相互参照を張る。
- **`human` の 🧍 は据え置き。** 人間は住人でも場でもない第三の語彙であり、既に出荷済みである。
  ラベルの二人称化("you")はアイコンマップでは表現できないので、`human` boolean が唯一の出所の
  ままにする —— マップにも載せると 🧍 の出所が2つになり、ラベルだけ別経路という歪んだ形になる。
- **`人間` の欠陥は身元の不在ではなく配線の欠落だった。** #222 は「human も同じ問題を抱えている」と
  書いたが、`AgentChip` は身元を持っている。渡していない呼び出し側(ログ行、question カード)が
  問題であり、そこは配線の修正で閉じる。

## Considered options

- **`BOARD_ROSTER_AGENT` を置き、`HUMAN_ROSTER_AGENT` と同型にする** —— 前例があり実装も最小。
  しかし roster は委譲判断の材料であり、決して振れない行を混ぜると行の意味が失われる。`human` が
  roster に居るのは「registry に定義が無いから」ではなく「実際に振れるから」であって、前例の
  読み方を取り違えている。
- **アイコンマップに `tidepool → 🌊` を1行足す** —— 最も安く、`AgentChip` も design-sync も
  触らない。しかし絵文字は住人の語彙であり、盤面をその語彙で綴ると ADR 0017 の世界観の内側に
  盤面自身が引き込まれる。加えて `icons` が「registry 由来の agent アイコン」から「盤面に出てくる
  名前のアイコン」へ、宣言なく意味を広げる。
- **用語を立てず、UI 側だけで `tidepool` と `human` を特別扱いする** —— 今日の痛みは消える。
  しかし「盤面上に名前として現れうる主体」という集合が言語化されないまま残り、盤面名義の記録を
  描く面が増えるたびに同じ分岐を書き直すことになる。
- **`AgentChip` に `board` prop を足さず、question カードが自前でマークを描く** ——
  design-system を触らないので design-sync の往復が要らない。しかし「誰か」を描く責務が2箇所に
  割れ、`ui_kits` の kit と本番 WebUI の乖離(issue #206)をもう1つ増やす。
