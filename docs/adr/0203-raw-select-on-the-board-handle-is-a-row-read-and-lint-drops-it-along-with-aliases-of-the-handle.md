# 盤面 handle の生 SELECT は行の直読みとして lint で落とし、handle の別名も落とす

2026-10-06 の grilling(issue #1433)で決定。ADR 0154 決定3 の lint(`no-board-db-in-expect.grit`)は `expect(...)` の
引数に字面の `t.db` が現れる形しか見ておらず、行を変数に入れてから渡す形(#1421 の 48c4a20、レビューが merge 前に止めた)と、
`const db = t.db` の別名を経る形(main に3ファイル、#518 の一括置換で入った)を素通りさせていた。箇所と grit の実測は #1433 の
コメントに置く。

## 決定

1. **ADR 0107 決定2 の「行の直読み(`db.prepare`)は schema 層にだけ許す」は盤面 handle にも及ぶ。** `t.db.prepare` で
   SELECT を書くことは、行が `expect` に流れるかどうかに関係なく違反であり、lint で落とす。schema 層は `t.db` を使わないので、
   この規則には構造上誤検出が無い。ADR 0154 決定3 の「再発がコードに入ったこと」は lint を新たに足すかどうかの基準であって、
   既存の決定を機械で強制するこの場合には当てはめない。
2. **盤面 handle の別名の宣言(`const $name = t.db`)を lint で落とす。** 別名を経た assert は決定3 の文言どおりの違反であり、
   別名が1本でも残ると隣を写すエージェントの先例になる(ADR 0107 決定6)。流れを追う形(別名から `expect` まで)は、grit の
   名前照合がファイル全体でスコープを見ないので誤検出が出る。
3. **残る漏れは許容する。** ドメインの読み口の戻り値を変数経由で渡す形、helper、`t` 以外の名前の盤面 handle(`tp` /
   `tidepool` / helper 引数)は、ADR 0154 決定3 の helper と同じく seam 合意とレビューに任せる。最後のものは assert に使った例が
   0件で、grit は型を見ないので、塞ごうとすると漏れるか、`:memory:` の `f.db` と混在するファイルで誤検出するかのどちらかになる。

## Considered options

- **行を変数に入れて渡す形を流れで追う** — 名前照合がファイル全体なので、同名の `:memory:` の db と結び付いて誤検出する。
- **(a) を塞がない** — 決定2 の読み方では既に違反であり、塞ぐ費用は grit 1ファイルで済む。
