# poll の想定外の例外は盤面を落とさない —— 何も握っていなければ行で報せて次の poll に任せ、続けば撃ち直しで確かめる question を立て、slot を握っていれば worker が走らなかった pickup として後始末へ入る

2026-10-21 の grilling(issue #945)で決定。scheduler の `poll()` は想定外の例外を受けておらず、`pollNow` の void された鎖が reject を
引き継ぐので、Node の既定で盤面の process が落ち、同じ process に乗る人間面(WebUI・管理 MCP)も一緒に消えていた。Mac の盤面は
`systemd-run --scope` で起こす者が居ない。着地の pass・tick(ADR 0229 決定1)・通知の tick はみな例外を閉じており、poll だけが外に
あった。`pollNow` の形は #1842 の code で、決定ではない。実測(壊れた registry は候補の読みで slot より前に投げる、など)と
`file:line` は #945 のコメントに置く。

## 決定

1. **poll は想定外の例外を受け、盤面を落とさない。slot を握る前なら、log に出し「最後の poll の失敗」(いつ・例外の本文)を
   「今なぜ pickup が起きないか」の読み口に1行持ち、次の poll に任せる。** poll は毎時と契機で自分から走り直すので、ADR 0112 が
   落ちた後始末を停止にした理由(人間が来るまで終わらない)は当たらない。行は「停止ではないが pickup を待たせているもの」の2つ目
   (1つ目は想定どおりの後始末、ADR 0109 決定2)で、停止の列挙には入らない。**成功とは、門を越えて本体(候補の読み)に入った poll
   が投げずに終わることである。** 門で返った poll(Pause・開いた停止・slot 握り中)は行も次の計測も触らない —— 成功に数えれば、
   一時停止や塞がった slot が信号を消す。行は process の memory に持つ(再起動は人間の行為で、起動時の registry 読みは別に拒む)。
2. **本体に入った poll が成功を挟まず投げ続け、最初と最新の間が10分以上なら、Tidepool 名義の確認 question を1枚立てる。** 回数は
   条件にしない —— poll は契機(登録・回答・解放・run now)で続けて撃たれ、2回は数秒の間に起きうる。本文の一致も条件にしない ——
   本文は変わる部分(commit・task id)を含み、一致を要求すると壊れた push が2度来ただけで計測が戻る。一過性(網の瞬断・git の
   lock・push の途中の registry)は秒〜1分で消え、10分続く同じ失敗は天候ではない。**停止の列挙には入れない** —— pickup を止めて
   いるのは失敗そのもので、question に門の役は無い。入れれば門が poll を止めて受理の検査が撃てず、「検査できない kind の回答は拒む」
   (ADR 0137 決定5)と衝突する。形は Quarantine 族を**借りる**(ADR 0112 決定2 の借り方、資源ではない): **受理の検査は、その場で
   poll の本体を撃ち、投げなければ受理**(ADR 0112 決定3 の「門は再実行そのもの」)。加えて、**本体に入った poll が成功すれば回答
   なしで決着する**(ADR 0184 決定5 の観測決着の形)—— 直した push の後に契機で poll が通れば、開いた question が残らない。
   question が断言するのは3つだけ —— いつから・何回・最初と最新の例外の本文。原因の所在は断言しない(ADR 0112 決定5)。
3. **slot を握った後(`pickupTask` が返った後)の想定外の例外は、worker が1度も走らなかった pickup(ADR 0118)の族である。**
   `spawn_failed` event を書き、failure question(retry / abandon)を立て、同じ一撃で後始末へ入って slot を空ける。ADR 0274 決定1
   は族を「task に帰属しうるか資源に帰属するか」で分ける —— 想定外の例外は帰属が不明なので資源の停止にできず、retry / abandon に
   落ちる。ADR 0274 型(todo 先頭へ、question なし)は資源の question が無いので同じ task を毎 poll 拾って黙り、盤面全体の停止型は
   abandon が消える(ADR 0118 決定4 が同じ理由で退けた)。
4. **process 全体の床を1つ置く —— `main.ts` に unhandled rejection の受け手、log だけ。** 同じ見落とし(#1624 / #1758 / #945 /
   #2036)が2か月で4件あり、共有する前提は「各 site が catch を覚えている」だった。床は「人間面が開いたままなのが復旧経路」
   (ADR 0036)を site ごとの注意でなく機構で保証する。床は分類ではなく、決定1〜3 の catch と役が違う。置くのは `bootTidepool`
   の外(ホストの副作用だけを持つ入口)で、テストは引き続き reject を失敗として見る。床そのものは1関数として module に出し、
   domain 層の export として test する(ADR 0107)。同期の throw(`uncaughtException`)は範囲外 —— 状態が壊れている可能性があり、
   同じ扱いにできない。
5. **決めないこと。** 一撃(`onSpawnFailed` など)そのものが slot を握ったまま投げる場合は、この ADR の下では process が生き、
   log と行が残り、slot は再起動まで塞がる —— adapter 側の同じ問い(#2036)に scheduler 側も寄せる。壊れた registry を資源の側で
   分類する(Registry reachability に「読める」を足す)は派生 issue。起動時に registry が読めず起動を拒むのは同期の throw で変えない。

## 退けた案

- **catch を外して投げさせる** —— ADR 0112 が退けた。再起動しても同じ所で落ち、人間面が消える。
- **盤面全体の停止に入れ、受理の検査なし** —— ADR 0137 決定5 が拒む。検査が撃てないのは門に入れたからで、門に入れる理由が無い。
- **連続2回で立てる** —— 契機の連打で数秒に2回起きる。**本文の一致で連続を定義** —— 本文の変わる部分で計測が戻る。
- **1回目で question** —— 一過性に question が立つ。1回目は行で見える。
- **poll ごとに event を書く** —— ADR 0229 が60秒ごとの記録を退けたのと同じ。

## 帰結

- 契機が無ければ次の失敗は毎時の tick なので、question は最初の失敗から最長約1時間後に立つ。push は question に乗る。
- 壊れた registry は候補の読みで slot より前に投げるので、決定1〜2 の経路に乗り、本文が question に出る。
- `src/board-call.ts` の `void Promise.reject(error)`(「盤面へ上げる」として置かれた code)は決定4 の床の下で log になる —— 明示の log に
  書き換えるのは派生 issue。
