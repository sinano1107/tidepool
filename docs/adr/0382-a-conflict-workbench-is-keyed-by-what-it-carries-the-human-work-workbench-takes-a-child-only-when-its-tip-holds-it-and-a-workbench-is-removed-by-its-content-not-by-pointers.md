# conflict を受ける作業台は運ばれる側で鍵を分け、人間担当の work の作業台は子を含む tip だけを子の入口が取り込む —— 作業台の寿命は指し手でなく中身で決める

2026-11-17 の grilling(#3352)で決定。ADR 0371 は作業台を (workspace, 書く先の ref) ごとに1つとし、同じ鍵の入口に共有させた(決定1・7)。
鍵を決めた #3182 決定6 の時点では1つの鍵に入口は1つで、その後に入口が積み重なった —— 保護ブランチの鍵に local 着地と `take in`
(#3184 決定9、理由は「鍵は足さない」)、`task/<root>` の鍵に追いつき・merge back の撃ち直し・`pr_merge`。回答は sha も branch も
運ばないので(ADR 0371 決定2)、入口は鍵にある tip が自分の question のための人間の commit か、別の question のものか、誰も触らない
古い値かを区別できず、書く先と違う tip を全部取り込もうとして拒んだ。#3284 の実装の上で、古い tip が無関係な clean な着地を止める、
A の merge が C の回答で着地する(ADR 0371 決定6 に反する)、残骸が作り直されない、を観測した。#3344・#3347 は同じ根の疑い。
観測と場面の表は #3352 のコメントに置く。

## 決定

1. **conflict を受ける作業台の鍵は (workspace, 書く先の ref, 運ばれる側) である。** 運ばれる側は入口が merge で書く先へ運ぶ ref
   (子や task のブランチ、origin の保護ブランチ、GitHub の head)。運ばれる側が同じ入口は1つを共有する(受理の 11 と積み残しの
   `retry` が同じ子を運ぶとき、`pr_merge` と外の commit の `retry` が同じ head を運ぶとき)。local 着地は task ごとに1つになる。
2. **鍵が持ち主を決める。** conflict を受ける作業台の tip は、書く先に含まれていなければその入口のもので、祖先の条件(ADR 0371
   決定3)を欠けば拒む。書く先に含まれれば取り込むものは無く、入口は盤面の手で進む。ただし「無い」と判定するのは、作業ツリーが
   clean で、HEAD が書く先の branch にあり、`board/*` 以外の branch と stash に書く先に無い commit が無いときだけで、崩れていれば拒む
   —— commit を忘れた「捨てる」を盤面が push で上書きしないため。読めない作業台はどの入口でも拒む。
3. **人間担当の work 自身の作業台は (workspace, `task/<H>`) のまま、人間の書きかけと子の conflict を同じ場所で受ける(ADR 0374
   決定8)。** 人間自身の入口(取り込み・完了)はいつもその tip を自分のものとし、子の merge back の入口は tip がその子を含むときだけ
   取り込み、含まなければ盤面の手で merge する。子の conflict をここで受けるのは H が書き始め済み(`task_work_started`、担当は凍って
   いる、ADR 0374 決定4)で `done` の前だけで、それ以外は子ごとの作業台で受ける。
4. **purely-local の保護ブランチは、人間自身の内容の作業台 (workspace, 保護ブランチ) を `take in` と封じ込めの修理が共有し、
   着地は決定1 の task ごとの作業台で受ける。** task の内容と人間の内容は混ざってはならない(ADR 0371 決定6)。local 着地の
   `merge` は、答えている task 以外のどの task(決着済み・cancel 済みを含む)のブランチの commit を含む tip も拒み、`take in` と
   封じ込めの回答は未決着か着地待ちの task のものを拒む(hold は着地待ち)。数えるのは書く先にも答えている task の tip にも無い
   commit だけである。封じ込めの Quarantine が未取り込みの commit を持つ人間の内容の作業台を開くときは、理由文がそれと捨て方を言う。
5. **寿命は中身で決め、指し手(開いている question)は数えない。** 決定1 の作業台は取り込みが成功し、tip が取り込んだままで作業ツリー
   が clean なら消す。開くときは、決定2 の「取り込むものが無い」の条件を満たせば作り直し、そうでなければそのまま使う。人間担当の work
   の作業台は作り直さず、`done` でだけ消す。人間の内容の作業台は取り込みの後も消さない(共有する相手の question が path を名指して
   いる)。workspace の削除の扉は、人間の内容の作業台に未取り込みの commit があれば拒み、無ければ消す。
6. **書く先の branch が無い作業台(作りかけ)は、盤面の手がある入口では取り込むものが無いとして進み、完了の扉・取り込みの操作・
   `take in`・封じ込めの回答では拒む。** 盤面の手の無い入口で「無い」とすると、人間が入れたと思う commit を落とす。

## 退けた形

- **共有のまま、tip がまだ運ばれていない運ばれる側を含むかで持ち主を推測する**(この grilling で一度採った)—— 巻き戻しで運ばれる側
  が既に書く先にあり、人間の「捨てる」commit が無視されて盤面が落とした内容を push する。1つの着地の作業台に A と C が載ると互いの
  回答を拒み合って詰まる。cancel した task の merge が別の task の着地に乗る。
- **人間担当の work の作業台も子ごとに分ける** —— 書きかけの無い場所で子の conflict を解き、自分の作業台へ `board/task/<H>` を merge
  するとき同じ conflict をもう一度解く。
- **回答に「作業台を取り込む / 盤面の手で進む」の選択肢を足す** —— ADR 0371 決定2 を覆し、選び違えれば同じ拒否に戻る。
- **封じ込めの回答は検査だけにし、修理は `take in` で入れる** —— 「直して答える」の1手が2回の回答になる。

## 帰結

- ADR 0371 決定1・7(鍵と共有)、決定2 の読み(条件を欠く tip を常に拒む)、ADR 0373 決定9(開くのは鍵ごとに冪等 —— 鍵が増える)、
  ADR 0374 決定11 の「そこを指す開いた question がある間は消さない」、#3184 決定9 を、この ADR が置き換える。
- 同じ書く先の2つの作業台が両方 tip を持つと、2つ目の取り込みは1つ目の包む commit を欠いて A7a で1回増える(#3347 と同じ費用)。
- `pr_merge` の「拒否した」印は `refs/heads/board/*` の外に置き、拒否だけが書く(引き直しの prune で消えず、人間が merge する ref と
  分かれる)。作業台の番地は互いに入れ子にならない葉で、運ばれる側の名前は1対1に符号化する。これらと文面は spec #3273 への上書きが持つ。
