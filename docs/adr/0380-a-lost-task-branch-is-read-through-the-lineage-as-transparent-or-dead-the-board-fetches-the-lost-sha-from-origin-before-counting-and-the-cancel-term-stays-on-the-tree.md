# 失われたタスクブランチは系譜が記録で「透明」か「死んだ」と読み、数える前に盤面が origin から取りに行き、cancel の項は木のまま読む

2026-11-15 の wayfinder(map #3178、ticket #3269)で決定。ADR 0375 決定3 は、タスクブランチが失われた task の「成果が捨てられた」を、cancelled の
祖先と同じ線(`parent_id` の祖先)で読むと決め、同 決定5 は、失われた祖先を帰り先にする task を系譜の読みが飛ばすと決めた。2つの線は集合が
違う —— 系譜が数えるのはタスクブランチを持ち列が同じ workspace の祖先だけである(ADR 0372 決定4)。別の workspace に固定された子孫は成果が
生きているのに数えられ、handoff だけの祖先や PR を開いている根の下の task は、数えられないまま運ばれない。穴を1つずつ塞ぐと例外が並んだ
(別 workspace、handoff だけ、PR、着地済み、誰の列で比べるか)。原因は、1つの述語に性質の違う2つを載せたことにある: cancel は計画を捨てる
人間の判断で木に沿い、失われたブランチは成果を運ぶ線の事実で系譜に沿う。この ADR は失われた側を系譜の性質に置き直す。読んだコード・
scratch の git の実測・`file:line` は ticket に置く(#3269)。決定はコードと ADR の読みで、この形の盤面は走らせていない —— remote-backed は
grep だけである。

以下、「失われた event」は ADR 0375 決定1 の event、「数える祖先」は ADR 0372 決定4 の祖先を指す。

## 決定

1. **効いている失われた event を持つ `done` の work は「透明」か「死んだ」のどちらかで、記録だけで読む。** 透明なのは、失われた sha が作成時の
   sha と同じもの(handoff だけで編集が無い)と、内容が保護ブランチに届いた着地の記録を自身か数える祖先が持ち、その記録より前に完了していた
   ものである。それ以外は死んだ。届いた記録に数えないもの: 失われたので終えた記録(ADR 0375 決定7)、`nothing_to_land`、閉じた PR。
   「根なら PR を開いていない」の条件(ADR 0375 決定3)は消える(決定4)。
2. **「成果が捨てられた」の失われた側は、task 自身の系譜で読む。** 数えるのは、自身が死んだ task と、数える祖先に死んだ task を持つ task で
   ある。`parent_id` の祖先全部では読まない。間に無事な祖先を挟んでも数える —— その祖先の成果も死んだ祖先へ帰る。ADR 0375 決定4 が倒す
   付帯子も、`parent_id` の子孫でなく、数えられた task に付いたものである。
3. **系譜の読みは、失われた祖先に git を当てず、決定1 の記録で読む。答えは3つになる。** 透明な祖先は系譜から外し、task は次の数える祖先か
   保護ブランチへ帰る —— tip が fork 元のままの決着済みの祖先は、ブランチが在る間も帰り先に選ばれない(#3269 の実測)ので、行き先は変わら
   ない。死んだ祖先を数える task は「帰り先なし」で、merge back の数え直しも系譜の読みも飛ばす(ADR 0375 決定5 はこの場合だけに当たる)。
   「帰り先なし」は「保護ブランチへ帰る(自分が根)」と別の答えで、その task を着地の根に数えない。
4. **失われたと数える前に、盤面は origin から失われた sha を取りに行く。** remote-backed の workspace では、ADR 0373 決定5 の「object が無い」を
   確かめる前に、object の無い ref の sha を origin から取り、取った後に全部の ref を調べ直す —— 根の head が届けば、merge back が届いていた子の
   tip も届く。届いた ref は基準へ書き戻し、event を刻まない。PR を開いている根はこれで戻り、レビューも修理も通常どおり走る。origin に届か
   ない(通信・認証の失敗)ときは失われたと決めず、回答を拒む。origin の head が失われた sha と違っても、その head へは戻さない(基準に
   無い値を書くことになる)。受理は今も merge back のやり直しで保護ブランチを fetch するので、ネットワークに出る受理は新しくない。
5. **登録の床は親の系譜で問い、子が親と違う workspace の列を明示したときは子の系譜でも問う。** どちらかが帰り先なしなら拒む。無事な親の下に、
   死んだ祖先と同じ workspace を明示した子は、親で問えば通るが、子自身の系譜は死んだ祖先を数える。逆向き(帰り先の無い親の下に別
   workspace を明示した子)は今どおり立たない(ADR 0301 決定7、#2510)。列が空の task の workspace は ADR 0372 決定1 の導出で読む。
6. **cancelled の祖先の項(ADR 0271 決定1)は、今どおり `parent_id` で読む。** 帰り先の述語は1本のまま(ADR 0301 決定3)で、中の項が、cancel は
   木で、失われたブランチは系譜で読むと分かれる。cancel を系譜で読むと、ブランチを持たずに cancel された祖先は数えられず、生き延びた RCA が
   分解した work が保護ブランチから切られて着地する(ADR 0301 追記2 の逆)。失われた側を木で読むと、別の workspace の子孫のレビューを倒す。

## 退けた形

- **失われた側も `parent_id` の祖先で読み、例外を足す**(ADR 0375 決定3 と、この ticket の最初の案)—— 例外が5つ並び、どれも系譜の規則の写しだった。
- **handoff だけの失われた祖先の下の task を数えに入れる**(ticket の案)—— 運べる成果のレビューを倒す。
- **PR を開いている根を条件で数えから外す**(ADR 0375 決定3)—— 直下の修理子は失われたブランチを fork 元と帰り先にして立ち、レビューは根の
  内容を持たない tree を読む。
- **cancelled の祖先の側も同じ線に揃える** —— 決定6 の場面。別の workspace の完了済みの子がレビューを倒されたまま着地する穴は cancel の意味の
  問いで、この map の外に置く(#3270)。

## 帰結

- ADR 0375 決定3・5 はこの ADR が置き換え、同 決定4 の対象と決定7 の条件を直す(0375・0271・0301・0372・0373 に追記)。
- 系譜の読み手(fork 元、完了時の merge back、数え直し、着地の根、閉じた根、レビューが読むブランチ)が3つ目の答えを受けること、決定2 の
  倒す走査が cancel の cascade と別になること、権限の文の当時版が失われた event・`task_branch_created`・着地の記録を spawn の時点で読むことは
  spec が持つ(#3178 の「Spec へ渡すもの」)。記録だけで系譜を近似している述語の列挙は #1796 に足した。
- 確かめていない(同上): GitHub が sha 指定の fetch を受けること(今の経路がそうしているという読み)。registry の `path` を無関係な repo へ
  差し替えた場合に、push 済みの根が差し替え先へ戻った後の merge。push 前の commit を持ったまま失われた PR の根の着地(ADR 0375 決定7 は PR を
  開いている根を対象にしないままである)。決定1 の着地済みの行は、PR の head が origin に残るなら決定4 でほぼ出番が無い見込みだが、残ることを
  確かめていない。未決着のまま失われた祖先は範囲に入れていない(ADR 0375 帰結のまま)。
