# 盤面が書いた文は読み手が持つ行為の選び方を変えることだけを言い、盤面の語の定義はその語を使う文が運ぶ

2026-11-27 の triage → grilling(issue #3977、#3973 の triage で見つかった疑い)で決定。#2512 の問いもこの grilling で一緒に決めた。
ADR 0324 決定3 は、Board call の 4 本の prompt に「盤面の語を名前だけで使わない」を決めたが、worker session・他の Board call・
management MCP の読み手には同じ線が無かった。組み上がった文を読み手ごとに描画すると、自律プロセス(RCA・meta-review・
Interview・repair)の読み手にも、名前だけで届く盤面の語が広くあった。定義の多くは伏せられうる tool の記述に乗っていて、
読み手に無い節や伏せた verb を指す文もあった(#1941 / #2201 / #2512)。語ごとの表は #3977 のコメントに置く。

2 つは根が別である。読み手に無いものを指す文は、`taskVerbSwap` による出し分けが一部にしか当たっていないことから出る。
定義が届かないのは、実行時の読み手に向けた定義の出所がどこにも無いことから出る。ただし前者の線が残る文を決め、
残る文が定義の要る語を決めるので、1 本の ADR に置く。

## 決定

1. **盤面が書いた文は、読み手が持っている行為の選び方を変えることだけを言う。** 外す文は 4 種: 伏せた verb や道具に触れる文、
   読み手に無い節を指す文、床が担保することの言い直し、定数の打ち消し(打ち消すなら定数の側を置き換える)。例外として、
   拒否が一時的な失敗と見分けられない床の言い直しと、呼び出しの入力の約束(「〜は拒まれる」)は残す。ADR 0301 決定5
   (帰り先の無い reviewer の文は権限について何も言わない)と ADR 0432 決定4(一部の入力にしか要らない説明は、入力がその値を
   持つときだけ出す)を一般化する。
2. **盤面の語に定義を付けるのは、決定1 で残った文の行為の選択に、その語の意味が要るときだけ。** それ以外は語を使わずに
   言い換えるか、入力の中身が意味を語るなら名前のままにする(ADR 0324 決定3 の Interview root と同じ形)。
3. **定義は語ごとに 1 か所の出所を持ち、その語を使う文が出所から挿して運ぶ。** 同じ読み手の複数の文が同じ定義を運ぶ重複は
   受け入れる。tool が伏せられれば、その文と一緒に定義も消える。ADR 0324 決定1 の欄の record は残し、欄の文が使う盤面の語の
   定義は語の出所から挿す。欄が何かは欄の record、語が何かは語の出所が持つ。GLOSSARY.md とは機械的に結ばない。
4. **範囲は盤面が書いた文すべてである。** worker session の全種類、すべての Board call、management MCP。system prompt・注入の節・
   task prompt・tool 記述・verb の応答と拒否の文を含む。盤面が書かない文(注入される skill、対象 repo の CLAUDE.md、registry の
   agent 定義と profile、起草者が書く記憶の行の本文)は外す。ADR 0324 決定3 の範囲をここまで広げる。
5. **翻訳の用語集は、訳す文に出る語の対だけを載せる。** 用語集を入れる目的は訳語の揺れを防ぐこと(#47)で、出ない語の対は
   訳語の選び方を変えない。ADR 0062 が予測した「最小キャッシュ長を越えれば翻訳のキャッシュが戻る」見込みは手放す。
   差は 1 回あたり数百トークンで、翻訳の結果は永続的にキャッシュされる。
6. **漏れと食い違いはテストで守る。** 出所の語は対応する GLOSSARY.md の見出しを持ち、見出しが無い語は GLOSSARY.md に足す。
   文の変種ごとに描画した文に GLOSSARY.md の見出しの語が出たら、出所の定義を運んでいるか、語ごとの例外の一覧に載っていなければ
   落ちる。確かめる単位は読み手の組み合わせではなく文の変種である(決定3 で、定義は文と一緒に動く)。すべての tool と文の部品が
   1 回以上描画されたことも確かめる。内容の食い違いは機械では見ず、review で見る。

## 退けた形

- **2 つを 1 つの根として直す** —— 出し分けを広げても、定義の出所が無いことは直らない。
- **読み手ごとに「Terms」の節を組み上がった文から作る** —— 散文の照合が脆く、伏せた tool の分まで拾うと決定1 とずれる。
- **定義を注入の節にまとめて書く** —— 使わない読み手にも届き、決定1 に反する。
- **GLOSSARY.md から生成する・照合する** —— 読み手も言語も違い、GLOSSARY.md は実装の詳細を持たない(ADR 0324 も指す先として退けた)。
- **出所の語の見出しの存在だけを確かめる** —— 改名と削除しか捕まらず、名前だけで使う文の再発(#3977 そのもの)を見逃す。
- **読み手の状態の組み合わせを網羅して描画する** —— 組み合わせが多すぎ、決定3 の下では要らない。

## 帰結

- 部品の中の分岐の描画漏れは受け入れ、見つかったら変種を足す。GLOSSARY.md に見出しの無い語と、例外にした語が後から盤面の
  意味で使われる場合も、テストは捕まえない。
- 実装は #3973 → #2512(決定1)→ #3977(決定2・3・6)の順で、#2512 と #3977 は #3937 の後に入れる。決定5 は #3979 に入れる。
- 記憶の行の本文が盤面の語を名前だけで運ぶ件は #3983 に置く。
