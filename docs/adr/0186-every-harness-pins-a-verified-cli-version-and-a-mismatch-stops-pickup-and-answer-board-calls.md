# どの Harness も検証済みの CLI の版に固定し、版の不一致は pickup と答えを取りに行く Board call を止める

2026-10-01 の grilling(issue #1270)で決定。Codex は ADR 0098 決定4 で版を固定していたが、Claude Code CLI は固定して
いなかった。ホストの CLI は自分で更新され、ベンダーが面を変えると予告なく盤面へ届く。#1269 はその実例で、`TaskOutput` が
面から消え、封じ込めの検査が人間が宣言を直すまで pickup を止めた。実測(各ホストの版、CLI の更新と版の門の振る舞い)は
#1270 のコメントに置く。

## 決定

1. **版の固定は experimental 面に限らない。** 盤面は Harness ごとに検証済みの CLI の版を1つだけ宣言し、ホストはその版に
   留まる。spawn ごとの面の観測(ADR 0039 決定3)は残す。固定が要る理由は、盤面が CLI に依存していながら毎回は観測して
   いない面があることである。使用量画面(ADR 0078)、429 / 404 の envelope(ADR 0104 / 0184)、出力と設定キーの形が
   それに当たる。これらのずれは封じ込めの停止としては現れず、別の壊れ方として出る。1か所で押さえる手段は版の固定しか
   ない。これは ADR 0098 決定4 の固定を、experimental 面の受け止めから全 Harness の原則へ広げる。
2. **版の一致は Harness の封じ込め能力の問いに含める。** 判定は完全一致で、範囲は許さない。不一致なら、その Harness を
   正準経路とする agent の pickup が止まる。Codex の先例と同じ資源である。版は Harness の性質であり、Claude Code は
   Anthropic と Moonshot の2つの Provider が共有するので、Provider 単位では狭すぎる。
3. **答えを取りに行く Board call は、版が一致しない間、Board call の口(ADR 0136)で断る。** 版の不一致を名指しして
   失敗させる。止める理由は出力の形が検証されていないことで、それは版の性質だからである。封じ込めのほかの問い
   (サンドボックス・ツール面)では止めない。道具を持たない呼び出しには関わらないからである。probe は断らない。版が
   戻ったことを確かめる手段が probe そのものである。口は1か所なので、Codex の Board call(#456)も同じ門を通る。
4. **盤面は自分が起こす CLI の自動更新を閉じる。** 自動更新は対話の起動でしか走らない(`-p` では走らない)。盤面が
   起こす対話の起動は使用量画面の読み取りだけなので、盤面が起動するすべての `claude` に自動更新の停止を渡す。それ以外の
   経路(人間の手による更新など)で版が変わったら、決定2 の検査が止める。
5. **ホストの CLI は、盤面の checkout が宣言する版に追従する。** 固定の版は repo の1か所に置き、盤面のコードと
   導入スクリプトの両方がそこを読む。VM は起動のたびに、Pi は deploy の段で、その版を入れる。checkout の版を入れることは
   ADR 0101 決定4(起動時に pull しない)とぶつからない。入れるのは、持ち主がすでに選んだ checkout が宣言する版だけである。
6. **ベンダーが固定の版を引退させたら、盤面は従い、引退として名指しして止まる。** CLI は遠隔の最低版の門で起動時に
   exit 1 する。盤面はこの門を外さない。外す手段はテレメトリや機能フラグの取得も一緒に止めるうえ、ベンダーが「続けられ
   ない」とした版を走らせ続けることになる。止まる資源は決定2 と同じである。
7. **版を上げるのは、適合試験を通した意図的な変更に限る。** 適合試験は、盤面自身の読み取り関数に新しい版の実物の出力を
   食わせ、機械で判定する。人が目で見る手順にはしない。場所は Lima VM で、CI では回せない(サブスクリプションの認証が
   無い)。429 の envelope は再現できないので、未確認の面として手順書に名前を挙げ、既存の fail-closed に任せる。

## 退けた案

- **今のまま検出だけに任せ、止まったら宣言を後から直す。** 封じ込めの観測が見ていない面のずれを、別の壊れ方のまま
  残す。速さ優先で出る版の不具合を、fail-closed だけで受け止めることになる。
- **ホストで凍結するだけで、盤面は版を検査しない。** 人間の手による更新を見逃す。
- **版ごとのバイナリのパスを指して起動する。** native の配置に依存し、npm で入れた Pi と形が揃わない。古い版が
  掃除されると消える。
- **封じ込めの隔離が開いている間は、原因を問わず Board call を止める。** サンドボックスの不在のような、道具を持たない
  呼び出しには関わらない原因でも、翻訳や下書きが止まる。

## Consequences

- ADR 0039 決定5(deploy 時の canary は作らない)の根拠の一方、「自動更新は deploy と deploy の間に起きる」は消える。
  評価し直したが、結論は変わらない。もう一方の根拠、盤面が spawn ごとに全ホストで実測できることが残るからである。CLI の
  更新は版上げの deploy に限られるので、VM の適合試験と Pi の sandbox smoke(deploy-pi)の2段構えになる。
- 固定の版は、新しいモデルや別名が新しい CLI を要求したときにも上げる必要がある。
