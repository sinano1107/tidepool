# work が立つのは帰り先のある系譜だけで、帰り先は1本の述語と1つの表で読み、床・cascade・verb・文・画面はすべてそれを読む

2026-10-22 の grilling(issue #2505)で決定。Interview の root の下の RCA の所見の行への異議が work の修理子を立て、修理子は祖先に
work が無いので測っている repo の保護ブランチから fork して PR を開く —— 異議の門(ADR 0283 決定2)が理由を「行の主題」で書き、主題も
work の祖先も持たない Interview の木の RCA が漏れていた。洗い直しで、同じ形は異議の門の外にも出た: RCA 自身の分解(Interview の root・
meta-review の下)、祖先の cancel を生き延びた RCA が cancel の前に立てた分解子(cascade が RCA の下へ降りないので残り、pickup される)、
その下の承認 question(#2177)。原因は「ここに task が立ってよいか」を床・cascade・異議の門・画面がそれぞれ自前で判定していたこと。
測定の表と `file:line` は #2505 のコメントに置く。

## 決定

1. **帰り先の述語は1本 —— これから立つ子について、親と祖先で読む。** 帰り先が無いのは (a) 系譜のルートが保護ブランチを対象にする仕事
   —— work(受験者を除く)か独立監査(主題の無いルート review)—— でないとき(Interview の root、meta-review、受験者。新しいルートの
   種類も既定でこちら)と、(b) 親自身が cancelled(型を問わない —— ADR 0268 決定3)か、親と祖先に cancelled の work があって成果が捨てられたとき(ADR 0271 決定1)。work の祖先の有無は理由にならない ——
   独立監査の修理子は work の祖先を持たずに保護ブランチから切られ、それが正しい(CONTEXT.md「Review」/ ADR 0056)。
2. **帰り先の無い系譜に立たない task は性質で決める: 宛先がブランチに依存する task。** work、完了時レビュー・統合レビュー、人間の
   review 子、承認すると work を立てる question(答えで work を立てる種類は `approval` だけ)。それ以外 —— RCA、記憶・routing の修理子、
   出題の監査、meta-review の提案 question、失敗・escalate・probe 破綻の question —— は立つ。ADR 0271 決定3 の線「仕事の宛先が親の
   生死に依らない付帯子だけ残る」を、cancel のときだけでなく登録のときにも読む。
3. **全員がこの述語と表を読む。** 登録の床(扉を問わず拒む)、異議の門(修理子を飛ばし、帰責と RCA は立てる)、verb の差し替え(分解の
   verb を伏せる —— MCP の登録と Codex の宣言)、権限の文と当時版、`get_current_task`、cascade、cancel の面、直接 cancel の門、流し読みの
   予告と commit の文(人間の登録扉は床の拒否をそのまま返す)。今の門の3条件(Interview の root か・監査か・主題を持つか)と「異議された task 自身が
   cancelled」はこの1本に畳む。
4. **cascade は表から導き、付帯子で止まらない。** 表は性質を2つ1か所に持つ —— 宛先がブランチに依存するか(決定2)と、宛先が親の生死に
   依るか(ADR 0271 決定3: 親が待っている子と、RCA・修理子以外の付帯子 —— 提案 question を含む)。cancel された task の子は後者で倒れ(今どおり)、
   生き延びた付帯子の下では前者で倒れる —— RCA は残り、RCA の分解子とその下の承認 question は倒れ、RCA の escalate の question は残る。
   倒れた task の子にも同じ規則が掛かる。cancel の面の「捨てられる done の work」も同じ範囲を数える。床に乗る他の規則(受験者・親の
   実行の事実など)は cascade を動かさない。
5. **帰り先の無い系譜で reviewer の文を持って走る task には、権限について何も言わない。** RCA・出題の監査・Interview の root・meta-review
   は Authority 節も Roster 節も持たない —— 読み取り専用は床が担保し(道具を外し、書き込みを拒む)、修理という行為は知らせず、完了の仕方は
   完了 verb の説明が言う。分解を伏せた task では `complete_rca` の説明から「decompose で立てた repair task」の節を外し、`get_current_task`
   にも欄を足さない(今の捨てた成果の欄と監査の notice は外す)。当時版は spawn の時点の状態で選び、Authority 節が無かったことも写す
   ((b) は途中で変わる)。走行中に cancel が届いた review は止めず、分解を呼べば床の拒否で知る。
6. **画面の予告も同じ出所。** 判断の行への異議が work の修理子になる行で、帰り先が無い行すべてに「修理は立たない、帰責と RCA だけ」を
   出す(ADR 0268 決定6 の Interview の root の印を一般化)。commit 画面の文は例外を列挙せず性質で書く。
7. **別 workspace への分解子(registry の編集の提案)も今は立たない。** その work には帰り先(その workspace の保護ブランチ)があるが、
   帰り先を work 自身の workspace で読む形は系譜の読みが workspace を見ない欠陥(#2033)の後でしか決められない(#2510)。

## 退けた案

- **work の祖先を持つかで判定する**(issue の案)—— 独立監査の修理子と、その RCA の修理子を止める。
- **異議の門だけ直す** —— RCA の分解・人間の分解・cancel の前に立った分解子が残る。3つは1つの事態の出口なので事態の側で塞ぐ。
- **打ち消しの1行を足す / cancel で捨てた成果だけ打ち消しのまま残す** —— 同じ文面で「修理を振れ」と「修理は立たない」が食い違う
  (#2217 と同じ)。1行も spawn 時にしか組まれず、走行中の review が実際に知るのは床の拒否なので、残す理由が無い。
- **「読み取り専用・修理は立たない・所見は完了 verb で」の文に置き換える** —— 読み取り専用は床が担保し、修理は外した後の worker が
  知らない行為で、完了の仕方は verb の説明が言う。言うことが残らない(同じ形の文の総なめは #2512)。
- **cancel が届いた走行中の review を止める** —— 生き延びるのは RCA だけで、その仕事(帰責・起草・`complete_rca`)は cancel で変わらない。
- **人間の review 子を帰り先の無い系譜に立てる** —— 宛先の修理が着地せず、判断への不服は異議 → RCA の扉と重なる。失うのは Interview の
  root への second opinion で、採点への不服は root の行への異議で出す(ADR 0268 決定1 と同じ線)。

  既に立っている work の移行は要らない。
