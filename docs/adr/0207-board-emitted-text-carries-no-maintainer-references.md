# 盤面のコードが発する文に保守者向けの参照を入れない

2026-10-07、issue #1429 で「エージェントが読む地の文」について決め、同日の issue #1508 の grilling で線を引き直して
書き換えた。registry の定義の検査や実行設定の扉が返す拒否文に `(ADR 0110 決定1)` の形の引用が入っており、
triage はこれを「決定」だけ英訳して残す案を推していた。`src` の文字列リテラルの中で ADR を引く箇所はほかにも
37行あった(仕分けの実測は #1508 のコメントに置く)。

## 決定

1. **線は読み手が agent か人間かではなく、保守者として読む立場かどうかで引く。** 保守者 —— このリポジトリの
   コード・コメント・ADR・テスト・commit を読み書きする立場 —— 以外の読み手は、agent も WebUI の人間もホストの
   運用者も、盤面を運用している保守者自身も、走っている盤面が発する文字列を盤面の利用者として読む。
   agent か人間かで仕分けると、question の本文のように WebUI と管理 MCP の両方へ同じ文字列が出る面で線が
   引けない。
2. **盤面のコードが発する文字列(`src`・`public/` のコメント以外の文字列 —— system prompt・tool 記述・tool の
   出力・拒否文・question の本文・event の message・ホストのログ)には、保守者向けの参照(ADR 番号・issue 番号・
   CONTEXT.md)を入れない。引用はその文を組み立てるコードのコメントに置く。** 利用者にとって参照は、辿れても
   辿れなくてもすることを変えず、トークンと注意を使い、意味を推し量らせて判断を乱しうる。agent には辿る経路が
   無く、tidepool 自身を対象 repo にした worker では、引用は盤面の checkout の ADR を指すので、workspace の版と
   ずれうる。保守者にとっての手がかりは、文を grep すればコメントに着くので失われない。
3. **外すのは参照だけで、説明は地の文に残す。** `(ADR 0019: repair is not a re-enactment)` の後半のように、読み手が
   使える中身は参照と一緒に消さない。
4. **再発は lint で止める。** `src`・`public/` のコメント以外の文字列にある `ADR \d{4}` を落とす。issue 番号と
   `CONTEXT.md` は、色コードなどの誤検出があり実績も1件ずつなので、規則には入るが lint では拾わない。
5. **範囲の外:** 保守者が回す道具の出力(`scripts/` の canary など)と、worker が自分で書く文(result・PR 本文が
   対象 repo の ADR を引くこと)。
6. **これは ADR 0015 とは別の線である。** ADR 0015 が決めたのは地の文の**言語**で、ここで決めるのは**中身**で
   ある。英訳しても解決しない —— `ADR 0110 decision 1` も、利用者にとっての無用さは変わらない。

## 退けた代替案

- **「決定N」を `decision N` に訳して引用を残す**(#1429 の triage の推奨)。言語の線は守るが、参照というノイズは残る。
- **読み手が agent の文だけ外し、人間が読む文には残す**(#1429 時点のこの ADR)。同じ文字列が両方へ出る面で
  線が引けず、面ごとに文字列を分けるのは誰の行動も変えない参照のために経路を増やすことになる。
- **前例に揃える。** そう決めた記録は無く、前例は根拠にならない。
