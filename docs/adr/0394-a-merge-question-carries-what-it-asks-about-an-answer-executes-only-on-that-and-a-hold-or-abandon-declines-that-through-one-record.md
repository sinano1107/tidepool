# merge question は問うた内容を持ち、回答はその内容にだけ執行し、hold と abandon は1つの記録でその内容を断る

2026-11-21 の grilling(issue #3402、族の根として #3485・#3407・#3408 を寄せた)で決定。`pr_merge` の question は PR 番号しか持たず、
何について問うたか(どの head、どの理由)は本文の文章にしか無かった。盤面が「もう問うた」と知る状態は「その PR に開いた question があるか」
だけだった。立てる経路が1回きり(PR を開いたとき、キューの行を外す tick)だった間はそれで足りていた。ADR 0376 決定7 が、条件を収束の
たびに読み直す書き手を初めて足したことで、欠落が4つの症状になった —— hold が何も断れない(#3402)、寄り道の後に人間が見ていない head を
merge しうる(#3485)、理由の違う書き手が衝突する(#3407)、回答が根の verdict を収束の回から借りる(#3408)。読んだコードと場面は #3402 に置く。

1. **着地の question は、問うた内容を2つの部分で持つ。** **外の部分**は盤面の外から来た head(sha と、盤面が push していない head か
   書き換え・巻き戻しか)で、無ければ無し —— `pr_merge` の question だけが持ち、回答を拒むかの判定(決定3)と `pr_merge` の断った記録
   (決定5)に使う。立てる時点の外の部分は、どの本文を選ぶかに依らず出所の判定の結果で、同じかどうかは sha と種類の組で比べる —— 同じ sha
   でも、取り込みの後に盤面が push していない head から書き換えへ読みが変われば一致しない(問うた時の種類のまま執行すると、寄り道を通さずに
   内容の落ちた head を merge する)。**盤面の部分**は
   問うた時点のタスクブランチの tip(書き換えの question では本文が名指す欠けたブランチも)で、`pr_merge`・`local_merge`・
   `pr_promotion_retry` の3つが持ち、断った内容の記録(決定5)にだけ使う。理由(CI 赤・面の変化など)は本文と推奨を決めるだけで、どちらにも
   入れない。本文は立てる時も直す時も同じ組み立てで、外の部分があれば外の本文を先に置き、ほかの理由は後ろに1行添える(ADR 0387 決定1 の
   「CI 赤と重なればこの本文を先にする」を書き換えの本文にも当てる)。線は ADR 0387 と同じく「盤面の push か、外から来たものか」で、人間が見たかではない —— 盤面自身の push や修理で内容が進んでも
   回答は拒まない。1つの塊を判定と記録の両方に使う形は退けた —— 理由ごと・question の種類ごとに例外が要った。
2. **`pr_merge` の question の書き手は1つで、開いた question と外の部分が違えば、同じ question のまま外の部分と本文を直し、推奨を hold に
   し、直したことを根に刻む。** 同じ外の部分が開いていれば何もしない。1つの PR に question は1つのまま、本文は今の外の head を言う。取り下げて
   新しい id で立て直す形は退けた —— 安全性は同じだが、人間が答えている途中の question が閉じ、hold のたびに id が変わる。ローカル着地の
   question は開いている間は根が候補から外れるので直す書き手が来ず、昇格失敗の question は今どおりタスクごとに複数開きうる —— どちらも
   この決定の外である。
3. **`merge` の回答は、今の外の部分が無しか、問うた外の部分と同じときだけ執行する。** それ以外 —— 人間に見せていない外の head —— なら
   回答を拒み、拒否文で足された commit を列挙し、決定2 で question を直す。外の部分が無ければ head は盤面の push した値なので、理由が消えた
   question(人間が落とされた commit を origin へ push し直した後など)への `merge` もそのまま執行する —— `external` の根でも ADR 0376 の
   Status 追記どおり merge する。書き換え・巻き戻しの question への `merge` は寄り道(取り込み → 追いつき → push、ADR 0376 決定8)を通し、
   その後にもう一度この条件で確かめる —— 寄り道の間に外の head が動けば拒む。外の commit を盤面は merge しない(ADR 0376 決定4)のは寄り道が
   保つ。「伝えた head の集合」で判定する形は退けた —— 書き換えの head を question で伝えると merge が通り、理由ごとの例外が要る。
4. **回答が収束を通るとき(`merge` の寄り道、昇格失敗の `retry`)は、回答の根を id で指して1回だけ撃つ。** 候補を数え直す収束の全体では
   ない。根が止まれば(門・Quarantine など)、拒否文はその理由を言う。
5. **断る回答 —— `pr_merge` の hold、ローカル着地の hold、abandon promotion —— は、根に1種類の記録を刻み、断るのは question が問うた時点の
   内容である。** 「問うた時点」は question を最後に立てたか直した時点 —— 人間が最後に見た本文の時点である。記録は断った question と、
   その時点の盤面の部分の写しを持ち、`pr_merge` では外の部分も写す。比べるのは写した内容の全体で、どちらかが違えば問い直す —— hold の後に外の
   誰かが head をもう一度動かしても、盤面の部分が同じなら問い直さない形では、人間はその head を見ない。回答の時点の head を刻む形は
   改める —— question が開いている間に届いた内容まで、人間が見ないまま断ったことになる。同じ計算が2箇所にあり、3箇所目を足す前に出所を1つに
   する。`hold` は外の部分が一致しなくても拒まない —— 断るのは人間が見たもので、今の内容が違えば決定7 / ADR 0289 の問い直しが続く。
6. **断った後に何を止めるかと、いつ効かなくなるかは、種類ごとに分けたまま残し、読み手は記録が指す question の種類で絞る。** abandon promotion
   は昇格を止め、後の `pr_opened` / `pr_branch_pushed` で効かなくなる(ADR 0225)。ローカル着地の hold は根の着地を止め、merge の執行の
   記録で効かなくなる(ADR 0289)。PR の hold は question を立てることだけを止め(push は続く)、その PR の決着の記録か、同じ PR に新しい
   question が立つと効かなくなる。種類で絞らないと、abandon → retry で PR を開く → PR の hold の順で、PR の hold を断念と読んで着地が止まる。
7. **PR の hold の後は、断った内容と今の内容が違うときだけ問い直す。** 問い直しは新しい question を立てる(答えた question は閉じている)。
   条件を読み直すのは収束だけなので、実際に起きるのは外の push の question だけで、tick の question はキューの行が外れているので問い直さない。
   ADR 0387 の帰結「hold の後は人間が GitHub で merge か close する」は tick の question について変わらない。

## Consequences

- ADR 0387 決定2 の「伝えた」の記録は決定3 に置き換わって無くなる。同じ question に同時に走る回答が互いの直しで通らないこと(ADR 0387 Status
  追記 (1))は、決定2 の直しと決定3 の検査の間で保つ —— 形は実装の spec が決める。
- ADR 0376 決定7 の作業台の「1回拒んだ」印は、伝えたことの記録ではなく作業台の状態なので、決定3 の外に残る。
- abandon の記録は今は回答の transaction の外で、ローカル着地の hold は中で刻まれている。1種類にするときにどちらへ揃えるかは spec が決める。
- 人間の根で完了レビューを待つための local merge の hold が戻らない #3469 は、この族に入れない —— 欠けているのは記録の対象ではなく、
  「待つ」という意図を hold が表せないことである。
