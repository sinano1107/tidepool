# merge question は問うた内容を持ち、回答はその内容にだけ執行し、hold と abandon は1つの記録でその内容を断る

2026-11-21 の grilling(issue #3402、族の根として #3485・#3407・#3408 を寄せた)で決定。`pr_merge` の question は PR 番号しか持たず、
何について問うたか(どの head、どの理由)は本文の文章にしか無かった。盤面が「もう問うた」と知る状態は「その PR に開いた question があるか」
だけだった。立てる経路が1回きり(PR を開いたとき、キューの行を外す tick)だった間はそれで足りていた。ADR 0376 決定7 が、条件を収束の
たびに読み直す書き手を初めて足したことで、欠落が4つの症状になった —— hold が何も断れない(#3402)、寄り道の後に人間が見ていない head を
merge しうる(#3485)、理由の違う書き手が衝突する(#3407)、回答が根の verdict を収束の回から借りる(#3408)。読んだコードと場面は #3402 に置く。

1. **着地の question —— `pr_merge`・`local_merge`・`pr_promotion_retry` —— は、問うた内容を持つ。** 内容は本文が人間に告げていることに
   限る —— 理由、盤面が push していない head(無ければ無し)、本文が名指す盤面の内容の tip。ローカル着地と昇格失敗の question は tip だけを
   持つ。盤面自身が push した head は内容に入れない。入れると、盤面が修理を push するたびに内容が変わり、escalate の question が push ごとに
   問い直される。ローカル着地と昇格失敗にも当てるのは、完了時レビューの修理が question の開いている間にタスクブランチへ戻りうるからで、
   当てなければ `merge` / `retry` が人間の見ていない修理まで執行する。
2. **書き手は1つで、開いた question と内容が違えば、同じ question のまま内容と本文を直し、直したことを根に刻む。** 同じ内容が開いていれば
   何もしない。1つの PR に question は1つのまま、本文は今の内容を言う。取り下げて新しい id で立て直す形は退けた —— 安全性は同じだが、人間が
   答えている途中の question が閉じ、hold のたびに id が変わる。同じ question のまま直すのは、ADR 0387 決定2 の「拒まれて同じ question に
   答え直す」手応えを保つためである。
3. **回答は、執行の前に question の内容が今の状態と一致するかを確かめる。一致すれば理由ごとの行為を執行し、一致しなければその回答を拒み、
   決定2 で question を今の状態に直す。直す先が無ければ —— `external` の根で理由が消えた(人間が落とされた commit を origin へ push し
   直した)とき —— 回答を拒んで question を盤面の観測として閉じる(決定ログは立てない)。`auto_if_ci_green` の根は無人 merge に戻さず
   (ADR 0387 の帰結)、推奨 merge の question に直す。** 盤面が push していない head の question への `merge` はその head を merge する。書き換え・巻き戻しの
   question への `merge` は寄り道(取り込み → 追いつき → push、ADR 0376 決定8)を通し、その後の head が盤面の push した値であることを確かめて
   から merge する —— 外の commit を盤面は merge しない(ADR 0376 決定4)のは理由ごとの行為が保つ。「伝えた head の集合」で判定する形は
   退けた —— 書き換えの head を question で伝えると merge が通ってしまい、理由ごとの例外が要る。
4. **寄り道は、回答の根を id で指して1回だけ撃つ。** 候補を数え直す収束の全体ではない。根が止まれば(門・Quarantine など)、拒否文はその
   理由を言う。question が理由を持つので、回答は収束の候補の読みに頼らない。
5. **断る回答 —— `pr_merge` の hold、ローカル着地の hold、abandon promotion —— は、根に1種類の記録を刻み、断るのは question が問うた時点の
   内容である。** 記録は断った question と、その時点の内容の写しを持つ(内容は決定2 で後から直るので、id だけでは足りない)。比べるのは内容の
   組全体で、ローカル着地と abandon は tip だけの組になる。回答の時点の head を刻む形は改める —— question が開いている間に届いた内容まで、
   人間が見ないまま断ったことになる。同じ計算が2箇所にあり、3箇所目を足す前に出所を1つにする。
6. **断った後に何を止めるかと、いつ効かなくなるかは、種類ごとに分けたまま残す。** abandon promotion は昇格を止め、後の `pr_opened` /
   `pr_branch_pushed` で効かなくなる(ADR 0225)。ローカル着地の hold は根の着地を止め、merge の執行の記録で効かなくなる(ADR 0289)。
   PR の hold は question を立てることだけを止め(push は続く)、その PR の決着の記録か、同じ PR に新しい question が立つと効かなくなる。
   PR の hold に abandon と同じ規則を当てると、hold の後も続く盤面の push のたびに hold が消える。
7. **PR の hold の後は、断った内容と今の内容が違うときだけ問い直す。** 問い直しは新しい question を立てる(答えた question は閉じている)。
   条件を読み直すのは収束だけなので、実際に起きるのは外の push の question だけで、tick の question はキューの行が外れているので問い直さない。
   ADR 0387 の帰結「hold の後は人間が GitHub で merge か close する」は tick の question について変わらない。

## Consequences

- 人間が落とされた commit を origin へ push し直して理由が消えても、開いた question は収束では直らない。次の回答が決定3 で拒まれ、question は
  今の状態(例: 推奨 merge の escalate)に直るか、`external` の根なら閉じる。無人 merge には戻らない(ADR 0387 の帰結)。
- ADR 0387 決定2 の「伝えた」の記録は決定3 に置き換わって無くなる。同じ question に同時に走る回答が互いの記録で通らないこと(ADR 0387 Status
  追記 (1))は、決定2 の直しと決定3 の一致の検査の間で保つ —— 形は実装の spec が決める。
- ADR 0376 決定7 の作業台の「1回拒んだ」印は、伝えたことの記録ではなく作業台の状態なので、決定3 の外に残る。
- 人間の根で完了レビューを待つための local merge の hold が戻らない #3469 は、この族に入れない —— 欠けているのは記録の対象ではなく、
  「待つ」という意図を hold が表せないことである。
