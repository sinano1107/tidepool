# 起草と第2回の帰責は結果が無ければ盤面が撃ち直し、撃って3回失敗したものは人間の面に出す

2026-09-28 の grilling(issue #1049)で決定。Behavior candidate の起草(ADR 0120 決定1(b)(c))は commit 時か第2回の後の1回きりで、
失敗は `memory_draft_failed` に畳まれて終わり、meta-review の材料にも再起草の契機にも無かった。第2回の帰責も失敗すれば
`uncertain` が最終値として残り(#575)、ADR 0115 決定2 の「`uncertain` は最終値にならない」と食い違っていた。どちらも異議という
学習入力が黙って消える。材料(異議エントリ・steering・当時の decision log・RCA の findings)は event に残っている。今の実装の
walk-through は #1049 のコメントに置く。この ADR は ADR 0115 の「第2回は1回だけ」と上の一文を改め、ADR 0120 決定1(書き手)は変えない。

## 決定

1. **撃ち直すのは盤面で、対象は「あるべき結果が無い」帰責。** 起草は「今の規則で起草に当たる最新の帰責なのに、それを出所とする
   candidate が無い」、第2回の帰責は「RCA が決着したのに第2回の帰責が無い」。失敗を記録した event ではなく結果の不在で拾うので、
   commit 直後の起草が try の外で落ちた場合や、撃っている最中に盤面が再起動した場合も拾える。1つの帰責から candidate は1本まで ——
   撃っている最中の呼び出しと重ねないため、盤面は process 内に in-flight の集合を持つ(再起動で呼び出しが殺されることは ADR 0136 が保証する)。
2. **宛先の agent がいない起草は失敗ではなく、起草しない。** 登録者が人間か盤面の `task_ambiguity` / `missing_information` は、
   人間エントリと同じく何も残さず skip する。何度撃っても結論は同じ。
3. **「撃てなかった」は何も書かず、数えない。** client なし・表の行なし・throttle・容器の前提の不成立(ADR 0136 決定7)は撃つ前に
   盤面が知っている事実で、次の機会を待つだけ。撃って失敗したとき(exec・CLI の認証・検証・is_error)だけ失敗 event を残す ——
   起草は `memory_draft_failed`、第2回の帰責は専用の失敗 event で、`objection_attributed` には判断だけを置く。
4. **契機は pickup の poll で、撃って失敗してから1時間以上空ける。** poll に相乗りして fire-and-forget で撃ち、poll を待たせない。
   間隔が無いと、pickup が続く時間帯に一時障害の数分で上限を使い切る。INDEX は撃つ時点のもので組む。
5. **撃って3回失敗したら打ち切り、settings の Memory 面と管理 MCP に出す。** 3 は盤面の定数(最初の1回も数える)。行は異議
   エントリ・cause・round・最後の失敗理由を見せ、**Retry**(もう3回)と **Dismiss**(学ばない、または手で書き終えた)を持つ。
   どちらも追記だけの event で、「打ち切り」は直近の Retry 以降の失敗が3回あり Dismiss が無いことから導く。行が閉じるのは
   撃ち直しが成功したときと Dismiss だけ —— 人間が手で書いた Behavior の case(ADR 0153 決定3)を見て閉じる推論はしない。
6. **第2回の判断としての `uncertain` は撃ち直さない。** 同じ証拠で問い直しても変わる見込みが無く、cause を強いれば誤った教訓が
   起草される。ADR 0115 の一文は「初回の `uncertain` は第2回へ持ち越され、第2回の判断として残ることはある」と読む。

## 退けた案

- **meta-review が起草し直す** —— 帰責を出所に起草する verb が要り、ADR 0120 決定1 の書き手が1つ増える。周期ごとにしか拾えず、
  未回答の提案で止まる(#1046)。
- **失われてよいとし、人間が手で書く** —— 一時的な失敗まで人間の手作業になる。面が要るのは打ち切った残りだけ。
- **失敗 event に「撃てなかった / 失敗」の区別を足して、それを対象にする** —— throttle の間じゅう保留の件数ぶん event が毎時増え、
  try の外の落ち方と再起動は拾えない。
- **上限なしで撃ち続ける / 打ち切りをどこにも出さない** —— 前者は失敗し続ける1件に毎時 Board call を払い、後者は出発点の「黙って消える」に戻る。
- **管理 MCP には出さない** —— そちらで操作する人間には消えたのと同じになる。

配分評価の `board_call_failed`(#1062)と、初回の帰責の失敗が RCA を立てる前提(#1063)は別 issue で扱う。

## 追記(2026-09-28 の grilling、issue #1063 / ADR 0168)

初回の帰責は撃ち直さない —— 結果は commit がその場で使うので、結果の不在で拾う機構に乗らない。撃てなかった・失敗した entry は
未帰責のまま RCA に倒し、決定1 の第2回の対象は「初回が `uncertain` または無い」と読む。決定3 の失敗 event は初回の失敗も同じ kind で
持つ(`round` で区別)。

## 追記2(2026-09-28 の grilling、issue #1062 / ADR 0172)

配分評価も決定1 の対象に加わる —— 「統合点レビューが完了したのに、それを指す `allocation_reviewed` が無い」を sweep が拾う。
決定5 の一覧は3用途で1つのまま、置き場所を settings の Memory 面から振り返り Board call のティア設定の隣へ移した。
