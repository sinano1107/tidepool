# Edit・直接 cancel・注入 query の英訳は登録者ではなく文面の書き手で読み、承認で実体化した子は分解した agent のものに留まる

2026-10-08 の grilling(issue #1396 / #1397)で決定。ADR 0194 決定1 以後、登録者は「その task の存在を決めた判断の主」である。
承認で実体化した子では、登録者は人間の approve だが、文面は分解した agent が書いたままである(ADR 0197 決定2)。それでも
Edit・直接 cancel の門と注入 query の英訳の門は、登録者が `human` かを「人間が書いた task」の代わりに読み続けていた。
この3つの門で判定がずれていたのは、承認で実体化した子だけである。人間の root・人間 decompose の子・agent の子・
盤面の task は、どちらで読んでも同じ答えになる。

## 決定

1. **Edit の範囲は「文面の書き手が人間の task」である。** 承認で実体化した子は範囲から外れる。approve が認めたのは子の存在で、
   文面と申告には触れていない。Edit を開けたままにすると、ADR 0197 決定2 の前提「approve には文面を直す手段が無い」が成り立たない。
   そのうえ、要求の学習(決定4)と英訳の門は、人間が書き換えた文面を agent の文面として扱う。これは ADR 0198 決定4 が
   Edit を広げない理由に挙げた見落としと同じ形である。この決定で 0197 決定2 の前提は確定する。中身に不満があるときの経路は、
   承認するときなら reject に理由を書くこと、承認した後なら異議 → 修理である。
2. **直接 cancel の人間側の判定は「分解判断に乗る task なら分解判断の書き手が人間、乗らない task なら登録者が人間」である。**
   ADR 0198 決定1 を改める(盤面の root の段はそのまま)。承認で実体化した子は、元の分解判断を持ち越している(CONTEXT.md
   Cancel の abandon の段と同じ読み)。子の数によらず、直接 cancel はその判断の一部か全部を捨てることになる。一部を捨てれば判断の
   前提が壊れる。全部を捨てれば、人間が agent の分解を直接破棄することになり、#129 / #130 が異議の経路に絞った組み替えに
   当たる。判断ごとの直接破棄は観測されていないので #1582 に置いた。ADR 0198 帰結の「『人間が登録した task』の判定は Edit の
   範囲としてだけ残る」は、この決定で役目を終える。どの門も登録者だけでは読まなくなるからである。
3. **注入 query の英訳の門は「文面の書き手が人間の task、または異議の材料を持つ task」である。** ADR 0194 決定6 を改める。
   0194 決定6 自身が、ADR 0175 が登録者を書き手の代わりにした点を直したものだった。決定1 で承認で実体化した子の文面は
   agent が書いたまま変わらなくなったので、書き手だけで読めば足り、Edit の event を読む必要は無い。

## 退けた案

- **直接 cancel は「存在を決めた者」(ADR 0194 決定1)で読み、承認で実体化した子を範囲に残す** —— approve した人は兄弟の
  組み方を書いていないので、抜いたときに何が壊れるかを知りようがない。子が1つなら、1子を cancel することは判断ごとの破棄と同じになる。
- **Edit を開けたままにし、英訳の門で Edit の event を読む** —— 見落としを英訳の門1つで塞いでも、要求の学習と申告の学習は
  人間の書き換えを agent に宛て続ける。
