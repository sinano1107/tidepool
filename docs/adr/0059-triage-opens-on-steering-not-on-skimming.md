# トリアージセッションは操舵で開き、流し読みでは開かない

issue #225 のグリリング(2026-08-09)で決定。ADR 0004 の**開く契機と activity の定義を改訂する** — ステージング、タイムアウト自動コミット、コミットが「run now」である線、未振り分け scratchpad の持ち越しは、いずれも無傷である。

実機で観測されたのは、fugu の decision log エントリが着地した瞬間(同一秒)に triage セッションが開き、**人間が意識的にトリアージを始めていないのに盤面が止まった**という事象だった。WebUI の既定タブは triage で、未読の question かログが1件でもあれば描画した瞬間にサーバ側でセッションが開く。「WebUI を開いた」が「盤面を止めた」になっており、queue タブへ移動しても止まったままで、解除は30分の無活動タイムアウトまで来なかった。

## 決定

### 1. セッションは最初の実アクションで開く

回答・異議・scratchpad への書き込みのいずれかが最初に来た瞬間、サーバ側が暗黙に開く。**ログの流し読みは開かない。**

ADR 0004 が pickup を止める理由は「人間がキューを再操舵している間、スケジューラから中間状態を見せない」ことだった。**読んでいるだけの人間はまだ何も再操舵していない。** ステージングの意味論が必要になるのは最初の効果が出る瞬間からであり、それより前に盤面を止める根拠は存在しない。

### 2. `log_entry_displayed` はセッションを要求しない

CONTEXT.md の Displayed は「エントリが実際に人間の視界に入ったこと**自体**を記録するイベント」であり、帰属先はセッションではない。**観測であって操舵ではない。** 異議率の分母はセッションの有無に依らず健全に保たれる(`session_id` は今日どこからも読まれていない)。

決定1だけを入れて displayed を必須のままにすると、セッション外の流し読みが1件も記録されず、**読んだのに未観測扱いのエントリが生まれて分母が静かに壊れる** — ADR 0004 が「nothing may degrade recording」で退けた失敗そのものである。

### 3. 流し読みは開いたセッションの activity に数える

displayed が飛ぶたびに自動コミットが繰り下がる。ADR 0004 が書いた「放置」は**不在**であって沈黙ではなく、長いログを読んでいる人間は放置していない。

暴走しない: クライアントは一度報告したエントリを重複排除するので、**画面を開きっぱなしにしても一度も延びない** — 未読を新しく視界に入れている間だけ延びる。これは「人間がまだここにいる」の正確な代理である。

### 4. 面を離れることは閉じる契機ではない

閉じるのはコミットとタイムアウトの2本のまま。モバイル PWA では画面オフやアプリ切り替えで離脱イベントが頻発するため、**離脱を意思の信号に使うと誤爆がキューを動かす**(自動コミットなら未確認の front-insert が適用され、abandon なら人間の回答が unblock した親が先頭に来ない)。

代わりに、開いているセッションは**全タブ常設のバナー**が示し、そこから commit できる(ADR 0058)。今回の実害は「止まっていること」ではなく「**止まっていることに気づけないこと**」だった。

## Consequences

- 「未読のある既定タブを描画した」だけでは盤面は止まらない。今回の実機の id=3 はそもそも開かない。
- 開いているセッションは「人間が実際に操舵を始めた」の証拠になる。30分の無活動タイムアウトの意味が「離席」に純化される。
- 異議のサーバ側 API がセッション不在で拒否する形は残るが、入口が暗黙に開くので人間からは見えない。
- 決定3により、30分以上かけてログを読む人間が skim の途中でセッションを閉じられ、以降の異議が拒否される道が消える。

## Considered options

- **明示操作で開く**(「トリアージを始める」ボタン)— 盤面を止めるという重い効果を人間の明示的な意思に結びつけられる。却下したのは、一本道フローの入口にゲートが1枚増えて朝の操舵のテンポが落ちること、そして「読んでから異議を打つ」という自然な順序では結局「読み終えた時点で開く」= 決定1と同じ挙動を人間の手数で実現することになるため。
- **現状のまま、可視化だけで解く** — 変更は最小で、今回の20分の迷いは可視化だけでも消える。却下したのは、「WebUI を開いただけで盤面が止まる」という因果そのものが残るため。
- **pickup 停止を最初のステージングに結びつける**(セッションは今のまま開くが、止めるのは front-insert が staged された瞬間から)— 「止める理由はステージされた効果があるときだけ存在する」という一貫した読み。却下したのは、ADR 0004 の pickup 停止がステージ適用の整合性だけでなく「人間が見ている盤面が足元で動かない」ことも担っており、そこを捨てる判断になるため。
- **タイムアウトを短くする** — 離脱の実害を時間で削る。却下したのは、長いログを読んでいる人間が skim の途中で切られる側(症状3のもう一方の角)が悪化するため。決定3と組にしない限り成立しない。
