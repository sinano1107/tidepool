# repo の食い違いは task に紐づく操作の入口で記録から読み、ブランチを初めて切る task は分かれる元の記録と比べる

**Status 追記: 決定5 の「名前の場所に分かれる元のブランチが無い場合の読み方」と、帰結の「#3886 を先に決める」の段は決まった。着地が終わっていない task は削除の扉が終え、その下には子を足さないので、生き残った根から分かれる子は無い。着地済みの祖先のブランチが無ければ系譜の読みが飛ばす。決定5 が残るのは、ブランチが在る場合である —— 同じ checkout を別の repo で登録し直すと、着地済みの祖先のブランチは在り、新しい repo がその内容を持たなければ子はそこから分かれる([ADR 0421](0421-the-delete-door-ends-the-landing-of-every-completed-task-it-leaves-under-the-name-and-refuses-while-the-board-still-has-something-to-carry.md) 決定1・3・5 と帰結、2026-11-26、issue #3890)。**

2026-11-25 の grilling(issue #3849、族に #3699 / #3700 / #3804)で決定。ADR 0399 の比較は、行き先を読む所が投げる例外として実装され、
比較を付けるのは操作を組む各呼び手、止まりの種類を決めるのは例外が通り抜ける各 catch だった。同じ形の写し漏れが3件続いた(#3699・
#3700・#3804)。数えると、扉を通って届く穴はその写しの外にあった。削除の扉は未決着の task があれば拒むので、タスクブランチを持つ
task の再 pickup は登録し直しの後に起きない。起きるのは、生き残った根の着地と、その根の下に後から足された子の初回の pickup である。
子は自分の記録を持たないので比べず、旧い repo の内容から分かれて新しい repo を記録するか、素の git エラーで workspace の Quarantine に
なる(実測。根の pickup と完了は fixture の手続き、収束は手で呼び、dial は `external` だけ —— 条件と表は #3849)。出元 repo の
差し替えは削除を通らず、子が走っている最中にも根の記録を食い違わせる。着地では、型を落とす包みが PR のある根に断念を出す(読み)。

この ADR は、何が止まり、誰の止まりで、出口が何かだけを決める。門を置く行、読む順、経路ごとの扱いは spec が実測つきの表で決める ——
grilling は機構まで書いた版を2回見直し、どちらも経路ごとの食い違いが10件を超えた。spec が決める点は #3849 に列挙する。

## 決定

1. **食い違いの止まりは、task に紐づく操作の入口の門が、記録と今の宣言から読んで立てる。** 食い違えば操作を始めない。止まりの器は
   ADR 0399 決定5 のまま(pickup は task の失敗の question、根は PR 昇格失敗の question)。同じ食い違いが、見つかる経路によって
   別の question になることは無い。
2. **操作の途中の例外は、中断にだけ使う。** 行き先を読むたびの比較(ADR 0399 決定3 / ADR 0378 決定7)は残り、網に出ない保証は今どおり
   そこが持つ。例外の種類を見るのは、食い違いを別の記録にする所だけで、読みとその所の間の包みは種類を保つ。それ以外の catch は
   選り分けない。出元 repo の差し替えは操作の途中にも起きるので、これは床でなく本線である。
3. **門は、task の作業を始める所と内容を外へ運ぶ所の場所を作る唯一の口である。** 途中の比較を持つ場所は門の戻り値としてだけ得られる。
   task の内容を運ばない所(走り終えた作業の合流である解放など)と、止まりの出口になる回答(断念、「この根の着地を終える」)は
   通さない。昇格失敗の question への retry は収束を走らせる操作で、出口ではないので通す。
4. **人間の前の扉は、食い違いを拒否で返し、task に何も書かない。** 人間担当の work の扉、merge question への merge の回答、昇格失敗の
   question への retry がそれである。`pr_merge` の hold は ADR 0394 決定5 のまま、読まずに受ける —— 拒むと、その question を
   閉じる回答が無くなる。ローカル着地の hold は変えない(ADR 0401 決定4)。
5. **ブランチを初めて切る task は、分かれる元の task の宣言の repo の記録も今の宣言と比べ、食い違えばその task を止める。** 止まりは
   決定1 の門のもので、人間担当の work の扉では決定4 の拒否になる。分かれる元の内容が、今の宣言の保護ブランチに既に在れば止めない(新しい repo が同じ履歴を持つ場合)—— task の種類に依らない。
   そこから分かれても、新しい repo に無い内容は運ばれない。出元 repo の記録は比べない ——
   根の着地が比べる。記録を持たない分かれる元(面接の task)は比べない。扉を通る出口は、その task の cancel である。名前の場所に
   分かれる元のブランチが無い場合の読み方は、ここでは決めない(#3886)。ADR 0399 決定3 の「2回目以降の pickup」に、初回のこの比較を足す。
6. **収束の門は、することの無い根に問わない。** 今「何もしない」で返る根(回答済み、開いた昇格失敗の question を持つ、断念か hold から
   内容が変わっていない)は、門より先に返る。workspace の Quarantine が開いている間は、今どおり収束は question を立てない(ADR 0241 決定6)。
7. **宣言の repo の記録が今の宣言と食い違う task のブランチは、出元 repo へ送らない。** 設定でも差し替えでも同じである。出元 repo の
   記録の食い違いでは止めない —— 差し替えは今どおり残りをすべて送る(ADR 0395 決定3)。

## 退けた形

- **比較の付与を型で必須にするだけ** —— 子の初回の pickup には比べる記録が無い。
- **Quarantine から外す判断を、Quarantine を立てる口1つにまとめるだけ** —— 食い違いを別の記録にする所は Quarantine の前だけではない。
- **例外の種類を見る所をすべて述語に置き換える** —— 述語が真で、捕まえた失敗が無関係なとき、どちらの止まりを書くかが箇所ごとに要る。
  入口で読めば操作が始まらず、この場合が起きない。
- **食い違った根を、子を塞ぐ根の3つ目の種類にする**(この grilling の最初の案)—— 既存の塞ぎは直接 cancel の範囲・行の形(PR 番号)・
  告知・一覧の読みと結び付いている。戻せる塞ぎを直接 cancel の範囲に入れると完了時レビューを外して着地でき、外すと子に出口が無い。
  出元 repo の差し替えでは、走っている子まで塞ぐ。収束が読まない根(着地済み・断念・cancel)の下では、知らせが行だけになる。
- **子を登録する扉が、食い違う祖先の下を拒む** —— 扉は git を読まないので、保護ブランチから分かれて自分で根になる正しい場合まで拒む。
- **登録に世代を持たせ、task を登録に結び付ける** —— 登録には db に書く瞬間が無く(行は最初の撮りで作られ、手で足した名前も
  受け入れる、ADR 0373 決定13)、同じ repo の登録し直しで着地を続ける決定(ADR 0370 決定1)を止める。出元 repo の差し替えは同じ登録の
  中で起きるので、値の記録と比較は残る。
- **task ごとの記録をやめ、根だけが覚える** —— 自分で根になる task と、publish を挟んだ purely-local の記録は、根の記録から導けない。

## 帰結

- #3804 は決定1・3・4 に畳む。pickup 側の2回目以降の比較は、削除の扉の await の窓(#3372 / #3322)と手編集の下の床として残る。
- ADR 0399・ADR 0394・ADR 0395 に Status 追記を置いた。
- #3886(名前の場所に無いタスクブランチの読み方)を先に決める。決定5 は分かれる元を知る必要があり、ブランチが無いときに何を
  分かれる元と読むかは #3886 の決定である。失われたものと読むなら、子は保護ブランチから分かれて止まらず、根は収束の候補から外れる。
  出元 repo から取り戻すなら、取りに行く前に決定5 の比較が要る。登録の扉が運ぶなら、決定7 が守る状態を扉が作る。決まるまで、別の
  repo へ新しい path で登録し直した名前では、子の pickup が素の git エラーで workspace の Quarantine になる形が残る(実測)。
- 限界: 門を通った後の await の間の登録し直しは、決定2 の所が受ける。purely-local の記録はどの宣言とも一致するので、hold した local の
  根から分かれる子は決定5 で止まらない(ADR 0399 の限界と同じ線)。誤った登録し直しを戻すには、その名前の未決着の task と question をすべて決着させる必要がある —— 削除の扉が拒むので、
  決定5 で止まった子は cancel し、食い違いの question が立った PR の根は着地を終える(受ける回答はそれだけである。ADR 0399 の挙動、#3888)。
  task の issue を番号だけで持ち今の宣言で引く読み(#3885)と、記録する前の PR を持つ根に断念が出る疑い(#3887)も外に残る。
