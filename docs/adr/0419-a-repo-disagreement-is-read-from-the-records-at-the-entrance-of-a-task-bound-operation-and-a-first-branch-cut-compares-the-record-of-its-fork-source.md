# repo の食い違いは task に紐づく操作の入口で記録から読み、ブランチを初めて切る task は分かれる元の記録と比べる

2026-11-25 の grilling(issue #3849、族に #3699 / #3700 / #3804)で決定。ADR 0399 の比較は、行き先を読む所が投げる例外として実装され、
比較を付けるのは操作を組む各呼び手、止まりの種類を決めるのは例外が通り抜ける各 catch だった。同じ形の写し漏れが3件続いた(#3699・
#3700・#3804)。数えると、扉を通って届く穴はその写しの外にあった。削除の扉は未決着の task があれば拒むので、タスクブランチを持つ
task の再 pickup は登録し直しの後に起きない。起きるのは、生き残った根の着地と、その根の下に後から足された子の初回の pickup である。
子は自分の記録を持たないので比べず、旧い repo の内容から分かれて新しい repo を記録するか、素の git エラーで workspace の Quarantine に
なる(本物の扉で実測)。出元 repo の差し替えは削除を通らず、子が走っている最中にも根の記録を食い違わせる。着地では、型を落とす
catch が PR のある根に断念を出す。読み手の表・実測・`file:line` は #3849 に置く。

## 決定

1. **食い違いの止まりは、task に紐づく操作の入口の門が、記録と今の宣言から読んで立てる。** 門は1つの読みで、食い違えば操作を
   始めない。止まりの器は ADR 0399 決定5 のまま(pickup は task の失敗の question、根は PR 昇格失敗の question)。入口で止まれば、
   途中の catch が何を握っても記録は変わらない。
2. **操作の途中の例外は、中断にだけ使う。** 行き先を読むたびの比較(ADR 0399 決定3 / ADR 0378 決定7)は残り、網に出ない保証は今どおり
   そこが持つ。例外の種類を見るのは、食い違いを別の記録にする口だけである —— 捕まえた失敗から workspace の Quarantine を立てる口、
   PR 昇格失敗の question を立てる口、読まずに hold を受ける回答(ADR 0394 決定5)、issue 展開の失敗の数え。それ以外の catch は
   選り分けない。出元 repo の差し替えは操作の途中にも起きるので、この口は床でなく本線である。
3. **門は、task の作業を始める所と内容を外へ運ぶ所の場所を作る唯一の口である。** pickup、人間担当の work の扉、収束、PR を扱う
   tick、merge question の回答がそれで、途中の比較を持つ場所は門の戻り値としてだけ得られる。解放、失敗時の token の確かめ、issue
   展開の確かめ直し、面接の root の読む場所は通さない —— 解放は走り終えた作業の合流で拒む理由が無く、残りは task の内容を運ばない。
   「この根の着地を終える」と断念は出口なので通さない。
4. **人間の前の扉は、食い違いを拒否で返し、task に何も書かない。** 人間担当の work の扉と merge question の回答がそれである。
   question は人間に届ける器で、扉の前には操作した本人がいる。
5. **ブランチを初めて切る task は、分かれる元の task の宣言の repo の記録も今の宣言と比べ、食い違えばその task を止める。** 比べる
   のは pickup と `start_work` が共有するブランチを切る所(ADR 0414 決定9 の、書く前に確かめる拒否)で、止まりは ADR 0399 決定5 の
   まま、宣言を戻して retry すれば再開する。分かれる元のブランチが名前の場所に無いか読めないときも、git のエラーより先に止める。
   新しい repo が同じ履歴を持ち、子が保護ブランチから分かれるときは止めない。比べるのは宣言の repo の記録だけで、出元 repo の記録は
   根の着地が比べる。ADR 0399 決定3 の「2回目以降の pickup」に、初回のこの比較を足す。
6. **収束の門は、「何もしない」で返る出口の後、ref の比較と完了の門の前に置く。** 出口は、回答済み、開いた昇格失敗の question、
   断念、hold から変わっていない、の4つである。断念は ADR 0399 決定5 の出口なので、その後に問い直さない。workspace の Quarantine が
   開いている間は、今どおり収束は question を立てない(ADR 0241 決定6)。
7. **出元 repo の設定がタスクブランチを送るとき、宣言の repo の記録が今の宣言と食い違う task の分は送らない。** task はブランチの
   名前から引く。出元 repo の差し替えでは今どおりすべて送る(ADR 0395 決定3)。

## 退けた形

- **比較の付与を型で必須にするだけ** —— 子の初回の pickup には比べる記録が無い。
- **Quarantine から外す判断を、Quarantine を立てる口1つにまとめるだけ** —— 食い違いを別の記録にする口は Quarantine の前だけではない。
- **例外の種類を見る所をすべて述語に置き換える** —— 述語が真で、捕まえた失敗が無関係なとき、どちらの止まりを書くかが箇所ごとに要る。
  入口で読めば操作が始まらず、この場合が起きない。
- **食い違った根を、子を塞ぐ根の3つ目の種類にする**(この grilling の最初の案)—— 既存の塞ぎは直接 cancel の範囲・行の形(PR 番号)・
  告知・一覧の読みと結び付いている。戻せる塞ぎを直接 cancel の範囲に入れると完了時レビューを外して着地でき、外すと子に出口が無い。
  出元 repo の差し替えでは、走っている子まで塞ぐ。収束が読まない根(着地済み・断念・cancel)の下では、知らせが行だけになる。
- **登録に世代を持たせ、task を登録に結び付ける** —— 登録には db に書く瞬間が無く(行は最初の撮りで作られ、手で足した名前も
  受け入れる、ADR 0373 決定13)、同じ repo の登録し直しで着地を続ける決定(ADR 0370 決定1)を止める。出元 repo の差し替えは同じ登録の
  中で起きるので、値の記録と比較は残る。
- **task ごとの記録をやめ、根だけが覚える** —— 自分で根になる task と、publish を挟んだ purely-local の記録は、根の記録から導けない。

## 帰結

- #3804 は決定1・3・4 に畳む。pickup 側の2回目以降の比較は、削除の扉の await の窓(#3372 / #3322)と手編集の下の床として残る。
- ADR 0399 に Status 追記を置いた。
- 限界: 門を通った後の await の間の登録し直しは、決定2 の口が受ける。同じ repo のまま新しい path で登録し直すと、食い違いは無いのに
  タスクブランチが名前の場所に無く、根の着地と子の pickup が git のエラーで止まる —— この決定の外で、#3886 が持つ。task の
  issue を番号だけで持ち今の宣言で引く読み(#3885)と、記録する前の PR を持つ根に断念が出る疑い(#3887)も外に残る。
