# meta-review は4種別と枝ごとを直接移せるが scope は広げる向きだけで、定義の path は枝ごとの移動でだけ変わる

2026-09-30 の triage / grilling(issue #1039)で決定。ADR 0162 が人間の面に4種別と枝ごとの移動を作ったが、meta-review の
`move_memory` は Knowledge 1件のまま(ADR 0122 決定1)で、構造検査が置き場違いを見ても実行する verb が無かった。加えて
今の `move_memory` は scope の向きを問わず、覆いの門(ADR 0161 決定6)が直接には拒む畳みを「移してから畳む」の2手で通せた。
コードの調査・文面・反転するテストは #1039 のコメントに置く。

## 決定

1. **同じ scope の中の移動は、4種別の approved / candidate すべてを meta-review が直接移せる。** 単位はエントリ1件
   (`move_memory`)と枝ごと(`move_memory_branch`)。ADR 0122 決定1 と ADR 0161 決定2 の「`move_memory` は変えない」を改める。
2. **scope を跨ぐ直接の移動は、盤面全体へ広げる向きだけ。** 移す前に見えていた読み手は移した後も見える。workspace 間の
   置き直しと狭める移動は人間の操作に残り、今通っている Knowledge のそれも閉じる。
3. **approved の Behavior / Exemplar の scope は、向きを問わず直接には変えない。** candidate は決定2 のまま移せる。
4. **open な提案 question が名指すエントリは、meta-review は scope を跨いで移せない。** 名指す = candidate・replaces・既存の
   後継・invalidate の target。同じ scope の中の移動は通る(ADR 0162 決定6)。
5. **scope を跨ぐ枝ごとの移動は、決定3・4 で移せないエントリが配下に1件でもあれば全体を拒む。**
6. **別 path の定義を置き換えられるのは、書く先の同じ scope・path に既に定義があるとき(枝の統合)だけ。** 定義の無い path
   への付け替え(枝の改名)は枝ごとの移動が持つ。ADR 0161 決定2 の「path は問わない」を改め、人間の面にも掛ける。
7. **Definition の path を変えるのは枝ごとの移動だけ。** 1件の移動が Definition で変えられるのは scope だけ。ADR 0162 決定4 の
   「エントリ1件は4種別すべて」を改め、人間の面にも掛ける。
8. **直接できない移動を人間に渡す提案 op は作らない。** meta-review はその判断を `log_decision` に書いて置き場は動かさない。
   op を作るかは、その記録を見てから(issue #1186)。

## なぜ同じ scope の中は承認済みの Behavior も直接か

届く相手を決めるのは scope と宛先だけで、path は INDEX 上の位置にしか効かない。本文は盤面が写し、承認は本文に属する
(ADR 0162 決定5)ので、承認の線にも覆いの門にも触れない。

## なぜ scope は広げる向きだけか

ある読み手の視界から消すかどうかは、ADR 0161 追記6・7 が人間に残した判断と同じもの。届けたい読み手に届けるだけなら
広げれば足りる。移動にだけ門が無いと、畳みの門は2手で迂回できる。

## なぜ approved の Behavior / Exemplar は広げる向きも閉じるのか

Behavior は届いた worker の判断を左右する。広げると、承認 question で人間が見た scope の外の worker に人間の目なしで届く。
scope は宛先と並んで届く相手を決める欄で、宛先の変更は既に移動ではなく編集として人間の側にある。決定4 も同じ理由 ——
question の detail は提案時点の scope を写した文で、pin は `path_moved` をたどって複製に適用される。

## なぜ決定6・7 は人間にも掛けるのか

覆いの門を meta-review だけに掛けたのは、狭めるかどうかが人間に残す判断だから。定義だけが別 path へ替わって配下の leaf が
旧 path に残る割れは、判断ではなくストアの状態で、誰が書いても同じに残る。人間にも代わりの手(枝ごとの移動)があり、
失うのは leaf の無い枝を文言ごと改名するのが1手から2手になる分だけ。ADR 0161 が「同じ path に限る」を退けた理由は
「文言を直しながらの改名が2手になる」だったが、当時は枝ごとの移動が無かった。

## 退けた案

- **移動に向きの門を掛けない** —— 元の読み手から消える移動が人間の目なしに通り、畳みの門の迂回が残る。
- **`define_memory` の `supersedes` を同じ path に限る** —— 新しい文言での統合が1手で書けなくなり、`fold_memory` の
  既にある後継への畳みは path を跨げるままなので規則が揃わない。
- **scope を跨ぐ枝ごとの移動は移せるものだけ移す** —— 枝ごとの移動が自分で枝を割る。
- **`move_memory` 1本に1件と枝ごとを持たせる** —— 必須引数も返り値も違い、「どちらか一方」の検査を verb が抱える。
- **枝の統合の途中の割れ(定義を畳んでから配下を移すまで)をここで消す** —— 枝ごとの移動の拒否規則(ADR 0162 決定4)を
  変える別の主題で、決まれば決定6 を導き直す(issue #1185)。
