# assignee 未指定は既定 agent への参照であり、「割当待ち」状態は作らない

タスク登録時の assignee は任意とし、未指定は「その時の盤面の既定 agent への参照」として pickup の瞬間に解決する(ADR 0009 の per-use 解決と同じ規約 — 値を焼き込まない)。「assignee が付くまで slot に入らない」という割当待ちゲートは採らない。既定 agent は registry の普通のエージェントを指す盤面設定であり(v1 では `TIDEPOOL_AGENT`、既定 workspace と同型)、特別なエージェントカテゴリではない。

理由:

1. **割当待ちは第3の停止状態になる。** blocked(下から)と held(上から)はどちらも木構造から導出され、解除への道(子の決着、question への回答)が構造に埋め込まれている。割当待ちの解除は「人間がいつか気づいて assign する」しかなく、登録時に決めなかっただけで偶発的に生まれる放置状態になる — 純手動解除が許されるのは明示的な意思(Pause)だけ、という既存の線に反する。
2. **assign-later 操作の抜け道を塞ぐ。** 割当待ちを採ると後から assign する操作が必須になり、それをエージェントに開くと decompose 時の assignable_to 検査を空欄で素通りして後から委譲先を広げられる(検査の再実行が必要になる)。参照方式なら未指定は権限を何も広げず、この穴自体が生じない。
3. **v1 は worker が1人。** 待った末の選択肢が1つしかなく、待つこと自体に意味がない。

Considered options:

- **未指定 = 未割当ゲート(assign されるまで pickup しない)** — 上記 1・2 で却下。assignee は実行に「絶対に必要」に見えるが、必要なのは pickup の瞬間であり、登録の瞬間ではない。
- **registry のエージェント側に `default: true` の印を置く** — 2つのエージェントが名乗る/誰も名乗らない、という不整合が表現可能になる。盤面設定(ポインタ1本)なら一意性が構造的に保証される。

スコープ注記: v1 の pickup は設定済みの単一 worker の id を assignee に刻む(未指定の解決はこの既存挙動と一致する)。複数 worker 時代に「事前割当された assignee を pickup が尊重するか」は本 ADR の範囲外で、その時の決定。
