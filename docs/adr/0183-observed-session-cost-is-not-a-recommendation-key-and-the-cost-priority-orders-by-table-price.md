# 観測された session 費用は学習器の推薦の鍵にせず、`cost` の鍵は表の価格である

2026-10-01 の triage / grilling(issue #1250)で決定。学習器は #548 の実装から、`cost` の task で事後平均が同点のとき、観測された
session 費用の平均が小さい候補を前に並べていた。この並べ方が先頭との比較にも使われるので、同点の安い候補が表の先頭に勝つ ——
ADR 0181 決定3 の「同点のときは表の並びのままで、直すのは人間である」と食い違う。根拠にできたのは ADR 0114 決定4 の一文
「本当の費用は学習器の session 合計が持つ」だけで、費用で先頭を離れる規則を決めた ADR は無い。さらに ADR 0182 決定4 の却下数の
枝は費用を読まないので、両者が無傷のあいだ推薦は pickup ごとに入れ替わっていた。実測は #1250 のコメントに置く。

## 決定

1. **観測された session 費用は推薦の鍵にしない。** 学習器の同点は、優先順位が何であっても selector の並びのままである。session
   費用の平均は task の大きさに左右され、ティアの中でも task の規模は揃っていない —— 少数の観測では行の差より割り当ての偏りを
   映す。受理率には帰責で環境要因を除く機構(ADR 0115 決定5)があるが、費用にはこれを均す機構が無い。その数字で、人間の置いた
   並びを覆さない。
2. **`cost` の鍵は表の価格である。** `cost` の task では selector の並びが既に価格順(ADR 0114 決定4)なので、同点なら表の価格が
   安い行が走る。「実際の session が安い順」ではない —— 単価が安くトークンを多く使う行は先頭のまま走る。価格は事実なので
   書き換えて直すものではなく、人間が応じる手段は行の出し入れと Provider 順位である。
3. **session ごとの費用と所要時間は観測として持ち続ける。** 読むのは routing meta-review の shadow 行の読み口で、セルごとの
   平均は読み手がいなくなるので持たない。表の価格と実費用が逆転している行の組が実際にあるかは、まだ誰も見ていない(#1252)。

## 退けた案

- **同点の安い候補へ先頭を離れる(今の実装を規則にする)** —— `cost` の趣旨には最も忠実だが、決定1 の偏った数字で先頭を離れる。
  入れ替わりを止めるには却下数の枝にも費用を通す規則が要る。
- **先頭は離れず、先頭に勝った候補どうしの並べ方にだけ残す** —— 効くのは、先頭に厳密に勝って互いに同点の、費用を報告する候補が
  2つ以上あるときだけで、同じティアに費用を報告する行が3つ要る。届かない鍵が残り、届いたときも同じ偏りで並べる。
- **行ごとの session 費用の平均を routing meta-review の材料に足す** —— 逆転が観測されていない今は読み手のいない材料で、
  task の規模の偏りを meta-review に渡すだけになる。
