# 閉じた memory 提案は再提案で戻り、過去の提案の一覧は pin した本文の今の居場所を添える

2026-10-09 の grilling(issue #1182)で決定。過去の提案の一覧(`list_memory_proposals` と meta-review の材料の節)は、焼いた pin の
id をそのまま返していた。pin した記憶が移動(`path_moved`)や復元で別の id になると、meta-review は tool description の指示どおり
その id で再提案して拒まれ、拒否もどこへ行けばよいかを言わなかった。triage の実測と仕様は #1182 のコメントに置く。

## 決定

1. **陳腐化や回答で閉じた提案 question は、pin した記憶が後で復元されても開き直さない。戻すのは次の meta-review の再提案である。**
   閉じた時点で question は終端になり、決着は event として記録されている(ADR 0163 決定3 の「旧の行は触らない、追記のみ」と同じ線)。
   閉じた後には他の前提(統合の replaces の版など)も変わりうるので、出し直すかはその周期の meta-review が判断する。
2. **過去の提案の一覧は、pin した記憶ごとに本文の今の居場所(本文が同じ鎖の末尾の id・path・scope)と、その末尾が生きているかを
   添える。** 鎖は `path_moved` と復元の複製の両方をたどる —— `read_memory_entries` と同じ範囲(ADR 0167 / ADR 0122 追記 #1225)。
   決定1 の再提案が届くには、復元された複製まで見えなければならない。末尾が再び落ちていれば再提案は通らないので、生死も一覧で分かるようにする。
3. **この注釈は人間の面の `moved` と別の鍵に置く。** `moved` は開いている question の pin が照合で今どこに解決するかで、
   `path_moved` だけをたどる(ADR 0162 決定6)。開いている question の pin は、移動以外で無効化されればその場で閉じるので、
   復元の鎖とは交わらない。2つは意味が違うので、同じ鍵に載せない。
4. **焼いた pin は書き換えず、一覧の pull と材料の節が seen に数える id は、名指す entry の鎖の末尾にする。**
   旧 id を数えても、後から照合する先が無い。数える範囲は名指す entry のままで、replaces には広げない。
5. **書き口は、無効化済みの id を拒むときに本文の今の居場所を名指す。** 一覧と同じ鎖をたどり、末尾も落ちていればその理由を添える。

## 退けた案

- **tool description で `read_memory_entries` を経由させる**: meta-review は毎回1手余計にかかる。同じ記録の読み方も、
  人間の面と meta-review で2通りに分かれたままになる。
- **`propose_memory_change` の入力の id を鎖でたどって解決する**: 書き口が、無効化された id を黙って受けるようになる。
- **`path_moved` だけをたどる**: 決定1 の戻り方が、復元された記憶に届かない。
- **復元の操作で、盤面が提案 question を立て直す**: 決定1。
