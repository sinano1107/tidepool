# 回答者の名義になるのは回答の選択肢が名指す行為だけで、回答の後に盤面の規則が決めた行為は盤面の名義である

2026-11-22 の grilling(issue #3507、#3461 を畳む)で決定。収束が刻む `pr_opened` の actor は根の assignee だった。これは、
worker の完了が PR を開いていた頃の値が #516 の移設で運ばれてきた写しである。調べると、人間の回答から起きる着地の event
の名義は、ADR 0196 の線(行為者 = 判断の主。merge の回答の `pr_merged` は human)と ADR 0225 決定1 の線(判断は回答の行が
運び、断った内容は盤面名義の event)のどちらを当てるかが決まっておらず、1回の `retry` の回答の中で取り込み・push・PR を
開くことの名義が割れていた。書き手の一覧は #3507 に置く。

## 決定

1. **人間の回答から起きる行為のうち、回答者の名義になるのは、回答の選択肢が名指す行為だけである。** `merge` の回答による
   merge、hold・abandon による断り、作業台の取り込み(ADR 0371 決定2 —— 取り込みの入口は今ある回答)がそれにあたる。
   回答の後に盤面の規則が決めた行為は、盤面の名義である(ADR 0196 決定2)。`retry` が名指すのは昇格の規則をもう一度走らせる
   ことで、PR を開くか、何も無いか、失敗するかは規則が決める。`merge` の回答の中で PR のブランチへ追いつきを push する
   ことも、要るかどうかを規則が決めるので盤面の名義である。
2. **収束が PR を開いて刻む `pr_opened` は、根の種類と経路によらず盤面の名義である。** 完了した主体は、agent でも人間でも
   PR を開くことについて何も判断していない。PR を開くかどうかといつ開くかは、門・quarantine・profile の読みを通って収束の
   規則が決める。人間の根の actor `human`(spec #3273 の [spec])はこれで改める。人間が完了したことは、根の
   `task_completed` が既に記録している。
3. **hold・abandon の回答の `landing_declined` は回答者の名義にする。** ADR 0225 決定1 の「盤面名義の event」を改める。断った
   内容は payload が運ぶ事実で、名義で事実と判断を分ける必要は無い。決定1 の線の外に置いて説明で残すと、同じ回答の行の中で
   merge は human、hold は盤面という割れ目が残る。
4. **PR を開く書き手は名義を引数で受け取らない。** 名義を呼び手が渡す形だと、呼び出しが移ったときにその値ごと運ばれる。
   #516 で起きたのがこれである。

## Considered options

- **ADR 0196 で統一(回答が無ければ起きなかった行為はすべて回答者)**: `retry` の後に規則が PR を開くことまで回答者に
  帰属させることになる。回答者はその結果を選んでいない。
- **ADR 0225 で統一(event はすべて盤面名義、判断は回答の行だけ)**: ADR 0196 決定1 の merge の回答の `pr_merged` を覆す
  ことになり、行為者の欄が判断の帰属を運ばなくなる。
- **収束が名義を1か所で決めて各書き手に渡す**: 決定1 の線では、収束の規則が書く event はいつも盤面になる。渡す引数を
  残すと、決定4 で述べた写しの経路も残る。
