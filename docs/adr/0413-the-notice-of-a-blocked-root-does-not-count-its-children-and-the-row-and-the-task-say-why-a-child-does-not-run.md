# 塞ぐ根の告知は子を数えない —— どの子がなぜ走らないかは、行と子の詳細が毎回導いて言う

2026-11-24 の grilling(issue #3703、#3689 の grilling の見直しの派生。#3664 を畳む)で決定。ADR 0265 決定6 の告知(盤面名義の判断行)は、閉じた観測を根に刻む瞬間に「閉じた根に塞がれた子」を1回だけ数え、id を並べていた。塞がれた子の集合は git を読んで導くもので、時間とともに変わる。1回の写しは3つの形でずれた —— 読みが失敗した子は数えられず(述語は読めなければ「塞がれていない」と返す、#3703)、観測の時点で走っていた子とその後に生まれる子は入らず、人間が着地を終えた根(ADR 0399 決定6)は同じ述語で子を塞ぐのに告知が無い(#3664)。同じ集合は、一覧の読み口が行ごとに毎回導き直している(`blocking_root`)が、画面はそれを描いていなかった。読み手の表と経路の読みは #3703 に置く。

## 決定

1. **告知は知らせで、子の集合を持たない。** 判断行は子の id も件数も言わず、git を読まない。書く条件は、根の下に終わっていない子(question を除く、走っているものを含む)が1件でもあること。文は「この根のブランチへ帰る子は、根の内容が保護ブランチに届くまで走らない。キューが skipped で示す」と出口を言う。ADR 0265 決定6 の「閉じた PR と走らない子を言う」を置き換える。判断行は人間に押し出す唯一の器(判断ログ・push・朝の triage)なので残す。
2. **人間が着地を終えた根にも同じ告知を書く。** 回答の transaction の中で、盤面名義で書く(ADR 0405 決定2)。出口は cancel だけを言う —— この根は内容に依らず塞ぐ場合があり(ブランチが名前の場所に無い)、PR の merge が宣言の保護ブランチに届くとも限らないので、「merge すれば走る」は約束しない。
3. **どの子がなぜ走らないかは、導き直す側が言う。** キューの行は固定長の原因を出し、子の詳細は塞ぐ根・PR・出口を出す。そのために行の理由は塞ぎの種類(盤面の外で閉じた PR / 人間が終えた着地)を持ち、task 単体の読み口も同じ理由を返す。資源単位の停止と重なる行でも、塞ぐ根の理由は出す —— 資源を直してもその子は走らない。
4. **行の理由を足すのは塞ぐ根だけ。** ADR 0102 決定1(資源単位の原因は痛みの観測まで足さない)は動かさない。その根拠は「quarantine には修理 question がある」で、塞ぐ根には question が無く、行と詳細が唯一の説明の面になる。形は ADR 0102 決定5・9 に揃える(文言は画面が持つ、可変長のものを行に出さない)。決定6(`skipped` と原因を同じ SQL の式から出す)には揃えない —— この原因は git を読むので SQL の外で当てる。
5. **述語は読めなければ「塞がれていない」と返すまま。** 1回きりの読み手がいなくなり、残る読み手(pickup・一覧・直接 cancel の範囲)は毎回読み直す。pickup は自分の経路で同じ失敗を見せる。

## 退けた形

- **告知をやめ、行と詳細だけにする** —— 行は見に行かないと分からない。PR を外で閉じた人間が、下に走らない子がいると知らされる機会が無くなる。
- **告知の読みが失敗したら投げて、観測ごと巻き戻す** —— 読みの失敗しか閉じない。告知のための読みが、本来の事実である観測を止める。
- **pickup が子を最初に飛ばしたときに、子ごとに書く** —— 3つとも閉じるが、poll の経路に書き込みが増え、子の数だけ push が鳴る。

## 残る穴

観測の時点で終わっていない子が無く、後から根の下に子が足された場合、告知は出ない。その子の行と詳細は理由を言う。
