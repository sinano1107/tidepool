# 着地の根の失敗は必ず人間に届き、読めない資源はその資源の軸で1回だけ止まる

2026-11-23 の grilling(issue #3554、#3671 を畳んだ)で決定。収束は、失敗した根に昇格失敗 question を立てて人間に見せる。ところが
question に写す tip を読む所でもう一度落ちると、ログだけ出して終わっていた。無人の収束は verdict を捨て、`landing_state` も null なので、
人間には着地の印の無い「done」しか見えない。ADR 0229 決定1 がログだけを選べたのは、キューの行に印が残るからで、ここには当たらない。
黙る場面は2つある。registry が読めないとき(resolver が投げ、tip を読む所で再び投げる)と、checkout が読めないとき(ref 検査と tip の
読みが同じ原因で落ちる)である。同じ git の失敗でも、`landRoot` のどこで起きたかによって question になったりログだけになったりした。
実測・経路の表・`file:line` は #3554 のコメントに置く。

## 決定

1. **問いに写す tip の読みは1つで、読めなければ null を返し、question は必ず立てる。** 昇格失敗・断念の問い直し・merge question の3つが
   同じ読みを使う。workspace を解決できない、または git が落ちたときも null を返す。tip は人間に見せたものの記録なので(ADR 0394)、
   読めなければ特定の sha を見せていない。null の記録への断る回答は効かず、次の収束で問い直される。これは ADR 0225 決定1 /
   ADR 0234 決定3 の「無い・読めない → 変わった」のとおりである。
2. **`landRoot` の失敗の出口は1つにする。** 断念・hold の枝も同じ境界(→ 昇格失敗 question)の内側に入れる。失敗がどこへ届くかは、
   失敗の中身で決まり、`landRoot` の中で起きた位置では決まらない。
3. **根ごとの catch に落ちた想定外の例外でも、無人の回なら昇格失敗 question(tip は null)を立てる。** その根に開いた失敗 question が
   あれば立てない(開いた question がある根は撃たれないので、question は重ならない)。その根に答えている回答がある回でも立てない。
   回答は拒否文で失敗を知る。`failed()` が取り込み中に question を立てないのと同じ線である。
4. **着地の ref 検査が git の失敗で読めないときは、その workspace の Quarantine で止める。** 立てるのは ref 検査そのもの
   (`assertLandingRefs`)で、収束と2つの merge の tick が同じ止まりになる。pickup は同じ checkout の読み失敗を既に workspace の
   Quarantine にしており(ADR 0370 決定1 の「比較が落ちた根は workspace の Quarantine で止まる」)、根ごとに止める扱いは実装の選択
   だった(#3168)。一過性の失敗でも人間の回答を待つ代償は、pickup と同じく受け入れる。
5. **registry が読めないときは、盤面全体の registry の Quarantine で1回止める。**
   - 旧 `registryReachability`(ADR 0052)を広げ、kind を `registryUnreadable` に改める。判定は「正本に到達できるか(remote があれば)」に
     「読み込みと検査が通るか」を足す。registry を持つ盤面すべてに置く。
   - 開いている間、pickup と収束は撃たない。どちらもどのみち registry を読めない。決着は今どおり回答の受理だけで、受理の検査は読み直し
     そのものである。
   - **立てるのは registry の読み込みの1点で、呼び手は何もしない。** 盤面の registry を読む関数が、読めなければ自分で止まりを立てて
     から投げる。人間の同期の要求も同じ1点を通り、人間にはその場でエラーが返る。ADR 0009 が人間の要求を Quarantine にしない理由は、
     名前の drift の扱いで、ここには当たらない。
   - 重複を避ける判定は、各プロセスの出口の1箇所(収束の失敗の境界と poll の catch)だけに置く。どちらも「開いていれば、自分の失敗の
     question も計測も足さない」と読む。読み込みを迂回する呼び出しは lint で禁止する。
   - 止まりの記録は、読み込みを囲む transaction の rollback で消えないように確定させる。

## 退けた案

- **各経路の catch が registry の故障の型を見て止まりを立てる。** 経路ごとに乖離し、読み手が増えたときに付け忘れる。
- **registry の故障を ADR 0294 の poll 失敗の計測に数える。** todo の無い poll は成功に数えられて計測を消すので、done の根だけが
  待つ盤面では届かない。
- **資源の故障を根ごとの昇格失敗 question のままにする。** 資源1つの故障で根の数だけ question が並び、人間は同じ修理に根の数だけ答える。
