# 執行が書き込みより先に commit する回答は書き込み直前の同期区間で条件を読み直し、落ちた後始末の受理が証明するのは投げた step の再実行である

**Status 追記: 決定1 の「執行が書き込みより先に commit する回答」の例に、閉じ切らなかった session の受理(その session の記録からの閉じ直し)が加わり3例になる。決定2 の「投げた step の再実行」の読みも同じ([ADR 0344](0344-a-session-closing-write-that-throws-is-an-unclosed-session-halt-keyed-by-the-session-not-the-slot-and-boot-recovery-closes-a-session-that-has-a-later-spawn.md) 決定3、2026-11-01、issue #2876)。**

2026-11-01 の grilling(issue #2891、#2879 の派生)で決定。落ちた後始末の受理(ADR 0112 決定3)は memory の残りが空になった瞬間に返り、
回答の transaction はその後の同期区間で走る。`await` の再開までに並んだ microtask の中で後始末の step が投げると、開いている question に
`quarantine_refired` が積まれ残りが立ち、直後の transaction がその question を閉じる —— 枠と残りを握ったまま停止の列挙から消え、梯子が
空の容器に偽の Containment question を立てる。ADR 0288 決定2 は merge question だけを「印の前の読み直し」の対象にしたが、その理由
「執行が書き込みより先に済む」は落ちた後始末の再実行にも当たる。測定と形の表は #2891 のコメントに置く。

## 決定

1. **執行が書き込みより先に commit する回答は、書き込み直前の同期区間で条件を読み直し、重なりを拒む印もそこまで持つ。** merge question
   (ADR 0288 決定2)と落ちた後始末の受理がその2例で、決定2 の「印の前の読み直しが要るのは merge question だけ」は撤回する。検査の
   contract は非同期の検査と同期の確認の2つに分かれ、確認は回答の書き込みと同じ同期区間で `submitAnswer` が呼ぶ —— 条件は書き込みの
   1か所に置くという ADR 0288 決定1 の形のまま、資源を検証する quarantine 族は確認を持たない。
   印を再実行の終わりで放す形は、「`submitAnswer` が確認から書き込みまで await を持たない」という別 file の性質に守りを預ける ——
   今日はその区間に macrotask の境が無く2つ目の回答は入れない(読みのみ)が、守りは契約に持つ。確認は通っても拒んでも印を放す。
2. **落ちた後始末の受理が証明するのは、投げた step の再実行が回答を書く瞬間まで投げなかったことである。** ADR 0112 決定3 の「完走」は
   ADR 0342 決定6 の step の模型ではここまでで、回収済み観測を待って枠が空くまでは梯子の観測(ADR 0112 決定4)のまま。受理の後に別の
   step が投げれば新しい question が1枚立つ —— 記録は常に「question が開いている ⇔ 投げた step が未再実行」を保ち、積み上がらない。
   受理が自分の撃ち直した step の繋いだ鎖(回収済み観測の後の後始末)まで待つ形は採らない: 容器が空になるまで `reclaimed()` は
   解決せず、梯子の tick は開いている failedTeardown question で凍るので、互いに解けない。

## 退けた形

- **回答の transaction の中で残りを読む** —— 門が2か所になる(ADR 0288 が退けた形)。
- **受理が枠の解放まで待つ** —— 上の凍結。採るなら ADR 0112 決定4 の門を「容器が空のときだけ凍る」に変える問いが付く。
- **0288 決定2 の例外を1つ足す** —— 性質が同じものを例外として2つ並べるより、性質で1つの規則にする。
