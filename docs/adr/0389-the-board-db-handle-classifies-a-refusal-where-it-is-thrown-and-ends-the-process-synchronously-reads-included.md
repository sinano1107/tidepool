# 盤面 DB の拒否は投げた所(`openDb` の handle)で判定し、同期で process を終える —— 読みの拒否も入り、境界の catch の投げ直しは消す

2026-11-21 の grilling(issue #2868、#3383 を寄せた族の根)で決定。ADR 0342 は (A) の判定を**受ける側**に置いた —— 底(床と
`uncaughtException`)が分類し、底に届く前に例外を受けて続ける境界の catch には投げ直しを手写しで求めた(決定4)。手写しは
`src/` の 20 file に 90 箇所あり、写し漏れが #3383 と #2868 の読みの catch の列挙として出ている。一方、盤面 DB を開く所は
`openDb` の1つだけである。ADR 0342 が「記録を書く扉」を退けた根拠は `.run(` の呼び出しの数で、開く所で handle ごと包めるかは
測っていなかった。試作では包んだ handle が `run` と transaction の中の文の throw を受けられ、上乗せは文1回あたり数十 ns だった。
壊した器での実測(最初に当たるのは書きでなく読みの `CORRUPT` / `NOTADB`)と試作は #2868 のコメントに置く。

## 決定

1. **(A) は「盤面 DB が操作を拒む」こと** —— 署名は ADR 0342 決定1 の6つの code のままで、読みか書きかを問わない。読みの拒否も
   全箇所に当たり、人間が直すまで続き、失敗の記録も同じ器に書くので、決定1 の3つの性質はそのまま成り立つ。ADR 0342 決定1 の
   「書きを拒む」を置き換える。
2. **判定は `openDb` が返す handle が、投げた所でする。** handle の文の呼び出し(transaction と、statement を返す呼び出しの先も
   含む)と `openDb` 自身の初期化が投げた throw を判定し、(A) なら呼び出しの中で同期に1行を stderr へ書いて終える —— throw を
   返さないので、間の catch は1行も動かない。非同期の終了では exit までの間に飲む catch が空の値や 409 を返す。stderr の読み手が
   止まれば同期の書き込みも止まるが、書き込み完了を待つ今の非同期の終了と同じ止まり方である。
3. **他の口は消す。** 境界の catch の投げ直し、MCP / HTTP の終了口、床の (A) の枝、`uncaughtException` の受け手(残る振る舞いは
   Node の既定と同じ)を消す。床は ADR 0294 決定4 の「log して続ける」に戻る。同じ判定を2か所に残すと、どちらが正本かが
   再び写しの問題になる。ADR 0342 決定3・4 を置き換える。
4. **1行は task id を持たず、SQL の頭を持つ。** handle は呼び手の task を知らない。人間がこの1行でするのは器を直すことで、
   どの task の操作だったかは直し方を変えない。
5. **壊れた器では起動も拒む。** 起動の掃き出しの読みが (A) に当たるので、ADR 0342 決定2 の「`in_progress` 行の無い盤面は起動が
   通る」は `READONLY`(読みは通る)にだけ残る。自動再起動はどのホストの形にも無いので(ADR 0318 決定3)、繰り返しにはならない。
   決定2 の「直るまで動かないのが正しい」と同じ向きである。

## 退けた形

- **境界の catch の投げ直しを lint で強制する** —— 「書いたか」を検査するだけで、写す箇所は残る。ADR 0342 が lint の問いの
  反転条件に置いた「漏れの観測」は #3383 で来たが、lint より手前に、写す箇所そのものを無くす形がある。
- **site の注意のまま、漏れを点で直す** —— #3383 の brief の形。漏れのたびに issue になる。
- **読みの拒否を (A) の外に置く** —— 壊れた器で最初に当たるのは読みで、外に置くと、飲む catch が空の候補や 409 を返し続ける。
