# 記録に使う現在時刻は書く同期区間で clock から読み、Promise を返す関数は現在時刻を Date で受け取らない

2026-11-23 の triage → grilling(issue #3525、#1006 と #3523 を畳んだ)で決定。盤面には、現在時刻を一度読んで `Date` で
async 関数に渡し、その関数が GitHub・LLM・push の送信・検査の子プロセスを待った後に、その古い時刻で記録(Quarantine・event・
`board_calls` の行・通知済みの印)を書く形が、30箇所余り残っていた。記録の時刻は事実が確定した瞬間より古くなり、await の間に割り込んだ
他の書き込みと `created_at` の並びが逆転する。#3384 は一部を書く瞬間に読む形に直したが、規則は commit メッセージにしか残らず、
同じ形が書かれ続けた(#3289 → #3384 → #3524 → #3525)。着地の tick では、await を握って clock を進めても Quarantine の時刻が
tick を撃った時刻のままであることを実測した。箇所の一覧・実測・ガードの試作は #3525 のコメントに置く。

## 決定

1. **記録に使う現在時刻は、その記録を書く同期区間で clock から読む。** I/O の有無で線を引かない。#3524 は「本物の I/O の await が
   挟まり、他の書き込みが割り込めるときだけ」を害の条件にしたが、その線は await ごとに中身の判断を要し、型でもテストでも固定できない。
2. **1つの同期区間の中で書く複数の記録は、その区間で1回だけ読んだ時刻を共有してよい。** 書き込みごとに読み直すと、同じ区間の記録
   どうしで時刻がずれる。同じ区間の記録が同じ時刻を持つことを前提にする読み手もある(#546 より前の統合レビューの見分け)。
3. **Promise を返す関数(async の有無を問わない)は、現在時刻を `Date` で受け取らない。** `Clock` か `() => Date` を受け取るか、
   自分が持つ clock を読む。async を付けずに Promise を返す包みも、包んだ先の await の後で受け取った時刻を書ける。
4. **対象は現在時刻だけ。** 期限のような事実の時刻(CLI 認証の期限など)は `Date` のまま渡してよい。型だけでは事実の時刻と現在時刻を
   区別できないので、ガードの例外として「記録された事実の時刻で、現在時刻ではない」という理由付きで並べる。
5. **ガードは、TypeScript の型検査器を使う構造テストにする。** 対象は `src` で、拒むのは、(a) Promise を返す関数の、`Date`(または
   `Date` の欄を持つ object)に解決される引数と、(b) 現在時刻を読む呼び出し(`clock.now()` と `() => Date` の呼び出し)から作った値
   (`getTime()` / `toISOString()` で変換した値を含む)が、async 関数の中で await の後に参照されること(外側で作って捕捉した値を
   含む)。Biome の grit plugin は構文しか見ないので、interface から型が付く引数(着地の tick の `now`)を取りこぼし、
   `{ now(): Date }` の形を誤検出した。規則は機械的に止まるので CODING_STANDARDS.md には書かない。構造テストは振る舞いを assert
   しない静的な検査で、ADR 0107 決定1 の seam には数えない。
6. **注入した clock の既定に壁時計を置かない。** 記録の時刻を読む関数は clock を必須で受け取る(#3523)。ガードに壁時計の禁止は
   足さない —— `Date.now()` の残りは締切の計算で、記録ではない(`SystemClock` の構築の1点だけは下の追記でガードに足した)。
7. **`board_calls.created_at` は、応答を受けて行を書く瞬間の時刻とする。** 今まではリクエストの開始時刻で、1リクエストの複数行が
   同じ時刻を共有した(#688)。開始時刻を残すと決定1の例外になり、重なったリクエストの行が応答順に並ばない(#1006)。

## 帰結

- 振る舞いを固定するテストは、振る舞いが変わる2点だけにする。着地の tick が await の後に立てる Quarantine の時刻と、
  `board_calls.created_at` が応答後の時刻であることである。残りの箇所はガードが止める。
- 着地の tick が記録する「head を初めて読んだ時刻」も書く瞬間になる。CI 未報告の猶予の起点(ADR 0231 決定4)が、実際に読んだ時刻に揃う。
- ADR 0323 帰結の「`use` と `created_at` で寄せる」は、帰責の event と行の時刻が一致しなくなるので、近い時刻で寄せる。読み手は人間の
  triage だけである。
- Status 追記: ADR 0323 帰結。

## 退けた案

- **#3524 の線(本物の I/O の await のときだけ直す)** —— 決定1。
- **名前(`now` / `at`)で拾うガード** —— 別の名前で現在時刻を渡す形を取りこぼす。
- **壁時計を一律に禁止するガード** —— 締切の計算をすべて例外に並べることになる。決定6。
- **`board_calls.created_at` を開始時刻のまま例外にする** —— 決定7。
- **記録を書く口(event・Quarantine・`board_calls` の行など)が自分で clock を読み、時刻を引数で受け取らない** —— 古い時刻を構造的に
  渡せなくなるが、呼び手のテスト約1300箇所(テストファイルの約半分)と、`Date` を下へ渡す関数約260個を書き換え、事実の時刻を渡す
  別の口と、書き手が clock を得る経路が要る。増える守りは、ガードが取りこぼす形(object の欄やフィールドで持ち回す時刻と、await の後に呼ばれる同期の closure が捕捉した時刻)だけである。
  共有の口(`recordedAnswer` / `quarantineUnlessClear`)にだけ当てる形も、決定3 で同じ形になるので規則を2通りにするだけである。
  ガードが取りこぼす形で同じ欠陥がもう一度出たら、この案を検討し直す。

## 追記(2026-11-24 の triage、issue #3691)

決定6 の着地後、clock の既定が `loadRegistryOrStop` の既定引数に再発した(#3681)。必須の `clock` は optional な欄を型で止めるが、既定引数は
型で止まらない。ガードに「`src` で `SystemClock` を構築するのは composition root だけ」を足す。決定6 と「退けた案」が退けたのは
`Date.now()` を含む壁時計の一律の禁止で、これは構築の1点だけを見るので締切の計算に例外を並べない。`scripts/` で盤面を自分で組む
script は対象にしない。
