# watchdog kill の question は、root の exit が観測されていれば報告なき exit と同じものを逐語で添える

2026-10-02 の triage / grilling(issue #1297)で決定。ADR 0189 は「報告なき exit」(ADR 0145)の failure question に
worker の最後の発話を添えると決め、決定2 で「最後の発話」を exit の形を問わないもの —— 途中で殺された worker の
言葉も判断の材料 —— と定義した。それでも watchdog kill の question(梯子の底)には載らなかった。理由は、梯子に入った
session の exit を盤面が捨てていたという配線の事情だけである。時間制限で止められた worker が何に詰まっていたかは
transcript にしか残らず、transcript は WebUI から読めない。配線の調べと実装の範囲は #1297 のコメントに置く。

## 決定

1. **梯子の底の question は、報告なき exit と同じものを同じ順で添える** —— worker の最後の発話、CLI が報告した失敗の
   文、stderr 末尾(ADR 0189 決定4 の並び)。どれも転記であって盤面の断言ではなく、どの判定にも使わない(ADR 0188
   決定1 / ADR 0189 決定1)。exit code / signal は添えない —— 盤面が自分で送った停止の結果であり、worker について
   新しく言うことが無い。
2. **梯子に入った session の exit は、捨てずに watchdog のメモリに退避する。** 置き場は梯子の他の記録(停止・強制
   回収の送達時刻)と同じで、pickup が替われば消える。再起動は越えないが、再起動すれば梯子ごと再起動中断の経路に
   落ちるので、失うものは無い(ADR 0145 決定4 と同じ理由)。
3. **回収 timeout に落ちた question にも添える。** root は exit したが孫が残って容器が空にならなかった場合で、
   退避した exit があれば決定1 と同じものを載せる。
4. **添えるものが無いことは劣化として記録しない。** 回収済み観測に至った時点で root の exit は必ず先に観測されて
   いるので(順序の根拠は #1297 のコメント)、そこで何も載らないのは3つとも空だったという事実である。回収 timeout
   で exit が無いのは、root がまだ生きているという既存の文面どおりである。

## 退けた案

- **question を立てる時点で、今の pickup の `worker_exited` を DB から読む** —— その pickup の exit かどうかを
  照合する読みが新たに要る。メモリなら pickup の切り替わりで消すだけで済む。
- **最後の発話だけを添える** —— 同じ exit なのに、報告なき exit と載るものが食い違う。揃えて壊れるものが無い。
- **「exit が観測されなかった」と書く** —— 今の機構では起きない事象の文面になる(決定4)。
