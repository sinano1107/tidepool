# 「失われた ref を諦めて基準へ戻す」は失われたタスクブランチの後始末も持つ —— git の成果が実際に失われた task は「成果が捨てられた」に数え、その根の着地はそこで終わる

**Status 追記: 決定3・5 は ADR 0380 が置き換えた —— 失われた側の「成果が捨てられた」は `parent_id` の祖先でなく task 自身の系譜で読み、失われた task は記録で「透明」(作成時から動いていない、または内容が着地済み)か「死んだ」と読む。「根なら PR を開いていない」の条件は消え、盤面は数える前に origin から失われた sha を取りに行く。決定4 が倒すのは `parent_id` の子孫でなく数えられた task の付帯子で、決定5 の「飛ばす」は死んだ祖先を数える task だけに当たる。決定7 の「編集があった根」は「死んだ根」と読む。帰結の「問われていない」の最初の2件は決まった([ADR 0380](0380-a-lost-task-branch-is-read-through-the-lineage-as-transparent-or-dead-the-board-fetches-the-lost-sha-from-origin-before-counting-and-the-cancel-term-stays-on-the-tree.md) 決定1〜5、2026-11-15、issue #3178)。**

2026-11-15 の wayfinder(map #3178、ticket #3249)で決定。ADR 0373 決定5 は、戻す先の object が無い ref を名指しの選択肢で基準に入れる道を
決め、失われた `task/<id>` を持つ task の後始末を別の ADR に送った。後始末が無いと、ブランチを失った着地待ちの根は着地の question の
`merge` が git の生のエラーを返し続け、通る回答は `hold` だけになる(#3242 の実測)。以下はコードの読みである —— `hold` の後も昇格失敗の
question が立ち直り続け、ブランチの無い task に付いたレビューと修理子は保護ブランチから切られて、失われた成果を持たない tree の上で走り、
親のブランチが失われて子のブランチが残っていれば、受理そのものが生のエラーで落ちる見込みである。この ADR は、その選択肢が task に何を
残し、何を倒し、どの着地を終わらせるかを決める。選択肢の側(何を基準に入れるか、保護ブランチの明示の検査、path の差し替えも通す理由)は
ADR 0373 決定5、`task_branch_created` と系譜の規則は ADR 0372 が持つ。実測・読んだコード・
`file:line` は ticket に置く(#3249。今の挙動の実測は #3242)。決定はコードと ADR の読みで、この形の盤面は走らせていない —— remote-backed は
読んでも測ってもおらず、「object が在る ref は復元される」は ADR 0373 決定5 の文と git の性質からの導出である。

以下、「失われた event」は決定1 の event、「根」は完了したときの帰り先が保護ブランチになる `done` の work を指す。

## 決定

1. **「失われた ref を諦めて基準へ戻す」は、失われた `task/<id>` ごとに、その task へ「ブランチが失われた」event を失われた sha つきで
   残す。** task の status は問わない。event が言うのはブランチが失われたことだけで、merge back が届いていたかは言わない。question や通知は
   task ごとに立てない(workspace の event `lost_refs_accepted` と、この event が知らせの全部である)。この選択肢が諦めるのは戻す先の object が
   無い ref だけなので、event を持つのは tip の object が repo に無い task に限られる —— merge back が届いていた子(tip は親の merge commit の
   親として残る)と着地済みの根は、親や保護ブランチが残っていれば書き戻されて event を持たない。
2. **`task_branch_created` は作成時の sha を運び、失われた event は、その後に `task_branch_created` が無い間だけ効く。** 比べる作成時の sha は、
   失われた event の直前の `task_branch_created` のものである。hold と断念の記録が「その後に着地の記録が無ければ効く」のと同じ形にする。未決着の
   task がブランチを失い、次の pickup が作り直して後で `done` になれば、作り直した後の成果は捨てられたに数えない。作成時の sha を持たない
   ブランチ(この event の実装の前に作られたもの)は「編集があった」側に倒し、移行は書かない。
3. **「成果が捨てられた」(ADR 0271 決定1)の判定に条件を1つ足す —— git の成果が実際に失われた task。** `done` の work で、効いている失われた
   event を持ち、失われた sha が作成時の sha と違い、根なら PR を開いていないもの。task 自身か、root までの祖先のどれかがこれに当たれば
   捨てられたに数える(cancelled の祖先と同じ線で、git は読まない)。event を持つだけで一律には数えない —— ブランチが無くても成果が生きている
   task がある(handoff だけで編集の無い task、内容が GitHub の head に在る根)。外れる task は event が残るだけで、レビューも修理も今どおり。
4. **数えられた task には ADR 0271 決定2・3 をそのまま当てる。** その task と子孫に付いた未決着の完了時レビュー・人間登録の review 子・work の
   修理子を倒し、RCA と、記憶・routing の修理子は残す(同 追記、ADR 0272 決定1、ADR 0279 決定4)。以後その下に宛先がブランチに依存する task は立たない。
   根かどうかでは分けない —— 倒す理由は「レビューする対象のブランチが無い」で、親に届いていた成果は親の統合点のレビューが親のブランチ越しに
   見る。倒さないと、失われた成果を持たない tree を読むレビューと、それを直す修理子が起動する。
5. **失われた祖先を帰り先にする task は、merge back の数え直しも系譜の読みも飛ばす。** 子のブランチが残っていても帰り先が無いので運べない
   (ADR 0271 決定1 が cancelled の祖先について言う「帰り先は確実に死んでいる」と同じ形)。git の生のエラーにはしない。
6. **親のブランチが残り、子のブランチだけが失われた場合、親の着地は止めない。** このとき失われたと数えられる子は merge back が届いて
   いなかった子だけだが(決定1)、止めても出せる問いが無く、人間は失われた ref の一覧を見て諦めると答えている。知らせは子の event と
   `lost_refs_accepted` の ref の一覧である。
7. **効いている失われた event を持ち、PR を開いていない根の着地は、そこで終わる。** 条件はこの1つで、着地がどこまで進んでいたか(local
   着地の question が開いている、hold 済み、昇格失敗の question が開いている、断念済み、remote-backed で PR 未作成)では分けない。編集が
   あった根(決定3 に当たる)は専用の記録で終え、handoff だけの根は今の `nothing_to_land` で終える —— 後者は、ブランチが在れば刻まれたはずの
   「運ぶ内容が無かった」という正常な終わりで、前者をそこへ畳むと、内容が失われたことと運ぶものが無かったことが同じ記録になる(ADR 0289
   Considered options と同じ理由)。終わった根は収束の候補から外れ、着地を待つ完了タスクに数えず、hold と断念の後の問い直しも起きない。
   ADR 0289 決定3 が恒久の「着地しない」を外した理由(hold の後に届いた修理が無言で止まる)は、届く先のブランチが無い根には当たらない。
   PR を開いている根は対象にしない —— 内容は GitHub の head に在り、着地は GitHub の merge で終わる。
8. **終わった根に開いている着地の question(local 着地、昇格失敗)は、受理が閉じて理由を event に残す。** ADR 0240 決定2 の「人間がまだ答えて
   いない失敗 question を盤面が先回りして潰さない」には当たらない —— 閉じるのは、失われた ref を諦めるという人間自身の回答の帰結である。
9. **決定1・4・8 の書き込み(event、倒す、question を閉じる)は、受理の書き戻し(ADR 0373 決定7 の順)と一緒に書く。** 受理は await を
   またぐので「回答と同じ transaction」にはできない。書き戻しより後の段で拒まれた回答でも、これらは残る —— ブランチが失われた事実は、後の拒否で変わらない。
10. **git の生のエラーを言い換える拒否文は足さない。** 受理の前は ADR 0370 決定1 の比較が消えた ref を違反として名指し(#3166、
    未実装 —— この決定はそれに依る)、受理の後は決定8 で question が残らない。
11. **要件「門を通った内容を、回答1つで落とせない」への例外が、ここで1歩広がる。** registry の `path` を無関係な repo へ差し替えて
    この選択肢に答えると、門を通った未着地の内容が、旧い path に残ったまま「着地しない」で閉じる。ADR 0373 決定5 が記録から外れることを
    承知で採ったのと同じ理由で採る —— 名指しの選択肢と event を経るので見える。採らなければ、ブランチを失った根には着地の出口が無い。

## 退けた形

- **失われた event を持つ `done` の work を一律に捨てられたに数える**(最初の版)—— handoff だけの task と PR を開いている根のレビューを、
  成果が生きているのに倒す。
- **失われた根の下の修理子を保護ブランチから切って根として着地させる** —— 失われた成果を持たない tree への修理になる。起動させない(決定4)。
- **失われた内容を取り戻す道を作業台からの取り込みと定める** —— 運ぶものが無い。人間が別の場所に写しを持つ場合に入るのは人間の内容として
  であり、task の成果としては戻らない。

## 帰結

- ADR 0271 決定1 と ADR 0301 決定1 (b) の述語に項が1つ足され、床・cascade・verb の差し替え・画面の予告は同じ述語から読む。ADR 0289 決定1 の
  「収束が候補から外す根」と ADR 0240 決定2 の除外の列挙に、着地が終わった根が足される。
- 人間担当の work も担当では分けず、同じ規則に乗る(ADR 0374 決定1 の「担当でなくタスクブランチを持つかで分ける」からの導出で、ticket は
  問うていない)。
- event の kind、question を閉じた理由を残す event の名前、着地の終わりを収束が失われた event から読むか別の記録を刻むか(決定7 の「専用の
  記録」の形と名前、書く時点)は spec が決める(#3178 の「Spec へ渡すもの」)。
- 確かめていない(同上): object が task の checkout や作業台に残っていて、受理の中で解放のやり直しがブランチを戻す場合に、先に倒した
  付帯子が戻らないこと。面接室の受験者の `task/<id>`。追いつきの merge だけで進んだ tip が「編集があった」側に倒れること。倒す付帯子が別の
  workspace で走っている場合。効いている失われた event を持つ未決着の task(次の pickup の前)の子孫の扱い。PR を開いている根と、object ごと
  失われた着地済みの根に付いたレビューが何を読むか。clone し直しで origin のブランチが戻る remote-backed の根。
- 問われていない(同上): 決定3 の祖先の読みは `parent_id` をたどる今の述語のままで、別の workspace に固定されて自分の保護ブランチへ
  帰る子孫(ADR 0372 決定4)も捨てられたに数える —— その子孫の成果は失われていない。決定5 が飛ばす task のうち、祖先が決定3 に
  当たらないもの(handoff だけの祖先、PR を開いている根)の下の task は、捨てられたに数えられないまま運ばれない。done の work の行が
  出す着地の状態(ADR 0265 決定7 の列挙)に、ブランチが失われて終わった着地をどう出すか。
