# 止まりを立て済みの失敗に無人の catch は自分の question を重ねず、後始末はその止まりの受理を待つ

2026-11-28 の triage → grilling(issue #4017、#4010 の triage の再確認の派生)で決定。registry の読みが落ちると、読み込みの1点が
盤面全体の registry の止まりを立ててから投げる(ADR 0403 決定5)。重複を避ける判定は「収束の失敗の境界と poll の catch」と列挙して
置かれていたため、列挙に無い registry の観測者の段(ADR 0442)が自分の question を重ねていた —— 後始末は落ちた後始末を、
枠を握った後の pickup は spawn の失敗を、issue の展開は展開失敗の question を、解放と pickup の門の包みは名前の場所の Quarantine を立てる。
人間は資源1つの修理に複数の question で答えることになる。数えた経路と箇所は #4017 に置く。

## 決定

1. **止まりを立て済みの型を受けた無人の catch は、自分の question・計測・行を足さない。** 判定は止まりの状態ではなく型で行う。
   置き場は段を列挙せず、無人の過程で失敗を question に変える catch すべてとする。poll の catch と収束の境界が止まりの状態を読むのは
   「開いていれば撃たない」という別の理由で、そのまま残す。
2. **後始末はこの型で止まったら、question を立てずに残りの手と枠を握ったまま待ち、止まりの受理が残りを撃ち直す。** 撃ち直しで
   registry がまた読めなければ回答を拒み、残りを持ち続ける。別の例外で投げれば、それは盤面のバグなので落ちた後始末になる
   (ADR 0342 決定1 / ADR 0433 決定2)。再起動を越えたら、受理は Harness Containment の受理と同じく後始末の再開を走らせる。
3. **枠を握った後の pickup は、この型を spawn の失敗にせず pickup の停止に乗せる。** task は位置を変えずに todo へ戻る(ADR 0274)。
   新しい行き先は作らない。
4. **止まりを立て済みの型は包みを越えて catch に届く。** 最初の撮りの確認の包み・pickup の門の包み・GitHub の読みの天候の扱いは、
   この型を自分の失敗に数えない。最初の撮りの確認を spawn の失敗に送っていたのは ADR 0373 決定13 の本文に無い写しで、決定ではない。

## 退けた案

- **観測者の段を列挙に足す** —— 今回の漏れは列挙が段の追加に追いつかなかったことで、足しても次の段で同じことが起きる。
- **止まりの状態で判定する** —— 後始末に当てると、止まりが開いている間に起きた無関係な盤面のバグまで黙り、人間に届かなくなる。
  型なら「この throw を投げた側が止まりを立て済み」と言い切れる。
- **後始末は解放を飛ばして先へ進む** —— 解放されない checkout を運び直す者が居なくなる。止まりは pickup を既に止めているので、枠を
  握ったまま待っても盤面の止まり方は変わらない。
