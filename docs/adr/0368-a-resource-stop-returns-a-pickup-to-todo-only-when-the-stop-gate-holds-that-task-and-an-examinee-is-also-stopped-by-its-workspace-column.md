# 資源の停止で todo へ戻すのは門がその task を外すときだけで、受験者も `workspace` 列の名前で止まる

2026-11-10 の grilling(issue #3144、#3120 の実装 run の派生)で決定。ADR 0274 決定1 は、資源の停止で戻した task について
「workspace / agent の停止なら修復まで候補から外れる —— 同じ枝をくり返さない」と書くが、これは前提で、確かめる機構が無かった。止める
名前は pickup の観測点(scheduler と adapter)が決め、外す名前は停止の門が別に数える。受験者ではこの 2 つが割れていた —— pickup は
`workspace` 列の実環境を registry で解き(許可ドメインの出所、ADR 0273 決定8)、門は面接室の名前だけを数える(同じ決定8)。実環境の
名前が drift した間、受験者は実環境の Quarantine に外されず、同じ pickup がくり返されて盤面が止まった(実測は issue #3144 の
コメント)。「task が依存する名前」を役ごとに各所で列挙する形からの漏れは、#2265・#3120 に続く 3 度目である。

## 決定

1. **資源の停止で `todo` へ戻すのは、その停止が門でその task を外すときだけである。** 戻す 1 か所で、門が使う述語そのものに確かめる。
   対象は task ごとの列挙で外す 3 種 —— `workspace`・`agent`・`workspaceContainment` の組。Provider の認証・盤面全体の封じ込め・
   Worker MCP 到達性は task の列挙に依らずに外すので、確かめるものが無い。ADR 0274 決定1 の「同じ枝をくり返さない」は、前提から
   戻す口の性質になる。
2. **門が外さない停止で戻そうとした pickup は、worker が 1 度も走らなかった pickup の失敗(ADR 0118 の `spawn_failed` と failure
   question)に落とす。** 新しい event kind は作らない。ADR 0274 決定2 が `spawn_failed` の流用を退けたのは、同じ原因で question が
   2 枚立つからだった。ここの 2 枚目の原因は資源の故障ではなく盤面の列挙の不整合で、理由には止めた資源と「門がこの task を外さない」
   ことを書く。
3. **停止の門は、どの task でも `workspace` 列の名前を数える。受験者も例外にしない。** Interview の役はそこに面接室を足す。ADR 0273
   決定8 の「受験者は面接室だけ」は「走る場所の単位」から来た線だが、受験者の pickup は実環境の registry の entry に依存している。
   受験者は実環境の repo を開かないので、repo の故障でも待つことになる。ただし root の再 pickup は同じ停止で止まるので、受験者だけ先に
   進めても Interview は終わらない。
4. **封じ込めの組も同じ集合と比べる。** (Harness, 実環境) の組が開いている間、その Harness に pin された受験者は待つ。受験者自身の
   封じ込めの判定は面接室の名前で立つので、これは依存していない停止で待つ代償である。集合を割れば、決定1 が確かめる対象も 2 つになる。

## 退けた形

- **停止の門に「この task の pickup が観測した、まだ開いている停止」の節を足す** —— 列挙の割れを門が黙って吸収し、割れたことが
  誰にも見えない。
- **決定1 の検査に当たった task を、その poll だけ候補から外す** —— 次の契機ごとに同じ pickup が 1 往復ずつ記録を増やし、人間に
  届かない。
- **drift の停止だけを受験者に効かせる(registry の entry と repo を別の資源にする)** —— Quarantine の種類が増え、買えるのは
  Interview を終わらせない受験者の先行だけ。
- **受験者の pickup で実環境を解かない** —— adapter も同じ名前を解いて許可ドメインを読むので、くり返しが adapter へ移る。drift 中に
  許可ドメインを空にして走らせれば、対象ごとに測る条件が変わる。
