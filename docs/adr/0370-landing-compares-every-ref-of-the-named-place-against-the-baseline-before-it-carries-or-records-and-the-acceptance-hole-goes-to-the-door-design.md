# 着地は運ぶ前と記録を書く前に名前の場所の全 ref を基準と比べる —— 受理が見せていない移動を受け入れる穴は、人間の内容の扉の設計に渡す

2026-11-11 の grilling(issue #3151、#3147 の派生)で決定し、翌日、同じ grilling の見直しで縮めた。ADR 0351 決定2 は「基準は切れない」を
pickup と解放の2つの時点の比較に載せたが、名前の場所の ref を読んで運ぶ操作はその外にもあった。着地の収束は比べずに今の `task/<id>` を
push し、Quarantine も回答も無いまま PR に届く —— poll は収束を pickup より先に走らせるので、pickup の比較が気づくのは push の後である。
Quarantine の受理は比べずに今の `task/<id>` を merge back し、全撮りで基準を上書きする —— 別の理由で立った Quarantine に回答すると、
門を通っていない commit が親のブランチに入り、本文には移動が出ない。どちらも実測した(表は #3151 のコメント)。

最初の版は、比較を名前の場所を読む全操作の最初に置く規則と、受理が「見せた値」だけを受け入れる層まで決めた。見直しで、その規則と層は
既存の決定と食い違い(下の「退けた形」)、未決の点を多く残すと分かったので取り下げた。決定の番号は引用先として残す。

## 決定

1. **着地は、名前の場所の ref を読んで運ぶ前と、ref から記録を決める前に、その workspace の全 ref を基準と比べる。** 対象は運ぶ手 ——
   push、local 着地の merge、GitHub の merge を決める積み残しの読み(PR の merge の回答と無人 merge の tick)—— と、`nothing_to_land` /
   `landing_finished` / 断念した根の問い直しを決める読み。比較はその workspace の ref を最初に読む手前に置く: 収束は workspace ごとに回の
   最初(根かどうかを決める lineage の読みの前)、回答と tick は ref を読む手前。動いていれば動いた ref を名指して workspace の
   Quarantine に落とし、その workspace の根はその回すべてそこで止まる —— 「門は quarantine より先に読む」(ADR 0241 決定3)は、ref が
   動いている場合に限って譲る。比較器は pickup と同じ1つ、範囲は全 ref(ADR 0351 決定2、ADR 0064 決定1)。着地は人間の内容の入口では
   ないので、着地が読む ref の帯域外の移動は常に違反で、新しい状態を足さずに今の Quarantine で止まる。
   - 外すもの: 外部 merge の走査(GitHub の PR の状態と DB しか読まない)、hold と断念の head の記録(何も運ばない —— 「読めなくても hold は
     拒まない」ADR 0289 決定3 を保つ)、閉じた PR の観測。
   - workspace の Quarantine が開いているだけでは、今どおり着地の回答と tick を拒まない(ADR 0289 決定2)。比較は Quarantine の有無に
     よらず走る。
   - 基準の行そのものが無い workspace では、着地が最初の撮りをする(pickup と同じ側 —— ADR 0351 決定2)。違反として止めると出口が無い:
     受理は行を作らず、pickup は収束の後にしか来ない。ADR 0103 決定1 の「行が無いときも不一致」は、基準はあるがその ref の行が無い
     場合に限る。
   - pickup・解放・verb・受理ほかの読み手の比較の置き場所は、ここでは変えない。
2. **比較の後に着地が運ぶ値は、比較で確かめた値か、その後に盤面自身が口を通して書いた値に限る。** 追いつきの merge commit(ADR 0105
   決定2)と fetch した保護ブランチは盤面の書き込みなので通る。塞ぐのは、比較から push までの await の間に帯域外で動いた値を運ぶ窓で
   ある。push の後の積み残しの読み直し(ADR 0241 決定7)は残す。
3. (取り下げ)受理は比べてから、見せた移動だけを受け入れる。
4. (取り下げ)見せた値を書くのは、名指しの文が人間に届く2箇所だけ。
5. (取り下げ)完了の門を通った `done` の task の `task/<id>` は、届いていない内容を落とす移動を見せた後でも受理しない。
6. (取り下げ)門の tip を基準の行と別には記録しない。保存の問いは #3156 が単独で持つ。
7. **着地の拒否文は、手の書き込みが確認の question を経ることを告げる。** 積み残しの merge back、追いつきの conflict、local 着地の
   conflict、外の push が落とした内容(ADR 0242 決定4)の文面に従った手の merge は ref を動かすので、retry や回答し直しは決定1 の比較に
   当たり、workspace の Quarantine を1枚経てから、もう一度 retry が要る。今は retry と、次の pickup で立つ Quarantine の2手で、それが
   「retry が拒まれる → Quarantine に回答 → もう一度 retry」の3手になる —— 比べずに運んでから気づくのをやめる費用として払う。
   ADR 0242 決定4 の「捨てる」手順は、名前の場所の HEAD が保護ブランチに居る(ADR 0356 決定1)今は `reset --hard` がローカルの保護
   ブランチを動かすので、文面を直すときに手順ごと直す。

## 残る穴と根

受理の穴は残る: Quarantine が開いている間に動いた ref は、見せられないまま受け入れられ、merge back で親のブランチへ運ばれる。根は、人間が
書いた内容を記録に入れる正規の扉が無く、Quarantine の受理 —— 故障の封じ込めの解除 —— がその入口を兼ねていることである。手で書かせる
決定(ADR 0064 決定7、ADR 0239 帰結、ADR 0240 決定4、ADR 0242 決定4 ほか)は、名前の場所が盤面の記録になる(ADR 0356)より前のもので、
回答は意図を運ばない。受理だけを直すには、意図した修理と誤操作を意図を知らずに見分けることになる。扉の設計は #3158 で、門(#1879)の
前に置く。「門を通った内容を回答1つで落とせない」をその要件として渡す。

## 退けた形

- **比較を、名前の場所を読む全操作の最初に置く**(最初の版の決定1・2)—— 「最初に」は名指しした操作の中でも成り立たない: pickup は
  比較の前に述語と面接室の開きが ref を読み(ADR 0329 追記 決定10)、解放は比較の前に自分の ref を読み書きする(ADR 0064 決定5、
  ADR 0369 決定7)。verb は比べないと決めてあり(ADR 0359 決定4)、一覧の外の読み手が 12 箇所あった。読み手の全件は #3158 に置く。
- **受理が見せた値だけを受け入れる**(同 決定3・4)—— 見せた値は workspace の行の2つ目の帳簿になる(ADR 0137 決定3 が状態を question に
  寄せ、ADR 0243 が2つ目の帳簿を退けた)。同時の回答に守りが無く、見せた値の形・寿命・比較の位置が決まらない。
- **内容を落とす移動を述語で拒む**(同 決定5)—— 祖先で測ると盤面自身が指示する巻き戻し(ADR 0242 決定4)を拒み、届いたかで測ると
  回答2回で抜けられ、path の差し替え(ADR 0351 決定7)は測れずに拒む。
- **受理の範囲から `done` の task の `task/<id>` を外す** —— ADR 0240 決定4 の手の merge は帰り先に書き、帰り先は `done` の work で
  ありうる。
- **受理の merge back を門の tip に固定する** —— 門の後に子孫から届いた内容を落とす。
- **着地が運ぶ読みの直前で、読む ref だけを比べる** —— 着地は運ぶ前に、今の ref から `nothing_to_land` / `landing_finished` を1度きりの
  event として書く。運ぶ手前だけ守ると、比べていない ref で決めた記録が残る。
