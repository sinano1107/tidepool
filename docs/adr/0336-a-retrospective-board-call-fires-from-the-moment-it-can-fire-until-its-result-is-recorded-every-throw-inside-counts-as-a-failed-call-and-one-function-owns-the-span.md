# 振り返り Board call の「撃つ」は撃てると決めた時点から結果の記録までの区間で、区間の中の throw はどこで起きても撃って失敗したと数え、区間は1つの関数が所有する

2026-11-01 の grilling(issue #2698、#2691 の実装の派生)で決定。ADR 0164 決定3 は「撃てなかった」(client なし・行なし・throttle・容器)と
「撃って失敗した」(exec・認証・検証・is_error)を列挙で分けたが、「撃つ」がどこから始まるかを書いていなかった。判事の入力の組み立て
(transcript の読み・Episode の marker)はどちらにも入らず、初回の帰責(#2691)は失敗 event に書き、sweep の3経路(第2回・停止・起草)は
try の外で組んで投げていた。投げた先は sweep の fire-and-forget の console で、失敗 event が無いので間隔も打ち切りも効かず、毎 poll 同じ
記録を読んで落ち、人間の面に出ない —— ADR 0164 が退けた「黙って消える」と同じ帰結。撃つ流れの写しは5本あり、try の位置を各写しが
決めていたので、#2691 が1本を直して3本が残った。実測と `file:line` は #2698 のコメントに置く。

## 決定

1. **「撃つ」の区間は、撃てると決めた時点から結果の記録まで。** client・行・容器が揃って「撃てる」と返った後は、入力の組み立てでも
   判事の呼び出しでも結果の書き込み(判定 event の追記・RCA の登録・candidate の作成)でも、throw は「撃って失敗した」で、その経路の
   失敗 event に書き、ADR 0164 決定4・5 の間隔と打ち切りに乗る。区間の外に残るのは「撃てなかった」と、決めた skip(宛先の無い起草・
   workspace の無い task、ADR 0164 決定2 / ADR 0173)だけ。判定の直後に続く起草は別の撃ちで、判定の区間には入らない。ADR 0164 が
   「撃てなかった / 失敗の区別を足す」を退けた懸念(保留の件数ぶん event が毎時増える)は当たらない —— 入力の組み立ては撃ち直しの門の後にある。
2. **ADR 0314 決定2 の線は動かさない。** 無い・parse できない記録は欄を空にして撃つ(失敗ではない)。それ以外の読みの例外(EISDIR・EACCES)は
   壊れた記録を隠して空欄で撃たず、決定1 の失敗になる。
3. **区間の持ち主は1つの関数。** 5経路(初回・第2回・停止・起草・配分評価)はそれを通し、種別ごとに違うもの(client・入力の組み方・判事の
   verb・結果と失敗 event の記録・Quarantine の呼び名)だけを渡す。sweep の門(in-flight の鍵・撃ち直しの間隔と上限)はその外側の wrapper。
   初回は call を1回解決して entry 全部に使うので、関数は解決済みの call を受け取る。乖離は関数を迂回しないと起きない(資源の読みを1つの
   関数に寄せた ADR 0331 決定5 と同じ形)。sweep の fire-and-forget の catch に届く throw は分類されなかった盤面のバグの印で、console に
   出すのは変えない。
4. **失敗 event の `reason` は接頭辞で壊れた段を言い、4種すべてで揃える。** `Input could not be built: `(盤面が自分の入力を組めなかった —— 記録の読み・
   marker の欠落)/ `Board call failed: `(判事の呼び出し)/ `Result could not be recorded: `(結果の書き込み)。欄は足さない —— 読み手は人間の
   面2つ(settings の halted refires と `list_halted_refires`)で機械の読み手は無く、直し方が違う(判事は Retry、入力は記録を見に行く)ので
   区別が要る。名前は観測点でなく壊れたもので付ける(ADR 0331 の流儀)—— #2686 の marker 欠落は「読めない」ではなく「組めない」。

## 退けた案

- **入力が組めないのを第3の分類にして、別の間隔・上限を持つ** —— 得るのは打ち切りまでの時間だけ。Board call は出ないので財布に響かず、3回でも1日かからない。
- **今のまま投げる** —— fail-open で、壊れずに済む運用を1つも挙げられない。
- **EISDIR 等も ENOENT と同じ null に広げる** —— 壊れた記録を隠して判事に空欄で撃つ。ADR 0314 決定2 が「無い・parse できない」の2つに限った線を越える。
- **失敗 event に段の欄を足す** —— wire-contract・MCP の説明・settings に手が入り、読む機械が無い。
- **記録の dir 全体の故障を資源の軸で1回止める** —— ADR 0314 が「読めない記録で盤面を止める」を退けており、読みは記録1本ごと。

## 帰結

- 記録の dir 全体が読めなければ(EACCES)、対象ごとに3回失敗して打ち切り一覧に同じ reason の行が並ぶ。隠れはしない。
- 起草は入力を撃てると決めた後に組むようになり、撃てないときの読みが消える。
- 撃つ流れが4本ある観測(#2567)はこの実装に畳む。
- worker 向けの記録の読み手(self RCA の証拠節・停止 RCA への `get_current_task` の行動列)は Board call ではなく verb / 注入の失敗で、#2800 に分けた。
- GLOSSARY.md「帰責」の撃てなかった / 撃って失敗の文。
