# 最初の撮りの前に、着地が終わっていない根のタスクブランチが名前の場所に在ることを確かめる —— 欠ければ撮らずに止まり、「諦める」が無いブランチを失われたと数える

**Status: 取り下げ。[ADR 0421](0421-the-delete-door-ends-the-landing-of-every-completed-task-it-leaves-under-the-name-and-refuses-while-the-board-still-has-something-to-carry.md) が置き換える —— 削除の扉が、名前に残す完了 task の着地を終えるので、着地が終わっていない根は次の登録に残らず、決定1〜4・6 は対象が無い。決定5 のうち着地済みの祖先の無いブランチを飛ばす部分だけが ADR 0421 決定5 に残る。見直しで見つけた漏れ(決定1 の「根」は git を読まないと決まらない、ほか)は #3886 のコメントにある(2026-11-26、issue #3890)。**

2026-11-26 の grilling(issue #3886、#3849 の実測から出た発見)で決定。削除の扉 → 登録し直し(ADR 0373 決定14)は checkout の path を
差し替える正規の道で、扉は PR を開いた根・hold した根・断念した根を名前に残したまま通す。新しい checkout が fresh clone だと、盤面が
記録した `task/<id>` は1本も無い。盤面はそれに気づかずに最初の撮りをして「ブランチは無い」を基準に入れ、その後で根の着地と根の下の
子の pickup が、無いブランチを git で読んで素のエラーで止まる。失われた event(ADR 0375 決定1)を書くのは「諦める」の受理だけで、
基準に行が無いものは失われたと数えないので、根は失われたとも読まれない。基準を撮った後に人間がブランチを戻しても、動いた ref として
拒まれ、「基準へ戻す」がそれを消す —— どの回答でも抜けられない(実測。条件と表は #3886)。

この ADR は、何を確かめ、何が止まり、出口が何かだけを決める。確かめる場所、受理の順、文面は spec が決める(点は #3886 に列挙する)。
「止まる → 運び込む → 受理 → 最初の撮り」の連鎖はコードの読みで、走らせていない。

## 決定

1. **基準の行が無い名前の最初の撮りの前に、その名前の着地が終わっていない根すべてについて、タスクブランチが名前の場所に在ることを
   確かめる。欠ければ撮らず、根を名指す workspace の Quarantine で止まる。** 最初の撮りをする入口すべてに掛かる(ADR 0383 決定2 の
   開く前の項と同じ位置)。面接室には掛けない。ADR 0370 決定1 の「登録し直した checkout を信じて着地を続ける」は、根のブランチが在る
   場合の決定として残る。
2. **在るブランチに確かめるのは2つだけである: 保護ブランチと共通の祖先を持つこと、PR の根は最後に push した sha を含むこと。**
   作成時の sha は比べない —— worker が履歴を書き換えた本物のブランチはそれを含まない(読み)。記録より先へ進んだ値は通る。完了時の
   tip を名指す記録は無く(#3156)、そこは登録し直した checkout を信じる線のままである。確かめに落ちたブランチの出口は、人間がその
   ref を消すか差し替えることで、基準がまだ無いので拒まれない。
3. **出口は既存の回答2つで、選択肢は足さない。** `repaired by hand` は決定1・2 を確かめ直す —— 人間が旧い checkout か出元 repo から
   運び込んだブランチは、基準がまだ無いので動いた ref ではない。「失われた ref を諦めて基準へ戻す」は、基準の行が無い名前では、
   決定1 の根のうちブランチが無いものと、その分解ツリーの中でブランチの記録を持ち ref が無い子孫を失われたと数え、既存の受理
   (失われた event、着地の question を閉じる、キューの取り下げ、付帯子を倒す —— ADR 0375 / ADR 0392 / ADR 0407)をそのまま通す。
   この回答が越えるのは決定1 の項だけで、ほかの項は今どおり拒む。失われた event の書き手は今どおりこの受理1つである。
4. **値の分からない失われた event は、成果が失われた側に読む。** この場面には失われた tip を名指す記録が無い。作成時の sha を書けば
   どの task も「運ぶものが無かった」と読まれ(ADR 0380 決定1)、編集のあった根の欠落を隠す。
5. **決定1 に当たらない、無いタスクブランチは問わない。失われた event も書かず、系譜の読みが飛ばす。** 着地が終わった根の木の task と、
   根のブランチが在る木の子孫がそれである。前者の内容は保護ブランチに、後者の内容は根のブランチに在る。event を書くと、内容が届いて
   いる task が「成果が失われた」と読まれ、その下の子の登録・分解・付帯子が止まる(merge back を記録する event は無い)。最初の撮りより
   後に消えた ref は、今どおり基準との比較が先に止める。
6. **盤面は取り戻しに行かず、登録の扉も運ばない。** 出元 repo に在るのは push 済みの PR の根だけで、取れる値は最後に push した sha
   までである —— それを黙って採ると、push の後に届いた merge back を欠いた head で着地が続く(ADR 0407 決定3 が挙げた害)。決定1 の
   止まりの間に、人間は完全な写しを持つ旧い checkout から運び込める(削除は旧い checkout を消さない)。登録の扉は旧い path を知らない。

## 退けた形

- **最初の撮りが、無いブランチに黙って失われた event を書く** —— 登録し直しの直後の poll が取り消せない記録を刻み、旧い checkout に
  しか無い内容(push していない hold・断念の根、push の後の merge back)を運び込む時間が無い。
- **「着地が終わったか」の述語に ref の有無を足す** —— ADR 0407 決定1 が消した「述語が git を読む」隙間を戻す。
- **基準を撮った後に止め、人間に戻させる** —— 戻したブランチが動いた ref になる(実測)。
- **木の中の task を全部名指す** —— 根を運び込んで子だけ諦めると、内容が根に在る子が「成果が失われた」と読まれる。
- **着地が終わった task も名指す** —— 過去の着地済みの task すべてで、正規の path の差し替えが毎回止まる。

## 帰結

- ADR 0419 決定5 の「分かれる元のブランチが無い場合」はこれで埋まる: 生き残った根のブランチは、最初の撮りより後には在るか、失われた
  event を持つ。失われた祖先は系譜に透明で(ADR 0380 決定3)、子は保護ブランチから分かれ、決定5 では止まらない。決定5 に当たらない
  無いブランチ(この ADR の決定5)は系譜の読みが飛ばすので、比べる相手が無い。
- 別の repo へ fresh clone で登録し直した名前でも、この止まりが食い違いの止まり(ADR 0399 決定5)より先に立つ。諦めれば根の着地は
  失われた event で終わり、食い違いの question は出ない(PR は GitHub に残る)。旧い repo のブランチを運び込めば、共通の祖先を
  持つ限り通り、根は食い違いの question、子は ADR 0419 決定5 で止まる。
- fresh clone で登録し直すたびに、生き残った根があれば人間は Quarantine に1回答える。dir を移しただけの checkout と、最初の操作の
  前にブランチを fetch した checkout は、決定2 を通れば止まらない。
- 限界: 削除の時点で根に届いていなかった merge back は、根だけを運び込むと黙って落ちる。削除の扉がその状態を通すかは読んでいない
  (#3889)。根を諦めて子だけ運び込んだ場合の読みは #3723 に残る。盤面が取り戻す問いは #3724 / #3535 の族に残る。
- ADR 0373 決定5・ADR 0370 決定1・ADR 0383 決定2・ADR 0380 決定3・ADR 0419 決定5 に Status 追記を置いた。
