# 絵文字入力は Twemoji 収録範囲に制限する、描画の統一方式は先送り

2026-07-15 の grilling(「emoji の表示をプラットフォーム固有ではなく共通化する必要があるのでは? Zenn は固定してる?」)で決定。動機はマスコットのブランド保護ではなく**世界観の統一** — 潮だまりの情景(エージェント絵文字・tide wash 演出・空状態アクセント)が閲覧環境によって別の絵にならないこと。機能的グリフ(⚠ ✕)は絵文字ではなくテキストグリフであり対象外(readme の既存方針どおり)。

事実確認の結果:

- Zenn は「固定」ではなく **Apple OS ではネイティブ絵文字、それ以外では Twemoji 画像**のハイブリッド(作者 catnose の解説記事 <https://zenn.dev/catnose99/articles/1e3925a010c3e5>)。哲学は「全環境で同一」ではなく「どの環境でも綺麗」。
- **Apple Color Emoji はプロプライエタリ**で、Apple デバイス外への画像配信はライセンス上不可。全プラットフォームで統一するならオープンセット一択(第一候補は保守フォーク jdecked/twemoji、CC-BY 4.0 で帰属表示が必要)。
- エージェント絵文字は将来ユーザーが自由に選べるようにする計画だが、任意の Unicode 絵文字 → 画像はコードポイント変換で機械的に解決でき、統一の障害にならない(Zenn のアイキャッチ絵文字と同じ構成)。

決定:

- **描画方式(OS ネイティブ / Zenn 式ハイブリッド / オープンセット全固定)は今決めない。** これは描画層だけの差し替えで後から選べる可逆な決定であり、Apple 絵文字前提でデザインしてきた現時点で無理に決めるものではない。他組織への販売が現実になった時点で再判断する(その時の推奨は全固定 — 顧客チームの中で同じ絵文字が人によって別の絵に見えるのは、世界観を売る上で不利)。当面は現状どおり OS ネイティブ描画。
- **不変条件だけ今コミットする**(実装面は issue #52 の loader 検証と issue #54 の icon ピッカーが担う)**:** (1) 絵文字は Unicode 文字として保存する(画像参照や独自 ID にしない)。(2) 絵文字の入力面(エージェント絵文字のピッカー等)は **Twemoji 収録範囲の絵文字に制限する**。収録外の絵文字が一度でも保存されると、将来どの統一方式に切り替えてもその絵文字だけ描画が壊れ、可逆だったはずの描画決定が不可逆になる。Zenn が入力側で同じ制限をかけているのはこのため。

Considered options:

- **Twemoji 全固定を今決める** — 販売を見据えれば最有力だが、見た目の哲学を今決めきる材料がない。不変条件が道を守る限り、決断を遅らせるコストはゼロ。
- **Zenn 式ハイブリッドを今決める** — 「どの環境でも綺麗」は達成するが「どの環境でも同一」はしない。実装も全固定の上乗せ(UA 判定 + 二重描画)であり、閲覧者が実質1人の現状には過剰。
- **入力制限なし** — 最新の絵文字も選べるが、将来の統一移行を壊すデータが蓄積する。制限による実害はほぼない(Twemoji は数千種を収録)。
