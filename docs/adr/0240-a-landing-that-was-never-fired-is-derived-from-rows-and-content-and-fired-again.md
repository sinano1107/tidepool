# 撃たれなかった着地は、印ではなく行の状態と内容から導いて撃ち直す

2026-10-12 の grilling(issue #1766、発端は #1625 / ADR 0231 と #1777 / ADR 0239)で決定。後始末は後始末の印を消して
から着地と再発火を撃ち、その間には await がある。ここで盤面が落ちると、起動時の復旧は印の無い行を拾わないので、
誰も撃ち直さない。ADR 0109 追記1 の「完了と着地の間で盤面が落ちても、着地は失われない」が成り立つのは、印を消す前の
区間だけである。merge back が conflict して workspace の quarantine を受理しても、merge back はやり直されない。
既存の retry は修理を欠いた push で PR 昇格失敗 question を閉じ、積み残しは運ぶ面の無いまま残る。実測は #1766 に置く。

## 決定

1. **撃たれなかった着地は1つの経路で撃ち直す。** 範囲は、根の最初の着地、門が開いた祖先の着地、開いている PR への
   push、断念した昇格の問い直し(ADR 0225)、行われなかった merge back である。どれも「撃つ前に止まった」ことから
   生まれ、違うのはどこまで進んでいたかだけである。
2. **撃ち直す対象は行の状態と内容から導き、印は持たない。** 対象は、どの面にも届いていないものだけである。後始末が
   未了の行と、その行が着地し直すことになる祖先は、その後始末の分なので外す。落ちた後始末の question が開いていれば
   起動時の復旧は撃ち直さず(ADR 0112 決定4)、merge back がまだ走っていないからである。昇格失敗 question が開いて
   いる根と、昇格の断念を記録した根も外す。人間がまだ答えていない、または答えた断念の選択を、盤面が先回りして潰さ
   ない(ADR 0225 と同じ線)。
3. **起動時は、容器機構の前提検査と後始末の復旧の後に撃ち直し、終わるまで最初の pickup を撃たない。** 同じ根への
   着地が並走すると、PR を二重に作りかける。
4. **merge back は、workspace の quarantine の受理の検査の中でやり直す。** 先例は ADR 0112 決定3(落ちた後始末の
   受理の検査は再実行そのもの)。後始末と同じ merge back(帰り先を checkout して merge し、休止位置へ戻す)を走らせ、
   conflict すれば merge を取り消して回答を拒む。拒否文には出口を2つ示す。手で merge を解くか、捨てるなら
   `git merge -s ours` で記録するかである(ADR 0239 帰結)。quarantine が開いている workspace には session が居ない
   ので、checkout を動かしてよい。受理した後は、その workspace の範囲で決定2 の撃ち直しを fire-and-forget で撃つ。
   pickup の契機は撃ち直しが落ち着いた後に撃ち、失敗は既存の PR 昇格失敗 question に落とす(ADR 0109 追記2 の形)。
5. **積み残しで merge 回答を拒むときは、運ぶ面を名指しする。** workspace の quarantine か、PR 昇格失敗 question
   である。どちらも無ければ、盤面が運んでいる途中だと言う。

## Considered options

- **着地の未了を表す印を新しく持つ** — 立てる箇所が後始末と人間の verb(retry・abandon・人間の完了)にまたがり、
  1つ漏れても黙って失われる。印は事実が閉じる前に消える代理である(ADR 0239 決定2)。
- **後始末の印を着地の後ろまで延ばす** — 復旧が merge back からやり直し、着地のネットワーク待ちの間も枠を握る。
  枠を空けてから着地を撃つ線(ADR 0109 追記)と食い違う。
- **無人 merge の tick か、人間の merge 回答の拒否で撃つ** — 届くのはキューの PR か、答えられた question だけである。
- **受理の後で merge back をやり直し、conflict すればもう一度 quarantine に落とす** — 同じ原因の question が2枚続く。
- **盤面は merge back をやり直さず、届くまで受理を拒む** — token や fetch の失敗まで、人間に git を打たせる。
- **起動時に、昇格失敗 question の開いた根も撃ち直す** — 断念の選択を先回りする。

## 帰結

- ADR 0109 追記1 が覆うのは印を消す前の区間で、その後ろはこの決定が覆う。
- 受理の時点で merge back が済んでいるので、retry が修理を欠いた push で question を閉じる形は起きなくなる。
- 着地を撃つ入口が2つ増える(起動と受理)。入口ごとに撃ち漏れ・二重撃ち・古い宛先が出る形そのものは #1838 が扱う。
  着地を1つの直列の収束に寄せるならば、この決定の撃ち直しはその特殊な場合になる。
