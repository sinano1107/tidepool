# 着地は入口が撃たず、記録と内容から根を導く1本の収束が撃つ

**Status: 帰結の「ローカル着地の question を持つ根は撃たない」は ADR 0289 で置き換えられた —— 外すのは開いている question・hold の head から変わらない内容・merge の記録で、行の存在では外さない**

2026-10-12 の grilling(issue #1838、発端は #1766 / ADR 0240)で決定。着地は、後始末・人間の完了・cancel・retry・abandon
と、ADR 0240 が足した起動と quarantine の受理から、相手を名指しして直接撃たれていた。守りも入口ごとに散っていた。その
結果、撃ち漏れ(#1766)・二重撃ち(#406, #412, #1835, #1836)・古い宛先への撃ち(#1734, #1642, #1729, #1834)・撃った
ことにする(#1766 の実測)が、入口ごとに別の issue として出続けた。入口と守りの所在は #1838 に置く。

## 決定

1. **入口は着地する相手を名指ししない。収束を突くだけである。** 収束は突かれるたびに、盤面全体の根(帰り先が保護
   ブランチになる done の work)を記録と内容から導いて撃つ。対象と除外は ADR 0240 決定2 のとおりである。
   `relandAncestors` の祖先の歩きは無くなる。突き忘れても着地は失われず、次の突きで拾われる。
2. **着地の書き込み(PR の作成・push・question の登録・`nothing_to_land` の記録)は、盤面で1本の列を流れる。** 走って
   いる間に来た突きは捨てず、終わった後にもう1回走らせる。収束は記録を await の前後で読むからである。merge の執行
   (無人 merge の tick・人間の merge 回答)は列に入れず、ADR 0236 の印のまま残す。push と merge の競合は、ADR 0231
   決定1 の head の固定ですでに安全である。
3. **守りは、どの入口から来ても根ごとに通る。** 断念した根(ADR 0225)には PR の有無によらず撃たず、内容が変わって
   いれば問い直す。盤面の外で閉じられた PR には push せず、閉じたことを観測として記録する。門は workspace の
   quarantine より先に読む。
4. **PR は、作る前に同じタスクブランチの PR を探す。** あれば作らず、その番号を記録する。タスクブランチの名前は
   タスクごとに一意である。
5. **収束を突く事象は pickup の契機(ADR 0119 決定1)と同じで、起動と毎時のティックを含む。** 契機の側は判定しない。
   pickup は、走っている収束が終わってから判定する。昇格失敗 question の retry は、答えている question を開いて
   いないと読む収束を1回待ち、その根の verdict で回答を受けるか拒むかを決める(ADR 0106 決定5)。
6. **止まっている原因が別の question(workspace / agent 名の quarantine)としてすでに出ていれば、失敗 question を
   重ねない。** その quarantine の受理は回答なので、決定5 によって収束を突く。着地を待つ完了タスクの数え(ADR 0217
   決定4 / ADR 0226)は、待ちの証拠の寄せ集めをやめ、収束が導く根から数える。失敗 question という証拠が無くなった根を
   数え漏らすと、registry を直さずに agent の quarantine を解除でき、次の収束でまた落ちる。
7. **push しても積み残しが消えなければ、着地したとは言わない。** push の後に積み残しを読み直す。残っていれば、
   quarantine が抱えていない限り失敗 question を1回立て、内容の届いていない子孫を名指しする。

## Considered options

- **変わったタスクや workspace を範囲として渡し、その範囲で導出する** — 範囲を正しく渡すことが入口ごとの責任として
  残る。これは名指しと同じ種類の誤りである。
- **名指しのまま入口を足す(ADR 0240 の形)** — 入口が増えるたびに同じ形の issue が出る。
- **ADR 0236 の印を根に広げ、PR の作成と push も取る** — 印は「付いていれば飛ばす」形なので、verdict を待つ retry と
  突きを取りこぼす。
- **merge の執行も列に入れる** — 人間の merge 回答が、push のネットワーク待ちの後ろに並ぶ。列と印が守る書き込みは
  別物(着地の面を作る側と、判断を執行する側)なので、ADR 0236 が退けた「同じ競合に2つの仕組み」には当たらない。
- **作成の拒否("already exists")の文面から番号を拾う** — gh の文面に依存する。
- **作る前に「作成中」を記録する** — 印を持たない線(ADR 0240)に反する。落ちた後に GitHub へ届いたかは、結局
  分からない。
- **定期の収束を置かず、着地の対象が変わる事象だけを列挙して突く** — 入口の列挙漏れという原因が残る。
- **pickup と収束の並走を許す** — 契機のたびに収束も走るので、ADR 0119 決定3 がまれだとして許した、同じ checkout での
  git の並走が毎回になる。
- **retry は突くだけで、回答をすぐに受理する** — 人間は結果をその場で見られず、失敗 question が積み上がる(#406)。
- **quarantine と失敗 question を重ねる(今のまま)** — retry は同じ原因で拒まれるので、quarantine が解けるまで失敗
  question は役に立たない。
- **push で積み残しが消えないと分かれば、push しない** — 根のブランチ自身の新しい内容まで運ばなくなる。

## 帰結

- この決定で、次の線が置き換わる。ADR 0092 決定3 の「走査は新設しない」。ADR 0106 決定4 の「呼び手は2つの扉だけ」。
  ADR 0119 決定3(後始末は着地の後に pickup を撃つ)は、すべての契機に広がる。ADR 0119 決定5 の「契機を捨てる」は、
  pickup の側だけに残る。
- ADR 0240 の起動時の撃ち直しと受理後の撃ち直しは、この収束の契機の2つになる。
- 収束は突かれるたびに、候補の根について git で内容を比べる。ネットワークに出るのは撃つときだけである。盤面の外で
  閉じられた PR の木や、断念した根の木の子は、着地が終わらないので毎回候補に残る。費用はそうした木の数に比例して
  増える。候補の絞り方は実装の spec で決める。
- 積み残しの測り方(merge される head を何で読むか)は #1837 が決める。この収束は、その述語を中身を問わずに使う。
- ローカル着地の question を持つ根は、今と同じく撃たない。その後に内容が変わったときの扱いは #1780 に残す。
