# 自動テストは3つの seam を持ち、挙動はそれが現れる最も低い seam で1度だけ言う

issue #513 の grilling(2026-09-01)で決定。2026-09-01 のアーキテクチャレビューが `src/tasks.ts` の
輸出面を絞る案を出したが、その上流に「サーバー境界の下にあるテストは意図か遺産か」があった。
ADR 0027 は主戦力を `bootTidepool` 経由の統合テストに固定したが、線を引いたのは**上側**(ブラウザと
サーバーの間)で、下側については何も言っていない。実態は、自前の db でドメイン関数を直接叩く層が
ADR 0027 の後も意図して増え続け、harness 自身が db を引数に取る fixture builder を輸出しており、
どの規約も「新しいテストをどの層に置くか」を言っていなかった。計数と速度は #513 にある。

## 決定

1. **自動テストの seam は3つ。** (i) サーバー境界 — `bootTidepool` 経由の HTTP と MCP。主戦力のまま
   (ADR 0027)。(ii) ドメイン層 — `src/*` の export された関数と型。ADR 0106 決定7 の着地 module の
   interface テストもこの層の一例で、4つ目の種類ではない。(iii) schema 層 — migration の前後の行を SQL
   で言う。ADR 0027 の「止める」は上側の線で、この ADR はその下を名付ける。
2. **ドメイン層の interface は export であり、assert は戻り値か読取面の export を通す。** 行の直読み
   (`db.prepare`)は schema 層にだけ許す。ドメインテストが行を覗くのは `/tdd` の反パターン「interface
   でなく DB を読む」そのものである。
3. **挙動は、それが現れる最も低い seam で1度だけ言う。** 上の seam は写像(HTTP status・toolError・
   attribution・経路タグ)だけを言う。既存の重複は判断が要るので一斉には消さず、触るときに片方を消す。
4. **harness の盤面 handle は `db` を公開し、用途は setup に限る。** fixture builder が db を取る既存の
   形の入口を開けるだけで、assert には使わない。混在ファイルが2本目の接続を開く形は消える。
5. **export はテストのためではなく呼び手のためにある。** テストの setup のためだけの export は認めず、
   production の呼び手経由で言い直す(`cancelTask` は abandon 回答の内部段なので隠す)。ファイル外に
   呼び手の無い export は implementation へ戻す。
6. **機械的な既存違反は一括で置き換える。** 行を覗くドメインテストと、自前で db を開く混在ファイルが
   対象。この repo のテストはエージェントが隣を写して書くので、残った違反は規則より強い先例になる。
7. **規則は seam 合意の入口に置き、機械的には強制しない。** `docs/agents/workflow.md` の seam 合意と
   `/implement-tidepool` の seam ステップがこの ADR を指す。lint は痛みが出たら足す。

## Considered options

- **下の層を `bootTidepool` へ寄せて畳む** — 14倍遅い層へ50件を書き直し、ADR 0027 の後にも意図して
  作られた層を消す。
- **規則を書かず現状維持** — 規則が無いので次のレビューが同じ提案をする(今回がそうだった)。
- **`db` を隠したまま fixture builder を足す** — builder が増え続け、隠しても各ファイルが2本目の接続を
  開くだけだった。
- **lint で `db.prepare` を落とす** — 一括置換が先に要り、seam 合意が守れる規則に機械を足す理由が今は無い。
- **重複も一括で消す** — どちらを残すかをペアごとに読む必要があり、残っても害は「同じ挙動を2度言う」
  だけで、下の層は安い。
