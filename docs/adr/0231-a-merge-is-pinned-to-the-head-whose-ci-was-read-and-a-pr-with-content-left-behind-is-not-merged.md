# merge は CI を読んだ head に固定し、積み残しのある PR は merge しない

2026-10-10 の grilling(issue #1625、発端は #1392 / ADR 0217)で決定。無人 merge と人間の merge 回答は、CI を読んでから
head を指定せずに merge していた。そのため、CI を読んでいない head が merge されうる窓が2つあった。CI を読んでから
merge するまでに head が動く窓と、修理(付帯子)が done になってから、その内容が後始末の merge back と再発火の push を
経て PR に載るまでの窓である。後者では head が動かないので、head を固定しても塞がらない。経路と時系列は #1625 に置く。

## 決定

1. **merge は CI を読んだ head に固定する。** 無人 merge と人間の merge 回答の両方で、CI と同じ読み取りで head を読み、
   その head と一致するときだけ GitHub に merge させる。無人 merge の失敗の後の読み直し(ADR 0229 決定2)も head を
   返す。読み直した head が CI を読んだ head と違えば、失敗は ADR 0229 決定3 の「開いたまま失敗」に落とさず、キューに
   残す — head が動いたことは次の tick で新しい head の CI を読む理由であって、人間に問うことではない。失敗の文面で
   見分けないのは、gh のメッセージは盤面の契約ではないからである。
2. **積み残しのある PR は merge しない。** 付帯子の決着と、その内容が PR に載ったことを区別する(CONTEXT.md「積み
   残し」)。積み残しは2区間を覆う — 分解ツリーに後始末が未了のタスクがある(merge back 前)、またはタスクブランチが
   盤面の push した先に無い内容を持つ(push 前。ADR 0105 の内容の述語で測り、盤面の外の push で先へ進んだ側を
   積み残しと読まない向きに比べる)。
3. **積み残しは回答時と merge 時に読み、門には混ぜない。** 無人 merge はキューに残り、人間の merge 回答は拒まれて
   question は開いたまま残る。登録時の着地は積み残しを運ぶ側なので、門(登録時・回答時・merge 時の3時点で読む決着の
   述語)に入れれば永久に運べない。後始末中の付帯子だけを門に入れる案も、門の定義を「決着」から変えるので取らない。
4. **盤面の外で push された head の猶予の起点は、盤面がその head を初めて読んだ時点である。** 盤面は自分が push した
   head を記録に刻み、記録に無い head を読んだら観測として刻む。起点は ADR 0227 決定2(この grilling でその場で
   改訂)に置く。起点を無人 merge キューの行に持たないのは ADR 0227 と同じ理由 — `escalate` の PR には行が無い。

## Considered options

- **head を固定するだけ** — done から push までの窓では head が動かないので、古い head の緑をその head に固定して
  merge できてしまう。
- **区別せず、続く着地が merge 済みを検出するのに任せる** — tick の merge が着地の merge 済み検査と push の間に入ると、
  修理は保護ブランチに届かず question も立たない(ADR 0105 決定3 の穴)。
- **盤面の外の push は起点が無いので猶予を過ぎたとみなす(ADR 0227 の旧決定2)** — 人間が push した直後の head が、
  check の報告前に merge されうる。

## 帰結

- 後始末を終えた後、push の前に盤面が落ちると、積み残しは自動では運ばれず、merge されないまま残る(fail-closed)。
  運ぶ再発火は #1766 が決める。
