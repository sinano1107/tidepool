# 失われた event を刻んだ task の checkout を盤面は消さず、やり直した解放は失われた `task/<id>` を書かない —— 写しの保護は「失われた」の判定に頼らない

2026-11-21 の grilling(issue #3533)で決定。give-up と「基準へ戻す」は、名前の場所に戻す先の object が無いことで ref を失われたと
数える(ADR 0373 決定5、remote-backed では先に origin から取る —— ADR 0380 決定4)。解放待ち(ADR 0369)の task の checkout には、その
sha の唯一の写しが残っていることがあり、判定はそれを見ない。give-up の後のやり直した解放は、完了の成果の最後の写しである checkout を
消し、未決着なら人間の commit を keep-around せずに上書きしていた(実測は #3533)。

## 決定

1. **盤面は、checkout を開いた後に失われた event が刻まれた task の、その checkout を消さない。** 解放済みの checkout を消す述語が
   読み、受理・後始末・解放の直後のどの呼び手にも効く —— ADR 0369 決定7(削除は「運ぶ」段の完了だけに依る)をここで改める。盤面が
   自分で「成果は名前の場所から失われた」と記録した task の写しを、その記録に反して消さない。起点を開きに置くのは、give-up の回答では
   失われた event が解放のやり直しより先に刻まれるからで、「効いている」で読まないのは、子の pickup の固定(ADR 0372 決定3 / ADR 0392
   決定1)が作り直すと効かなくなるからである。残した checkout は ADR 0369 決定5 と同じく盤面がもう触らない。ADR 0388 が退けた「消す前に
   確かめる」は閉包の確かめで外からの損傷の窓を守る形で、盤面自身の記録を1つ読むこの述語はその理由に当たらない。
2. **ADR 0392 決定3 は完了済みの解放にも当てる。** 失われた event が効いている task のやり直した解放は、門の掛かる完了済みの task でも
   投げずに、`task/<id>` を書かず解放の失敗として刻む(負う解放から外れる)—— 0392 決定1 が ref と基準の行を消した後、門の側は
   回答を拒み続け、出口が無い。0392 と 0393 は片方だけでは穴が残るので一緒に入る(#3480 は #3533 の実装に畳む)。0392 の帰結の
   「#3480 は #3533 の後」はこれが置き換える。
3. **checkout を残したことは記録し、その記録を刻んだ回答が1回だけ在り処を告げる。** 決定1・2 で残した時点で残したことと在り処を
   task に刻む —— 失われた event を刻んだ回答が後半で拒まれても、次に残す回答が告げ、done の task にも後から引ける面が残る。文は
   事実だけを言う: 在り処、盤面はもう触らないこと、人間が消してよいこと、retry は新しい checkout で拾い直し、タスクブランチが
   失われていれば fork 元から作り直すこと。名指すのは disk に在って残した checkout だけで、中身が揃っているとは言わない(S1 は欠ける)。
   残った成果を名前の場所へ着地させる盤面の経路は要るが、この ADR は持たない(#3536)。
4. **「失われた」の判定は変えない。** 盤面は checkout から戻す先の sha を取りに行かない。ADR 0392 決定3 は「checkout に tip が残る形を
   数えない判定は #3533 が持ち、自分は写しも本当に失われた形だけを受ける」と置いたが、その前提は外れ、やり直した解放の失敗は
   checkout が tip を持つ形(#3533 の S2・S3)も受ける —— 写しは決定1 が残す。

## 退けた形

- **数える前に盤面が checkout から取りに行く**(#3480 の grilling で決めた方向)—— 決定1・2 の後は判定が外れても写しは消えず、失うのは
  自動の復旧だけで、人間が届く。取りに行く機構(sha で取る信頼しない写しの変種、無関係な履歴を拒む merge-base、上限超過の扱い、
  面接室の写し)は詰めるたびに漏れが出た。詰めた設計と再開の条件は #3535 に置く。
- **残った成果を着地させる経路をこの ADR の散文の手順で書く**(人間担当の work の作業台で fetch して merge)—— 盤面の host(ADR 0371
  決定9)、木のどこに着けるか、retry との順序、面接室、人間しか書けない path で、盤面の操作として形を成さなかった。#3536 が設計する。
- **0392 と 0393 を順に入れる** —— 0393 が先なら give-up の後のやり直した解放が人間の値を上書きし、0392 が先なら S2 で受理がどの
  回答でも拒まれる。
- **受理の削除だけで飛ばす** —— 削除の述語は1つで呼び手は3つあり、受理だけ塞いでも後始末と解放の直後が同じ記録を読まずに消す。

## 帰結

戻す先が消えるのは、盤面が基準の値を名前の場所で押さえず、人間の ref の移動と gc に任せているからで、同じ機構が checkout と作業台の
借りる元も消す(#3479)。押さえる側の設計は #3534 が持つ。
