# task は自分の中身が向かう repo を覚え、根を指す記録は根の id で持ち、食い違った根だけを止める

**Status 追記: 決定3 の「出元 repo の記録が無いのは、PR を記録した根に限り食い違い」は、今の宣言が `repo` を持つときに限る。宣言の repo が無ければ盤面は GitHub に届かない(GitHub client は宣言の GitHub repo が無いと PR の操作を撃たずに投げる)ので、記録の無い PR の根をそこで止めても守るものが無い。記録があれば、今どおり宣言の出元 repo と比べる —— 記録は上書きされないので、purely-local で始まり publish の後に push した根を purely-local へ登録し直したときは、出元 repo の記録がその根を止める(2026-11-22、issue #3601)。**

2026-11-22 の grilling(issue #3500、族に #3390 / #3584)で決定。削除の扉 → 登録し直し は、path の差し替え(ADR 0373 決定14)と
repo を移す道(ADR 0378 決定9)を兼ねる。PR を開いた done の根は削除の扉を止めず(ADR 0370 決定1 が生き残らせる)、別の repo で
登録し直すと、着地はその根の PR 番号で新しい repo の無関係な PR を読み、決着を旧い根に刻む。新しい repo で同じ番号が振られると、
番号から根を引く読み手が旧い根を返す(どちらも実測、issue #3500 のコメント)。根と PR の同一性を、代わりの鍵 —— 根の代わりに PR の
番号、根の repo の代わりに今の名前の値 —— で表していたことが根である。

## 決定

1. **task は、初めてその repo に届いたときに、その repo を1回だけ記録し、上書きしない。** 宣言の repo は pickup の fetch の後、
   task branch を作る処理の中で書く(祖先を固定する経路、ADR 0372 決定3 も含む)。出元 repo は最初の push の前に書く。purely-local で
   始まった根は、publish の後に初めて push するか PR を作るときに書く。届く前の値は書かない。失われたブランチを作り直す経路
   (ADR 0392)は記録を書き直さない。
2. **根を指す記録は、PR の番号ではなく根の id で持つ。** merge question、処理中の印、番号から根を引いていた読み手は、根の id を
   持つか根の id から辿る。PR の番号は根の属性であり、別の行から根を引く鍵にしない —— 番号に repo を足しても、repo を持たない読み手
   (merge question の重複除きなど)で同じ穴が開く。
3. **2回目以降の pickup と、根を運ぶ・PR を扱う所は、網に出る前に記録を今の宣言と比べる。** 比べ方は ADR 0378 決定4 の綴りで、
   行き先を読むのと同じ同期区間で、PR を読む前に比べる(ADR 0378 決定7 の線 —— 比べた後に await を挟むと、その間の登録し直しで
   新しい repo へ撃つ)(新しい repo に同じ番号の PR が無く読みが待ちに倒れる場合も止まる)。種類が違えば食い違いで、purely-local の
   記録だけはどの宣言とも一致する。宣言の repo の記録が無ければ食い違い(fail-closed、移行は書かない)。出元 repo の記録が無いのは、
   PR を記録した根に限り食い違い。面接室の受験者は面接室にしか届かず着地しないので、記録も比較もしない。
4. **`branch` は記録しない。PR の base と宣言の食い違いは、ADR 0395 決定4 の `retargeted` と同じく merge question に回す。** 同じ
   観測に扱いを2つ作らない。既存の経路は決定3 の比較の後で効く。まだ PR の無い根は今どおり宣言の `branch` 宛てに PR を作り、中身の
   違いは merge question と CI が受け止める。
5. **食い違えば、その task だけを止める。** 着地の根は PR 昇格失敗の question で止め、文は記録と今の両方を名指す。出口は、PR の無い
   根は断念(ADR 0225)、PR のある根は新しい選択肢「この根の着地を終える」(断念は「PR は無い」と記録するので、PR のある根には事実と
   逆になる)。2回目以降の pickup で見つかった task は、その task の失敗の question で止める。workspace の Quarantine にしない ——
   宣言は扉を通った正しい値で、壊れているのは根との結び付きであり、名前で始まる新しい作業まで止める理由が無い。
6. **「この根の着地を終える」は、既存の着地の終わりと同じに扱う。** その記録は着地の終わりの一つで、収束の候補から外れる。無人
   merge キューから取り下げる。根の開いた merge question は、PR の観測(merge・close)を刻まずに question だけを引退させる。終えた
   根の下には子を足さない(ADR 0265 決定6 と同じ塞ぎ)。
7. **着地の最初の撮りも、pickup の開く前の項を通す。** 最初に触れる4つの入口のうち着地だけが外れていた(issue #3390)。登録の後に
   名前の場所で origin を向け替える形は、決定3 の比較では塞がらない(宣言は変わっていない)。

## 退けた形

- **同じ名前の登録し直しを前の登録の続きとし、名前の repo を削除をまたいで残して登録の扉で拒む** —— 名前の値を変える手ごとに門か
  例外が要り(出元 repo の足す・差し替える・外す、登録し直しでの写し、改名、GitHub の外の ssh の綴り直し、`branch`)、grilling の
  2ラウンドで5つ足した。
- **GitHub の repo を id で記録し、PR の応答が載せる id と比べる** —— PR の無い所・読めない所には比べる相手が無い。盤面が読む
  `gh pr view --json` には base の repo の id の欄が無い(実測)。
- **`branch` を task の記録で比べる** —— ブランチの正当な改名で進行中の task がすべて止まり、出口が無い。
- **publish の扉が purely-local の記録を新しい repo へ書き換える** —— 書き手が増え、process が死ぬと巻き戻しが走らない(ADR 0391 が
  予告と畳みを置いた理由)。決定1 の「初めて届いたとき」で足りる。
- **削除の扉が PR を開いた根も数えて拒む** —— GitHub で閉じられた PR の根は、内容が来なければ決着が刻まれず、扉を永久に止める。

## 帰結

- 同じ名前は別の repo にも登録し直せる(ADR 0378 決定9 は真のまま)。開いた PR を持つ根はそこで止まり、人間が着地を終える。
- ADR 0378 決定6(名前の覚えた repo による手編集の門)と出元 repo の覚えた値は変えない。task の記録はそれに重ねる根ごとの床である。
- ADR 0383 決定2 の開く前の項は、着地の最初の撮りに広がる(Status 追記を置いた)。
- 限界: GitHub 上の repo の改名では、開いた PR を持つ根が止まり、人間が着地を終える(ADR 0378 の限界と同じ線)。GitHub 上で同じ
  名前の repo を作り直した場合は見分けられない。hold した purely-local の根を、別の repo へ登録し直した後に再開すると、元の場所の
  内容がその repo へ運ばれる(登録し直した checkout を信じる ADR 0370 決定1 と同じ線)。
- 改名で自分の PR の探索が取りこぼす疑い(#3578)は、根を運ぶ前の探索の話で、この決定に依らない。
