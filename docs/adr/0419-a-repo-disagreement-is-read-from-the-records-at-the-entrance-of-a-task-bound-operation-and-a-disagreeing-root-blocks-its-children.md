# repo の食い違いは task に紐づく操作の入口で記録から読み、食い違った根は子を塞ぐ

2026-11-25 の grilling(issue #3849、族に #3699 / #3700 / #3804)で決定。ADR 0399 の比較は、行き先を読む所が投げる例外として実装され、
比較を付けるのは操作を組む各呼び手、止まりの種類を決めるのは例外が通り抜ける各 catch だった。同じ形の写し漏れが3件続いた(#3699・
#3700・#3804)。数えると、扉を通って届く穴はその写しの外にあった —— 削除の扉は未決着の task があれば拒むので、タスクブランチを持つ
task の再 pickup は登録し直しの後に起きず、起きるのは生き残った根の着地と、その根の下に後から足された子の初回の pickup である。子の
初回の pickup は自分の記録を持たないので比べず、根の内容から分かれて新しい repo を記録するか、素の git エラーで workspace の Quarantine
になり、その Quarantine が根の食い違いの question を隠した(本物の扉で実測)。着地では、型を落とす catch が PR のある根に断念を出す。
読み手の表・実測・`file:line` は #3849 に置く。

## 決定

1. **食い違いの止まりは、task に紐づく操作の入口の門が、記録と今の宣言から読んで立てる。** 門は pickup・人間担当の work の扉・収束・
   PR を扱う tick の入口に置く1つの読みで、食い違えば操作を始めない。止まりの器は ADR 0399 決定5 のまま(pickup は task の失敗の
   question、根は PR 昇格失敗の question)。入口で止まれば、途中の catch が何を握っても記録は変わらない。
2. **操作の途中の例外は、中断にだけ使う。** 行き先を読むたびの比較(ADR 0399 決定3 / ADR 0378 決定7)は残り、網に出ない保証は今どおり
   そこが持つ。途中の catch は食い違いを選り分けない。例外の種類を見るのは、別の止まりを書く2種類の口 —— 捕まえた失敗から workspace の
   Quarantine を立てる口と、PR 昇格失敗の question を立てる口 —— だけで、門を通った後の await の間に登録し直しが入った場合を受ける。
3. **門は、task に紐づく操作の場所を作る唯一の口である。** 途中の比較を持つ場所は門の戻り値としてだけ得られ、門を通さずに task の
   網の操作を組むと型が合わない。通すことと付けることを別の手にしない。
4. **人間担当の work の扉は、食い違いを拒否で返し、task に何も書かない。** question は人間に届ける器で、扉の前には操作した本人がいる。
5. **記録が今の宣言と食い違う根は、子を塞ぐ。** ADR 0265 決定6 の塞ぎの3つ目の種類で、pickup の前に飛ばす。塞ぎは記録と宣言から
   毎回導き、記録を書かない —— 宣言を戻せば消える。子に失敗の question は立てず、止まりは根の question 1つである。根のブランチが名前の
   場所に無いか読めないときも塞ぐ(着地を終えた根と同じ)。ADR 0399 決定3 の「2回目以降の pickup」は変えない。
6. **食い違った根の塞ぎに、告知(判断行)は書かない。** ADR 0413 決定1・2 の告知は根の決着を刻む transaction で書くが、食い違いには刻む
   瞬間が無く、宣言が戻った後に偽の行が残る。行と子の詳細の理由(ADR 0413 決定3)は種類を足して言い、人間への知らせは根の question が持つ。
7. **出元 repo の設定がタスクブランチを送るとき、記録が今の宣言と食い違う task の分は送らない。** task はブランチの名前から引く。
   止まった根の内容を、新しい出元 repo に置く理由が無い。

## 退けた形

- **比較の付与を型で必須にするだけ** —— 塞がるのは比較の無い網の操作で、扉からは削除の扉の await の窓(#3372 / #3322)でしか届かない。
  子の初回の pickup には比べる記録が無い。
- **Quarantine から外す判断を、Quarantine を立てる口1つにまとめるだけ** —— 投げ直しのうち Quarantine の前にあるのは一部で、残りは
  握る catch・包み直し・文字列化の前にある。
- **例外の種類を見る所をすべて述語に置き換える** —— 述語が真で、捕まえた失敗が無関係なとき、どちらの止まりを書くかが箇所ごとに要る。
  入口で読めば操作が始まらず、この場合が起きない。
- **子の初回の pickup が、分かれる元の祖先の記録と比べる** —— 子ごとに失敗の question が立ち、同じ故障で複数回止まる。
- **task ごとの記録をやめ、根だけが覚える** —— 自分で根になる task(着地の後の修理、祖先がブランチを持たない場合)と、publish を挟んだ
  purely-local の記録は、根の記録から導けない。

## 帰結

- #3804 は決定1・4 に畳む。pickup 側の比較と人間の扉の門は、削除の扉の窓と手編集の下の床として残る。
- ADR 0399・ADR 0265・ADR 0413 に Status 追記を置いた。
- 限界: 門を通った後の await の間に削除と登録し直しの両方が入ると、決定2 の2種類の口が受ける。その窓が稀でない操作が見つかれば、
  決定2 を見直す。task の issue を番号だけで持ち今の宣言で引く読み(画面・親の文面)は、この決定の外に残る(派生 issue)。
