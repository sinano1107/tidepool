# purely-local の着地の帯域外判定は盤面自身の記録で行い、正当な非 ff は Tidepool 名義の merge で追いつかせる

issue #468 のグリリング(2026-08-27)で決定。#447 のライブ検証で、同一 workspace に独立に登録された
連続タスクの2件目が、1件目の着地(盤面自身の正当な書き込み)で進んだ保護ブランチに対して ff-only で
落ち、workspace quarantine → 人間の手動 rebase が毎回必要になることが2回実測された。ADR 0053 決定3 の
前提「ff できない = 帯域外の手作業で保護ブランチが動いた」は、盤面自身が保護ブランチを進める直列運用で
破れる。

## 決定

1. **帯域外の判定は ff の成否ではなく snapshot 比較で行う。** 着地の回答受理時、保護ブランチの現在
   位置を盤面の ref snapshot(ADR 0064 — 盤面自身の書き込みは rebaseline 済み)の行と突き合わせる。
   不一致 = 帯域外の証拠 → quarantine。着地経路で quarantine するのは**これだけ**である。検査は ff の
   成否と無関係に走るので、従来 ff が黙って飲み込んだ「保護ブランチの帯域外の巻き戻し」も捕まる —
   検知は弱まるのではなく強くなる。snapshot に保護ブランチの行が無いときも不一致として扱う
   (ADR 0064 決定6 と同じ fail-closed — 未設定に分岐は書かない)。
2. **一致していれば非 ff は正当な直列進行であり、盤面が追いつかせる。** ff 可能なら今日どおり ff、
   不能なら Tidepool 名義の真の merge commit で保護ブランチへ運ぶ。タスクブランチは書き換えない
   (rebase しない)— タスクブランチは差分の恒久記録(ADR 0053 根拠1)であり、系譜の着地判定
   (`rev-list`)の土台でもある。merge back が「ff-only では撃たない — 正当な非 ff が起きる」と結論
   した線(ADR 0053 決定2)の、保護ブランチ側の対称形である。
3. **綴りは今日どおり2つ。** 休止中は checkout + merge、走行中は worktree に触れない plumbing
   (`merge-tree --write-tree`)で ref だけを進める — 「盤面は走っているセッションの checkout を
   動かさない」(ADR 0064)は無傷。git ≥ 2.38 が新しい床になる。
4. **snapshot 一致下の merge 失敗(コンフリクト含む)は回答拒否であって quarantine ではない。**
   land は人間面からの同期操作で、失敗の時点で何も壊れていない(タスクブランチも保護ブランチも無傷の
   まま「自動では合わない」と分かっただけ)。エラーは回答者にそのまま返り、question は開いたまま残る。
   Quarantine は「資源が実行不能」の封じ込めであり、着地の失敗はタスク実行の不能を証明しない — 壊れ方が
   実行に及ぶなら既存の pickup の門が捕まえる。
5. **ADR 0053 決定4 が添えた「ff-only 着地による土台移動の事後検知」は自覚的に手放す。** 偶発的な
   副産物であって床ではなく(決定4 の主旨自体が「検知しない」)、#468 が示したのはその同じ検査が正当な
   直列進行を**確定的に**誤検知することである。運ばれる内容への最終判断は今日と同じく land question の
   人間回答が持つ。

## Considered options

- **同一 workspace の連続タスクを暗黙にチェインする**(2件目を1件目のタスクブランチから fork)—
  独立タスクに偽の結合を作る。2件目が1件目の**未承認**の成果の上に立ち、1件目が hold / cancel され
  れば承認されなかったコミットを道連れに運ぶ。着地は人間の判断を通るという決定3 の線と正面衝突する。
- **pickup の門で防ぐ**(未決着の着地 question がある間、同一 workspace の次のタスクを候補から外す)—
  stale は構造的に消えるが、スループットが人間の回答レイテンシに直結する。ADR 0092 が着地 question を
  トリアージの後方へ動かしたばかりで、待ちは長い — キューが人間待ちで凍る。
- **quarantine → 人間 rebase を仕様として固定する** — ADR 0053 の「人間の手は分解ツリー1本につき
  1回」が「タスク1件につき1回」へ劣化したまま固定される。
- **plumbing への一本化** — 綴りは1つになるが、休止中は `update-ref` 後に worktree の reset 手当てが
  要り、盤面が worktree を触る面が1つ増えるだけで得るものが無い。
