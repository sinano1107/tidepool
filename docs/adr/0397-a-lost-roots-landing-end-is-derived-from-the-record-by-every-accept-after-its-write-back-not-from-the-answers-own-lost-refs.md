# 失われた根の着地の終わりは、受理ごとに書き戻しの後で記録から導く —— その回答が失った ref からは導かない

2026-11-21 の grilling(issue #3492)で決定。ADR 0375 決定9 は、着地の終わり(決定7)と question を閉じる処理(決定8)を、give-up の受理の書き戻しと一緒に書くとした。しかし #3298 は根の判定を書き戻した後の ref で読むために(同 決定6、取り違えると根でない子に恒久の記録を刻む)、終わりを別の transaction に移した。そのうえで、終わりを書く処理は失われた event を刻んだ transaction が作った差分(その回答が失った `task/<id>` の一覧)だけを読んでいた。そのため、書き戻しが throw したり盤面が落ちたりすると差分は消える。失われた event は残るのに、終わりを書くべき根を読み直す者がいない。2回目の give-up は「失われた ref が無い」と拒まれ、根は着地の question を出し続ける(#3492 のコメントに実測)。

## 決定

1. **着地の終わりは、その回答が失った ref からではなく記録から導く。** 対象は、その workspace の work のうち、効いている失われた event を持ち、`done` で、PR を開いておらず、着地の終わりの記録が無いもの全部である。根かどうかの読み・透明の読み・終わりの種類は ADR 0375 決定6〜8 / ADR 0380 のままにする。
2. **導くのは workspace の Quarantine の受理で、選択肢を問わない。** 書き戻しの後に導く。違いが無く書き戻さない受理も同じである。比較を通った受理の後は ref が基準と一致しているので、どの選択肢でも根を読み違えない。書き手は受理1つのままにする。
3. **受理は、着地の終わりを書いた後で Quarantine を閉じる。** 書き戻しが落ちても盤面が落ちても Quarantine は開いたまま残り、次の受理が必ず来る。回復はこの順序に依るので、テストで固定する。

ADR 0375 決定9 のうち、決定8(question を閉じる)を書き戻しと一緒に書くという部分を、この ADR が置き換える。決定1・4(event と倒す処理)を書き戻しより先に書く点は変えない。

## 検討した選択肢

- **収束が拾う** —— 終わりの書き手が受理と収束の2つになる。spec #3273 group H の「受理が刻む」から外れる。
- **系譜を基準の値で読み、失われた event と同じ transaction で終える** —— 隙間そのものは消える。しかし系譜の読みは ref 名で git の履歴を当てるので、基準の sha に差し替える入力をその読みに足すことになる。影響は系譜を読むすべての呼び手に及ぶ。
- **書き戻しが落ちた後だけ拾い直す道を足す** —— 差分を読む処理が残り、回復の道が別に要る。決定1 は差分そのものをやめて道を1本にする。
