# 盤面自身の ref の書き込みは、書く前に基準へ予告し、書いた後に畳む

**Status 追記: 決定4 の口を通る書き込みに、盤面自身の checkout(HEAD の移動 —— 後始末と quarantine 受理の merge back の帰り先、休止位置)が加わる([ADR 0345](0345-a-teardown-step-is-idempotent-or-skipped-from-the-record-and-the-boards-own-head-move-goes-through-the-ref-gate.md) 決定2、2026-11-01、issue #2889)。基準に HEAD の行を持ち、予告→checkout→畳む。**

**Status 追記: Considered options の「落ちた後に書けたかは GitHub の PR では分からない」は狭まった —— merge した名義を読めば盤面自身の merge は見分けられる(ADR 0265 決定5)。予告の形は ref の書き込みに残る**

2026-10-13 の grilling(issue #1848、発端は #1841 の実装で見つかった #1846)で決定。ADR 0064 決定4 は、盤面が
session の最中に同じ checkout の ref を書いたとき、**書いた後に**基準(pickup で撮った全 ref のスナップショット)の
その行だけを撮り直して「盤面がやった」と説明する。git の書き込みと DB の書き込みは1つにできないので、撮り直す前に盤面が
落ちると説明が失われ、再起動後の後始末が盤面自身の push を worker の違反と読む(#1846)。説明が足りない形も同じ族である
(#304 / ADR 0081)。盤面の git は `execFileSync` で、kill -9 / OOM / 電源断で盤面が死んでも子の push は完走して写しを
動かす(Mac で実測)。書く箇所の表と窓の実測は #1848 に置く。

## 決定

1. **予告→書く→畳む。** 盤面が session 中に ref を書くときは、書く前に基準のその行を `<old>|<new> <refname>` の2値に
   し、git を書き、書いた後に1値へ畳む。比較は2値のどちらとも一致で通す。書く前に新しい値を知らない書き込みはしない。
2. **畳みは ref を読み返した2択である。** `new` と一致すれば `{new}`、違えば `{old}` に戻す。読み返した値を基準に入れる
   ことは無く、基準の行に入る値は pickup で撮った値と盤面が予告した値だけである。窓で worker が偽造して通るのは盤面が
   書こうとした値そのものだけで、どの箇所でも無害(タスクブランチの写しは誰も読まず — ADR 0242、保護ブランチの ff 先は
   人間が承認した tip か盤面が `commit-tree` で作った merge commit、fetch の予告は原本が言った値)。ADR 0064 決定4 の「成功したときにしか撮り直してはならない」は
   この規則に置き換わる —— 失敗時も畳むが、迎え入れる値は無い。**基準を読む側はすべて2値のどちらとも一致で通す** ——
   解放時の比較だけでなく、着地の帯域外判定(ADR 0103 決定1 の「記録した保護ブランチの位置」)も同じ。落ちて残った2値行
   の上で人間が merge question に答え直したとき、帯域外と読んで quarantine に落とすのは、この決定が消そうとした誤検知
   そのものである。
3. **fetch は値を先に知る形に分ける。** `ls-remote` で sha を知って予告し、その sha を fetch し(`refs/` には書かない)、
   `update-ref` で写しを書く。網は1往復増える。対象は registry の fetch、収束の保護ブランチの fetch、registry 到達性
   quarantine の受理検査の fetch。
4. **口は1つで、新しい値を引数に要求する。** 盤面の ref の書き込みは**すべて**この口を通る —— push・fetch・ff / merge・
   fork 元への追いつき・publish・registry の `update-ref`・後始末と quarantine 受理の merge back。merge は走行中も休止中も
   `merge-tree --write-tree` → `commit-tree` で merge commit を**書く前に**作り(ADR 0103 決定3 の plumbing)、ref の
   動かし方だけが2つある: 走行中は `update-ref`(worker の作業ツリーに触れない)、休止中は `merge --ff-only <その sha>`
   (checkout ごと動かす。reset の手当ては要らない)。conflict は merge-tree の段階で分かるので中断状態は残らず、dirty な
   ツリーは ff が拒んで何も残さない。
   (2026-10-13 に #1871 で書き直し。旧文は「checkout を動かす書き込み(休止中の merge・受理の merge back)は session 中に
   起きえないので口を通らず説明も持たない —— 次の pickup の全撮りが基準を作り直す」だった。基準の読み手は解放時の比較だけ
   ではなく着地の帯域外判定(ADR 0103 決定1)もあり、後者は次の pickup を挟まずに読む —— 直列の2件目の merge 回答は
   1件目の着地の直後に来る。「読み手が無い行だけ外す」線は読み手の列挙になり、ADR 0064 決定1 が退けた形である。)
5. **落ちて残った2値行は、次の pickup の全撮りで消えるに任せる。** 残っている間に通るのは `new` への移動だけで無害。
6. **タスクブランチの写しは見張りから外さない。** 読み手はゼロになった(ADR 0242)が、窓そのものが消えるので外す動機が
   無く、外せば ADR 0064 決定1 の「列挙は黙って古くなる」への例外になる。

## Considered options

- **今の形のまま、落ちるたびの誤検知を引き受ける**(ADR 0064 決定3 の線) — 決定3 の「30秒」は動かしたのが人間自身の
  場面の見積りで、ここでは `origin/task/<別の id>` を名指しされた人間が盤面の push を推理する。Pi は無人である。
- **写しは原本と照合する**(後始末で `ls-remote`) — 写し4箇所しか覆わず、後始末が網に出て、worker が fetch / push
  できないことが前提に入る(github.com が `allowed_domains` に無いことは未検証)。
- **fetch に「どんな値でも」を予告する** — 保護ブランチの写しの偽造が基準に入り、ADR 0064 が閉じた潜在バグが戻る。
- **休止中の merge は口を通さず、次の pickup の全撮りに任せる**(2026-10-13 の初版が採った形) — 「merge の綴りを増やす」
  が理由だったが、走行中の plumbing をそのまま使い最後の1手だけが違うので綴りは増えない(#1871 の実測)。
- **帯域外判定の記録を基準と別に持つ** — 帳簿が2つになり、それぞれに落ちる窓ができる。
- **休止中だけ書いた後に ref を読み返して基準へ写す**(PR #1873 が一時的に採った形) — 決定2 の例外になる。
- **起動時に2値行を畳む** — 機構が1つ増え、残っても無害。
- ADR 0241 が退けた「作る前に作成中を記録する」との違い: 2値行は消し忘れうる印ではなく(次の全撮りで必ず消え、残っても
  無害)、落ちた後に書けたかは ref を読めば分かる(GitHub の PR と違う)。
