# 運ぶものが無い完了は着地を要求しない

issue #313 のグリリング(2026-08-13)で決定。ADR 0052 の実環境動作確認 第3段で、ファイルを1つも
変更しない検証タスクの完了が PR 昇格を撃ち、GraphQL の「No commits between …」で落ち、
recommendation が `retry` 固定の failure question を立てた —— **retry は永久に失敗する**(タスクは
done であり、そのブランチにコミットが増える経路は存在しない)。purely-local 側にも同じ穴が別の形で
ある: 着地 question(ADR 0053 決定3)は差分を見ずに立つので、運ぶものが無いのに人間の手を1回
要求する(`merge` 回答の ff-only は no-op で成功するだけである)。

差分ゼロの完了は異常ではない。検証・監査タスク(「X が成立しているか確認して報告せよ」)、調査
タスク(「原因を特定して decision log に残せ」)、「変更不要と判断した」タスクは、いずれも handoff と
decision log という正当な成果を残して差分ゼロで完了する。issue #313 の観測は、この経路を誰も
踏んでいなかったことの露見であって、経路自体の異常ではない。

## 決定

### 1. 差分ゼロの分岐は remote / purely-local 分岐の上流に1箇所置く

完了した root work の着地処理は、着地の形(PR / merge question)を選ぶ**前に**、保護ブランチの
参照へ未着地の独自コミットがタスクブランチにあるかを見る。ゼロなら PR も merge question も
撃たない。ADR 0053 決定3 の `isRemoteBacked` ゲートと同じく **skip ではなく分岐**である ——
「昇格対象が無かった」が記録されずに消えるのは、それはそれで面の不正直さになる(決定2)。

remote-backed 側だけに置かない理由: 差分ゼロで「着地の面に出すものが無い」のは remote / local に
依らない同一の事実であり、purely-local の無意味な question は「人間の手は分解ツリー1本につき1回」
(ADR 0053 決定3)の線を悪化させる。分岐を1箇所に置けば規則も1つで済む。

判定は ADR 0053 決定1 の語彙に接続する —— 決着する瞬間のタスク自身の差分ゼロは「本当に運ぶものが
無い」ことを意味する。同 ADR の「未決着の祖先の差分ゼロは意味が逆」という注意はここでは発生しない
—— 着地処理は決着の瞬間にのみ走る。

副産物として、空のリモートブランチも新規には生まれなくなる。今日の昇格は push → PR 作成の順なので、
差分ゼロの失敗でも空の `origin/task/<id>` が残っていた。分岐は push の前に立つ。既存の1本
(2026-08-12 の観測分。failure question は abandon 済み)は削除しない —— タスクブランチは決着後も
削除されない恒久記録(ADR 0053 根拠1)であり、差分ゼロのタスクの恒久記録が空であることに嘘は無い。

### 2. 記録は盤面名義のイベントであり、question でも decision log でもない

分岐の記録は新しいイベント種別 `nothing_to_land` として盤面名義でそのタスクに刻む。

- **question を立てない** —— 人間に求める判断が存在しない。retry が永久に失敗し abandon が唯一の
  正解である question は、判断ではなく答え合わせである。
- **decision log に書かない** —— 既存の「abandon promotion は昇格の断念を decision log に記録して
  question を決着させる」(CONTEXT.md の Cancelled)は**人間の判断**の記録である。差分ゼロは盤面が
  観測した**事実**であり、事実は event・判断は decision log という区別に沿う。`pr_opened` /
  `pr_merged` と同じ列に並ぶ。
- **`task_completed` に載せない** —— 完了イベントは着地処理より前に流れるので後付けになる。

### 3. recommendation `retry` 固定の一般問題は issue #322 へ切り出す

回復可能な失敗(ネットワーク一時障害)と不可能な失敗を推奨が区別しない問題は残るが、観測された
痛みは差分ゼロだけで、それは決定1が上流から消す。エラー文字列から回復不能性を判定する機構は
それ自体が投機的なので、痛みの再観測待ちの記録として切り出した(observed pain over speculation)。

## Considered options

- **question を立てて人間に決めさせる** —— 判断すべき内容が無い。
- **failure question の recommendation を状況で分ける(差分ゼロなら abandon 推奨)** —— 撃てば
  必ず失敗すると分かっている昇格を撃ってから正しい畳み方を推奨するのは倒錯している。分岐は上流に
  置くべきである。
- **remote-backed だけに分岐を置く** —— purely-local の no-op question が残る(決定1)。
- **decision log / `task_completed` に記録する** —— 決定2で個別に退けた。
