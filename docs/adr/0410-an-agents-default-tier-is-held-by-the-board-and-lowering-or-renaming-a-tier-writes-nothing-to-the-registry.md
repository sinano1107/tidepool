# agent の既定ティアは盤面が持ち、段を下げる承認と段の改名は registry に書かない

2026-11-24 の triage / grilling(issue #3758、#3635 の根)で決定。段の一覧は盤面が持つ(ADR 0200)のに、agent がどの段で走るかは
registry の agent.md に名前で書いていた。このため段を下げる承認と段の改名は、registry への commit と盤面の記録を別々に書き、その間で
盤面が死ぬと食い違った(ADR 0401 決定6、#3615)。#3635 の triage では、registry の提案の question を閉じる経路が5つあり、閉じる前に
registry に問うのはそのうち2つだけだった。段の読み手と書き手の一覧、経路の表は #3758 と #3635 のコメントに置く。

## 決定

1. **agent の既定ティアは盤面が agent ごとに持ち、agent 名で引く。** agent.md の `tier` は schema から外し、残った行は未知キーの門
   (issue #2694)が拒む。値は盤面の段の一覧から選ばれ、盤面の実績から routing meta-review が下げる、盤面の運用の値である。
2. **既定ティアを設定していない agent は盤面既定で走り、段を下げる提案はふつう立たない。** 根拠は床を agent の既定ティアが決めた
   episode だけ(ADR 0111 追記2)で、床を盤面既定が決めた episode は盤面既定の過剰を言う。立つのは、盤面既定と同じ段を設定して走った後に
   設定を外した agent だけで、その提案は盤面既定から下げる(pin は決定4)。
3. **既定ティアを変える扉は盤面設定の扉**(settings タブの実行設定と管理MCP の設定変更)で、変更は `execution_settings_changed` に
   段の id で残す。agent フォームと registry-edit の PR は段を持たない。書く前に agent が registry に在ることを読んで確かめ、読めなければ断る。
4. **段を下げる提案は盤面の routing の提案で、承認は回答と同じ transaction で書く。** pin は agent が実際に走る段(既定ティアが
   無ければ盤面既定)、下げ先がその1段下にいること、根拠の episode が走った行、agent が registry に在ること。表の書き口の hook が
   崩れを決着させ、承認と周期の照合は registry を読んで agent の存在だけを確かめる —— どれも書かない。`agent_tier_changed` と registry の
   提案の種類は無くなる。
5. **agent を registry から消しても既定ティアの行は残り、settings が孤児として見せて消せる。** 同じ名前で作り直した agent は引き継ぐ
   —— 名前は専門性の連続性を担う(ADR 0019)。段の削除は、孤児を含めて既定ティアに指されている段を名指して断る。
6. **組み込みの agent は既定ティアを持たない。** 走る review / Interview の段は review の段と Interview の規則が決める(#2521 が持つ)。
7. **agent.md の退役欄の一覧(`model` / `effort` / `advisor`)とその拒否文を消し、未知キーの門に任せる。** 未公表の今は移り先を告げる
   文の読み手が無い。移り先を告げる要る退役が出たらそのとき足す。
8. **人間の直接の変更は「材料の記録の後に対象を変えた event」(ADR 0278 追記4・5)に載り、材料には数えない。** 人間が段を決めた
   ことは新しい実績ではない。

## 退けた形

- **agent.md に残し、question を閉じる書き込みに「registry に問うた」証を求める**(#3635 の triage の設計)—— 外への書き込みは残り、
  閉じる経路ごとに外を問う形(ADR 0288 が退けた形)も、改名の窓・削除時の clone の読み・tier 行の無い agent(#3638)も残る。外への
  書き込みを門で囲うより、書き込みそのものを無くす。
- **段の値を agent.md から一度だけ盤面へ取り込む** —— 移行用の仕組みで、未公表の今は読み手が無い。
- **退役の一覧に `tier` を足す** —— 未知キーの門が既に拒む。足すのは移り先を告げる文だけで、その読み手が無い。

## 帰結

- 段の改名と削除は registry を読み書きしない。改名の窓とその出口の文は消える。
- ADR 0001 の「commit hash = agent の厳密な版」は段を含まない —— 走った段は `worker_spawned` が持つ(ADR 0210 決定1)。
- agent の世代(ADR 0307 決定2)は、盤面が持つ実際の段で数える。
- agent 発で段を変える道は提案だけ。registry の無い盤面の暗黙の agent は既定ティアを持てない(ADR 0140 決定3 のまま)。
- 定義の置き場が registry から動いても(#3759)段は動かない —— 段を定義の中に置いたまま定義を製品 repo へ移せば、段を下げる承認が
  製品 repo の保護ブランチへの書き込みになる。
- 配備: registry に `tier:` 行が残る盤面では、その agent が pickup で Quarantine に入る。行を消し、settings で設定し直す。
  既定 agent に残っていれば、Quarantine でなく盤面の起動が止まる(Claude の adapter の起動時の既定の検査)—— registry repo で
  行を消してから起動し、settings で設定し直す。
- #3635 と #3638 はこの実装に畳む。ADR 0401 決定6 とその追記(2026-11-24)は段について対象を失う。
