# 盤面が運ぶときに守るのは運んだ場所が自前で持つ object で、tree のどこにあっても守る —— 名前の場所に外から起きた損傷は、運ぶ前でも後でも守らない

2026-11-21 の grilling(issue #3494、#3222 の実装の派生。#3484・#3501 を畳んだ)で決定。ADR 0388 決定1 は、運ぶときの集合から借りている object を「消しても失われない」として外した。実装では、名前の場所の損傷を、この確かめが3つの形で素通しした。

- (a) 借りている tree の下にある自前の object を、集合の walk が数えない。
- (c) 集合の object の loose が、名前の場所で zlib として正しく別の中身になっていても、確かめの `pack-objects` が通す。
- (b) 盤面の staging repo の `git add` が、名前の場所の壊れた同じ id の loose を使い、自前の store に書かない。

いったん「解放は消す前に、中身が別の場所にあることを確かめていない」を族の根にしかけた。しかしこれは、ADR 0388 が採ってから取り下げた「消す前に確かめる」と同じ形で、退けた理由に答えていなかったので捨てた。実測と各形の手順は #3494 に置く。

1. **運んだ場所の自前の store にある object は、tip の閉包のどこにあっても守る。** (a) と (c) は ADR 0388 決定1 の文面が既に守る側に入れており、実装の欠けとして直す。
   - 借りている tree の下の object も集合に数える。
   - 中身が別の object になった loose も破損に数える。
   - 新しい tree が直に指す object も同じに扱う。名前の場所で読めず、bytes が自前の store にあれば、ADR 0364 決定1 の検証の段でも ADR 0388 決定2 の入れ直しへ進める(#3501)。tree のどこにあるかで入れ直すか拒むかを分けると、同じ自前の object の扱いが位置で割れ、割れたままで守れる運用が無い。ADR 0388 決定3 の「除外で取りこぼした object は決定1 の確かめが捕まえ、決定2 が補う」は、この決定で初めて直に指された object にも成り立つ。
2. **借りている tree の下を数えても、ふだんは閉包をたどらない。** 自前の store にあって名前の場所に無い object から、今の集合を引く。残りがあるときだけ、alternates を付けて閉包の tree をたどり(blob は開かない)、届くかを見る。残りの大半は worker が捨てた届かない object で、全部を入れ直すと人間の repo に残骸を積む。
3. **名前の場所に外から起きた損傷は、運ぶ前でも後でも守らない。** ADR 0388 決定4 の線を、運ぶ前に延ばす。ADR 0388 決定1 の「借りている object は消しても失われない」は成り立つ前提ではなく、この限界の言い換えである。
   - 自前の store に無く、名前の場所で先に欠けているか壊れている object は守らない。正しい bytes が作業ツリーにしか無くても、運んで checkout を消す。(b) と、(c) の形が借りている object に起きた場合がこれにあたる。
   - 守るには、staging が名前の場所を借りずに作業ツリーの全 file を書く必要がある。そうすると退避のたびに作業ツリーの大きさに比例する費用が ADR 0367 の2〜3倍に重なる。worker 自身の commit は盤面が制御できない。
4. **盤面は名前の場所の健全性を確かめない。** 欠けや破損は、人間か盤面の次の git の操作が出す。確かめの費用は repo 全体に比例するうえ、決定3 で守らない損傷に気づいても盤面にできることが無い(#3484 は not planned)。

## Considered Options

- **消す前に、中身が別の場所にあることを確かめる** —— ADR 0388 が退けた形。保証を「消す」に置くと、窓の幅が偶然で決まり、消す箇所ごとに出口が要る。
- **毎回、閉包の tree をたどって集合を取る** —— 決定2 の2段目を毎回撃つ形。名前の場所が無傷のときにも、運ぶたびに repo の tree の数に比例する。
- **名前の場所に無い自前の object を全部入れ直す** —— worker の残骸を名前の場所に積む。ADR 0388 が「毎回入れる」を退けた理由と同じ。
- **借りている tree の下の object は限界として守らない** —— ADR 0388 決定1 の文面が守る側に入れた object を、walk の欠けに合わせて外すことになる。

## Consequences

- Status 追記: ADR 0388 決定1(借りている object の前提)・決定3(直に指された object)・決定4(運ぶ前に延ばす)、ADR 0364 決定1(検証の段から入れ直しへ進む)。
- 決定2 の2段目がどれだけの頻度と時間で走るかは測っていない。実装(#3494)で大きい repo について測る。
- #3494 から分けた問い(門の無い完了済みの解放で、worker の段の失敗で checkout を消すか)は #3579 に置く。
