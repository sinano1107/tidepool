# 帰り先の持ち主が解放を負う間、その系譜に触る人間の扉は拒む —— 述語は1つで、完了と書き始めるが読む

2026-11-21 の grilling(issue #3365)で決定。P の session から解放が済むまで `task/<P>` を動かすのは P の worker だけ、という
不変条件(ADR 0064 を盤面の側から読んだもの)は、規則としては書かれず、slot が1つであること(ADR 0001)と後始末が解放の後まで
slot を握ることで保たれていた —— worker の子は P の解放の後にしか走らない。ADR 0374 は slot の外を通る人間の扉(書き始める・
取り込み・完了)を系譜に入れ、決定9 で「走行中の session の有無は見ない」とした。その理由は兄弟の session で完了が詰まることで、
帰り先の持ち主は考えていなかった。結果、P の後始末の前に H を完了すると、扉の merge back が `task/<P>` を進め、続く P の解放の
退避が worker の tip を基点にそれを上書きする —— 盤面自身の書き込みは基準の行を畳むので、旧値の確かめも通る(実測は #3365 の
triage)。P の session 中にも届く —— 親を塞がない子(付帯子の人間担当の work)や早期統合復帰(ADR 0121)では、H が開いたまま P が
拾われ、扉の merge back を P の完了の門が上書きする(コードの読み)。同じ根で、P の解放の前に書き始めた H は P の commit を欠く
`task/<P>` から切られる(コードの読み)。

## 決定

1. **述語は1つ —— 帰り先の持ち主が解放を負う。** 持ち主は系譜の帰り先のタスクブランチの持ち主で(`parent_id` ではない、
   ADR 0380 の透明な祖先は飛ばす)、`in_progress`・後始末の印がある・印は消えたが解放が済んでいない(ADR 0369 の解放待ち)の
   どれかなら真。解放待ちを外すと、受理のやり直しが H の merge back の後に `task/<P>` を巻き戻す。
2. **完了の扉と書き始めるが、最後の await の後の同期区間でこの述語を読んで拒む。** 兄弟の session は今までどおり見ない ——
   ADR 0374 決定9 の理由はそのまま立つ。根(帰り先が保護ブランチ)には持ち主が無いので当たらない。
3. **拒否文は C2c の形に揃え、人間の回答待ちならその question を名指す。** 待てば解ける(session 中・後始末が走っている)なら
   「… once it has finished」。P の解放を止めている開いた question(封じ込めの確認、落ちた後始末、workspace の Quarantine)が
   あればその id を添える —— 種類を列挙しない。添えなければ、答えないと解けない場面で人間が待ち続ける(#3502 と同じ欠陥)。

## 退けた形

- **完了の扉だけを塞ぐ**(triage の案、述語は `in_progress` か後始末の印)—— 書き始めるの症状と解放待ちが漏れる。
- **読み手(解放の退避と門)に merge を足す** —— 退避と門が判断を持ち、受理のやり直しが前提にする巻き戻しと規則が割れる。
- **workspace 全体の session を見る**(`redoMergeBacks` の形)—— ADR 0374 決定9 が退けた、兄弟1つで完了が詰まる形に戻る。
- **取り込みだけの操作(`take_in_work`)も拒む** —— 書くのは `task/<H>` だけで、帰り先の動きは後の完了の merge が吸収する。
