# 登録者はその task の存在を決めた判断の主であり、記録の行為者と経路は呼び出し側が必ず名指す

2026-10-02 の triage / grilling(issue #1357、発端は #1348)で決定。RCA review が human 名義で登録されていた。記録に
「誰が / どこから」を書く関数が行為者と経路の既定値(human / webui など)を持ち、指定し忘れた呼び出しがそのまま通るためである。
同じ形の食い違いは RCA review の外にもあった。登録ごとの現状と読み手の一覧は #1357 に置く。

## 決定

1. **登録者は、その task が存在すると決めた判断の主である。** 文面を書いた者ではない。盤面の規則が立てる task は盤面の
   名義になる。人間の文と盤面の地の文が1つの task に混ざることがあり、登録者1つでは「誰が書いたか」を表せない。
2. **記録に行為者と経路を書く関数は、どちらも既定値を持たない。** event を書く最下層は既に両方を必須にしている。その上の層で
   既定値を許すと、盤面の反応が人間の webui 操作として記録され、型の上では気づけない。
3. **名義の付け替え。**
   - 盤面の名義に変えるもの: RCA review、完了時レビュー、PR merge question、CI red で止まった auto-merge の question。
     どれも盤面の規則が立てる。RCA は帰責の cause をその入力の1つとして盤面の規則が立てる(close-only とタイムアウトでは
     Board call を呼ばずに立つ — ADR 0168 決定2)。
   - 変えないもの: 修理タスクと scratchpad 由来の task は human(人間の異議・コミットが存在を決める)。承認 question は
     分解した agent(agent の分解判断が存在を決め、盤面の規則は子か question かの形を選ぶだけ)。承認で実体化した子は
     human(決裁権外の子は agent には決められず、人間の approve が存在を決める。reject なら存在しない)。
4. **タイムアウトで閉じた triage の記録は、経路を盤面とする。** 束ねた登録も前挿しも、盤面の watchdog が起こしたものである。
5. **人間 decompose の門は、agent が登録した子だけを数える。** 盤面の名義の子(failure question・前提の破綻の question・
   RCA review)は agent の分解判断ではない。門の線は CONTEXT.md の「agent の判断がまだ存在しないところ」のまま変わらない。
6. **ADR 0175 決定3 を改訂する: 英訳するのは、人間が登録した task か、異議の材料を持つ task。** ADR 0175 は登録者を
   「誰が書いたか」の代わりに使った。決定1 でこの代わりは崩れる。RCA review は盤面の名義になるが、purpose に人間の方向
   コメントを運ぶ。どの異議を材料にしたかは登録の記録が既に持つ(ADR 0171)ので、新しい印は要らない。

## 帰結

- failure question・前提の破綻の question を持つ task にも、人間が子を足せるようになる。回答後の永久の締め出しは解ける。
  未回答の間に足した子も、abandon と答えれば abandon の範囲に入り一緒に cancel される。retry と答えれば親はその子を待つ。
  直接 cancel の門(question への回答が唯一の門)とは違い、decompose は「計画ごと破棄 + 親の先頭復帰」の組を壊さない。
- RCA review は #130 の Edit / 直接 cancel の範囲から外れる。盤面が登録した task を人間が cancel できるかは #1348 で決める。
- 登録者を文面の書き手として読む箇所が retrospective に残る(#1358)。盤面が実行した merge の event の行為者は #1359 で決める。
