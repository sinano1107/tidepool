# 盤面が model turn を立てる Board call は呼び出し1回 = 1行で usage を残し、ベンチマークの費用は支出の目的で分けて読む

2026-10-22 の triage → grilling(issue #2447)で決定。ベンチマークの走行の記録(spec #2439 / ADR 0298)は課題の費用を
`worker_exited.usage` から積むが、盤面自身の Board call の usage は翻訳(`translation_calls`、ADR 0296 決定5)を除いてどこにも残らず、
runner が受け取った usage を client が捨てていた。判断の段の行だけを替えた2走行は、振り返りの model が替わるのに費用の列が同じになる。
呼び手と書き先の `file:line`、使用量の TUI の実測は #2447 のコメントに置く。

## 決定

1. **盤面が model turn を立てる Board call は、種類を問わず呼び出し1回 = 1行で usage を残す。** 答えを取りに行く8用途(翻訳・下書き4・
   振り返り3)と、model turn を立てる probe(認証の検査と model probe、Claude と Moonshot)。`-p /usage` の ping は model turn を立てない
   (cost 0 / num_turns 0)ので行を持たない。probe を外す案は退ける —— 1回の上限は回数を抑えず、認証 probe は使用量を読めないまま候補の
   ある poll のたびに撃ち、Moonshot は従量課金である。揃えて壊れるものは無い。
2. **置き場は1つの表 `board_calls` で、`translation_calls` を畳む。** 行は用途・Provider / model / effort・token 4欄・費用(null は
   測れない)・作成時刻を持ち、断片数は翻訳の行だけが持つ。Provider は probe の分 `moonshot` も取る。task は持たない(決定5)。
   ADR 0296 決定5 の「記録は cache ではない」はそのまま。
3. **CLI が usage を報告した呼び出しは、成否を問わず1行。** schema に合わない答えも、予算の上限で止まった probe もターンは走っている。
   受け取れない率は model で変わり、それは構成の比較が測る差そのもの。usage の無い呼び出し(行の拒否・401・時間切れ・spawn の失敗)は
   観測できない消費として記録の外にある。行は成否を持たない(振り返りの失敗は `*_failed` の event が持つ)。
4. **答えを取りに行く呼び出しで envelope に usage が無いなら、呼び出しの失敗にする。** 版を固定して形を門で確かめている以上、欄の欠けは
   壊れた答えであって記録の劣化ではない。判定だけ受け取ると消費が黙って抜け、0 で書くと ADR 0296 決定5 が避けた偽のゼロになる。判定は
   runner の1箇所に置く。probe には当てない —— 401 や行の拒否の envelope に usage が無いのは観測の答えそのもので、行を書かずに読み続ける。
5. **ベンチマークの費用は支出の目的で分けて読み、どの task に付いたかでは分けない。** 課題は2種類 —— 期待解で対処を決める仕事の課題
   (宣言が `task`)と、最適化プロセスを走らせてその判断を読む最適化の課題(宣言が `interview`、今は Interview だけ)。課題の行の費用は
   どちらも、課題の木の session から記録から学ぶもの(RCA・記憶と routing の修理子)を除いた分で、仕事の課題では仕事の支出、最適化の
   課題では最適化の支出として読む。記録から学ぶ支出(振り返り Board call・meta-review・RCA・修理子)、人間面(下書き・翻訳)、観測
   (probe)は走行の節に用途と task の種別ごとに置く。Board call を課題の木に紐づける案は退ける —— 課題の木を足す今の算出は Board call を
   考えずに作られた形で、README の人間の手順(異議)の数で増減する学びの支出を対処の費用に混ぜる。同じ理由で RCA と修理子の session も
   課題の行から外す。所要時間は分けない —— 着地は付帯子を待つ(ADR 0092)ので、RCA の時間は実運用でも対処の時間に入る。
6. **行を書くのは Provider に依らない呼び手で、client は usage を返すだけ。** Codex の client(#2417)は費用 null で同じ表に乗る。

## 帰結

- 使用量の読み取りの TUI は起動のたびに quota の確かめ(`max_tokens: 1` の `messages.create`、binary の読みでは haiku 系)を1回撃つが、usage をどこにも
  報告しないので行にできない(2.1.300 / 2.1.308 で実測、固定版 2.1.286 は未測)。headless の `-p "/usage"` は model を呼ばないので、
  #2010 の置き換えでこの欠けごと消える。
- ベンチマークの記録は「usage の無い呼び出しと、使用量の読み取りの quota の確かめは含まない」と書く。
- settings の translation spend は用途が翻訳の行だけを読む。Board call 全体の費用の面は足さない —— 読み手がいない。
- meta-review の worker の費用は、決定5 の走行の節で初めて記録に載る(課題の木の外にあり、どこにも足されていなかった)。

## 退けた案

- **ベンチマークの記録に「Board call の消費は含まない」と書くだけにする** —— 判断の段の行だけを替えた比較が差ゼロになる。
- **結果の event の payload に usage を足す** —— 5種類以上の event に散り、下書きは event を持たず、起草の成功の event は task を持たない。
- **翻訳の表の隣に別の表を置く** —— 同じ形の表を読み手が2本足す。

## 追記(2026-10-22 の triage、issue #2493)

決定5 の「記録から学ぶもの」は task 自身の種別で判定し、祖先では判定しない。RCA・学びの task の下に立つ work の修理子(RCA の所見の行への
異議が立てるものも、RCA が行為として立てるものも)は、最も近い work の祖先のブランチから fork してそこへ帰る(ADR 0283 決定2)ので、成果物を
直す対処として課題の行に残る。祖先で外すと、RCA が対処として立てる修理子まで学びの支出に入る。
