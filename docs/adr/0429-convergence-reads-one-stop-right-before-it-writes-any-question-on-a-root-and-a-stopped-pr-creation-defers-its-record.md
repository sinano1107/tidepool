# 収束は根に question を書く直前に止まりを1つの読みで読む —— PR を作った後に止まっていれば記録ごと見送る

2026-11-26 の triage と grilling(issue #3879)で決定。

収束が根に question を書く直前に止まりを読むかは、道ごとの呼び手の写しで決まっていた。失敗 question の道は workspace の Quarantine だけを読み(門は読まない)、外の push の merge question は門と Quarantine を読み(ADR 0376 決定7 の Status 追記、#3844)、`merge` の回答の途中の立て直し(ADR 0394 決定3)と PR を作った直後の merge question は await の後に何も読まなかった。例外の一覧は散文のコメントで保たれ、#3844 と #3879 は同じ一覧から続けて漏れた2件である。PR を作った直後の question は一覧にも載っていなかった。調べた道の一覧と、question を飛ばした場合の再発見の追跡は #3879 に置く。

## 決定

1. **収束が根に question を書く道は、どれも書く直前に「門 → workspace の Quarantine」の1つの読みを通る。** 止まっていれば question を書かず(取り替えもしない)、その verdict を返す。答えている回答はその verdict で拒まれる(ADR 0241 決定5)。失敗 question の道も門を読む —— ADR 0241 決定3 の「門は他の理由より先」を、書く直前の読みにも揃える。
2. **`merge` の回答の途中の立て直しもこの読みを通る。** 立て直す question は ADR 0376 決定7 の question なので、その前に profile も読む(同 Status 追記)。答えた question は古い head を問うたまま開いて残り、止まりが解けた後の回答が読み直して取り替える。
3. **PR を作った後の await の間に止まっていれば、PR の記録ごと見送り、その verdict で止まる。** 次の収束が ADR 0241 決定4 の道(作る前に同じタスクブランチの PR を探す)で PR を見つけ、記録し、question を立てる。ref が動いたときに記録の手前で止まるのと同じ形である。
4. **1つの読みに入れないもの。** agent 名の Quarantine は入れない —— profile を読む道(決定7 の question と、PR を作る前の push)だけが今どおり読む。registry の止まりは足さない(ADR 0403 決定5)。外の push の question は答えている回にも立てる(ADR 0376 決定7)。tick は workspace の Quarantine 単独では止まらない(ADR 0370 決定1 / ADR 0399 決定5)。ここに挙げたもの以外に、読みを外す道は置かない。

## 退けた形

- **PR を作った直後の question は今どおり立てる** —— Quarantine の間は回答がその verdict で拒まれるだけで害は小さいが、#3844 が外の push の question を立てないと決めた線と食い違い、例外が1つ増える。
- **PR 番号は記録し、question だけ飛ばして後で立て直す機構を足す** —— 番号を記録した根は、積み残しが無ければ毎回 `up_to_date` で終わり、tick はキューの行の無い PR を読まないので、飛ばした question は二度と立たない。立て直す機構は、決定4 の回復の道と同じことを2つ目の道で言う。
- **道ごとに読みを足す点修正** —— 3件目の漏れを防がない。

## 帰結

- 記録を見送っている間、PR は GitHub に開いたまま記録に無い。その間に人間が merge か close すれば、次の収束が見つけた PR の状態を観測として刻む(ADR 0241 決定4 の道のまま)。盤面が PR を閉じることは無いので、give-up が挟まっても記録の有無で結果は変わらない。
- 次の収束は同じ sha をもう一度 push する —— 同じ値なので head は動かない。
- 回答の verb の側の立て直し(収束の外)は、この ADR の外である(#3918)。
