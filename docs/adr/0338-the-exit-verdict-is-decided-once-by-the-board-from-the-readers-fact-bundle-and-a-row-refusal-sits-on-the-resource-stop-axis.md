# exit の決着は読み手の事実の束から盤面が1箇所で1度決め、行の拒否は資源の停止と同じ軸に乗る

2026-11-01 の triage → grilling(issue #2791、#2776 の根)で決定。root の exit を受けた盤面の決着は、adapter が `onRowRefused` /
`onSessionStoppedByResource` を `onWorkerExited` より**先に**撃ち、先に `todo` と後始末の印を置いた handler が勝って報告なき exit の
決定(ADR 0145)が再観測で黙って退く、という呼び順の契約で成り立っていた。ADR 0309 決定1 が cap について廃止した形(「分類を exit より先に
撃つ」)を、ADR 0331 の実装(#2742)が資源の停止で再導入し、#2776 の直しが4箇所目になるところだった。順序の根拠は実装の comment と
呼び順の釘1件だけで、ADR 0184 / 0331 のどの決定も callback の形は決めていない。束の各欄は Claude では既に読み手(`StreamObservation`、
ADR 0316 決定1)の出力で、adapter は何も足していなかった。`file:line` と釘の表は #2791 のコメントに置く。

## 決定

1. **adapter は exit の通知に、帰結に要る事実の束を添える** —— ターンが走ったか、停止(1 session に1つ: 登録済みの資源の停止か、未登録の
   行の拒否の事実)、上限到達の分類(値か Promise、ADR 0309 決定1 のまま)。盤面へ別口で先に届ける callback と呼び順の契約は廃止する。
   ADR 0309 決定1 の「分類」はこの束に広がり、ADR 0316 決定1 の「分類は呼び手が足す」は「読み手の出力のうち帰結に要る事実を呼び手が束にして
   渡す」になる。Claude の束は読み手の出力の転送、Codex は読み手(ターン)・process の事実(MCP の起動時 exit)・probe(cap)の3出所を同じ束にする。
2. **盤面は束が揃ってから1度だけ決め、順を明文にする**: 人間の停止 > 停止(ターンが走っていない)> 上限到達 > 時間制限の停止の梯子 >
   報告なき exit の failure question。停止があってターンが走った session は梯子か failure question へ落ち、資源の question と2枚になる
   (ADR 0145 決定5 / ADR 0331 決定2)。Claude では停止と上限到達は同じ result 行の1つの status で排他で、この順は型のためにある。Codex では MCP 起動時 exit の停止と
   `turn.failed` の probe が重なる経路は未実測で、重なればこの順が答えである。slot・後始末・
   status の再観測は残す —— exit より前に決めた主体(人間の停止、ADR 0149 決定4 の一撃、封じ込め drift の回収)のためのもので、
   廃止するのは同じ exit 処理の中の呼び順だけである。
3. **行の拒否は資源の停止と同じ軸に乗る。** `todo` へ戻るのはターンが走っていない session に限る。ADR 0184 決定4 の「1ターンも走っておらず」は
   前提から門になり、ターンが走った後の 404 は行の Quarantine の question と failure question の2枚になる(ADR 0331 決定4 が 401 と drift に
   延ばした線を 404 に延ばす)。
4. **登録の持ち主は変えない。** 資源の停止は観測点(adapter —— init 行の途中の回収は adapter しか見られない)、行の Quarantine と
   表の行でない Interview の対象の分岐(ADR 0199)は盤面の決定の枝(task と pin を読む)。「停止を登録せずに戻さない」(ADR 0331 決定1)は、
   盤面側の登録と `todo` への復帰を同じ transaction に置くことで保つ。
5. **ターンが走ったかは記録に書かない。** 読み手は盤面の決定1つで、復旧は帰結を撃たない(ADR 0316 決定3)。

## 退けた案

- **上限到達を停止より先に置く**(#2791 本文の箇条)—— 排他なので型のためだけの順で、今の挙動(0ターンの停止は `todo`)を変えずに
  畳む側に置けば既存の釘がそのまま守る。
- **行の拒否を別の slot のまま残す** —— 順序契約が1本残り、404 だけターンの門が無い非対称も残る。
- **盤面が記録(transcript)から分類し直す** —— ADR 0316 決定3 が決めた線の反転。再起動を跨いだ0ターンの exit を復旧が分類し直さない
  非対称は ADR 0331 の帰結のまま。
- **`turnRan` を `worker_exited` に書く** —— 読み手が無い(ADR 0316 の読み手の規則)。

## 帰結

- ADR 0309 決定1・2、ADR 0316 決定1、ADR 0331 決定2・9、ADR 0184 決定4 に Status 追記で指す。GLOSSARY.md の行の拒否の段落を決定3 に揃える。
- 「資源の停止を先に登録する」(ADR 0331 決定1)、0ターンの event kind(ADR 0331 決定9)、復旧の非対称(ADR 0331 帰結)は変わらない。
- 実装は1 slice(#2791 のコメントが仕様)。#2776(Codex の0ターンの 401)はこの後、束の停止に1つ署名を足す形になる。
