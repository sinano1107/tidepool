# 着地は1つの module が verdict で答え、門は3時点で同じ述語を読む

2026-09-01 のアーキテクチャレビュー(`docs/architecture-review-2026-09-01.html`)から起こした grilling
(同日)で決定。「この完了は着地したか、次に何をするか」の決定が worker MCP・merge poll・人間面の
回答経路・triage の読み口・tasks の述語に散り、着地判定と PR 昇格失敗 question の race という同じ
種類のバグが8週で別々のファイルで10回以上直されていた。原因は interface が verdict を返さないこと
にある — 非 strict の着地は5箇所で黙って return し、呼び手は着地の痕跡を呼び出しの前後で撮って結果を
DB から再導出していた。co-change の計数と `file:line` はレビュー文書と実装 issue にある。

## 決定

1. **着地の問いは1つの module が答え、答えは verdict である。** `strict` boolean による2方言(worker の
   再発火は黙る / 人間の同期 retry は throw)を廃し、module は常に「対象なし / 運ぶものなし / 門で待つ /
   着地した(面の種類つき)/ 失敗した(閉じた理由つき)」のどれかを返す。それを人間へのエラーにするか、
   question に落とすか、黙るかは transport の仕事で、着地の性質ではない。
2. **module の範囲は着地の全決定である。** 3面の実行、祖先の再発火、PR 昇格失敗 question の登録と引退、
   ADR 0079 決定3 の観測3契機、`auto_if_ci_green` の無人 merge poll(ADR 0105 の merge 時の門の読み直し
   を含む)をすべて内側に置く。「着地済み」の4つの測り方(盤面の痕跡・ブランチの内容・PR 番号の有無・
   PR の merge 観測)は module の内部の継ぎ目であり、interface には出さない。
3. **門は1つの述語 — 分解ツリー全体に未決着の付帯子ゼロ かつ 未束ねの異議ゼロ — を、登録時・回答時・
   merge 時の3時点で読む。** ADR 0092 決定1 の登録時の門(付帯子のみ)を決定5 と同じ述語へ広げる。狭い門が
   漏らすのは `external` ダイヤルだけ(未束ねの異議を抱えたまま PR が開き、盤面の外には回答時の検証が
   ない)で、痛みは未観測だが UX を損なう挙動なので先に塞ぐ。安全である根拠: triage の close(commit も
   timeout も)は異議のあるタスクごとに必ず修理子を登録するので、異議で待たされた着地は必ず付帯子の
   決着という再発火の契機を持ち、永久に待つ経路は無い。
4. **呼び手は2つの扉だけ — worker session の complete と人間面。** WebUI と管理MCP は人間面の扉を経由し
   (ADR 0032 の「同格のもう一つの人間向け UI」)、着地を直接呼ばない。2 adapter が seam を実にする。
5. **失敗 question の登録と引退は module の内側で verdict から導く。** 人間の同期 retry は回答処理の途中に
   走るので、人間面の扉だけが「いま答えられている question を引退の対象から除く」を interface に渡す。
   引退の判定を2箇所に分けて持つ形(#406 → #412 の二重実装)は残さない。
6. **module は合成 root で1度構築され、両扉に必須の依存として渡る。** GitHub の不在は構築時に宣言された
   不在で、remote-backed の着地は「失敗: GitHub 未設定」を返す。optional callback の配線を落とした盤面が
   黙って着地しない今日の形は、ADR 0041 の「不在は宣言される」に反していたので、その型へ戻す。
7. **テストは module の interface に第2層を置く。** 主戦力は ADR 0027 どおり server boundary のまま。
   race を pin していたテストは、決定点が1つになって窓が消えた時点で削る。

## Considered options

- **2方言を残し、共通部分だけ集める** — 呼び手の DB 再導出が残り、locality の欠如がそのまま残る。
- **4 transport が module を直接呼ぶ** — WebUI と管理MCP の cancel / complete が逐語で2重化している
  現状を module の呼び手として固定する。扉の延長(人間面 参照)を先に済ませれば消える重複である。
- **門を2時点に分ける(登録時は付帯子のみ、回答時と merge 時は異議も)** — grilling の第1ラウンドで
  推した案。「異議が修理子にならず消えると着地が永久に待つ」を根拠にしたが、束ねが必ず修理子を作る
  ことを確認して落ちた。
- **question の登録・引退を扉側に残す** — 決定5 の「回答中の question を除く」を扉に置く代わりに、
  引退の規則そのものが2箇所に住み続ける。
