# Claude token の期限 metadata は任意であり、事前警告は設定された期限ごとに1度だけ出す

issue #320 の実装時に決定。ADR 0070 決定5 は setup-token と期限日を並置する形を選んだが、認証の生死を答える
cliAuth probe は実際の認証呼び出しから独立に判定でき、期限日を必要としない。移行 issue #319 の完了後も、期限が
不明または記録されていない資格情報で検査・停止・復旧を働かせる必要がある。したがって
`TIDEPOOL_CLAUDE_TOKEN_EXPIRES_AT` は認証成立の必須設定ではなく、事前警告だけを有効にする任意の metadata とする。

未設定なら事前警告だけを無効にし、起動時・定期・機会的な認証検査、board-wide halt、修理 question、回答時の
復旧検証は通常どおり働く。不正値も同じく事前警告だけを無効にし、設定名と理由をログへ警告する。現在日時から
1年後を推測する fallback は置かない — 寿命をコードに埋めず明示値だけを事実として扱う ADR 0070 の理由は保つ。

30日前の warning question は「盤面の生涯で1度」ではなく、設定された期限ごとに1度とする。警告済みの期限を
question に記録し、同一期限の poll と再起動では重ねない。token を更新して別の期限を設定した後は、その期限に
対する次の警告を1枚立てられる。

この決定は ADR 0070 の決定5だけを改訂する。setup-token への移行、401による確定判定、cliAuth halt、既存の
question 通知経路を使う他の決定は変更しない。

退けた対案は期限設定を必須にすること — metadata の欠落で実際には検査可能な認証まで起動不能にし、失効検出という
主機能を予防通知の設定品質へ従属させるため採らない。
