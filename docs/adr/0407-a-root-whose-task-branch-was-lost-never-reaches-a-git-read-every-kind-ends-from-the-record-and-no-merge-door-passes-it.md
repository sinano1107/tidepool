# タスクブランチを失った根は git の読みに届かない —— 全種類を記録で終え、merge の扉はどれも通さない

2026-11-23 の grilling(issue #3582)で決定。ADR 0375 決定7 と ADR 0397 は、失われた根のうち終える種類(死んだ根、handoff だけの根)を列挙し、
残りを「ブランチが在る」前提の着地へ渡していた。残りは2種類あった —— 祖先の着地の記録で透明な根と、PR を開いた根である。どちらも
着地が自分の `task/<id>` を git で読む所で落ち、生のエラーの昇格失敗 question が立って、`retry` も同じエラーで拒まれる。終える2種類も、
昇格失敗 question が開いていれば `retry` で同じ読みに届く。#3492・#3581・#3582 は、この1つの落ち口への別々の入口だった。
列挙の外を git に落とす形をやめ、失われた根の全種類を記録で読む。実測・読み手の表・`file:line` は #3582 のコメントに置く。決定はコードの
読みと fixture の実測に依り、本番の盤面では観測していない。

以下、「失われた根」は、効いている失われた event(ADR 0375 決定1・2)を持ち、帰り先が保護ブランチの `done` の work を指す。

## 決定

1. **失われた根は、着地のどの経路でも `task/<id>` の git の読みに届かない。** 収束・`retry` の回答・`end landing` の回答・merge の扉の
   どれも、git を読む前に記録で判定する。失われた根の種類は記録で全部決まり(決定2〜4)、判定の外へ落ちる種類を残さない。
2. **PR を開いた失われた根も、着地が終わる。** merge の記録(`pr_merged`、`pr_merge_observed`)があれば `landing_finished` で終え、無ければ
   PR なしの死んだ根と同じ `landing_ended_branch_lost` で終える。閉じられた PR の根も後者で、close の観測を待たない。未 merge の PR は
   GitHub に残し、盤面は merge も close もしない。開いている merge question と無人 merge キューの行は、受理が回答の帰結として片づける
   (ADR 0375 決定8 / ADR 0397 決定2 のまま)。ADR 0375 決定7 の末尾(PR を開いている根は対象にしない)を置き換える。その理由
   「内容は GitHub の head に在る」は、ADR 0380 決定4 が数える前に取り戻すと決めた後は、取り戻せなかった根にしか当たらない。
   「成果が捨てられた」の述語は PR の条件を既に外しており(ADR 0380 決定1)、同じ根のレビューを倒しながら着地だけを続けていた。
   続けると、push 前に失われた commit(修理子の merge back を含む)を欠いた古い head が、無人で merge される。
3. **祖先の着地の記録で透明な根は、`nothing_to_land` で終える。** 内容は祖先の着地と一緒に保護ブランチへ届いている。ブランチが在れば
   通常の比較が書く記録と同じである。ADR 0375 決定7 が畳むことを退けたのは「内容が失われた」と「運ぶものが無かった」で、この根は
   内容を失っていない。この種類を「終えない」と決めた ADR は無く、コードの分岐だけがそうしていた。
4. **死んだ根と handoff だけの根の終わりは変えない**(ADR 0375 決定7)。
5. **失われた event が効いている根は、merge の扉を通さない。** 無人 merge の tick は飛ばし、merge question の `merge` と local 着地の
   `merge` の回答は拒む。受理は失われた event を書き戻しより先に、終わりを書き戻しの後に書くので(ADR 0397 決定2・4)、間の窓と、
   書き戻しが落ちた後に、扉が古い head や失われたブランチへ届く。拒否文は既存の「ブランチが失われた」の文を使う。
6. **昇格失敗 question への `retry` と `end landing` の回答は、失われた根では同じ判定で終わりを書く。** 収束が開いた昇格失敗 question の
   根を飛ばすのは、人間がまだ答えていない question を先回りして潰さないためで(ADR 0240 決定2 / ADR 0397 決定3)、答えた回答には
   当たらない。回答が名指すのは「もう一度試す」「着地を終える」で、どの記録で終えるかは盤面が記録から決める(ADR 0400)。
   `end landing` が失われた根に `landing_ended_pr_left` を書くと、merge 済みの根で事実と違う記録になる。`abandon` は今どおりで、
   question が閉じた次の収束が終える。

ADR 0397 決定1 の「PR を開いておらず」と、決定3 のうち回答にも飛ばしを当てていた部分を、この ADR が置き換える。判定が1つの関数で、
書くのが受理と収束である点は変えない。ADR 0399 決定5・6 の `end landing` は、失われていない根では今どおり `landing_ended_pr_left` を書く。

## 退けた形

- **着地の手前に、透明な根と PR の根の分岐を足す** —— 終える種類の列挙に2つ足すだけで、列挙の外が git に落ちる形が残る。同じ漏れを
  3度塞いだ後の4度目になる。
- **失われた根でだけ `end landing` の選択肢を隠す** —— question が立った後に失われた根に届かない。
- **透明な根に専用の終わりの kind を足す** —— 読み分ける読み手がいない。

## 帰結

- 判定は記録だけを信じる。「諦める」が記録を書いた後・git を書く前に落ちると、ref が無傷でも失われたと読まれ(#3624)、その影響が
  PR の根にも及ぶ。倒れる向きは「merge しない」で、PR は GitHub に残る。
- merge の有無は記録で読むので、GitHub で merge 済みでも観測の前なら `landing_ended_branch_lost` が書かれ、観測は終わった根に届く。
- 失われた tip が push 済みで、PR の head が GitHub に残っていても、取りに行く先から object が消えていれば、この決定で着地が終わる。
  人間は GitHub 上で merge できる。直す場所は取り戻す側(ADR 0380 決定4)で、派生 issue に送った。
- 決定3 は「祖先が着地したなら、その前に完了した子の内容は届いている」という ADR 0380 決定1 の読みに乗る。
- 確かめていない: 決定5 の窓を着地の ref 検査が既に覆っているか。終えた後に人間が GitHub 上で残った PR を merge した場合の表示。
  本物の GitHub が、branch を消した後の sha 指定の fetch に応じるか(ADR 0380 帰結のまま)。
- 失われていない `done` の子が、失われて透明な親の下で着地の根になる場合は、この ADR の範囲に入れていない(派生 issue)。
