# 帰責の単位は異議群で、entry を1つの値で読む読み手は最後の異議群の判定を読む

2026-09-28 の grilling(issue #1087、ADR 0168 の派生)で決定。同じ判断への2度目の異議は正当で、別の session なら別の修理タスクへ
束ねられる(ADR 0085)。書く側は既に異議群単位だった —— 帰責 event は材料にした異議の id 列を持ち、case 描画もその帰責の steering だけを
読む(#958)。一方、読み手(一覧・Precedent・`propose_from_objection`・打ち切りの行の cause)は entry への最新の帰責を id 順で読み、
第2回の撃ち直しの回数・打ち切り・Retry / Dismiss は entry を鍵にしていた。ADR 0168 が第2回の門を異議群単位にしたことで、
同じ entry が複数の session で異議されると読み手と門と回数が別々の単位で答える。今の実装の walk-through は #1087 のコメントに置く。

## 決定

1. **帰責の単位は異議群(entry × 束ねた session)。** 判定、第2回の門、撃ち直しの回数、打ち切りの行、Retry / Dismiss をこの単位に
   揃える。前の異議群の Dismiss は後の異議群の第2回を塞がず、前の異議群の起草の撃ち直しは後の異議群が第2回を待つ間も続く ——
   撃ち直しの対象は entry ごとに1つではなく異議群ごとに並ぶ(ADR 0164 決定5「行が閉じるのは成功と Dismiss だけ」に戻る)。
2. **entry を1つの値で読む読み手は「最後の異議群の判定、無ければ未帰責」を読む。** 「最後」は異議群の順で決め、event の id 順では
   ない —— 前の異議群の第2回が後の異議群の判定より後に着地しても追い越さない。「同じ entry への追記は最新が有効」(spec #563)は
   こう読み替える。未帰責の読みは ADR 0168 決定3 のまま(cause は空、`propose_from_objection` は `uncertain` と同じ文言で拒む)。
   前の異議群の判定は event に残り、異議ごとに cause を見せる形は読み手が現れてから。
3. **routing 学習器の負の信号はすべての異議群の判定を見る。** どれか1つが `capability` なら負 —— 配分評価の「1つでも負なら負」
   (ADR 0111 決定2)と同じ形。最後の異議群だけを見ると、前の `capability` が後の `preference` で消える。
4. **第2回の撃ち直しと Retry / Dismiss の鍵は異議群の最初の異議 event の id。** 失敗 event もそれを持つ。修理子の登録 event の id は
   「当時の decision log の切れ目」であって異議群の名前ではない。
5. **前の異議群の RCA が走っている最中に再異議されて commit されると、その RCA の reviewer の `propose_from_objection` は
   「最後の異議群が未帰責」で拒まれる。** これは受け入れる —— 後の異議群の第2回が着地すれば起草でき、後の commit が立てる RCA の
   reviewer は起草できる。RCA 子と異議群を結ぶ印を足す案は、第2回の証拠にする RCA 子の範囲(task 全体)と同じ構造なので、
   その派生 issue で扱う。

## 退けた案

- **entry 単位に戻す** —— 後の異議は entry 全体の問い直しになり、書く側(異議の id 列、#958 の case 描画)をこの単位に戻す工事になる。
  前の異議群と後の異議群の判定を区別する読み手は持てない。
- **束ね済みの entry への再異議を禁じる** —— 食い違いは構造的に消えるが、同じ決定の別の面への方向づけ(A で「Y にせよ」、B で
  「テストを書け」)は修理タスクの entry に打つしかなくなり、判定と負の信号が修理 worker に付き、元の決定の Precedent からその異議が抜ける。

学習器の outcome が session 単位の2値であることの粗さは既存の決定(ADR 0111 / 0115 決定5)で、この決定の外 —— 派生 issue に置く。
