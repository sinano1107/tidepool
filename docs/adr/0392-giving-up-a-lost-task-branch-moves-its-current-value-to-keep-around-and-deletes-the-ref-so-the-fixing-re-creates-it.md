# 失われた `task/<id>` を諦めるときは今の値を keep-around へ移して ref を消す —— 作り直すのは固定と `start_work` で、在る ref を task の成果として採らない

2026-11-21 の grilling(issue #3480)で決定。give-up の選択肢(ADR 0373 決定5)は、object の無い ref を今の値で基準に入れる。
`task/<id>` の場合、その task には同時に失われた event が付く(ADR 0375 決定1)。人間がその ref を別の commit へ動かしていると、
基準は「ref は人間の値」と、task の記録は「ブランチを持たない」と、同じ名前について食い違う2つを書く。ref を読む手はこの状態を
1箇所ずつ避けており(ADR 0380 決定3 の写しが4箇所)、作成の箇所(ADR 0372 決定3 の固定と `start_work`)だけが避けずに、在る ref を
クラッシュ後の回復(ADR 0329 決定2)と読んで人間の sha で `task_branch_created` を書き直していた —— 人間の commit が task の成果と
作成時の sha(ADR 0375 決定2)に入る(実測は #3480 のコメント)。在る ref を採る分岐が誤るのは give-up を通ったときだけで、ほかの
経路では基準に無い値は Quarantine が戻す(ADR 0351 / 0373 決定3)。

## 決定

1. **give-up は、失われた event を書く `task/<id>` を「基準へ戻す」と同じ手で消す。** 今の値(sha を持つもの)は
   `refs/keep-around/<sha>` で持ち続け(ADR 0373 決定4)、ref と基準の行を消す。task の決着を問わない —— done の task のこの ref を
   git で読む手は無く(ADR 0380 決定3)、残して守るものが無い。これで「失われた event が効いている間、`task/<id>` は無い」が成り立ち、
   未決着の task は次の固定か `start_work` が fork 元から作り直す(spec #3273 group H)。人間の写しは keep-around から作業台で拾い
   直す(ADR 0371)—— 人間の内容として入り、task の成果としては戻らない(ADR 0375 の退けた形と同じ線)。
2. **作成の箇所は、失われた event が効いているのに ref が在れば、採らずに止まる —— 止めるのはその task で、workspace ではない。** **Status 追記: ADR 0428 決定1・3 が置き換えた(issue #3877)。**
   決定1・3 のあとは届かない状態で、黙って記録し直すより止まる側を選ぶ。壊れているのはその task の記録と ref の組だけで、workspace の
   Quarantine に畳むと、ref は盤面が書いた値として基準に在るので「基準へ戻す」は何も変えず、どの回答でも抜けられない。task に
   failure question を立て、ref と値を名指し、出口は task の cancel。
3. **受理がやり直す解放(ADR 0369 決定6)は、失われた event が効いている task の `task/<id>` を書かず、解放の失敗にする。** 解放が
   ref を作れば決定1 の不変条件が破れ、決定2 の守りで task が詰まる。checkout に tip が残っている形を「失われた」と数えないのは
   判定の側の問いで、#3533 が持つ —— この ADR はそれが入った後の、写しも本当に失われた形(checkout が読めない)だけを受ける。
   失敗は解放で checkout を読めなかったときと同じ形(ADR 0356 決定2)で、failure question の retry は fork 元から作り直した
   ブランチで拾い直す。
4. **人間に見せる選択肢の文は、`task/<id>` が今の値で入らないことを言う。**

## 退けた形

- **作成の箇所で退避して作り直す**(triage の案)—— 食い違う状態が次の pickup まで残り、読む手の避け方が増え続ける。
- **今の値を作成時の sha として採る**(今の振る舞い)—— 人間の commit が task の成果になり、ADR 0375 決定2 の「編集があったか」の比較も壊れる。
- **ref の門の側で give-up を拒む** —— object が本当に失われた ref の出口が無くなる(ADR 0373 決定5 の理由)。
- **未決着の task だけ消す** —— 変更は小さいが、決着で分かれる理由を壊れる運用で挙げられない。

## 帰結

- give-up でも書き戻す ref ができるので、`restoreBaseline` の clean の検査が走る。回答の経路は先に clean を確かめているので、扉の
  振る舞いは変わらない。
- ADR 0380 決定3 の「失われた祖先に git を当てない」は記録の規則として残る。その写しが前提にしていた「人間の値で残る」場面は無くなる。
- 実装(#3480)は #3533 の後 —— 先に入れると、完了の tip が checkout に残る解放待ちの task で受理が抜けられなくなる(実測は #3480 のコメント)。
- Status 追記: ADR 0373 決定5。
