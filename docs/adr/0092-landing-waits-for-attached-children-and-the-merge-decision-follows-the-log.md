# 着地は付帯子の決着を待ち、merge 判断はログ流し読みの後に置く

**Status: 決定3 の「条件は起動の瞬間に読み直す」は ADR 0105 で `auto_if_ci_green` の merge 実行時にも適用されるよう拡張済み** — 門はキュー投入時だけでなく merge の直前にも読まれる。 決定1 の登録時の門の述語は ADR 0106 で「未束ねの異議ゼロ」まで広げられ、決定5・ADR 0105 決定4 と同じ述語になった。

issue #399 の grilling(2026-08-21)で決着。ADR 0049 は「付帯子は親の完了を塞がない」と決め、昇格を
止めるべき判断は「merge の門が持つ」と先送りした。その門は今日まで存在せず、work の完了は review 子の
有無を見ずに着地へ進む — purely-local の merge question、`escalate` の PR open 時 question、
`auto_if_ci_green` の無人 merge キューの3面すべてが、レビュー中・修理中の成果を運ぶ。report は
purely-local の面で観測されたが、最も重いのは review flag 付きのタスクがレビュー中に無人 merge されうる
ことである。

## 決定

1. **着地は、分解ツリー全体に未決着の付帯子がゼロのときにだけ走る。** 門は着地(PR 昇格 / merge
   question / auto-merge キュー投入)に置き、完了・blocked 導出・pickup・condensation の入力は ADR 0049 の
   まま触らない。付帯子は型で列挙しない — review 子も異議由来の修理・RCA も等しく待つ。走行中の
   タスクへ出た異議は、修理を経てから着地するのがこの規則から自然に出る。範囲が直下ではなく
   **分解ツリー全体**なのは、決着済み分解子への修理が系譜経由で親のタスクブランチへ merge back される
   (ADR 0053)からで、着地する枝は1本、そこへ流れ込むものすべてが門の対象である。
2. **着地は全体を遅らせる — PR も開かない。** 完了時に PR だけ開いて決裁面を保留する形は退けた。
   1箇所の関門で3面を覆え、ADR 0073「PR の粒度 = 説明責任の単位」が保たれる(レビュー前の PR は
   説明責任を果たしていない)。代償は remote-backed で CI の開始がレビュー分だけ遅れること。
   `external` の PR もレビュー後に開く — 盤面が遅らせるのは自分の行為だけで、merge 面の統治は外のまま。
3. **再発火は付帯子の決着が起こし、条件は起動の瞬間に読み直す。** 走査は新設しない。起動時に
   「未決着の付帯子ゼロ」を再検査するので、待っている間に新たな付帯子が付けばもう一度待つ。cancel も
   決着であり着地を進める — 「レビューしない」は人間の明示の決定で、着地を永久に塞ぐ理由ではない。
   strict 経路(回答時の同期再試行、issue #66)は「review still running」の形で人間に見える。
4. **Triage の一本道を「質問 → ログ流し読み → merge 判断 → キュー確認 → コミット」に改める。**
   着地 question(purely-local の land question と PR の merge question)をステップ1から抜き、流し読みの
   後ろへ置く。門だけでは足りない — 異議は Commit 時に修理子へ束ねられる(ADR 0046)ので、merge question
   が流し読みの前にある限り、人間は異議を出す前に merge を答えるか、出した後でも修理子が存在せず門に
   映らない。一般 question(エスカレーション・quarantine 確認・decompose 承認)は答えないと盤面が止まった
   ままなので先頭に残す。
5. **未束ねの異議を持つタスクの着地 question は、merge 判断ステップに現れず、回答時に拒否される。**
   盤面は回答受理の直前に「未決着の付帯子ゼロ かつ 未束ねの異議ゼロ」を検証する。question 自体は
   「まだ答えられない決定」として open のまま残る — ADR 0079 の「正しさは回答時の検証が担う」の型。

## 却下した案

- **付帯子を型で選ぶ(完了時レビューのみ / review type のみ)** — ADR 0049 が嫌った「閉じた列挙は新しい
  扉が開いた瞬間に黙って古くなる」をそのまま門へ持ち込む。着地済みタスクに付く異議修理は門の手前に
  いないので、型を問わなくても矛盾は起きない。
- **異議の raise 時点で着地 question を引退させ、修理決着後に立て直す** — question の生死が増えるだけで、
  回答時の検証で同じ正しさが得られる。
- **束ねを Commit から raise 時点へ前倒しする** — 「束ねは Commit の行為」(ADR 0046)を崩す。
