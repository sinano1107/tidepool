# 削除の扉は、名前に残す完了 task の着地を終える —— 盤面がその名前でまだ運ぶものを持つ間は拒む

2026-11-26 の grilling(issue #3890、元は #3886)で決定。削除の扉は、基準・覚えた repo・registry の行を消すが、着地が終わっていない
完了 task(PR を開いた根、hold した根、断念した根と、その下の done の子)を名前に残して通していた。残った task は、消えた記録に
依存したまま次の登録の下で動く。別の repo へ内容を運ぶ(ADR 0399)、比較を付け忘れる経路と子の初回の pickup(ADR 0419)、
新しい checkout にブランチが無い(ADR 0420)、止まった根の出口が無い(#3888)は、どれも「task が、それを作った登録より長生きする」
という1つの前提から出ている。ADR 0420 は3つ目の当て布で、その決定2・4・5 は、照合する記録が削除で消えたことの回避だった。

続ける側を守る理由は見つからなかった。dir を移すだけなら削除は要らない(`path` を直せば ref が基準と同じなので通る —— ADR 0373
決定6)。ADR 0370 決定1 の末尾が根の着地を続けさせた理由は「止めると出口が無い」で、続けたい運用を名指した ADR は無い。前提を外す。

決定はコードと ADR の読みに依り、走らせたものは無い。読みの表と spec が決める点は #3890 に置く。

## 決定

1. **削除の扉は、通すときに、その名前の着地が終わっていない完了 task すべての着地を終える。** 根だけでなく、その下の done の子孫も
   終える —— 根だけ終えると、子孫が次の登録で根として読まれる。扉の確認は、終わる task を名指し、PR を持つものは PR が GitHub に
   残ることを言う。盤面はその PR を merge も close もしない。これで、次の登録に持ち越される、着地が終わっていない task は無い。
2. **終わりの記録は新しい1種類で、PR の有無によらず同じものを書く。** 言うのは「登録が削除されたので着地が終わった」である。
   「この根の着地を終える」の記録(ADR 0399 決定6)は流用しない —— PR を持つ根のための記録で、PR の無い hold・断念の根には
   事実と逆の文になる。
3. **削除で着地が終わった task の下には、子を足さない。** 閉じた PR の根と同じ塞ぎで(ADR 0265 決定6 / ADR 0399 決定6)、出口は
   子の cancel である。その task の内容は保護ブランチに届いておらず、保護ブランチから分かれる子は、直す対象の内容を持たない。
   ADR 0419 が退けた「食い違った根を塞ぐ根の3つ目の種類にする」との違いは、この塞ぎが戻らないことである。
4. **扉は、盤面がその名前でまだ運ぶものを持つ間は拒む。** 今拒むもの(未決着の task、PR をまだ開いていない着地待ちの根、無人
   merge のキューの行)は今どおり拒む —— 終えると盤面の約束を落とす。加えて、後始末の済んでいない完了 task(完了から、解放が
   merge back を撃つまでの間)と、push していない内容を持つ PR の根が在れば拒む。どれも待てば通る拒否である。通して残るのは、
   人間が脇に置いたもの(hold・断念)と、盤面の外で決着するもの(`external` の PR)だけになる。
5. **着地済みの祖先のタスクブランチが名前の場所に無ければ、系譜の読みは読まずに飛ばす。** 内容は保護ブランチに在るので、在る
   場合の読みと結果が同じである。失われた event は書かない。
6. **ADR 0420 は取り下げる。** 根が残らないので、最初の撮りの前の確認も、基準の行が無い名前の「諦める」も要らない。

## 退けた形

- **照合できる記録を削除の後も残す**(完了時と盤面が書くたびの tip を event に残す、#3156)—— 止める場所・出口・repo の食い違いの
  決定はそのまま要り、守る相手の運用(根を抱えたまま checkout を差し替える)を具体で挙げられなかった。
- **扉が、残る根を数えて拒む** —— ADR 0399 が退けた形。GitHub で閉じられた PR の根は決着が刻まれず、扉を永久に止める。
- **子を塞がず、保護ブランチから分かれさせる** —— 決定3 の理由。
- **決定5 を記録で判定する(削除より前に作られたブランチは読まない)** —— 削除の時点を名前ごとに記録する機構が要る。在るブランチが
  別の repo の内容を持つ場合は、ADR 0419 決定5 が既に止める。

## 帰結

- 開いた PR や hold・断念の根を持ったまま checkout や repo を差し替えると、その着地は削除の時点で終わる。PR は GitHub に残り、
  人間はそこで merge できるが、盤面は修理の push も merge の観測もしない(ADR 0407 の帰結と同じ線)。hold・断念の根は再開できない。
  手順書の「別の repo で登録し直すと、PR が開いたままの完了 task は食い違いの question で止まる」は、この形に書き直す。
- ADR 0370 決定1 の末尾(基準の行が無い名前に根が残る場合)は対象が無くなる。誤った登録し直しを戻す道(#3888)は、塞ぐ根が残ら
  ないので開く見込み(spec が確かめる)。
- ADR 0399 決定5(根の食い違いの止まり)は残る —— 出元 repo の差し替えは削除を通らない。ADR 0419 決定5 も残る —— 同じ checkout を
  別の repo で登録し直すと、着地済みの祖先のブランチは在り、新しい repo がその内容を持たなければ子はそこから分かれる。
- 限界: 決定4 の2つの追加(#3889 と、push 前の merge back)のうち、後者が届くかは読んでいない。決定3 の塞ぎの行・告知・一覧・
  cancel の範囲は今 PR の番号に結び付いており、PR の無い task での形は spec が決める。
- ADR 0226・ADR 0234・ADR 0370 決定1・ADR 0373 決定14・ADR 0380 決定3・ADR 0399 決定6・ADR 0407 決定1・ADR 0419 決定5・ADR 0420 に
  Status 追記を置いた。
