# Spend-down の対象はウィンドウの集合で、両方を同時に外せる

issue #302 の triage(2026-08-20)で決着。ADR 0030 は Spend-down を「対象ウィンドウ(session / week)を
一つ選ぶ」形で定め、原則「使い切ってよいのは、もうすぐ失効する予算だけ」から、他方の線は必ず残るとした。
実運用では**実験時に両方の線を外したい**場面が多く、片方ずつ切り替える迂回は意思を表現できていない。

## 決定

1. **Spend-down の状態は「有効なウィンドウの集合」**にする。session と week を独立に有効化・取り消しでき、
   両方有効なら盤面に残る線は100%ハードキャップだけになる。「both」という第三の値は作らない — 集合なら
   各ウィンドウが自分のリセットで個別に自動失効し(ADR 0030 の「取り残された状態は必ず放置」はそのまま
   ウィンドウ単位で成立)、session が先に失効しても week 側は生き続ける。
2. **fable 線は従来どおり week に従う**。week が有効なら fable の線も外れ、session だけでは外れない。
3. **原則の読み替え**: 「使い切ってよいのは、もうすぐ失効する予算だけ」は、Spend-down を**一つしか選べない
   理由**ではなく、**人間が何を選ぶべきかの指針**に格下げする。両方外せば週の生きた予算も燃えることは
   承知の上での人間の選択であり、システムは止めない。Pause と同じく人間専用・WebUI 専用の盤面状態で、
   管理MCP には開かない(ADR 0088 の線と同じ)。

## 却下した案

- **enum に "both" を足す** — 1行のまま済むが、session が先にリセットしたときの挙動(week だけに縮退するのか、
  全体失効か)を別途決める必要があり、集合モデルならその問いが消える。
- **別物の「実験モード」(全ペース線オフ、手動でしか戻らない)** — 自動失効しない状態は放置事故の温床で、
  Spend-down の意味論と二重になる。求められているのは Spend-down の対象が足りないことであって新しい状態ではない。
- **機能追加なし(offset を大きくする / 片方ずつ切り替える運用)** — offset は「予約」であって「線を外す」
  意思の表現ではない。
