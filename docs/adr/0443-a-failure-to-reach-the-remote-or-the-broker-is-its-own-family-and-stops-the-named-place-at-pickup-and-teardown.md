# remote か仲介に届かない失敗は1つの族として型を持ち、pickup と後始末では名前の場所を止める

2026-11-28 の triage → grilling(issue #3999、#3943 の実装レビューの派生)で決定。ADR 0433 決定2 で、無人の過程の catch の型の無い
失敗は盤面のバグの行き先へ行くようになった。網に出る失敗(remote や仲介に届かない、断られる、remote にブランチや object が無い)は
どの族の型も持たないので、#3944 / #3945 が catch を型の付いた失敗に絞ると、pickup の修復案内(ADR 0067 決定2)が落ち、後始末の
網の失敗は盤面全体の落ちた後始末になる。ADR 0441 決定4 はこの型を決めずに残していた。数えた投げ手と段の表は #3999 に置く。

## 決定

1. **remote か仲介の側を直すか待てば通る失敗は、新しい族「remote の側の失敗」の型を持つ。** 網に出る git の一般の失敗(stall・
   ssh の拒否を含む)、remote に object が無い失敗、仲介に届かない・断られる・不正な応答、温めた token の期限切れ、remote に
   ブランチが無い失敗がこれに入る。名前の場所の側の失敗にも git の道具の失敗にも入れない。
2. **pickup と後始末の解放は、remote の側の失敗を名前の場所1つの Quarantine にする。** pickup では、git の道具の失敗と同じく修復案内を
   付ける。案内は今どおり Quarantine の瞬間の仲介の probe で作り、型は案内を付けるかどうかだけを決める。後始末の行き先を決めた ADR は
   これまで無かった(`settleBranches` のコメントの ADR 0052 は ff できない分岐の Quarantine を決めたもので、網の失敗には触れていない)。
3. **pickup の門の包み(失敗した場所を運ぶ型)は残し、catch は包みの中身の型で行き先を分ける。** host の失敗は場所を止めないので
   包まずに通すが、remote の側の失敗は場所を止めるので、どの場所かが要る。
4. **網に出る git を起動する前段の fs の失敗も、disk が満ちたら host の失敗にする**(ADR 0433 決定5 を前段に当てる)。clone が自前で持つ
   cwd の確認は消し、起動口の cwd が無い失敗の型1つにする(ADR 0441 決定1)。
5. **宣言が無い失敗は2つに分ける。** 出元 repo の宣言が無いのは名前の場所の設定を直せば通るので、名前の場所の側の失敗(ADR 0433
   決定4)。呼び手の門の後にしか届かない「宣言の repo が無い」は型を付けない不変条件の門(ADR 0433 決定6)。
6. **着地の段は変えない。** 着地の網の失敗は昇格失敗 question か ADR 0376 の読めなかった head の文へ行き、盤面のバグと同じ行き先なので、
   型が付いても行き先は動かない。

## 退けた案

- **名前の場所の側の失敗に入れる** —— その族は修復案内を付けない(#3945)ので、ADR 0067 決定2 の案内が落ちる。案内を付けるかどうかが
  族で分かれる以上、同じ型にすると catch が分けられない。
- **git の道具の失敗に入れる** —— 網や仲介の不達が「手元の git が壊れた」と読まれる。仲介の失敗は git でもない。
- **後始末の網の失敗を落ちた後始末にする** —— 網の不達は場所1つの故障で、盤面全体を止める理由が無い。pickup と行き先を揃えれば修復の
  経路も1つになる。
