# publish は覚えた repo も ref と同じく予告し、宣言と origin が揃ったときだけ畳む —— 中断の出口は巻き戻しの1つ

2026-11-21 の triage → grilling(issue #3336)で決定。publish(ADR 0066 決定2)は1つの await の無い区間で、checkout の origin と写し、
基準の行の覚えた repo(ADR 0378 決定10)、registry の `repo:` を書き、失敗は同じ process の catch が巻き戻す(ADR 0066 決定5)。await の無い
区間が防ぐのは交差であって process の死ではない。写しは予告と畳みで死を越える(ADR 0243 決定5)が、覚えた repo の戻し先は memory の中にしか
無い。registry の書き込みの途中で死ぬと、覚えた repo は宛先、宣言は無しで残り、検査は「`repo:` を戻せ」と案内する —— 人間が origin を外して
巻き戻そうとしても、覚えた repo を人間は戻せない。ADR 0389 決定2 は盤面 DB の拒否を投げた所で同期に終えるので、区間の中の DB の書き込みは
どれも catch を飛ばす出口になった(覚えた repo の UPDATE が拒まれると、origin と push だけが残る)。再現は #3336 の本文とコメントに置く。

## 決定

1. **覚えた repo も、書く前に予告する。** publish は覚えた repo の行を `予告の前の値|宛先` の2値にしてから `remote add` を撃つ。位置は写しの
   予告と同じ DB の書き込みで、`remote add` より前である —— 予告が拒まれれば、痕跡が1つも無いうちに process が終わる。
2. **2値の間、どちらの値も違いと読まない。** 覚えた repo の検査は、宣言が予告の前の値でも宛先でも通す。それ以外の repo は今どおり拒む ——
   registry の手編集で別の repo へ移る経路は作らない。
3. **畳むのは、宣言と origin が揃ったときだけ。** 揃うとは ADR 0378 決定3 の述語(origin の有無が宣言と一致し、同じ repo を指す)が通ること
   で、揃った宣言の側へ畳む。宣言だけで畳まない —— remote-backed の registry は push が届いてから写しを書く前に死ねば古い宣言を見せ、古い
   値に畳んだ行は戻らない。origin は checkout の実物なので古くならない。publish の成功と catch の巻き戻しも、終わりに同じ規則で畳む。
4. **中断の出口は巻き戻しの1つ。** registry に届く前に止まった publish は、宣言が無しで origin がある —— 案内は今の origin の検査の文
   (`remote.origin` を外す)で、外せば揃って畳まれる。完了させたい人間は、その後もう一度 publish する(宛先へは同じ sha の push なので
   up-to-date で通る。残った写しと送るブランチが名前で衝突する #3411 の形は別)。registry に届いた後に止まった publish は、宣言と origin が宛先で揃っているので、人間を待たずに完了として畳まれる。

## 退けた形

- **次の起動で盤面が registry へ書き足して完了させる** —— 起動に自動の registry 書き込みが1つ増え、registry に届いたかを確かめる読みも要る。
- **次の起動で盤面が巻き戻す** —— 宛先に載ったブランチは戻せないので、巻き戻しきれない。
- **書く順番を入れ替える** —— 覚えた repo を registry の後にすると、間で死んだとき「purely-local なのに `repo:` がある、消せ」と案内する。
  どちらの順でも、間の状態に正しい案内が1つに決まらない。

## 帰結

- 限界: 中断した publish が宛先に push したブランチは、盤面が消さない。push の後に registry の commit が落ちる今の通常の失敗でも同じものが
  残る。盤面に GitHub 上のブランチを消す扉は作らない。
- 盤面の外への書き込みと記録を catch / finally で揃える他の箇所(#3199 ほか)は、族の根の issue が持つ。この ADR はその先例である。
- 実装は #3336 のコメントの spec。#2868 は #3336 で塞ぐ —— ADR 0389 の即時終了で悪化するのは、この族の中では publish だけである。
