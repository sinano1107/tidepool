# PR の決着は PR を開いた根に刻み、読み手は1本の述語を通る —— `external` の根は内容で終わり、読めなければ止まる

2026-10-16 の grilling(issue #2054、同日の triage sweep が立てた family の根)で決定。PR の決着(merge された・閉じられた)を
書く経路は2つの id に割れていた —— 人間の `merge` 回答と merge question 面の観測は question の id に、無人 merge の tick と
収束は根(PR を開いた work)の id に刻む。読み手は task id だけ(収束の閉じた根の除外・観測の重複除け・retry)、両方の join
(収束の merge 済み述語、#2034 がそれを写した Precedent)、何も読まない(pickup・人間面)に分かれ、取りこぼしが読み手ごとに
issue になった(#2026 / #1907 / #1822 / #346)。書き手と読み手の表、`gh` の読み取りの実測は #2054 のコメントに置く。

## 決定

1. **PR の決着は、その PR を開いた根の id に刻む。** 人間の `merge` 回答も、遅い走査・回答受理直前のバックストップの観測も、
   workspace と PR 番号で引いた根に `pr_merged` / `pr_merge_observed` / `pr_close_observed` を書く。question の側に残るのは
   人間の判断(`question_answered`)だけで、観測で閉じた question は回答なしの done のまま(ADR 0079 決定1 の「判断は question 面に
   住む」はそのまま)。PR の決着でない観測(昇格の観測・提案の前提の崩れ・quarantine の解除)は今どおり question の id に残る。
   `merge` 回答の `question_answered` と `pr_merged` は1つのトランザクションで書く。
2. **根の PR の決着を答える読みは1本。** 収束・pickup・Precedent・人間面はその述語を呼び、自分の SQL で引き直さない。読み手ごとの
   引き直しが取りこぼしの出所だった。観測で閉じた question の見え方もこの述語から導く —— merge question が回答なしで done なら
   観測で閉じたもので、どう決着したかは根の記録が言う。
3. **`external` の根は内容で終わる。** 収束が「根の内容は保護ブランチにある」と git で確かめたとき、PR の有無によらず
   `landing_finished` を根拠(merge の記録 / 内容)つきで1回刻み、以後候補から外す。GitHub は読まない(ADR 0079 決定2 のまま)。
   内容で終わることは決裁を引退させない —— 無人 merge キューの行と開いた merge question を閉じるのは PR の状態の読み取り
   (tick・走査・バックストップ)だけで、執行 / 観測の記録もそこが書く。
4. **バックストップが PR の状態を読めなければ、`merge` も `hold` も拒む。** question は開いたまま残り、拒否文は読めなかった事実と
   理由を言う。「観測しなかった」に倒すと、merge 済みの PR への `hold` が決定として残り、merge はどこにも記録されない。
   読めないときに進まない形は、無人 merge キュー(ADR 0229 決定3)と積み残し(ADR 0242 決定3)と同じ。
5. **落ちた後の merge は、merge した名義で執行と観測を分ける。** PR の状態と同じ1回の読み取りで merge した名義を読み、盤面自身の
   名義なら `pr_merged`(執行)として根に刻む。merge question では人間の回答の記録が失われているので、question は観測の経路で
   閉じ、決定2 の導きで「盤面の merge だが回答の記録は無い」と読める。merge の前に意図を予告する形は採らない。
6. **盤面の外で閉じられた根の付帯子は cancel せず、pickup が飛ばす。** 飛ばすのは、lineage の帰り先が閉じた記録を持つ根のブランチで、
   根の内容がまだ保護ブランチに無い子(ADR 0250 決定1 の前の場合)。観測の時点で盤面名義の判断行を decision log に流し、閉じた PR と
   走らない子、出口を2つ言う —— GitHub で reopen して人間が merge する(届けば子は自分で根になる)か、子を cancel する。そのために
   人間の直接 cancel の範囲を広げ、閉じた根の付帯子は人間が直接 cancel できる(ADR 0198 が守った「規則が要求する入力」は根が死んだ
   時点で意味を失う)。飛ばす述語と cancel できる述語は同じ1本。
7. **人間面は3つ。** done の work の行に着地の状態(キュー / merge question / 盤面の merge / 外での merge / 閉じた / 取り下げ /
   内容で終了)を1語で出す。観測で閉じた question にはその印を出し、回答の応答も同じ形で返す(tier 提案の 400 も揃える)。
   agent / workspace の削除の扉の拒否は、着地を待つタスクを数でなく id で名指す。

## Considered options

- **2つの id に書いたまま、読み手が全部 join する**(#2034 の形を広げる) —— join を6箇所に写す。取りこぼしの出所そのもの。
- **events に workspace と PR 番号の列を足し、PR を key にする** —— 未公表なので可能だが、PR を第一級の key にする理由が今は無い。
- **`external` の PR も GitHub で観測する** —— ADR 0079 決定2 を破る。内容の比較は今すでに毎回やっている。
- **読めないとき `hold` だけ受理して「未検証」の印を残す** —— 人間面に3つ目の状態を増やす。
- **merge の前に `question_answered` と「merge 中」を予告し、再起動後に畳む**(ADR 0243 の形) —— PR が `OPEN` だった(merge の前に
  落ちた)とき閉じた question を開き直す畳みが要る。merge した名義を読めば、ADR 0243 が退けた前提(「GitHub の PR は書けたか分からない」)
  は崩れる。
- **閉じた根の付帯子を盤面が cancel する**(sweep の案) —— 誤って閉じた人間の自然な直し方(reopen して自分で merge)を潰す。
  「登録し直す」操作は存在しない —— 閉じた根の下に子は足せず、新規登録は保護ブランチから始まる。
- **cancel せず、直接 cancel の範囲も広げない** —— 盤面名義の付帯子は人間が片づけられず、木が永久に残る。
- **閉じた根の付帯子を question で問う** —— 判断は人間の操作(reopen + merge か cancel)に残り、question の種類を増やさない。

## 帰結

- #2026 / #1822 の形(question の id に刻まれた決着を根の側で読めない)は決定1 で消える。#1849 は決定3、#2037 は決定4、#1820 は
  決定5、#1907 は決定6、#1735 / #346 は決定7。spec #1839 の「開いた PR の根の子孫は候補にしない」は決定3 で入れられる。
- reopen で盤面の決裁に戻す線(ADR 0229 決定3)は開け直さない。`escalate` には `hold` があるので理屈は立つが面ごとに規則が割れる。
  別 issue に残す。
- `hold` は恒久の「着地しない」決定(ADR 0053)で、その後の外での merge は観測しない。収束からは決定3 で抜ける。
- ADR 0079 決定2・ADR 0198・ADR 0236・ADR 0243 に Status を追記した。実装は spec が切る(#2054 のコメント参照)。
