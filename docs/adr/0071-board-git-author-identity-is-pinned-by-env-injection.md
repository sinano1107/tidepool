# 盤面の git コミット名義は env 注入で固定する — ambient env に負けない

issue #312 のトリアージ(2026-08-13)で決定。実環境動作確認 第3段(ADR 0052)で、tidepool 自身を workspace
にした worker セッション内で `npm test` を走らせると、盤面のコミット名義(`tidepool`)を検証するテスト8件が
worker のエージェント名(`tako`)を観測して落ちる、とエージェント自身の handoff が報告した(PR #308)。

原因は git の優先順位である。盤面のコミット名義は `-c user.name=tidepool` 相当のフラグで付けていたが、git は
`GIT_AUTHOR_NAME` / `GIT_COMMITTER_NAME` 等の**環境変数を `-c` 設定より優先する**。worker セッションは spawn
時にエージェント名義の4変数を env に注入する(issue #53 / ADR 0024)ため、その env を継承して走る盤面コードの
コミットは worker の名義で記録される。worker セッション固有の話ではない — ambient に `GIT_*` が立っている
任意の環境(CI、人のシェル)で盤面コミットが誤名義になる潜在バグであり、壊れているのはテストではなく実装側で
ある。

## 決定

**盤面のコミット名義はフラグではなく env 注入で固定する。** 盤面がコミットを作る git 呼び出しは、4変数
(`GIT_AUTHOR_NAME` / `GIT_AUTHOR_EMAIL` / `GIT_COMMITTER_NAME` / `GIT_COMMITTER_EMAIL`)を呼び出しの env に
明示注入する — worker の名義を spawn 時に同じ4変数で固定している機構(ADR 0024 / issue #53)と対称であり、
どちらの層も「継承した環境が何を運んでいても、名義は自分の設定から機械的に決まる」を満たす。

**機構は1本のみ。** env 注入に一本化し、`-c` フラグとの併用はしない — 2本あると、片方だけを直した呼び出しが
静かに紛れ、どちらが効いているかが呼び出しごとに変わる。

これにより3層の名義(盤面 = `tidepool`、GitHub の merge = machine user、worker = エージェント名)は環境に
依らず成立し、名義を検証するテストは「実際の配線」の検証のまま worker セッション内でも緑になる。

## 退けた対案

- **テスト側を環境非依存に書き換える**(期待値を注入する、コミットを撃つ層をテストダブルにする)— テストの
  期待は正しく、壊れているのは実装側。検証を弱める方向は ADR 0024 の名義の線を守る番人を外すことになる。
- **spawn の identity を tidepool にする** — ADR 0024 が分けた「誰が書いたか」を潰す。3層の名義が分かれて
  いることは実環境動作確認 第2段で価値が実証済みである。
- **`npm test` 実行時だけ `GIT_AUTHOR_NAME` を固定する** — 症状だけが隠れ、潜在バグ(ambient env で盤面
  コミットが誤名義)はそのまま残る。テストが実配線を検証する意味も失われる。
