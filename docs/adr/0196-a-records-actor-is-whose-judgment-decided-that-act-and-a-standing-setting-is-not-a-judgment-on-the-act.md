# 記録の行為者はその行為を決めた判断の主であり、常設の設定はその行為についての判断ではない

2026-10-05 の grilling(issue #1359、発端は #1357 / ADR 0194)で決定。`auto_if_ci_green` の無人 merge で盤面が merge した
`pr_merged` が human 名義で記録されていた。ADR 0194 は登録者を「その task の存在を決めた判断の主」としたが、event の
行為者に同じ読みを当てるかは決めていなかった。調べた経路は #1359 に置く。

## 決定

1. **記録の行為者は、その行為を決めた判断の主であり、実行した主体ではない。** escalate の回答による merge も、GitHub
   上で実行するのは盤面だが、`pr_merged` は human で書かれている。この欄は今もこの意味で使われていて、この決定はそれに
   名前を付けるものである。GitHub 上の名義は実行者を表し、判断の帰属は盤面の記録が運ぶ(CONTEXT.md GitHub identity)。
   行為者を実行者と読むと、記録は GitHub の名義を写すだけになり、判断の帰属を運ぶ場所がなくなる。
2. **その個別の対象について判断した主体がいなければ、盤面の名義にする。** ダイヤル・保護・周期のような常設の設定は、
   個別の対象についての判断ではない。常設の設定と盤面の規則だけで起きた行為は、盤面の行為である。ADR 0194 は既にこの線で
   分けている。人間の異議を盤面がタイムアウトで執行したもの(決定4)は human のままで、人間が選んだダイヤルの下で盤面の
   規則が立てる merge question(決定3)は盤面の名義である。
3. **`auto_if_ci_green` の無人 merge の `pr_merged` は盤面の名義にする。** 経路は `board` のまま。この PR を merge すると
   判断した人間はいない。同じ watch が CI red で立てる merge question は既に盤面の名義なので、merge だけを human にすると、
   同じ watch の中で名義が割れる。

## Considered options

- **human(ダイヤルを選んだ人間の判断の執行)**: 決定2 の線で退けた。人間が複数になると(#362)、ダイヤルを選んだ人間と
  この merge のときにいる人間が別人になりうるので、「どの人間か」が決まらない。
- **PR を開いた agent(authority profile は agent のもので、無人 merge は agent の決裁権の行使)**: agent は完了しただけで、
  merge について何も判断していない。CONTEXT.md の Merge ダイヤルの「決裁権内」という書き方がこの読みを許していたので、
  書き方を直した。

## 帰結

- 今日この行為者を読むものは無い(`pr_merged` の読み手は kind と `pr_number` しか読まない)。変わるのは記録だけである。
- キューに入った後でダイヤルが取り下げられても盤面が無人で merge する欠陥は、名義の問題ではないので #1392 で扱う。
