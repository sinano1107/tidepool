# 上の seam が写像を言うのは production に読み口のある記録だけで、assert の中の盤面 db は lint で落とす

2026-09-25 の grilling(issue #946)で決定。ADR 0107 決定4 は harness の `t.db` を setup に限ったが、#518 の一括置換の後に
3 PR(#545 / #918 / #936)で5箇所、`t.db` で events を読んで assert する形が入った。うち2箇所は決定3 と決定4 の衝突から
来ている — 決定3 は経路タグを上の seam が言う写像に挙げるが、task を持たない盤面スコープの event にはサーバ境界の読み口が無い。
一方、同じく盤面スコープで経路を直書きする memory / meta-review 設定の route は、上の seam で経路を言わずに済ませていた。
箇所ごとの調査は #946 のコメントに置く。

## 決定

1. **上の seam で写像(経路タグ・印の受け渡し)を言うのは、その記録を読む production の読み口があるときだけ。** 読み口が
   あればその口で言う — 回答が刻む `question_id` の印は、meta-review の材料の読み口から適用が外れることで言う。読み口の無い
   記録の写像は上の seam では言わない。誰も読まない書き込みを assert しても守るのは消費者のいない値であり、書き込み自体は
   ドメイン層の export が受け取った値を記録することで言える。ADR 0107 決定3 の写像の列はこの条件つきで読む。
2. **決定4 に例外は設けない。** 「読み口の無い記録に限り `t.db` で assert してよい」は、例外そのものが隣を写す先例になる
   (ADR 0107 決定6 が一括置換の理由にした形)。
3. **決定7 の lint を足す。** `expect(...)` の引数の中に盤面 handle の `db` が現れる形を Biome の plugin で落とす。再発が
   実際にコードに入ったことを決定7 の「痛み」とみる。helper 経由で期待値を作る形は漏れるが、setup での読みと機械的に区別
   できないので許容し、seam 合意とレビューに任せる。

## Considered options

- **人間向けに盤面 event の読み口を足す** — 経路の記録の目的(事後の追跡)には沿うが今は呼び手が無く、テストのための面になる。
  追跡の面の欠落は別の問題として観測を待つ。
- **lint を足さずレビューに任せる** — 5箇所は入った PR ではなく、後続 issue(#919)の Standards レビューで見つかった。
