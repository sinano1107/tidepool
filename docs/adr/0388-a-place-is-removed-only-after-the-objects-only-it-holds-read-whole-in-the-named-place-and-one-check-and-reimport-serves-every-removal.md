# 場所を消すのは、その場所だけが持つ object が名前の場所で欠けも破損も無く読めてから —— 確かめと取り込み直しは1つの手で、消す箇所の全部が撃つ

2026-11-21 の grilling(issue #3222、#3153 の ponytail-review の派生)で決定。完了の解放は、門の記録した tip の tree を読み、tip が
`task/<id>` から辿れれば task の checkout を消していた。tree の読みは blob を開かないので、名前の場所に blob が欠けていても checkout
—— その blob の最後の写し —— が消えた。盤面自身は ref から届く object を消さないが、名前の場所は人間の repo で、disk・人間の手・
`--shared` の借り元の prune で object を失いうる。checkout と作業台を消すほかの箇所も、確かめていたのは commit の在処と祖先関係だけ
だった。実測と消す箇所の表は #3222 に置く。

1. **場所を消す前に、消せば失う object が名前の場所で欠けも破損も無く読めることを確かめる。** 確かめる集合は「消す根拠の ref の閉包の
   うち、その場所が自前の object store に持つ object」—— 借りている object は消しても失われない。起点の記録に依らないので、task の
   checkout と作業台で同じ定義になる。確かめ方は門と同じく集合を pack に組む形で、欠けは `rev-list` が、破損は `pack-objects` が落とす
   (`rev-list` だけでは zlib の破損を素通しする)。ADR 0369 決定7 の「成果が着いている」はこの確かめを含む。
2. **確かめと取り込み直しは1つの手で、消す箇所の全部が撃つ。** 完了の解放(門のある経路)、退避(checkout の commit 済みの tip と、
   盤面が作業ツリーから staging repo に書いた WIP の2つの源を、それぞれその自前の store で)、作業台の削除(開き直し・取り込みの後・
   `done` の後・workspace の削除)。作業台では、持ち主の判定が消す根拠にした ref —— tip、stash の段、`board/*` 以外の branch —— を
   すべて根拠の ref に数える。
3. **欠けていれば、検証済みの写しの pack を名前の場所へ直に入れて(`index-pack --strict`)確かめ直す。** fetch では直らない —— 名前の
   場所は commit を既に持つので何も送られない(実測)。
4. **取り込み直しても揃わなければ消さず、どの場所でも workspace の Quarantine に落とす。** 理由文は欠けた object と残した場所の path、
   直せないときの出口(決定5)を名指す。task の checkout は済んでいない解放(ADR 0369 決定7)で、受理のやり直しが決定2 の手を撃つ。
   作業台も同じく残し、受理のやり直しが残った作業台に同じ手を撃つ。止め方を各箇所の今の出口に任せない —— 取り込みの後の削除は ref も
   event も書いた後なので回答を拒めず、今の「読めなければ残す」は書く先が欠けた object を指したまま誰にも告げない。
5. **消す場所が読めない(`.git` が無い・自前の写しが壊れている・上限超過)ときは、根拠の ref の閉包全体を名前の場所で確かめ、通らなければ
   残す。** 集合を出せなくても、作業ツリーにはファイルとして最後の写しがありうる。閉包全体は repo の大きさに比例するが、この稀な経路でしか
   走らない。場所そのものが無ければ失うものは無く、解放する —— 人間が自分で checkout を消すことが、揃わないまま止まった解放の出口になる。
6. **完了の門の取り込み(`--not --alternate-refs`、ADR 0364 決定1)は変えない。** 門が除外で取りこぼした object(名前の場所で門の前から
   欠けていたもの)は、決定1 の確かめが捕まえ決定3 が補う。門を決定1 の集合に変えると、worker が `-l` 無しに repack しただけで集合が
   閉包全体に膨らみ、門が上限超過で task を落としうる。

## Considered Options

- **何もしない**(名前の場所の故障は盤面の外)—— 失うのは成果そのもので取り戻せない。
- **起点(タスクブランチの pickup 時の値)から届かない分を確かめる** —— 作業台には開いた起点の記録が無く、場所ごとに集合が割れる。
- **閉包全体を毎回確かめる** —— 解放のたびに repo の大きさに比例する。起点側の欠けは名前の場所の故障で、その場所の成果ではない(#3484)。
- **欠けたら Quarantine だけ立てて人間が直す** —— `hash-object -w` 級の git の手を人間に求める。
- **門の取り込みも決定1 の集合に揃える** —— 決定6。
- **止め方は各箇所の今の出口に任せる** —— 決定4。
- **消さずに一定期間保管する** —— 作業ツリーごとの保管で disk が解放ごとに増え、空にする持ち主と寿命が新たに要り、欠けは誰にも告げない。
- **確かめずに毎回、自前の object を名前の場所へ入れる** —— 人間の repo に解放ごとに pack が増え、壊れた loose と正しい pack のどちらを git が読むかに依るので確かめは残る。

## Consequences

- Status 追記: ADR 0369 決定7(「着いている」に決定1)、ADR 0364(取り込み直しは fetch でなく pack を直に入れる —— 決定3)、
  ADR 0359 決定5 / ADR 0367 決定3(完了済みで読めない checkout も消す前に決定5)、ADR 0382 決定5(消す前に決定1・4、workspace の削除の扉も拒まず決定4)。
- 借りない checkout(Interview の root)では集合が面接室の閉包全体になり、解放のたびに門と同じ大きさの確かめが走る。
